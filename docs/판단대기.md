## 열린 판단

### A1(개정) — 두뇌를 Claude Code 헤드리스로 두는 구조 확정
- 사용자 답(1차): "지금 내 맥에 자동 구독 계정 로테이트 붙어있는데 이거 pi에 붙이면 되는거 아니야? 클로드 코드만 쓸수 있는건가? API 요금때문에 못붙여"
- 조사 결과:
  - 로테이터 = `claude-swap`(`cswap`, 메뉴바 LaunchAgent). **키체인의 Claude Code 자격증명을 4개 계정 사이에서 바꿔 끼우는 방식**이라 Claude Code 에만 효과가 있다.
  - Pi 는 별도 `auth.json` 을 쓰고, Pi 문서에 "Claude 구독을 서드파티 하네스에서 쓰면 **플랜 한도가 아니라 extra usage 종량 과금**" 이라고 명시돼 있다. 토큰을 옮겨 넣어도 요금이 붙는다. Claude Code 로 위장하는 방식은 약관 위반이라 설계에 넣지 않는다.
  - 결론: **구독·로테이션을 그대로 쓰려면 Claude 호출은 Claude Code 자체(`claude -p` 헤드리스)가 해야 한다.** Pi 는 그것을 커스텀 프로바이더로 감싸 터미널·상태기계·워처·정리를 맡는다(설계 §6-0). API 요금 0. 보조로 ChatGPT 구독의 Codex 모델을 Pi 에 등록해 두면 4계정이 전부 한도일 때 가벼운 턴을 잇는다(추가 요금 0).
- 선택지:
  - ① 위 구조 확정 — Pi 커스텀 프로바이더 ↔ `claude -p --resume`, Pi 도구 끔, Claude Code 의 도구·MCP·스킬·메모리·서브에이전트 사용 (**추천**)
  - ② Pi 자체 모델을 Codex(gpt-6-astra, ChatGPT 구독)로 두고 Claude 는 `claude -p` 도구 호출로만 — Pi 가 더 "네이티브" 하지만 두뇌가 Codex 가 되어 "판단·디자인은 Claude" 원칙과 어긋남
  - ③ 다른 생각(적어 주기)
- 위험: `claude -p` 헤드리스가 대화형과 다르게 동작할 수 있어 P1.5 스파이크로 먼저 검증한다. 안 되면 여기로 다시 올린다.
- 막힌 작업: P1.5(프로바이더). P1·P2·P4 는 진행 가능.
