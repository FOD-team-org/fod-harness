## 열린 판단

### A1 — 오케스트레이터(Pi 에이전트) 모델의 과금 경로 (가장 중요)
- 배경: Pi 는 자체 모델 호출이 필요하다. Pi 문서(providers.md)에 "Claude Pro/Max 구독을 Pi 에서 쓰면 플랜 한도가 아니라 **extra usage 로 토큰당 과금**" 이라고 명시돼 있다. 지금 Claude Code(Fable) 세션은 구독 플랜으로 돌지만, Pi 에서 Claude 를 쓰면 별도 요금이 붙는다. 무인으로 오래 도는 오케스트레이터라 토큰 사용량이 크다.
- 선택지:
  - ① Anthropic API 키(`ANTHROPIC_API_KEY`) — 종량 과금, 가장 단순·안정. 오케스트레이터 Opus 5.5.
  - ② Claude Max OAuth(`/login`) — 위와 같은 종량(extra usage), 키 관리만 편함.
  - ③ Pi 는 껍데기(상태기계·워처·정리)만 하고 두뇌는 `claude -p --resume`(헤드리스 Claude Code, 구독 플랜) 서브프로세스로 매 단계 호출 — 구독 안에서 돌지만 구조가 복잡하고 Claude Code 내부 동작에 의존.
  - ④ 오케스트레이터를 ChatGPT 구독의 Codex 모델(gpt-6-astra)로 — Pi 가 공식 지원(OpenAI 승인). 추가 요금 없음. 단, "디자인·판단은 Claude" 원칙과 어긋나고 검수 이중성이 약해짐(디자인 서브에이전트만 Claude API).
- 추천: **①** (구조가 가장 튼튼). 비용이 걱정이면 ④ 를 오케스트레이터로 두고 디자인·검수만 Claude API 로 쓰는 절충. ③ 은 권하지 않음.
- 막힌 작업: P1 이후 전부
- 답:
