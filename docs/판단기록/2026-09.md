### A19 — WisePharm 이관 순서와 레이아웃 (rev 1)
- 결정일: 2026-09-26
- 답: 1
- 해석: 레포마다 하네스 루트를 두고 backend 파일럿 → app → web 순서로 이관한다. 첫 task 는 `format:check` 추가, 그다음 엔드포인트 동등화 잔여 1건
- 반영: 판단 적용; 코드 커밋 없음(사용자 문서 직접 기입, 메인 세션 반영)
- 배경: 하네스는 루트 하나에 git 레포 하나다. WisePharm 은 레포 3개가 한 기능을 나눠 맡는다(스키마·문구 원본 web → backend → app). 레포별 위험도가 다르다: backend 는 push 해도 CI 만 돌고 운영 `.env` 가 없다. web 은 main push 가 운영 배포이고 루트 `.env` 가 운영 DB 다. [설계](../이관/2026-09-25-WisePharm-이관-설계.md) §2.
- 선택지:
  ① 레포마다 하네스 루트, backend 파일럿 → app → web 순서(첫 task = `format:check` 추가, 그다음 엔드포인트 동등화 잔여 1건)
  ② 레포마다 루트, 세 레포 동시 이관
  ③ web 하나를 루트로 삼고 나머지를 딸린 레포로(하네스 코드를 크게 늘려야 함)
- 추천: ① — 배포·운영 DB 와 떨어진 backend 에서 실제 레포 흐름(워크트리 의존성, 명의 훅, 검증 시간)을 먼저 확인한다. web 은 비밀 파일 읽기 차단(H11)과 web 판단 뒤에 한다.
- 막힌 작업: WisePharm 이관
