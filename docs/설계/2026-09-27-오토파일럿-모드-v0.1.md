# 오토파일럿 모드 설계 v0.1 (2026-09-27)

> 사용자 요청(2026-09-27): "너의 권장사항으로만 진행하는 autopilot 모드도 만들어줘".
> 켜 두면 하네스가 사용자 대신 **두뇌의 추천안**으로 판단에 답하고 멈추지 않고 진행한다. 되돌리기 어렵거나 밖으로 나가는 동작은 켜져 있어도 사용자 몫이다.

## 0. 요약

| 멈추는 곳 | 지금 | 오토파일럿 |
|---|---|---|
| 선택형 판단(추천 번호 있음) | 사용자가 `- 답:` 을 채울 때까지 대기 | 유예 시간(기본 30초) 뒤 추천 번호로 자동 답 → 적용 → 진행 |
| 승인 필수 판단(운영 배포·push·DB 마이그레이션·결제·스토어·비밀값 등) | 대기 | **대기(바뀌지 않음)** |
| 추천 번호 없는 판단, 재질문, 후속 질문 | 대기 | 대기 |
| 두뇌의 `대기: 사용자`(인터뷰·기획 단계) | 대기 | 두뇌에게 "추천안으로 정하고 진행" 답을 자동으로 보낸다. 연속 2회까지만 보내고, 그다음은 대기 |
| PROJECT_READY(기획 끝, 개발 시작 전) | 사용자가 `/develop-start` | 자동 `/develop-start` |
| DONE_ALL(백로그 끝) | 대기 | 대기. 새 범위는 사용자가 정한다 |
| 진행 정체 판단(자동 턴 한도) | 대기 | 같은 task 에서 **1번만** 자동 재개. 두 번째 정체는 대기 |

- 자동 답은 판단기록에 `답 출처: 오토파일럿` 으로 남는다. 알림과 창에 한 줄로 알린다.
- 켜고 끄는 것은 사용자만 한다. 두뇌는 켤 수도 끌 수도 없다.

## 1. 켜고 끄기

| 명령 | 동작 |
|---|---|
| `fodh autopilot on [--for 8h] [--max 30]` | 켠다. `--for` 가 지나거나 자동 답이 `--max` 에 이르면 스스로 꺼진다(기본: 기간 없음, 30개) |
| `fodh autopilot off` | 끈다. 유예 중이던 자동 답도 취소한다 |
| `fodh autopilot status` | 켜짐 여부, 켠 시각, 남은 기간, 자동 답 수/한도, 유예 중인 판단 |
| Pi 창 `/autopilot on\|off\|status` | 위와 같다 |

- 상태 파일: `.pi/harness-autopilot.json`.
  - 필드: `{ enabled, since, until?, maxAnswers, answered, perTask: {T: n}, stallResumed: {T: true}, pending: {A번호: 처음 본 시각}, chatReplies }`
  - 두뇌 쓰기는 훅이 막는다(`.pi/harness*.json` 보호, `pretooluse.mjs` 181행).
- CLI `on`/`off` 는 `assertNotBrain` 을 탄다. 두뇌가 스스로 켜서 자기 판단에 자기가 답하는 길을 막는다.
- 켜져 있으면 상태줄에 `오토 3/30` 을 붙인다.

## 2. 판단 자동 답

### 2-1. 대상

아래를 **모두** 만족하는 열린 판단만 자동으로 답한다.

1. 답이 비어 있다.
2. `held`(두뇌 턴 스냅샷 보류)·`followup`·`reaskOf` 가 없다. 재질문은 자동 답이 적용되지 않았다는 뜻이라 사람이 본다.
3. 승인 필수가 아니다. 판정은 기존 `approvalRequired(item, config.requiresApproval)` 를 그대로 쓴다: `승인 필수: 예` 항목, 설정 `requiresApproval` 낱말, 승인·push·운영 배포·결제·스토어·심사·환경변수·비밀값·외부 발송·약관·개인정보·DNS·키체인 낱말.
4. 선택지가 2개 이상이고, `추천` 이 선택지 번호로 **시작**한다.
   - 허용 꼴: `①…`, `1…`, `1번…`, `1)`·`1.`.
   - 번호는 선택지 범위 안이어야 한다.
   - `추천` 안에 다른 번호가 섞여도(`① … ③ 은 나중`) 맨 앞 번호만 본다.
5. 한도 안이다.
   - 전체 자동 답 수 < `maxAnswers`
   - 그 판단이 막는 task 마다 자동 답 수 < `perTaskMax`(기본 3)
6. 진행 정체 판단(`dedupeKey` 가 `stall:` 로 시작)이면 그 task 의 `stallResumed` 가 아직 없다. 고아 판단(`orphan:`)도 같은 규칙이다.

### 2-2. 흐름

1. 하네스(Pi 프로세스)가 두뇌 턴이 끝날 때(`agent_end`)와 watcher tick 마다 열린 판단을 훑는다(`autopilotSweep`).
2. 대상이면 `pending[A번호]` 에 처음 본 시각을 적는다. 알림: `오토파일럿: A31 을 30초 뒤 ①(<선택지 앞 24자>)로 답합니다 — 막으려면 직접 답하거나 /autopilot off`.
3. 유예(`autopilot.delaySeconds`, 기본 30)가 지나면 **다시 검사한다**. 그사이 사용자가 답했거나, 판단이 바뀌었거나(rev·질문 해시), 오토파일럿이 꺼졌으면 건너뛴다.
4. 통과하면 기존 `answerJudgment(root, id, '<번호>')` 로 답을 쓰고 `- 답 출처: 오토파일럿` 줄을 더한다. 그다음 기존 `applyJudgments` → `autoResume` 경로로 적용·진행한다. 새 적용 경로를 만들지 않는다.
5. 원장 `judgment:autopilot`: `{ id, selection, recommend(앞 80자), delaySeconds, taskIds }`. 한도 계수를 올린다.
6. 적용이 실패하면(재질문 생성 등) 그 판단과 재질문은 사람 몫으로 남기고 알린다.

### 2-3. 기록

- 판단기록 항목에 `- 답 출처: 오토파일럿` 을 남긴다(`completeJudgment` 가 옮긴다).
- `최근 결정` 줄은 `→ 답 "1"(오토)` 로 쓴다.
- 사용자가 나중에 결정을 바꾸고 싶으면 두뇌에게 지시하거나 새 판단으로 올린다. 이미 적용된 것을 자동으로 되돌리지는 않는다.

## 3. 두뇌의 `대기: 사용자`

- 지금 orchestrator 는 PICK·task 단계·RECLAIM 의 사용자 대기를 이미 거부하고 되돌려 보낸다(`index.ts` 253-293). 그 밖의 단계(INTERVIEW·RESEARCH·PRD_DRAFT·ARCH·프로젝트 REVIEW·WAIT_JUDGMENT)에서는 `awaitingUser` 로 멈춘다.
- 오토파일럿이 켜져 있고 `userHold` 가 없으면, 멈추는 대신 두뇌에게 이렇게 보낸다.

  > [오토파일럿] 사용자가 추천안으로 진행하도록 맡겼다. 방금 물은 것은 각 질문의 추천으로 정해 기록하고(인터뷰 답은 `--source autopilot`) 진행하라. 승인 필수 동작이나 추천을 정할 수 없는 것만 `fodh judgment add` 로 등록하고(추천 번호를 맨 앞에) 대기: 사용자.

- 같은 상태에서 연속 `maxChatReplies`(기본 2)번까지만 보낸다. 상태가 바뀌면 계수를 0 으로 되돌린다. 넘으면 지금처럼 멈추고 알린다: `오토파일럿: 두뇌가 사용자 답을 계속 기다립니다`.
- 사용자가 직접 입력해 `userHold` 가 걸린 턴은 건드리지 않는다.

## 4. 단계 관문

- **PROJECT_READY**: `/develop-start` 와 같은 함수로 PLANNING 에 들어간다. 사용자 전용 전이(`userOnlyTransitions`)지만 오토파일럿은 사용자가 켠 것이므로 하네스 프로세스가 대신한다. 두뇌 CLI 로는 여전히 거부된다. 알림: `오토파일럿: 기획 완료 → 개발 시작`.
- **DONE_ALL**: 진행하지 않는다. 알림: `오토파일럿: 백로그를 모두 끝냈습니다 — 새 범위는 사용자가 정합니다`.
- **paused(memory)·paused(slot)·CLEANUP_FAILED·DEADLOCK**: 지금 동작 그대로다. 회복 규칙이 따로 있다.

## 5. 두뇌 안내

- 오토파일럿이 켜져 있으면 자동 재개 지시(`instruction`) 맨 앞에 한 줄을 붙인다.

  > [오토파일럿 켜짐] 판단의 추천은 번호로 시작한다(예: `① …`). 사용자에게 채팅으로 묻지 말고 판단으로 등록한다. 승인 필수 동작은 지금처럼 [승인] 판단으로 올린다.

- 켜져 있을 때 `fodh judgment add` 에 선택지가 있는데 `--recommend` 가 범위 안 번호로 시작하지 않으면, 거부하고 이 꼴을 안내한다. 꺼져 있으면 지금과 같다.
- brain-rules 에 오토파일럿 절을 더한다: 추천은 두뇌가 실제로 고를 안이다. 승인 필수를 피하려고 낱말을 바꾸지 않는다.

## 7. 테스트

1. `recommendedOption`
   - 꼴: `①`, `1번`, `1)`, `1.`, `1 `
   - 범위 밖이면 없음. 번호로 시작하지 않으면 없음.
2. 대상 판정
   - 승인 필수 낱말, `승인 필수: 예`, held·followup·reaskOf, 선택지 1개 이하, 한도, 정체 두 번째는 제외된다.
3. 유예
   - 유예 전 사용자가 답하면 건너뛴다.
   - 끄면 취소된다.
   - 판단 rev 가 바뀌면 건너뛴다.
4. 흐름
   - 가짜 두뇌로 task 판단(`--blocks T --reclaim`) → 30초(테스트 시계) 뒤 ① 답 → 적용 → PICK 이 T 를 다시 고른다.
   - 판단기록에 `답 출처: 오토파일럿`, `최근 결정` 에 `(오토)` 가 남는다.
5. `대기: 사용자`: INTERVIEW 에서 두 번까지 자동 답이 가고, 세 번째는 `awaitingUser` 로 멈춘다. `userHold` 가 있으면 보내지 않는다.
6. PROJECT_READY 는 자동 PLANNING 으로 가고, DONE_ALL 은 멈춘다.
7. 두뇌(`FODH_BRAIN=1`)의 `fodh autopilot on` 은 거부된다. 두뇌가 `.pi/harness-autopilot.json` 에 쓰는 것은 훅이 거부한다.
8. 꺼져 있으면 기존 동작과 출력이 바뀌지 않는다(기존 테스트 무수정 통과).

## 8. 한계

- 승인 필수 판별은 낱말 기반이라 넓게 잡는다. 예: "설계 승인" 판단도 승인 필수로 보고 자동으로 답하지 않는다. 막는 쪽 오차라 그대로 둔다.
- 추천의 질은 두뇌 판단에 달렸다. 오토파일럿은 그 추천을 검증하지 않는다. 기록과 알림으로 사후 확인을 돕는다.
- Pi 창이 떠 있을 때만 동작한다. 창을 닫으면 자동 답도 멈춘다.

## 9. 구현 순서

워크스페이스 모드 W1 이 진행 중이다. Codex 는 한 번에 하나만 돌린다. 오토파일럿은 작고 독립적이라 **W1 다음, W2 전**에 넣는다. 사용자가 두 프로젝트(아이디어 폴더, 이후 WisePharm)에서 곧바로 쓸 수 있다. 판단 없이 진행한다(사용자가 요청했고, 되돌리기 어려운 동작은 범위에서 뺐다).
