## 1. 설계 원칙

| # | 사용자 요구(원문 요지) | 설계 원칙 |
|---|---|---|
| P1 | 작업이 끝나고 내가 판단했다고 할 때까지 멈춰 있는 게 문제 | **판단이 필요 없는 일은 절대 멈추지 않는다.** 멈추는 조건은 "남은 작업이 전부 판단 대기" 하나뿐 |
| P2 | 판단 문서를 스스로 읽지 않는 게 문제 | **문서가 진실이다.** 판단대기·백로그·상태 파일을 파일로 유지하고, 워처가 변경을 감지하면 오케스트레이터가 반드시 읽는다 |
| P3 | 워처는 "수정됐는지, 멈췄는지" 만 판단 | **워처는 판단하지 않는다.** 경로·rev·해시·heartbeat 만 전달. 해석·결정·다음 작업 선택은 오케스트레이터 |
| P4 | 언제나 검수 | **검수 없는 완료는 없다.** `REVIEW` 를 건너뛰는 전이 없음. 검수 증거는 커밋 SHA 에 묶인다 |
| P5 | project-start 는 아주 상세히 질문 | 인터뷰 프로토콜(§12) 18 영역, 라운드 단위 |
| P6 | 메모리 누수 금지, 작업+검수 끝나면 프로세스 정리 필수 | **하네스가 띄운 프로세스는 하네스가 소유·회수한다.** `CLEANUP`·`RECLAIM` 은 건너뛸 수 없는 상태 |
| P7 | 재생성 가능한 캐시·성능 무관 산출물 정리 | `harness.json` 에 선언된 **프로젝트 안** 경로만 삭제. 공유 캐시는 별도 목록·기본 꺼짐 |
| P8 | 다른 프로젝트에서도 재사용 | 하네스 = 전역 Pi 패키지 + `fodh` CLI. 프로젝트별 차이는 `.pi/harness.json` 하나 |
| P9 | 디자인=Claude, 나머지=Codex, Fable 은 직접 구현 안 함 | 라우팅 + 훅 경로 경계(§10). 오케스트레이터는 스펙·검수·문서·병합만 |
| P10 | (검수에서 추가) 부작용은 한 번만 | 실행 원장(§6-0-4). 결과 불명이면 증거를 먼저 대조하고 재개 |

### 3-2. develop-start (작업 루프)

```
PROJECT_READY ─/develop-start─▶ PLANNING ─▶ ┌────────────── task loop ──────────────┐
                                             │ PICK → SPEC → IMPLEMENT → VERIFY → REVIEW │
                                             │   → MERGE → DOCS → CLEANUP → PICK …       │
                                             │ VERIFY 실패 / REVIEW 반려 → FIX → VERIFY   │
                                             └───────────────┬───────────────────────┘
                                                             │ PICK 결과 (§3-4)
                              DONE_ALL / WAIT_JUDGMENT / WAIT_RETRY / WAIT_RESOURCE / DEADLOCK
```

| 상태 | 하는 일 | 규칙 |
|---|---|---|
| PLANNING | PRD → `docs/backlog.md` | 한 task = 한 브랜치·워크트리, 반나절 이내. PICK 전이는 백로그 ≥1 일 때만(P7 F5) |
| PICK | `ready` 이면서 의존이 모두 `done` 인 task 중 우선순위 최상 | 결과 5종 + `EMPTY` 는 §3-4 |
| SPEC | 위임스펙(무엇·왜·수용기준·파일·검증법·금지) `docs/위임스펙/…` | 스펙 개정 시 `spec.rev` 증가, `repairAttempts` 0 으로 |
| IMPLEMENT | design → Claude Agent(Opus 5.5) / 그 외 → `fodh codex task` | 오케스트레이터 직접 소스 수정은 훅이 거부(§10). git 프로젝트는 `fodh worktree create <task>` 가 필수 — 등록 워크트리 없는 `codex task` 는 거부, 비-git 만 루트 폴백(P7 F8) |
| VERIFY | 오케스트레이터가 `fodh verify run`(verify.commands) 실행. git 워크트리 task 는 **먼저 `fodh worktree commit` 으로 작업을 커밋한 뒤** 검증한다(보정 6 S4) | 실패 → `repairAttempts += 1` → FIX. REVIEW 전이는 하네스가 기록한 verify 증거(ok·같은 task·VERIFY 진입 이후·`cwd` = task 워크트리, 없으면 루트)가 있을 때만(P7 F12·보정 5 H2). `verify run` 의 기본 cwd 는 task 워크트리. 증거에 `head`(검증 직전 HEAD)·`clean`·`dirtyAfter` 를 기록하고 워크트리 task 는 `clean` 이어야 하며 검수 sha 는 `verify.head` 와 같아야 한다(보정 6 S4·보정 8 P4·P6); 실패 검사를 범위 밖으로 빼는 것은 사용자 판단 |
| REVIEW | 교차검수. Claude 산출물 → `fodh codex review`, Codex 산출물 → Claude 검수 Agent | 검수 문서에 대상 커밋 SHA. 반려 → `repairAttempts += 1` → FIX. MERGE 전이는 REVIEW 진입(`reviewSince`, 복귀 시 유지) 이후의 Codex 검수 ok meta 가 있어야 하며, Codex 구현 ok meta 가 있는 task(Claude Agent 검수 경로)만 면제(P7 F6·N2·N3) |
| FIX | 지적 반영(같은 위임 경로). **반드시 VERIFY → REVIEW 로 복귀** | `repairAttempts` 는 task 별 영속. **3 초과(4번째 실패)** 시 RECLAIM → `blocked(A번호)`. 대상 커밋이 바뀌면 이전 검수 통과는 무효(FIX 진입 시 `verify`·`review.commit` 삭제, 보정 8 P4) |
| MERGE | 병합·push. `requiresApproval` 해당 시 판단대기 | 원장에 사전/사후 기록(§6-0-4). `--review-commit` 은 워크트리 HEAD 그 자체(등록 브랜치·미커밋 0·`base..HEAD` ≥ 1), `--merge-commit` 은 루트 HEAD 의 조상(또는 HEAD) 이면서 검수 커밋을 포함하고 검수 커밋과 다른 커밋(fast-forward 로 루트 HEAD == 검수 커밋인 경우만 같음 허용)(P7 F14·보정 5 H1). 루트는 등록 `baseBranch` 에 있어야 하고(보정 6 S1) 병합 sha 는 REVIEW→MERGE 시점에 기록한 `mergeBase` 의 후손이어야 한다(보정 8 P3). 템플릿은 명령 단위로 고정: `fodh backlog get` → 루트 `git merge --no-ff <branch>` → `--merge-commit $(git rev-parse HEAD)` → `fodh state transition DOCS --task <T> --commit <review.commit>`(P7 F19) |
| DOCS | 작업일지·백로그·판단대기 "지금 상태" | `fodh judgment write` 로만 판단대기 수정. CLEANUP 전이 = `${docs.root}/작업일지/YYYY-MM-DD.md`(오늘 또는 어제, KST) 에 taskId 가 단어 단위로 있음 + 백로그 동기화 검사 통과 시 `docs.ok` 기록(P7 F15·보정 5 M1·L1). `fodh docs scaffold worklog` 가 오늘 파일을 만든다 |
| CLEANUP | §8. 건너뛸 수 없음 | 실패 → `CLEANUP_FAILED` → 1회 재시도 → `paused(cleanup)` + 알림. `cleanup.ok` 는 `cleanup run --task` 가 전체 범위(all: processes·storage·worktrees) 로 성공하고 잔존 0 일 때만 하네스 기록(부분 scope 는 미기록, 보정 5 M2), DoD(verify·docs·cleanup) 는 자기 보고 불가(P7 F15) |

### 3-3. 판단이 필요한 순간 (핵심) — RECLAIM 경유

- 어느 상태에서든 "사용자 결정 없이는 못 정한다" 가 나오면: `fodh judgment add`(배경·선택지·추천·회신 형식·rev=1) → **`RECLAIM`**: 이 task 가 띄운 프로세스 그룹 회수 → 잔존 확인 → 워크트리·검수 증거·`resumeTask{taskId,resumeState}`·task `resume{status,state,at}` 는 보존 → task `blocked(A번호)` → PICK. 판단 답이 적용되면 PICK `RESUME` 이 원래 단계(예: MERGE)로 돌아가며, `state.taskId` 가 남아 있는 동안 PICK 은 다른 task 를 집지 않는다(P7 F22). RECLAIM 실패는 CLEANUP_FAILED 와 같은 경로.
- `WAIT_JUDGMENT` 진입 시: 판단대기 "지금 상태" 갱신 → CLEANUP 실행 → 알림(A3) → 턴 종료(토큰 0).

### 3-4. PICK 의 결과 5종과 자동 재개

| 결과 | 조건 | 다음 |
|---|---|---|
| `DONE_ALL` | 백로그 ≥1 이고 미완료 0 | 정지(v0.3.2 ①). 사용자가 `/develop-start` 또는 IDLE. 백로그 추가는 사용자 |
| `EMPTY` | 백로그 자체가 비어 있음(P7 F5) | PICK 에 머물고 `대기: 사용자` 로 턴 종료. PLANNING 복귀는 사용자 `/develop-start` |
| `WAIT_JUDGMENT` | ready 0 이고 `blocked(A*)` ≥ 1, 다른 원인 없음 | 워처 변경 감지 → 답 반영 → PICK |
| `WAIT_RETRY` | ready 0 이고 일시 오류(네트워크·한도 4계정) 로 `paused(error/quota)` | 백오프 5·15·60분 재시도, 3회 뒤 판단대기 |
| `WAIT_RESOURCE` | 슬롯·메모리·예산 초과(`paused(memory/budget/slot)`) | 워치독이 회복 확인(스왑 < 경고치, 슬롯 빈 것) → PICK. 단계 안에서 `codex 슬롯 사용 중` 을 만나면 두뇌는 `대기: 슬롯 codex` 로 턴을 끝내고 프로바이더가 `paused(slot)` 로 보존, 워처 `slot-free` → RESUME(P7 F16). `awaitingSlot` 표지는 슬롯 획득·모든 전이에서 지우고, 워처는 소유자 생사를 직접 확인해 어긋난 표지를 치우며 소유자 unknown 10회 연속이면 알림 1회(`slot:unknown-owner`, 보정 5 M3·L2). 워처 `slot-free` 판정은 **슬롯 파일** 기준: 비었거나 현재 소유자가 죽었으면 free, 소유자가 바뀌었으면 표지 갱신 + 원장 `slot:owner-changed`(P7 F17). `paused(slot)` 전이는 `awaitingUser` 를 풀고, slot-free 자동 재개는 `lastPaused=slot` 이면 `awaitingUser` 를 무시한다(P7 F18) |
| `DEADLOCK` | ready 0 이고 미완료 task 들이 의존 순환 | 판단대기 항목 자동 생성(순환 목록·추천 해소안) → WAIT_JUDGMENT |

## 4. 판단대기 문서 규격·워처·답 문법

### 4-1. 문서 규격 (`docs/판단대기.md`)

```markdown
# 판단대기
## 지금 상태
(오케스트레이터가 갱신. 어디까지 됐고 무엇을 기다리는지 5줄 이내)

## 열린 판단
### A12 — 제목 (rev 1)                     ← 번호는 원장 고유·재사용 금지. 문항을 고치면 rev 증가 + 답 초기화
- 배경: …
- 선택지: ① … ② … ③ …
- 추천: ② (이유)
- 막힌 작업: T07, T09
- 회신: 번호 하나 또는 자유 서술. 승인이 필요한 동작이면 번호 또는 `승인` 을 꼭 포함.
- 답:

## 결정 완료
| 번호 | rev | 답(원문) | 해석 | 반영 커밋 | 날짜 |
```

- `답:` 값은 그 줄에만. 안내문은 `회신:` 줄에 두어 `답:` 값에 섞이지 않게 한다(검수 #5).
- 사용자는 채팅으로 `A12 2` 처럼 답해도 된다. 오케스트레이터가 `fodh judgment answer A12 "2"` 로 문서에 옮긴다.

### 4-2. 워처 — "감지만" (P3), 영속 인박스

| 감지 대상 | 방법 | 인박스에 쓰는 사실 |
|---|---|---|
| 판단대기 수정 | **부모 디렉터리** `fs.watch` + 5초 폴링(매번 경로 재읽기, rename 저장·ENOENT 대응). SHA-256 변경 + 10초 안정 | `{kind:"judgment-changed", path, rev, hashBefore, hashAfter, changedLines}` |
| 자기 수정 억제 | `fodh judgment write/add/answer` 가 저장 뒤 기대 해시를 워처 상태에 기록 → 그 해시로의 변경은 무시 | — |
| 동일 해시 재저장 | 새 이벤트 없음. **단, 미처리 인박스 항목은 취소하지 않는다** | — |
| 두뇌 정지 | heartbeat = 프로바이더가 마지막 stream-json 이벤트를 받은 시각. 활동 상태에서 `stallMinutes`(기본 10) 초과 | `{kind:"stalled", state, task, lastEventAt, runId}` |
| 자식 초과 | 레지스트리 항목이 `timeoutMinutes` 초과 또는 사라짐 | `{kind:"child-timeout", pid, pgid, runId, minutes}` |
| 세션 복구 | `session_start` 에서 상태 파일이 활동 상태 | `{kind:"recover", state, task, savedAt}` |

- 인박스 `.pi/harness-inbox.jsonl` 항목 상태: `detected → queued → delivered(runId) → applied(runId)`. 프로바이더는 턴마다 **`applied` 가 아닌 항목 전부**를 순서대로 프롬프트에 붙인다(마지막 하나만 보내지 않음, 검수 #6). 두뇌는 처리 뒤 `fodh inbox ack <id…>` 로 `applied`. 재시작·세션 회전 때 `applied` 아닌 항목은 다시 붙는다.
- Pi 쪽 주입은 `pi.sendMessage({customType:"harness-watcher", content, display:true}, {triggerTurn:true, deliverAs:"followUp"})`. Pi `followUpMode` 는 하네스가 `"all"` 로 고정하지 않고, 인박스가 전달 완전성을 보장한다.
- 워처는 파일을 해석하지 않는다. "답이 채워진 A번호" 판독은 오케스트레이터가 `fodh judgment read --answered` 로 한다(A2 ① 은 그대로: 답 필드가 채워진 항목만 반영).

### 4-3. 답 문법과 적용 규칙 (검수 #5)

| 답 | 처리 |
|---|---|
| 선택지 범위 안의 번호 하나 (`2`, `②`) | 그 선택지 채택. 결정 완료 표에 해석 = 선택지 원문. 선택 번호로 보는 것은 동그라미 숫자(①~⑩) 또는 답 맨 앞의 독립 숫자(1~10)뿐이며 본문 속 `T02`·sha 의 숫자는 무시(P7 F21) |
| 번호 + 조건 (`2, 단 …`) | 번호 채택 + 조건은 위임스펙 제약으로. 해석 문장을 결정 완료에 남긴다 |
| 자유 서술 | 오케스트레이터가 해석문을 쓴다. 승인 필수 동작(§10) 이면 **번호 또는 `승인`/`진행` 토큰이 없으면 적용하지 않고** 재질문 |
| 부정·유보·모순 (`1은 하지 마`, `나중에`, 번호 두 개) | 적용하지 않음. 새 번호(A-n, rev 1) 로 좁힌 재질문 생성. 막힌 task 는 그대로 blocked, 다른 task 계속 |
| rev 불일치(문항이 rev 2 인데 답은 rev 1 기준) | 적용하지 않음. 재질문 |
| 빈 값 | 미답 |

- 적용 후 항목은 결정 완료 표로 옮기고 원문·해석·반영 커밋을 남긴다. 되돌리기는 사용자가 결정 완료 표를 보고 새 항목으로 요청.

## 6. 위임 브리지

### 6-0. 두뇌 = Claude Code 헤드리스 (A1 확정)

확인한 사실(변경 없음): cswap 은 키체인 `Claude Code-credentials` 를 4계정 사이에서 교체하며 Claude Code 에만 효과. Pi 의 Claude OAuth 는 extra usage 종량. 따라서 구독 플랜 안에서 Claude 를 쓰는 경로는 Claude Code 자체(`claude -p`). cswap 은 `~/.claude/sessions/{pid}.json` 으로 실행 중 세션을 인식.

#### 6-0-1. 과금 경계 (검수 #2)

- 사전 조건 `fodh doctor` (매 `/develop-start`·`/project-start` 와 세션 시작 때): `ANTHROPIC_API_KEY`·`ANTHROPIC_AUTH_TOKEN`·`ANTHROPIC_BASE_URL` 미설정, `~/.claude/settings.json`·프로젝트 settings 에 `apiKeyHelper` 없음, `claude -p` 자식 env 에서 위 변수 제거. 하나라도 실패 → 두뇌 호출 금지 + 알림.
- 실행 중: stream-json `rate_limit_event.rate_limit_info` 에 `isUsingOverage`, `overageStatus`, `unifiedWindows.{five_hour,seven_day}.utilization` 이 실린다(실기 픽스처: `overageStatus:"rejected"`, `overageDisabledReason:"org_level_disabled"`, `isUsingOverage:false`). 프로바이더는 `isUsingOverage===true` 또는 `overageStatus!=="rejected"` 를 보면 **즉시 abort → `paused(billing)` → 알림**. 사용자 확인 항목: 4계정 모두 extra usage 꺼짐([A9](../판단대기.md)).
- 표현 정정: "API 요금 0" → "구독 한도 안에서 실행하며, extra usage 가 켜진 계정을 감지하면 멈춘다".
- `system.init.model` 로 실제 모델 id 를 원장에 기록(`opus` 별칭 검증, 검수 #17).

#### 6-0-2. Claude ↔ 하네스 연결 = `fodh` CLI (검수 #1)

- 패키지가 `bin/fodh` 를 전역에 둔다(`npm link` 또는 `pi install` 뒤 심링크). 두뇌는 Bash 로 호출하고 JSON 결과를 읽는다.
- 명령군: `fodh state get|transition <to> --task T07`, `fodh backlog set …`, `fodh judgment add|answer|read [--answered]|write-status`, `fodh inbox list|ack`, `fodh codex task|review|research --spec <file> [--resume <thread>]`, `fodh proc register|list`, `fodh cleanup run|report`, `fodh slots status`, `fodh doctor`.
- **상태 단일 작성자**: `.pi/harness-state.json`·원장·인박스·레지스트리는 `src/core` 라이브러리만 쓴다. `fodh` 와 Pi 확장이 같은 라이브러리를 쓰고, 파일 잠금(`proper-lockfile` 류) + tmp→rename 원자 저장.
- `fodh codex …` 는 (1) 슬롯 확보(§8-3) (2) 프롬프트 머리말 삽입 (3) 전용 프로세스 그룹으로 spawn + 레지스트리 등록 (4) 원장 기록 (5) 결과 파일 경로 반환. 두뇌가 Bash 로 `codex exec` 를 직접 치면 훅이 거부한다(§10).
- 보조 두뇌(Pi 의 Codex 모델, 4계정 모두 한도일 때): Pi 내장 도구 `read`·`bash` 만 켜고 같은 `fodh` 를 쓴다. 모델 전환 시 확장이 `pi.setActiveTools()` 로 도구 집합을 바꾼다(`--no-tools` 플래그는 쓰지 않는다).

#### 6-0-3. 프로바이더 계약 (검수 #3·#6)

- 명령: `env -u CLAUDECODE -u CLAUDE_CODE_ENTRYPOINT -u ANTHROPIC_API_KEY … claude -p --dangerously-skip-permissions --resume <sid> --output-format stream-json --verbose --include-partial-messages --append-system-prompt-file <하네스 규칙> --settings <프로젝트 .claude/settings.json> --model <opus|…> < prompt.txt`. 최초 턴은 `--session-id <uuid>`(하네스 생성) 로, 이후 `--resume`. stdin 은 프롬프트 파일. `--verbose` 없으면 오류(실기).
- 프롬프트 = 인박스 미적용 항목 전부(순서대로) + 이번 단계 지시. 대화 이력은 Claude 세션이 갖는다.
- 이벤트 처리:

| stream-json | 프로바이더 |
|---|---|
| `system/init` | `session_id`·`model`·`permissionMode`·`tools` 원장 기록. `permissionMode!=="bypassPermissions"` 면 abort |
| `stream_event/content_block_delta(text)` | Pi `text_delta` |
| `assistant`(tool_use 블록) | 표시용 요약 텍스트(`[tool] Bash: …`)로만. **Pi `toolCall` 로 반환하지 않는다** |
| `user`(tool_result) | 표시용 요약. 사후 감사 로그(§10) |
| `system/hook_response` | exit 2 면 감사 로그 + 표시 |
| `rate_limit_event` | §6-0-1 검사. utilization 도 상태 파일에 기록 |
| `result` | `stop_reason`·`terminal_reason`·`is_error`·`api_error_status`·`permission_denials`·`usage` 원장 기록. `permission_denials` 각각 → `fodh judgment add`(중복은 병합). Pi `done(reason:"stop")` |
| 프로세스 비정상 종료·stdout 끊김 | `done(reason:"error")` + 실행 관리자에 통보 |
| abort(deadline·사용자) | 프로세스 그룹 TERM→KILL, `done(reason:"aborted")` |

- 한도 오류 판정: `result.is_error && api_error_status ∈ {429, …}` 또는 stderr 의 한도 문구. 처리는 §6-0-4.

#### 6-0-4. 실행 관리자·원장·재시도 (검수 #7·#8)

- **runId** 를 턴마다 발급. 원장 `.pi/harness-ledger.jsonl` 한 줄 = `{runId, taskId, state, action, status: pre|running|ok|fail|unknown, evidence, at}`. 부작용 동작(commit·push·codex task 시작·워크트리 생성·삭제·알림 발송)은 `pre` 를 먼저 쓰고 결과를 `ok/fail` 로 닫는다. 닫히지 않은 `pre/running` = `unknown`.
- **deadline**: `brain.maxTurnMinutes`(기본 45). 초과 시 abort → 프로세스 그룹 회수 → `result` 없음 → 원장 `unknown` 표시 → 상태 `recovering`. 다음 턴 프롬프트는 "복구 모드: 원장의 unknown 항목을 증거로 대조하라(`git rev-parse`, 원격 SHA, codex `-o` 결과 파일, 워크트리 존재)" 로 시작한다.
- **agent_end 분류**: `stop` → 다음 단계 프롬프트. `error` → 백오프(5·15·60분) 재시도, 연속 3회 → `paused(error)` + 알림. `aborted` → 위 복구.
- **한도 오류 재시도**: 원장에 이 턴의 `unknown` 이 없을 때만 `cswap switch` 후 같은 프롬프트로 1회 재시도. `unknown` 이 있으면 복구 모드로 간다. cswap 자동 전환(90%)이 먼저 일어났는지는 `cswap status` 로 확인해 중복 전환을 피한다. 4계정 모두 한도 → `paused(quota)` → WAIT_RETRY.
- **단일 실행 잠금** `.pi/harness.lock`(pid·시작시각). pid 가 죽어 있으면 stale 로 회수. 같은 프로젝트에 Pi 두 개는 뜨지 않는다.

#### 6-0-5. 헤드리스 거부 분류 (검수 #17)

| 거부 종류 | 식별 | 처리 |
|---|---|---|
| 설정 오류(훅 파일 없음·settings 무시·모델 없음) | `system/init` 이상, `fodh doctor` 실패 | 두뇌 호출 금지 + 알림 |

### 6-1. Codex (`fodh codex task|review|research`)

- 프로세스: 전용 pgid, 레지스트리, 원장. `timeoutMinutes` 초과는 워처가 알리고 회수는 실행 관리자.

- 검수 문서: 머리말(대상 커밋 SHA·모델·effort·서브에이전트 모델), 지적(높음/중간/낮음, 파일:줄, 재현, 수정안), 판정, 반영 커밋. 대상 커밋이 바뀌면 통과 무효.
- `repairAttempts` 3 초과 → RECLAIM → blocked + 판단대기.

## 8. 정리(CLEANUP·RECLAIM) — 필수

### 8-1. 프로세스 (검수 #11)

- 하네스가 띄우는 자식은 전부 `spawn(..., {detached:true})` 로 **전용 프로세스 그룹**. 레지스트리 `.pi/harness-procs.json` = `{pid, pgid, startedAt(ps lstart), cmd, taskId, runId, kind}`.
- 종료 대상 = **레지스트리의 pgid 와 그 자손만**. `killPatterns` 는 그 집합 안에서 고르는 필터일 뿐, 시스템 전역 `pkill -f` 는 하지 않는다. pid 재사용은 `startedAt` 대조로 걸러낸다.
- 절차: 그룹 `SIGTERM` → 5초 → `SIGKILL` → `ps -o pid,pgid` 로 잔존 확인 → 레지스트리 정리. 잔존이면 CLEANUP_FAILED.
- 보호: 활성 두뇌(현재 runId 의 `claude -p`), `neverKill` 패턴(사용자 개발 서버·에뮬레이터·대화형 codex·ChatGPT.app·Pi 자신) 은 레지스트리에 있어도 건드리지 않는다.
- 실행 시점: 각 task 의 CLEANUP, RECLAIM, `WAIT_*` 진입 직전, `session_shutdown`.
- 메모리 워치독: 60초마다 `vm_stat`·`sysctl vm.swapusage`. 스왑 > `swapWarnGB`(8) → 끝난 task 의 잔존 그룹 회수 → 경고 주입 → 지속 시 새 위임 거부(`paused(memory)`). 회복 조건: 스왑 < 경고치 − 2 GB 가 5분 지속.

### 8-2. 저장공간 (검수 #12)

- 기본 삭제 = `cleanup.rebuildablePaths` 중 **프로젝트 루트 안** 경로만. 각 경로는 realpath 로 정규화, `..`·심링크 통과 금지, `keepPaths` 가 우선.
- 공유 캐시(`~/Library/Developer/Xcode/DerivedData/<App>-*`, `~/.gradle/caches/*/transforms`, `$TMPDIR/cxc-*`) 는 `cleanup.sharedCaches` 별도 목록, 기본 `enabled:false`. 켜져 있어도 관련 빌드 프로세스가 없고 이 프로젝트 소유(이름 접두)일 때만.
- 워크트리 제거: 하네스가 만든 것(상태 파일 등록) + 병합 완료 + `git status --porcelain` 빈 것 일 때만 `git worktree remove`(`--force` 없음). 아니면 보존하고 보고.
- 보고: before/after `df -h /`·`vm_stat` free·swap. 삭제한 경로와 크기 목록.

### 8-3. 머신 전역 슬롯 (검수 #16)

`~/.pi/agent/fod-harness/slots.json` (잠금 파일 보호):

## 9. 컨텍스트·세션 전략 (검수 #14)

- 문서가 진실. 백로그·판단대기·상태·원장으로 어느 세션에서든 복구.
- **Pi 세션은 회전하지 않는다**(`ctx.newSession()` 은 명령 컨텍스트 전용). claude-code 모델의 `contextWindow` 를 크게 잡아 Pi 자동 압축이 개입하지 않게 하고, Pi 세션은 표시·명령용으로 둔다. 사용자가 원하면 `/new`.
- **Claude Code autocompact 가 1차 수단**(v0.3.1, §6-0-6): 사용자 설정 250K 그대로, 하네스 불간섭. Pi 자동 압축은 끈다(`compaction.enabled=false`, 프로바이더 usage 는 마지막 호출분만 보고).
- **Claude 세션 회전은 보조 수단, 기본 꺼짐**(`brain.rotateAtTokens: 0`): 켜면 task 경계(CLEANUP 뒤) 에서 마지막 `usage` 문맥 크기가 임계를 넘을 때 오케스트레이터가 handoff 요약을 `docs/작업일지/YYYY-MM-DD.md` 에 쓰고 새 `--session-id` 로 시작. 인박스 미적용 항목·현재 task·상태는 상태 파일에서 자동 재주입.
- 회전 중 실패(새 세션 init 실패) 는 이전 sid 로 되돌린다(상태 파일에 `previousSessionId`).

## 10. 가드레일 (검수 #4)

- 두 겹: (a) Claude Code `PreToolUse` 훅(하네스가 프로젝트 `.claude/settings.json` 에 설치, 스크립트는 패키지 `hooks/`) (b) Pi 사후 감사(stream-json 도구 호출 로그 + 승인 필수 동작 판단대기 생성).
- 훅 규칙(입력: 도구명·입력·cwd·세션; 상태는 `.pi/harness-state.json` 읽기):
  1. 비밀값 패턴이 write/edit 내용에 → 거부
  2. 프로젝트 밖 `rm -rf`·대량 삭제 → 거부
  3. `requiresApproval` 동작 → 거부 + 사유 "판단대기 항목을 만들어라" (프로바이더가 `permission_denials` 로 항목 생성)
  4. **경로 경계**(P6): `FODH_BRAIN=1` 세션(두뇌·doctor·두뇌의 서브에이전트)에서만 적용, 상태 파일 유무와 무관(미초기화 = 워크트리 없음). Write/Edit/NotebookEdit 대상이 소스 경로이면서 **등록된 워크트리 밖**이면 거부(이유: 위임). 문서 경로(`docs.root`, `.pi/`, 루트 `CLAUDE.md`·`AGENTS.md`·`README.md`) 는 허용, 루트 밖·`.claude/skills` 는 거부. Bash 는 리다이렉트·`tee`·`cp|mv|install|rsync`·`sed -i`·`perl -pi`·`dd of=`·`git checkout --|restore|stash`·`git apply`/`patch`(대상 트리 기준) 로 **루트 안 소스**를 겨냥할 때만 거부(`/dev/null` 등 장치·인터프리터 인자·heredoc 본문·`git stash list|show` 제외). 패턴 기반이라 완전하지 않음 → 사후 감사가 보완
  5. **상태 인지**: `git commit`·`git push`·`git merge` 는 상태가 MERGE(또는 DOCS) 일 때만. 이력·참조 재작성(`branch -f/-D`, `checkout -B`, `update-ref`, 인자 있는 `reset`, `rebase`, `filter-branch`, `reflog expire`) 은 상태와 무관하게 거부(보정 8 P3). `codex exec`·`codex ` 직접 실행 거부 → `fodh codex …` 안내
  6. **가드 자기수정 금지**: `.claude/settings.json`·`hooks/*`·`.pi/harness*.json` 을 Write/Edit/Bash 로 바꾸면 거부(오직 `fodh` 가 바꾼다)
- `fodh doctor` 가 훅을 **실제 차단 시험**으로 검증한다: 마커 명령(Bash `echo FODH_DOCTOR_MARKER`)과 규칙 4 Write(`src/FODH_DOCTOR_MARKER.ts`)를 `claude -p --model haiku --max-turns 3` 로 보내 두 거부가 모두 실리는지(`hookDenials 2`) 확인. 훅 미적용으로 파일이 생기면 지우고 실패. 실패 시 IMPLEMENT·MERGE 진입 금지(`-p` 는 잘못된 settings 를 조용히 무시할 수 있음).
- 서브에이전트에도 같은 훅이 적용된다. 디자인 서브에이전트의 쓰기는 규칙 4 의 워크트리 예외로 허용된다.
- **거부 분류(P6 2차)**: 훅 거부 문구는 `하네스 가드[승인|경계|보호]: …`. `[승인]`(requiresApproval·doctor 표식)만 프로바이더가 판단대기 + 작업 회수(위임 취소)로 잇는다. `[경계]`(규칙 2·4·5, git worktree·파괴적 git, codex 직접 실행)와 `[보호]`(규칙 1·6, `FODH_` 환경변수, 비밀값, 상태·설정 해석 실패)는 원장 `hook:<kind>` + TUI 알림만 남기고 두뇌가 위임으로 우회하거나 포기한다(brain-rules 3행). 분류 없는 훅 오류는 원장 `hook:unclassified` 만.
- **셸 파서(P6 보정 2)**: 훅과 사후 감사는 `hooks/shell-parts.mjs`(무의존 ESM) 하나를 함께 쓴다. heredoc 본문은 명령 그룹에서 빠지되 `<<<`(here-string)·`$(( ))`/`(( ))` 안의 `<<` 는 heredoc 시작이 아니다. 종료 표지가 없는 heredoc 은 두뇌에서 `[보호]` 거부(사후 감사는 남은 줄을 명령으로 검사). realpath 가 EACCES·ELOOP·ENAMETOOLONG 을 내면 사용자 세션은 lexical 경로로 비교하고 두뇌는 `[경계] 경로를 확인할 수 없습니다` 로 거부.
- **사후 감사(P6)**: 턴이 끝나면 거부되지 않은 도구 입력에서 쓰기 문맥(리다이렉트 대상·tee·`sed -i`·복사 대상·인라인 코드의 `writeFile|open(…,'w')` 첫 리터럴)의 경로가 경계 밖이면 원장 `audit:path-boundary warn` + 턴당 1건 알림(같은 경로는 세션당 1회). 거부하지 않는다.
- **두뇌 보호 설정(P6)**: `fodh config set` 은 두뇌(`FODH_BRAIN=1` 또는 잠금 소유자의 자손 프로세스)에서 전면 거부, 사용자 터미널에서도 `delegate.codex.command`·`brain.command`·`brain.switchCommand`·`delegate.codex.sandbox` 는 `--approve` 필요. `fodh memory reset` 도 두뇌 거부. 사용자 전용 전이(PROJECT_READY→PLANNING, DONE_ALL→PLANNING/IDLE)와 `fodh state transition --system` 도 같은 판정(`assertNotBrain`)으로 두뇌 거부(P7 N1·N9). 인라인 `sh|bash|zsh -c`(결합 플래그 포함)·`eval`·`source`·`node -e`·`python -c`·`perl -e` 문자열 안의 `FODH_` 는 거부.
- 알려진 한계(README 표, 사후 감사로 보완): Bash 로 만든 스크립트가 다시 파일을 쓰는 경우, MCP 도구를 통한 쓰기, `cd` 효과 미추적, `git stash pop|apply`·`git checkout <ref> <path>`(`--` 없음), 이중 fork 로 launchd 에 붙은 자식의 부모 체인, symlink·대소문자 우회의 잔여, 셸로 넘기는 heredoc 본문·`sh -c` 문자열 안의 명령(N2, P7 뒤), `( … )`·`$( … )`·백틱 안의 명령(검수 3차 지적, P6 이전부터 동일).
- 승인 필수 목록(A8, 16종, v0.2 와 동일): 프로덕션 DB 마이그레이션·데이터 삭제/이관 · 스토어 업로드·심사 제출·답변 · 결제·광고·구독 설정 변경 · main 직접 push·`push --force`·브랜치/태그 삭제 · 환경변수 삭제·비밀값 생성/회전 · 프로젝트 밖 파일 삭제·대량 삭제(100+) · 유료 결제·플랜 변경·유료 리소스 생성 · 도메인·DNS·인증서 · 외부 발송(이메일·Slack 게시·SNS·고객 답변) · 프로덕션 배포(프로젝트별 해제 가능) · 사용자 계정 생성/삭제/권한 · 약관·개인정보 문안 · 시스템 설정(launchd·키체인·셸 프로필).

**P1.5 통과 기준**(Fable 실기, 실제 `claude -p` haiku):
1. 최초 `--session-id` 턴 → `result` 수신 → 두 번째 `--resume` 턴이 이전 문맥을 기억
2. `--verbose` 누락 시 오류를 프로바이더가 설정 오류로 분류
3. 훅 마커 차단 → `permission_denials` → 판단대기 항목 자동 생성(중복 병합)
4. Agent 서브에이전트가 헤드리스에서 실행되고 텍스트가 표시됨(`--forward-subagent-text` 선택)
5. `.mcp.json` 의 MCP 서버가 `system.init.mcp_servers` 에 로드됨
6. deadline 초과 → abort → 프로세스 그룹 잔존 0 → `recovering` 프롬프트 생성
7. 인박스 항목 3개가 한 턴에 순서대로 전달되고 ack 로 `applied`
8. `rate_limit_event` 파싱, `isUsingOverage:true` 모의 입력에서 `paused(billing)`
9. 한도 오류 모의 → 원장 unknown 없음 → `cswap switch`(실제 전환은 `--dry-run` 또는 모의) → 1회 재시도
10. `system.init.model` 이 요청 모델과 일치, 원장에 기록
