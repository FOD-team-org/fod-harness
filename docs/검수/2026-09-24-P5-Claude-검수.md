## 4. 새 발견

### 중간

**M1. `interview next`가 "물은 횟수"가 아니라 "호출 횟수"를 세서, 재호출 한 번이면 사용자에게 한 번도 보이지 않은 질문이 판단대기로 넘어간다**

- 위치: interview.ts:127-131(선택 즉시 `asked`·`askCount+1`), 66(`askCount >= maxAsks` → mustDefer). INTERVIEW.md:5, 8(mustDefer는 전부 defer). resume.ts:55-68(자동 재개는 상태당 최대 3회까지 같은 지시를 다시 보냄)
- 재현: `interview start` → `interview next`로 Q01-01~Q02-03 6개를 받는다 → record 없이 `interview next`를 한 번 더 부른다 → 같은 6개가 askCount 2가 된다 → 세 번째 `next`에서 6개가 모두 `mustDefer`로 나온다. 템플릿대로 하면 전부 `defer`되어 "추천안 채택/직접 답하기" 판단 항목이 된다. 이 동작은 테스트 interview.test.ts:33-35에 기대값으로 고정돼 있다.
- 실제 경로: 약한 두뇌가 질문을 채팅으로 내보내고도 `대기: 사용자` 표지를 빠뜨리는 경우가 있다. 또는 턴이 오류로 끝나 재개될 수 있다. 그러면 자동 재개가 INTERVIEW 지시를 다시 보내고, 두뇌는 지시대로 `next`를 다시 부른다. 사용자가 답하기도 전에 한도가 소진된다. 설계 P5 "인터뷰 아주 상세히"를 정면으로 깎는다.
- 수정안(택1):
  - ① next를 라운드 단위로 멱등하게 만든다. 직전 라운드의 asked 문항 중 record·defer·skip이 하나도 없고 그 뒤 사용자 입력도 없으면(상태에 `openRound` 표지를 두고 record·defer·skip·사용자 input 훅에서 해제), 같은 문항을 askCount 증가 없이 그대로 돌려준다.
  - ② askCount 확정을 턴 종료 시점으로 옮긴다. 프로바이더가 `대기: 사용자`로 끝난 턴에서만 해당 라운드를 "물음"으로 확정한다.
  - 공통: 테스트 33-35를 "답 없는 연속 next는 같은 라운드 반환"으로 바꾸고, 사용자 입력 이후 재질문에서만 askCount가 늘어나는지 검증한다.

**M2. 인터뷰 가드를 두뇌가 허용된 명령으로 스스로 끌 수 있다**

- 위치:
  - config.ts:218-233: `setConfig`에 키 제한이 없다.
  - hooks/pretooluse.mjs:127: 단독 `fodh` 명령은 검사 없이 통과한다.
  - hooks/pretooluse.mjs:99-105: protectedPath는 `.pi/harness*.json`만 보호한다.
  - claude-md.ts:36: CLAUDE.md의 "쓸 수 있는 fodh 명령"에 `fodh config set`이 나열된다.
- 재현(둘 다 훅을 통과):
  - ① INTERVIEW에서 `fodh state transition RESEARCH`가 `인터뷰 필수 질문이 남아 있습니다`로 거부된다 → `fodh config set interview.enforce false` → 전이 성공.
  - ② 두뇌가 Write로 `.pi/interview-bank.md`에 `- [선택] Q01-01 | …`를 쓴다 → 필수가 선택이 되어 가드를 통과한다(extraBank가 같은 ID를 덮어씀, interview.ts:45).

  - INTERVIEW.md 금지 절에 "가드 설정·은행 파일을 바꾸지 않는다"를 한 줄 넣는다.
