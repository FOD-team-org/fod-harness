## 새 발견

### N1 (중간) F4 두뇌 판정이 env만 본다

- 위치: `src/cli/index.ts:106`
- 내용: `process.env.FODH_BRAIN === '1'`만 검사한다. 사용자 전용 명령에는 이미 `assertNotBrain`(`src/core/brain-guard.ts:5-12`: env와 Pi 잠금 소유자 후손 여부)이 있고 `config set`·`memory reset`이 이 방식을 쓴다. 스펙 F4-2는 "다른 사용자 전용 전이가 이미 있다면 같은 방식으로 맞춘다"고 요구했다.
- 재현: 두뇌가 docs/ 아래에 `env -u FODH_BRAIN fodh state transition PLANNING` 한 줄짜리 스크립트를 쓰고 `sh docs/x.sh`로 실행한다. 훅은 명령 토큰만 검사하므로 FODH_ 조작을 잡지 못한다(`hooks/pretooluse.mjs:195-206`, README "스크립트 내부 쓰기" 한계). env가 없는 fodh 프로세스는 이 가드를 통과한다. 부모 체인 검사는 이 경우를 잡는다.
- 영향: PROJECT_READY 정지를 우회할 수 있다. 시나리오 A의 두뇌는 의도적으로 우회하지 않았으므로 실제 위험은 중간이다.
- 수정안: 검사를 `await assertNotBrain(root, 'PROJECT_READY→PLANNING 전이')` 호출(또는 같은 판정)로 바꾸고 실패 원장은 그대로 둔다. 같은 계열로, 설계 v0.3.2 ①의 사용자 전용 전이인 DONE_ALL→PLANNING과 DONE_ALL→IDLE(`state.ts:99`)도 두뇌가 CLI로 그대로 통과한다. 여기에도 같은 판정을 넣을지는 Fable이 판단한다(F5 가드 덕분에 DONE_ALL→PLANNING 뒤 빈 백로그로 PICK에 가는 경로는 막혀 있다).

### N2 (중간) F6 task 가드가 두뇌가 쓰는 delegate 값에 달려 있다

- 위치: `src/core/state.ts:176`
- 내용: `to === 'MERGE' && task?.delegate === 'claude'`일 때만 증거를 요구한다. `delegate: 'claude'`는 두뇌가 IMPLEMENT에서 `fodh backlog set --delegate claude`를 칠 때만 생긴다(`templates/prompts/IMPLEMENT.md:6`). delegate가 없거나 두뇌가 `--delegate codex`로 써도(`src/cli/index.ts:136-137`) 가드가 사라진다. 자동으로 기록되는 값은 `startCodex`의 `delegate: 'codex'` 하나뿐이다(`src/core/codex.ts:106`).
- 재현: design task를 두뇌가 Claude Agent로 구현하면서 `--delegate claude`를 빼먹는다(또는 직접 작성한다). 그러면 REVIEW→MERGE가 Codex review 없이 통과한다. 시나리오 A와 같은 "지시 생략" 유형이다.
- 영향: F6의 task 쪽 가드는 두뇌가 지시를 따를 때만 동작한다. 스펙 원칙("프롬프트 준수에 기대지 않는다")에 어긋난다.
- 수정안: 조건을 "이 taskId의 `kind: 'task'`, `status: 'ok'` Codex meta가 없으면 review 증거를 요구한다"로 바꾼다. Codex가 실제로 구현했다는 증거가 있을 때만 알려진 한계(F6 ②)로 면제한다. 테스트를 두 건 더한다: delegate 미설정 거부, 두뇌가 쓴 delegate codex에 task meta가 없으면 거부.

### N3 (낮음) REVIEW 재진입 때 enteredAt이 초기화되어 앞선 검수가 무효가 된다

- 위치: `src/core/state.ts:41`, `:177`
- 내용: WAIT_JUDGMENT→REVIEW(프로젝트 판단 복귀)나 paused→PICK→RESUME REVIEW(task)에서 enteredAt이 새로 기록된다. 그 전에 끝난 유효한 `codex review`는 가드에서 인정되지 않는다.
- 재현: 프로젝트 REVIEW에서 codex review(ok)를 받고 미결 판단 때문에 WAIT_JUDGMENT로 간다. 답을 적용해 REVIEW로 돌아오면 PROJECT_READY 전이가 거부되어 Codex 검수를 다시 해야 한다.
- 영향: 스펙 문구("REVIEW enteredAt 이후")대로 구현한 결과다. 재검수 비용이 들고, 두뇌가 오류 문구를 보고 다시 검수하는 턴이 한 번 더 생긴다.
- 수정안: 둘 중 하나를 Fable이 정한다. (a) 판단 답이 검수 결론을 바꿀 수 있으므로 지금 동작을 유지하고 설계에 명시한다. (b) `reviewEnteredAt`을 따로 두어 ARCH·VERIFY→REVIEW 진입 때만 갱신하고 resume·판단 복귀 때는 보존한다.

### N4 (낮음) F7 진단 실패가 턴 결과를 덮어쓴다

- 위치: `src/provider/turn.ts:312-322`
- 내용: 불일치 검사가 바깥 `finally`의 `try` 안에 있지만 따로 `catch`가 없다. `readState`, `appendLedger`, `notify`가 던지면 runTurn의 정상 반환이나 원래 예외가 이 예외로 바뀐다. 바로 아래 감사 의심 알림(`:323-329`)도 건너뛴다. catch가 상태를 `recovering`으로 바꾼 뒤에도 실행되므로(`:304-306`) 중단된 턴에서도 "보고 X ≠ 실제 recovering"이 뜰 수 있다.
- 영향: 진단용 코드가 턴 분류를 바꿀 수 있다.
- 수정안: 블록을 `try { … } catch { /* 진단 실패는 무시 */ }`로 감싼다. 정상 종료한 턴(`result`가 있고 예외가 없는 경우)에서만 검사한다.

### N5 (낮음) F7 정규식이 꾸밈 문자를 상태명으로 잡는다

### N6 (낮음) F3 경고가 fodh 호출마다 원장에 쌓인다

- 위치: `src/core/config.ts:206-212`, `src/core/notify.ts:50-54`

- 수정안: 원장에서 같은 root와 같은 키 집합의 최근 `ok` 기록을 찾아 dedupe를 프로세스 사이로 넓힌다(예: `.pi/harness-config-warned.json`에 해시 저장). 아니면 스펙대로 두고 README에 적는다.

### N7 (낮음) PICK 템플릿에 EMPTY 처리가 없다

- 위치: `templates/prompts/PICK.md`; `extensions/orchestrator/index.ts:90-96`
- 내용: PICK 상태에서 백로그가 비는 경우는 드물다(사용자가 backlog.md를 비우는 경우, 빈 백로그로 WAIT_*·recovering에서 복귀하는 경우). 이때 두뇌는 EMPTY를 받아도 멈추라는 지시가 없어 자동 재개가 정체 감지까지 반복된다. `/develop-start`는 PICK에 빈 백로그면 `:90-91`에서 '백로그 계획은 PLANNING 상태가 필요합니다'를 던지므로 `:96`의 EMPTY 분기에는 사실상 도달하지 않는다. 사용자가 PICK에서 빠져나갈 명령도 없다(PICK→PLANNING 전이 없음).
- 수정안: PICK.md 끝내는 조건에 "EMPTY면 `대기: 사용자`로 멈춘다"를 한 줄 넣는다. 설계 §3에 EMPTY 결과를 추가하는 것은 Fable 동기화 범위다. PICK→PLANNING 사용자 전이를 둘지도 함께 판단한다.

### N8 (낮음) 인터뷰 문서 답 칸의 번호 의미가 바뀌었다

  - 재현: 조건이 `resumeState ∈ {RESEARCH, REVIEW}`뿐이라 `paused(error)`에도 적용되는데, 사유 문구는 "슬롯 대기로"라고 적는다. INTERVIEW, PRD_DRAFT, ARCH는 이 복귀 경로에서 빠져 있다.
  - 수정안: 의도한 동작이면 사유 문구를 일반화하고 나머지 프로젝트 단계를 포함할지 판단한다. 아니면 `lastPaused === 'slot'`으로 한정한다.
- **L4. `worktree commit` 세부 사항**
  - 위치: `worktree.ts:23-31`, `54-66`.
  - 워크트리 HEAD가 등록 branch인지 확인하지 않는다(detached나 다른 branch도 커밋된다).
  - untracked 파일을 크기 제한 없이 utf8로 전부 읽는다.
  - `git diff`의 문맥 줄에 이미 있던 비밀값 패턴 때문에 오탐으로 거부될 수 있다.
  - `.gitignore` 보강(F11)은 루트 작업 트리에만 적용된다. 워크트리 안에 `.pi/`가 생기면 `add -A`에 포함된다.
  - 변경이 없으면 git 오류가 그대로 나가, 템플릿의 "이미 커밋됐으면 재사용"과 메시지가 어긋난다.
  - 수정안: branch 확인, 크기 상한, `--unified=0`, 워크트리에서 `.pi/` 제외(`:(exclude).pi`), 변경 없음이면 HEAD를 반환한다.
- **L5. 작업일지 날짜가 KST 자정을 넘으면 거부된다**
  - 위치: `state.ts:188-190`.
