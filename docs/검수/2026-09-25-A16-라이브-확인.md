## 발견

- **F34 (중간) — 두뇌가 판단 없이 RECLAIM 에 들어가 멈춘다.** SPEC/T01 에서 두뇌가 `fodh state transition RECLAIM --task T01` 을 직접 실행(10:36:29). 이어 `fodh reclaim` 이 `--task 및 --judgment가 필요합니다` → `task를 막는 열린 판단 번호가 필요합니다` 로 실패했고, `Skill fodh-judgment` 를 불렀지만 판단은 등록되지 않은 채 `대기: 사용자` 로 끝냈다. RECLAIM 은 F28 대상 상태가 아니어서 하네스가 대기를 받았다. 사용자 지시 뒤 A1 을 등록했지만 다시 `대기: 사용자`(10:42). 정식 입구(`fodh reclaim`, `judgment add --reclaim`)만 남기고 RECLAIM 에서의 사용자 대기를 거부하는 수정 → [보정 1](../위임스펙/2026-09-25-Pi-0.87.1-이관-보정-1.md) F34.
- **haiku 두뇌 품질(기록만).** MERGE 에서 병합 대신 "T02 초기 설정 완료" 확인 판단(A2)을 등록하고 RECLAIM, 답 적용 뒤에도 다시 MERGE→RECLAIM(A3 고아 판단). 게이트가 모두 하네스 증거로 잠겨 있어 상태는 다치지 않았다. 두뇌 비교(A14)는 opus 5.5·fable 5.1 로 한다.

## 참고

1. `kill -INT` 는 Pi 가 session_shutdown 을 거치지 않고 끝나 `.pi/harness.lock` 이 남는다(SIGHUP·SIGTERM 은 정상 종료 경로라 해제됨). 다음 시작이 죽은 pid 잠금을 인수하므로 기능 문제는 없다. 두뇌 턴 기록(`brainTurn`)도 다음 session_start 가 닫는다(보정 12 S3).
2. SIGHUP 뒤 원장의 두뇌 턴 결과는 `brain:0 unknown {abortKind:'user'}` 로 남는다. 신호 종료를 사용자 중단과 구분하지 않는다(기능 영향 없음, 관찰만).
3. 0.87.1 첫 실행은 변경 기록을 화면에 띄운다(1회). 이후 `lastChangelogVersion` 이 갱신된다.
4. 시드 설정의 `delegate.codex.effort` 는 옛 키라 미지 키 경고(#3)만 내고 무시됐다. 그래서 T02 수행자 Codex 는 기본값 `workerEffort: xhigh` 로 돌았다(사용자 규칙은 high). A14 씨앗은 `workerEffort`·`brainEffort: high` 로 고쳤다.
