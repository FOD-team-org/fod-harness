## 스펙·설계 불일치

1. **backlog 템플릿 생성 vs develop-start 판정** (스펙 §6 내부 충돌): H1 의 원인이다.
2. **DONE_ALL**: 설계 §3-4 는 "알림 후 IDLE", 스펙·코드는 정지 상태에서 사용자가 IDLE|PLANNING 을 고른다.
3. **WAIT_JUDGMENT 진입 절차**: 설계 §3-3 "지금 상태 갱신 → CLEANUP → 알림(A3) → 턴 종료" 인데 스펙은 침묵하고 코드에 없다(L10). `stopForJudgment` 는 CLEANUP 도 없다.
4. **CLEANUP_FAILED**: 설계 §3-2 "1회 재시도 → paused(cleanup) + 알림". 스펙은 전이만 허용하고 주체가 없다(M4).
5. **DoD 커밋 관계**: 설계 §5 "교차검수 대상 커밋 = 병합 커밋의 부모", 스펙 §1 "review.commit == --commit". 코드는 merge.commit 과 review.commit 의 관계를 보지 않는다. 증거도 모두 두뇌의 자기 보고(`--verify-ok`, `--review-high 0`)라 P3 에서 검수 문서·git 확인으로 대체해야 한다.
6. **DoD 검사 시점**: 설계 §5 "`fodh state` 가 전이 때 검사", 스펙은 `backlog set --status done` 에서 검사. 전이 쪽 가드가 없어 M3 이 생긴다.
7. **INTERVIEW 질문 채널**: 설계 §12 "유한 선택지는 TUI 선택", 스펙 §6 "유한 선택지는 판단대기 항목". 스펙을 따랐으나 채팅 대기와 자동 재개가 충돌한다(M1).
8. **agent_end 분류**: 설계 §6-0-4 "`error` → 백오프 5·15·60 재시도, 연속 3회 → paused(error)". 스펙·코드는 첫 error 에서 프로바이더가 `paused(error)` 로 바꾸고 오케스트레이터는 재개하지 않는다. 재시도는 PICK 의 WAIT_RETRY 로 옮겨졌지만 대상 task 가 없다(H2·M6).
9. **승인 필요 처리**: 설계 §3-3·§6-0-5 "판단 → RECLAIM", brain-rules 3행은 RECLAIM 이 없다(M8).
10. **IMPLEMENT 분류**: 설계 §3-2 "design → Claude Agent(Opus 5.5)" 는 P1 에서도 가능한 경로인데 스펙은 전부 '위임 필요' 스텁으로 뒀다. P1 실기에서 task 루프가 IMPLEMENT 를 한 번도 통과하지 못해 VERIFY~CLEANUP 실경로는 검증되지 않는다.
11. **fodh 명령군**: 설계 §6-0-2 의 `fodh proc register`, `fodh cleanup run`, `fodh slots status` 는 없다. 레지스트리에 taskId 를 넣는 생산자가 없다(L12).
12. **§9 세션**: `ctx.newSession()` 을 쓰지 않는다. 설계("명령 컨텍스트 전용, 회전하지 않음")와 일치한다.
