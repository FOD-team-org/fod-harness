# P7 도그푸딩 계획 (2026-09-24, Fable 운영)

목적: P1.5~P6 를 합친 하네스로 장난감 프로젝트 하나를 **처음부터 끝까지** 돌려, 상태 기계·자동 재개·위임·검수·정리가 사람 개입 없이 이어지는지 확인한다. 사용자가 없으므로 인터뷰 답·판단 답은 Fable 이 사용자 역할로 채팅/판단대기에 쓴다(기록에 "사용자 역할 = Fable" 명시).

## 준비
- 새 토이 `scratchpad/live13`: `git init`, `npm init -y` + `test/` 에 node 테스트 1개, `.pi/harness.json {brain:{model:haiku}, verify:{commands:["npm test"]}, delegate:{codex:{waitMinutes:1, workerModel:"gpt-6-astra", effort:"high"}}}` (도그푸딩은 astra high 로 — sol xhigh 는 비용·시간), `.claude/settings.json` 훅, `fodh skills install`, `fodh claude-md generate`, `fodh doctor` (hookDenials 2, claudeMdLoaded true).
- 두뇌는 haiku(약한 두뇌 원칙 검증). 관찰 방식은 tmux + `capture-pane`.

## 시나리오 A — `/project-start` (INTERVIEW → RESEARCH → PRD_DRAFT → ARCH → PLANNING → READY)
1. `/project-start` → 라운드마다 free 문항에 사용자 역할로 답(가계부 CLI 도구 컨셉), choice 는 `deferred` → 판단대기 A번호에 Fable 이 "- 답: ①" 형식으로 기입 → 워처가 답을 감지해 재개(`/judged` 없이). 18 영역 완료까지(예상 7~8 라운드).
2. 확인: `docs/결정기록/…-인터뷰.md` 뷰, 판단대기 결정 완료 표, INTERVIEW→RESEARCH 가드 통과, RESEARCH 의 `fodh codex research` 위임(read-only) + 보고서 저장, PRD_DRAFT `docs/PRD.md`, ARCH 문서 2개, PLANNING `docs/backlog.md` task 2~3개(반나절 이내 단위), READY 전이.
3. 실패 관찰 포인트: 자동 재개 3회 상한, `대기: 사용자` 표지 누락 시 동작, 프롬프트 25줄 안에서 haiku 가 명령을 정확히 치는지.

## 시나리오 B — `/develop-start` (PICK → SPEC → IMPLEMENT → VERIFY → REVIEW → MERGE → DOCS → CLEANUP → PICK …)
1. task 1(Codex 경로): SPEC 스캐폴드 → `fodh codex task` 위임(워크트리) → `대기: 위임` → VERIFY(`npm test`) → REVIEW(Claude Agent 검수, 높음 0) → MERGE(`git merge` 는 MERGE 상태에서만 허용) → DOCS → CLEANUP(워크트리 제거·프로세스 0) → PICK.
2. task 2(design 경로, 있으면): Claude Agent 위임 → `fodh codex review` 교차검수.
3. 강제 실패 1회: task 1 스펙에 일부러 실패하는 테스트 조건을 넣어 VERIFY 실패 → FIX → VERIFY → REVIEW 복귀와 `repairAttempts` 증가 확인.
4. 가드 확인: IMPLEMENT 상태에서 두뇌가 `src/` 에 Write 시도하면 훅 거부(P6 규칙 4) → 판단대기가 아니라 위임으로 우회하는지.
5. 종료: 모든 task done → READY/IDLE, `/cleanup`, `/quit`, 잔존 프로세스 0, `vm_stat`/swap 기록.
