## 테스트 공백(참고)

- 실제 pick·cleanup·orphan·훅 승인 경로를 거치는 통합 테스트는 없다. 이들은 출처가 없어 대상이 아니라는 단위 검증만 있다.
- agent_end 스윕은 가짜 Pi 의 `isIdle() === true` 에 기댄다. 실제 Pi 가 agent_end 시점에 idle 이 아니면 watcher 경로만 동작한다. 안전 문제가 아니라 반응 속도 문제다. 실기에서 확인한다.

## 문제없음으로 확인한 것

- v0.1 설계 검수 H1~H5 가 코드에서 실제로 닫혔다. 출처 곁 파일은 깨지면 전부 대상 아님으로 처리한다(실패하면 닫는 쪽).
- 출처 곁 파일·오토파일럿 상태 파일은 훅이 보호한다. 두뇌의 on/off·설정 변경은 `assertNotBrain` 으로 막힌다.
- 승인 필수·차단어·설정 규칙·선택지 부족·번호 없음·답 있음·held·followup·reaskOf·cleanup 은 제외된다. DONE_ALL 은 멈춘다. headless 는 제외된다.
- 답 쓰기는 `harness-judgment-apply` 잠금 안에서 idle·hold·abort·스냅샷을 다시 보고 `expectEmpty`/`expectedRaw` CAS 를 한다.
  - `applyJudgments` 에는 항상 expected 를 넘긴다.
  - 충돌 재시도에서 사용자 답을 덮어쓰거나 두 번 적용하지 않는다.
  - 동시 스윕은 sweep 잠금으로 직렬화된다.
- 정체는 범위마다 1회, 전체·task·범위·같은 제목 한도가 배치 안에서도 지켜진다. 채팅 회신 루프는 `maxAnswers × (maxChatReplies + 1)` 로 막힌다.
- 꺼진 상태에서 `instruction()`·`judgment add` JSON·판단 파일·판단기록·CLAUDE.md 가 바이트까지 같다. `applyAndResume`·`startDevelopment` 추출 뒤 의미가 같다.
- `fodh-answer` 해시가 맞지 않으면 출처를 무시한다. `(오토)` 표기가 정상이다. PROJECT_READY 자동 시작 뒤에도 두뇌 CLI 는 `userOnlyTransitions` 에 막힌다.
