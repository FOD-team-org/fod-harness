## 2. `--resume last` + 감독 강제 종료 (검수 실기 3·5, H1 재현)

`fodh codex task --task T01 --spec docs/위임스펙/T01-resume.md --title '재개 시험' --resume last` (스펙: `sleep 150` 뒤 `src/marker.txt` 작성)

| 확인 | 결과 |
|---|---|
| resume argv | `codex exec resume 01a0d202-… -c sandbox_mode="workspace-write" --skip-git-repo-check -m … --json -o … -`; spawn cwd = 워크트리 |
| resume 에 cwd·샌드박스 적용 | `marker.txt` 가 **워크트리** `src/` 에 생성됨(루트 아님) → 적용 확인 |
| 도구 자식의 프로세스 그룹 | **`sleep 150`(pid 85956) 은 자기 pgid 85956** — 감독 그룹(85280)에 속하지 않는다. codex 가 도구 명령을 별도 세션/그룹으로 띄운다 |
| 감독만 `kill -9` | codex(85285)·네이티브(85286) 가 pgid 85280 을 유지한 채 ppid 1 로 계속 실행. `sleep` 도 계속 |
| 슬롯 | `fodh slots status` `alive.codex=false` → 다른 프로젝트가 즉시 슬롯을 가져갈 수 있음(H1 ①) |
| cancel | `감독 프로세스 소유권을 확인할 수 없습니다` 로 거부(H1 ③) |
| 60초 뒤 tick | meta `lost`, 슬롯 null, `codex-done`(lost) 발행. 그러나 고아 codex 는 그 뒤에도 실행을 이어가 15:08:23 에 `marker.txt` 를 쓰고 `turn.completed` 로 정상 종료했다(H1 ②: lost 마감 뒤에도 워크트리에 계속 씀) |
| 사후 cancel | meta 가 이미 lost 로 끝나 있어 delegation 만 해제됨 |

발견:
- **F7 (H1 보강)** 그룹 회수만으로는 codex 의 **도구 자식**(자기 pgid)을 잡지 못한다. 감독의 `stopChildren` 과 워처·cancel 의 회수는 신호를 보내기 **전에** `ps -axo pid=,ppid=,pgid=` 로 (그룹 구성원 ∪ 그 pid 들의 ppid 자손 폐쇄) 스냅샷을 찍고, 그 집합 전체에 TERM→대기→KILL 을 보낸 뒤 같은 스냅샷 + 그룹으로 잔존을 확인해야 한다. codex 가 죽으면 도구 자식은 ppid 1 로 재부모화되므로 스냅샷 순서가 중요하다.
- **F8** 감독 사망 후 고아 codex 가 `turn.completed` 까지 끝낸 경우, lost 판정 시점에 그룹이 죽어 있고 events.jsonl 에 `turn.completed` 가 있으면 `status:'ok'`, `exit:null`, `supervisorLost:true` 로 마감하는 편이 결과 손실을 막는다. `turn.completed` 가 없으면 `lost`.
