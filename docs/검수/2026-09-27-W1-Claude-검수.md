- 대상: W1 작업 트리 변경(설정·멤버십·루트 판정·백로그·doctor). 기준 문서는 [위임 스펙](../위임스펙/2026-09-27-W1-워크스페이스-설정.md), [결과](../위임스펙/2026-09-27-W1-결과.md), [설계 v0.2](../설계/2026-09-27-워크스페이스-모드-v0.2.md).

## 테스트 품질

- `/` 경로 거부 사례는 공허하다. 실제로는 `.git` 이 없어서 실패한다.
- `rejects.toThrow()` 에 기대 메시지가 없는 사례가 많다.
- 빠진 테스트:
  - add 사전검사 원자성
  - Codex 자식·두뇌의 init/add 거부
  - 한 레포 `--repo` 거부
  - sync 복원
  - CLAUDE.md 스냅샷

## W2 API 주의

- 표지 함수 인자가 섞여 있다. `validateMarker` 는 파일 경로를, 나머지는 common dir 을 받는다. common dir 로 맞춘다.
- 멤버 모양이 모드마다 다르다(한 레포 `baseBranch` undefined). 기본값 채움은 한 곳에서 한다.
- 워크스페이스 모드에도 최상위 `config.verify`·`config.worktrees` 기본값이 남아 있다. W2 가 이것을 읽으면 멤버 설정을 무시하게 된다.
- `state.worktrees[].repo` 는 W2 가 채워야 doctor·remove 검사가 의미를 갖는다.

## 문제없음으로 확인한 것

- 결정 ①·②·③ 구현
- 두뇌·Codex 의 멤버십 변경 차단
- 표지 위조는 양쪽 동의(표지 ↔ 설정 목록)가 있어야만 통한다
- realpath 기반 경로 검사(symlink·`..`·HOME·`/`·중첩·중복·연결 워크트리·서브모듈)
- 로컬 명의만 사용(전역·`-c user.*`·`--author`·`--no-verify` 없음)
- init 사전검사가 모든 쓰기보다 먼저 돈다. 커밋이 실패하면 표지를 회수한다
- 명시적 `FODH_PROJECT_ROOT` 우선순위 유지
- 한 레포 backlog 표·시작 출력이 바이트까지 같다
- `validateWorkspace` 는 재귀하지 않고 멤버 파일을 읽거나 쓰지 않는다
