## 4. 새 발견

### 높음

**H1. P6의 새 거부(경계·삭제·env·파괴적 git)가 모두 "승인 판단 + 작업 회수"로 처리된다. 실행 중인 위임도 취소된다**

- 위치:
  - turn.ts:166-171, 183: tool_result가 `/hook error|PreToolUse/`이거나 `permission_denials`에 있으면 **거부 이유를 가리지 않고** `rememberDenial`한다.
  - turn.ts:89-108 `persistDenials`: 거부마다 `addJudgment(options ['해당 동작 승인','보류'], requiresApproval:true, blocks: taskId)`를 만든다. 그 뒤 `reclaimTask(root, taskId, firstId, { suspended: true })`를 부른다.
  - reclaim.ts:38-51: 해당 task의 위임이 있으면 `cancel`하고, processes 정리 → `blocked(A…)` → PICK으로 넘어간다.
  - templates/brain-rules.md:3: "승인이 필요한 동작(**훅 차단 포함**)은 `fodh judgment add … --reclaim`"
- 재현(코드 경로):
  1. IMPLEMENT 상태에서 T01의 Codex 위임이 실행 중이다.
  2. 두뇌가 작은 수정을 직접 하려고 `Write src/x.ts`를 부른다. 규칙 4가 바로 겨냥하는 행동이다. 또는 흔한 `fodh codex status 2>/dev/null`을 부른다(M1).
  3. 훅이 거부한다. 턴이 끝나면 `persistDenials`가 "Write: {…} / 해당 동작 승인?" 판단을 만든다. `reclaimTask`가 **돌고 있던 Codex를 취소**하고 T01을 blocked로 바꾼 뒤 PICK으로 보낸다.
- 실기 증거: Fable 실기 §3 ①에서 두뇌의 `Write src/x.ts`가 거부됐다. 그 직후 TUI에 `[훅 차단] 승인 필요` 알림이 떴고 턴은 `대기: 사용자`로 끝났다. 경계 거부가 승인 흐름으로 들어가는 것이 실제로 관측됐다. Fable은 이를 "스펙대로"로 판정했지만, 규칙 4 거부 문구("위임하세요")와 맞지 않는다.
- 영향:
  - 규칙 4의 거부 문구는 "위임하세요"인데, 하네스는 사용자 승인 요청으로 바꿔 버린다. 사용자가 "승인"을 골라도 훅에는 승인 토큰 경로가 없으므로 같은 동작은 다시 거부된다.
  - P1.5에서는 규칙 3(승인 필수)만 사실상 이 경로를 탔다. P6은 흔하게 걸리는 규칙(쓰기 경계, 루트 밖 리다이렉트, `git reset --hard`, 인라인 `FODH_`)을 크게 늘렸으므로, 정상 운영 중에 위임이 취소되고 판단대기가 쌓일 수 있다.

### 중간

**M1. Bash 경계 오탐: `2>/dev/null`, 인터프리터 스크립트 인자, heredoc 본문이 소스·루트 밖 쓰기로 거부된다(H1과 겹치면 위임이 취소된다)**

- 위치: pretooluse.mjs:77(리다이렉트 대상), 85-86(인터프리터는 `-e/-c`의 인자를 뺀 모든 operand), 92(`git stash`는 항상 `.`), 33(줄바꿈 = 명령 구분), 141(Bash 경로에도 루트 밖 거부 적용), 214
- 재현(훅 직접 호출, `FODH_BRAIN=1`):
  - `ls docs 2>/dev/null`, `fodh state get 2>/dev/null`, `cmd &>/dev/null` → `/dev/null`이 루트 밖이라 "프로젝트 밖 쓰기는 금지". fodh 조기 허용(219)보다 214가 먼저 돈다.
  - `python3 -m json.tool < .pi/harness-state.json` → operand `json.tool` → root/json.tool → 소스 거부. `node scripts/check.mjs`도 같다.
  - `git stash list`, `git stash show` → operand `.` → 소스 거부.
  - ``cat > docs/a.md <<'EOF'`` 다음 줄 `> 인용` → heredoc 본문 줄이 별도 명령 그룹이 되어 리다이렉트 대상 `인용` → 소스 거부. 본문에 `codex …`로 시작하는 줄이 있으면 codex 직접 실행으로도 거부된다.
- 영향: 스펙 §1은 Bash에 대해 "워크트리 밖 **소스 경로**"만 거부하라고 했다. 루트 밖 거부는 Write/Edit에만 요구했다. `2>/dev/null`은 LLM 두뇌가 아주 흔하게 붙이는 꼴이라서, H1이 고쳐지지 않으면 곧바로 위임 취소로 이어진다.
- 수정안:
  - boundary에서 `/dev/null`, `/dev/stdout`, `/dev/stderr`, `/dev/fd/*`, `/dev/tty`를 허용한다.
  - Bash 경계에서는 루트 밖을 거부하지 않는다(스펙대로). 규칙 2의 rm과 Write/Edit만 루트 밖을 거부한다.
  - 인터프리터는 `-m <모듈>` 인자를 빼고, 스크립트 파일(첫 operand)은 "실행"으로 보고 경계 대상에서 뺀다. 인터프리터를 막아야 한다면 이유를 "스크립트 쓰기 의심"으로 따로 둔다.
  - `git stash`는 `list|show`를 뺀다.
  - heredoc(`<<`, `<<-`, `<<'X'`)는 종료 표지 줄까지 본문을 명령 해석에서 뺀다.
  - 각 사례를 테스트로 고정한다.

**M2. `git apply`·`patch` 판정이 대상 트리가 아니라 패치 파일 경로를 본다 → 문서 경로에 둔 패치로 소스를 바꿀 수 있다**

- 위치: pretooluse.mjs:79(`patch` operand), 89-91(`git apply`의 뒤 인자). audit.ts:16-21도 같은 토큰을 본다.
- 재현(둘 다 훅과 사후 감사를 통과):
  - `Write .pi/scratch/fix.patch`(허용) → `git apply .pi/scratch/fix.patch`: operand가 `.pi/…`라서 허용된다. 실제로는 루트의 `src/`를 바꾼다.
  - `patch -p1 < docs/fix.diff`: `-p1`과 `<`는 빠지고 `docs/fix.diff`만 남아 허용된다.
  - 테스트 `git apply src/a.patch`, `patch src/x.ts`는 패치 파일 자체가 src에 있어서 통과할 뿐이다(hook.test 229-231).
- 영향: 스펙 §1이 목록에 넣은 두 명령의 목적(소스 변경 차단)을 이루지 못한다. 두뇌가 Write 거부를 받은 뒤 "패치를 만들어 적용"하는 우회는 유능한 두뇌에게 자연스러운 다음 수다.
- 수정안:
  - `git apply`(`--check`, `--stat`, `--numstat`, `--summary`가 없을 때)와 `patch`(`--dry-run`이 없을 때)는 **작업 디렉터리** 쓰기로 판정한다. 대상은 `git -C`/`--directory`, `patch -d`, 그것도 없으면 cwd다. 대상이 등록 워크트리 안이 아니면 거부한다.
  - 같은 원리로 `git checkout <ref> -- .`는 이미 잡히므로, `git stash pop|apply`·`git checkout <ref> <path>`(`--` 없음)는 한계 표에 올린다.
  - 사후 감사도 같은 규칙으로 경고한다. 테스트: 문서 경로 패치를 `git apply`하면 거부, `git -C <wt> apply`는 허용.

**M3. 사후 감사가 읽기 명령·sed 식·코드 리터럴까지 "소스 쓰기 의심"으로 알려 알림이 쏟아진다**

- 위치:
  - audit.ts:16: 트리거가 `>`나 `sed|node|python|rm|install|…` 단어가 **어디에든** 있는 것이다. sed는 `-i`가 없어도 걸린다.
  - audit.ts:17-21: 따옴표 안팎에서 `/`나 확장자가 있는 토큰을 모두 후보로 삼는다.
  - turn.ts:198-202: 경로마다 원장 + TUI 알림을 낸다. 중복 제거는 한 턴 안에서만 한다.
- 재현(`auditPaths('Bash', …)`, 루트 `/r`):
  - `sed -n '1,80p' src/core/x.ts` → `/r/src/core/x.ts`
  - `grep -n foo src/a.ts | sed 's/a/b/'` → `/r/src/a.ts`, `/r/s/a/b`
  - `cat package.json | node -e "…split('/')…"` → `/r/package.json`, `/`
  - Fable 실기 F1(low로 보고): `node -e "require('fs').writeFileSync('src/w.ts','x')"`는 정확한 `src/w.ts` 경고를 낸다. 그런데 식 전체 `require('fs')…'src/w.ts','x')`도 가짜 경로로 잡혀 한 번 더 경고된다. 원인이 같으므로(후보 필터가 너무 넓음) M3에 합친다.
- 영향: 두뇌는 보통 sed·node로 파일을 읽고 가공한다. 그러면 턴마다 여러 건의 "훅이 놓친 소스 쓰기 의심" 경고가 뜬다. 경고가 흔해지면 진짜 누락(heredoc 안의 `open(...,'w')`)이 묻힌다. 검수 요청 f의 "알림 폭주"에 해당한다.
- 수정안:
  - 후보를 "쓰기 문맥"으로 한정한다.
    - 리다이렉트 대상, `tee` 인자, `sed -i`·`perl -pi`의 파일, `cp`·`mv`·`install`·`rsync`의 마지막 operand, `dd of=`

  - 테스트: `sed -n … src/x.ts`, `sed 's/a/b/'`, `cat package.json | node -e …`는 빈 결과여야 한다.

### 8-2. 새 발견

**N1 (중간). `<<<` here-string과 산술 `<<`를 heredoc 시작으로 읽어, 다음 줄부터 종료 표지까지 모든 명령이 검사에서 빠진다**

- 위치: pretooluse.mjs:42-47(연산자 정규식 `<<-|<<|…`에 `<<<`가 없다). audit.ts:31-36도 같다.
- 따라가기:
  - `<<<`는 `<<` + `<`로 나뉜다.
  - `<<`가 `delimiter=false`를 걸고, 뒤의 `<`는 이를 지우지 않는다.
  - 다음 단어(`x`, `"$v"`)가 종료 표지로 pending에 들어간다.
  - 첫 줄바꿈부터 그 단어와 똑같은 줄이 나올 때까지 모든 줄이 heredoc 본문으로 처리되어 groups에서 빠진다. 그런 줄이 없으면 명령 끝까지 빠진다.
  - `$((1<<2))`도 `2))`를 표지로 삼아 똑같이 된다.
- 재현(두뇌, 상태 IMPLEMENT). 셋 다 첫 줄은 무해하고 둘째 줄이 검사 없이 통과한다:
  - `grep -q foo <<< "$v"\nrm -rf .git`
  - `cat <<< x\nprisma migrate deploy`
  - `echo $((1<<2))\ncodex exec …`
  - 빠지는 검사는 규칙 2·3(승인)·4·5·6 문자열 검사와 codex 직접 실행 금지다. 원시 문자열로 보는 비밀값·doctor 표식 검사만 남는다.
- 영향: 1차 트리에는 없던 회귀다. M1 heredoc 파서가 새로 만들었다. `<<<`는 LLM이 흔히 쓰는 문법이라 악의 없이도 걸린다. 여러 줄 Bash 한 번에서 뒤 명령의 가드가 통째로 꺼진다.
- 수정안:
  - ① 연산자 정규식 맨 앞에 `<<<`를 넣어 heredoc 표지를 만들지 않게 한다.
  - ② `$((`·`((` 안의 `<<`는 연산자로 보지 않는다(괄호 깊이 추적). 그게 어려우면 표지 후보가 식별자 모양(`/^[A-Za-z_][\w-]*$/`, 인용 제외)이 아닐 때 heredoc으로 보지 않는다.
  - ③ 종료 표지를 끝내 못 찾으면 fail closed로 한다. 두뇌는 `[보호]` "heredoc 종료 표지를 찾을 수 없습니다"로 거부하거나 나머지 줄을 명령으로 검사한다.
  - 훅과 audit에 같은 수정을 넣는다. 가능하면 두 곳의 파서를 공통 파일 하나로 합친다(현재 복제되어 있다).
  - 테스트: 위 세 명령은 거부, `cat <<< x`만 있는 한 줄은 허용.

**N2 (낮음). 셸로 들어가는 heredoc·`-c` 문자열은 규칙 검사와 감사 모두에서 빠진다(heredoc은 1차 대비 회귀)**

- 위치: pretooluse.mjs:30-41(본문을 groups에서 제외), 231-236(`-c` 문자열은 FODH_만 검사); audit.ts:139-146(인라인·heredoc은 fs API 호출만 탐지)
- 재현:
  - `bash <<'EOF'\ngit push --force origin main\nEOF`: 1차 트리에서는 본문 줄이 명령으로 검사됐지만 이제 통과한다. FODH_·codex·승인 규칙도 같다.
  - `bash -c 'echo x > src/a.ts'`: 훅(인터프리터 operand 제외)과 감사(fs API만 탐지)를 둘 다 통과한다. 1차 감사는 이 경로를 잡았다.

**N3 (낮음). `normalizePath`가 EACCES·ELOOP·ENAMETOOLONG을 다시 던져 사용자 세션의 편집 도구까지 "훅 입력을 해석할 수 없습니다"로 거부된다**
