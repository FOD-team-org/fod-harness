## 4. 계획과 달라진 점

- S3 이 VERIFY 가 아니라 IMPLEMENT 결과 확인에서 처리됐다. 두 두뇌 모두 미보고 파일을 VERIFY 전에 찾아 수정 스펙으로 지웠다. 계획이 기대한 "VERIFY 실패 → 판단" 경로는 S3b 에서 확인했다. 출처를 모르는 파일을 판단 없이 지운 점은 둘 다 같고, 운영에서는 주의점이다(사용자가 일부러 둔 파일이면 지워진다).
- S3b 를 더했다. S3 이 판단으로 가지 않아서, T02 완료 직후 main 에 사용자 커밋으로 항상 실패하는 테스트를 넣었다.
- 판단 답은 두 시험 모두 판단이 등록된 지 1분 안에 적었다. 그 두뇌 턴이 아직 돌고 있어 두 번 다 held 가 됐고 `/judged A1` 로 풀었다. 같은 시점·같은 문구라 비교에는 영향이 없다.
- 슬롯 대기는 Opus 쪽에서만 3회 났다(ChatGPT 앱이 몇 분마다 띄우는 짧은 `codex exec` 를 `codex-guard` 가 잡음). Fable 시험 중에는 겹치지 않았다. 시간 비교는 대기를 뺀 값으로 했다.
