## 스펙 대비 미구현·불일치

1. **자기 수정 억제의 전제**(설계 §4-2 "기대 해시로의 변경은 무시"): 기대 해시가 외부 편집까지 포함하게 되어 억제 범위가 스펙보다 넓다(H1). 스펙이 "기존 `save()` 가 기록"이라고 해서 이를 그대로 쓴 결과이므로, 스펙 문구도 "하네스가 쓴 내용 기준"으로 고쳐야 한다.
2. **§3 "새 항목을 만들 때마다 decideInbox"**: 같은 프로세스에서 발행한 경우에만 결정한다. CLI 발행, 종료 경합, 결정 예외가 있으면 결정이 유실된다(M2).
3. **§3 "콜백 예외를 전파하지 않고 폴링 계속"**: session_start 에서 예외가 나면 타이머가 아예 시작되지 않는다(M3).
4. **§4-1 "agent_end 와 워처 결정이 같은 경로"**: 경로는 같지만 중복 방지 상태는 공유되지 않는다(M1).
5. **§4-2 stalled 행**: 스펙 자체가 `recovering`(사용자 중단)을 예외로 두지 않았다. recover 행과 일관되게 고친다(H2).
6. 나머지(§1 설정 검증 메시지·기본값, §2-3 한계 기준·gone·dedupe, §2-4 대상 상태, §2-5 `addInboxOnce` 호환, §4-3 `/status` 필드, §5 CLI, §7 README·설계 ⑬, package.json 순서)는 구현과 테스트를 확인했다.

## 테스트 품질 소견

- 강점: core 테스트는 주입 시계로 안정화 경계(10999/11000ms)를 정확히 단언한다. 모든 활동·정지 상태를 `it.each` 로 전수 검사하고, 동시 tick 에서 하나만 발행되는지는 실제 파일 잠금으로 확인한다. `spawn:` 시각, 레지스트리 무변경, 기존 판단 메타데이터 보존도 단언한다. 확장 테스트는 unref, 디바운스 499/500ms, print 모드 타이머 0, shutdown 뒤 타이머 0, 원장·UI 이중 실패 비전파를 확인한다. 기존 P1 테스트 단언은 약화하지 않았다.
- 약점: L8 에 정리했다. 핵심은 테스트 전부가 "하네스 쓰기와 사용자 쓰기가 섞이는 경우"(H1·M4)와 "Pi 의 실제 모듈 격리·isStreaming 의미"(M1)를 대역으로 가려서, 실기에서만 드러날 결함을 통과시킨다는 점이다. Fable 실기에서 다음을 확인할 것을 권한다. ① 두뇌 턴 도중 문서에 답 쓰기 → 인박스·자동 적용 여부. ② Esc 중단 뒤 10분 방치. ③ WAIT_JUDGMENT 전이 직후 문서 답 → 턴 중복 여부.

### 회귀 점검 결과(문제 없음)

- **JudgmentConflict 재시도**
  - `applyJudgments` 의 `applied` 배열을 재시도 바깥에 둔 것은 의도된 설계다. 1회차에 완료한 항목은 journal 에서 빠지고 열린 목록에서도 사라지므로 중복 push 가 없다.
  - `completeJudgment`·`markFollowup` 의 충돌은 바깥 `applyJudgments` 재시도가 흡수한다.
  - 잠금 순서는 apply → 문서 → 워처 → 인박스로 1차와 같다. `tick` 은 문서 잠금을 잡지 않으므로 교착 경로가 없다.
- **externalPending**
  - 한 번 설정하면 하네스가 다시 써도 유지되고(`previous?.externalPending ??`), 발행 때만 삭제된다.
  - 원문이 비어 있으면(최초 생성) 설정하지 않는다.
  - 워처 파일을 잃은 뒤 첫 하네스 쓰기에서는 한 건이 더 발행될 수 있다. 이 건은 "답 없음"으로 닫히므로 무해하다.
- **decided/decisionFailures**
  - 성공하면 실패 계수를 지운다.
  - 3회째에는 원장 기록을 잠금 밖에서 남긴다(`:195`). 워처 잠금과 원장 잠금이 중첩되지 않는다.
- **자유 서술 타이머**
  - 루트당 1개이고 unref 된다.
  - shutdown 때 해제되고, in-flight 결정이 끝난 뒤에 다시 한 번 해제된다.
  - 발화 시점에 run 이 진행 중이어서 요청이 흡수되더라도 5초 poll 이 다시 결정하므로 적용이 누락되지 않는다.
- **resolveInbox**
  - 모든 상태를 applied 로 바꾸고 `resolvedBy` 를 기록한다.
  - 존재하지 않는 id 는 throw 한다. 호출자는 방금 조회한 id 만 넘긴다.
  - `addInboxOnce` 는 applied 를 dedupe 에서 제외하므로 같은 해시로 되돌린 편집은 다시 발행된다. 정체·자식 이벤트는 `emittedKeys` 로 한 번만 발행된다.
- **M1 최종 idle 검사**: `send()` 헬퍼 대신 준비된 `content` 로 `pi.sendMessage` 를 직접 호출한다. 검사와 전송 사이에 마이크로태스크 경계가 없다.
