## 4차(보정 3) — APPROVE_WITH_FIXES

I1~I4 는 코드와 probe 로 확인했다.

- **감지 입력(I1)**
  - HEAD 를 `rev-parse --verify HEAD^{commit}` 로 한 번 고정하고, 읽기는 모두 `<sha>:<prefix><path>` 로 한다. `-` 로 시작하는 경로·공백·비ASCII 경로도 안전하다.
  - 두뇌가 작업 디렉터리로 감지를 흔들 수 있는 fs 읽기는 남지 않았다.
  - `.git` 이동·HEAD 없음·상위 저장소 폴백은 fail closed 다.
- **HEAD 바꿔치기**: `update-ref`·`reset`·`checkout -B` 는 훅이 막는다. 검증 head 는 REVIEW 에서 검수 커밋과 같아야 한다.
- **새로 고침(I3)**: 상위 집합일 때만 기록한다. 사용자 heavy 는 제외한다. 잠금 안에서 단조 규칙을 다시 확인하고 hash 를 새로 만든다. 실행 전에 새로 고치고, 원장에 `via:'refresh'` 를 남긴다.
- **읽기 오류(I4)**: `SyntaxError` 만 삼킨다. run 은 `finish(ok:false)`, init·workspace 는 경고와 함께 완료된다.

## 보정 5 확인 — 마감

Fable 이 K1~K6 diff 를 직접 확인했다.

- `harnessGit` 고정 목록에 `core.attributesFile=/dev/null`·`GIT_ATTR_NOSYSTEM=1` 이 더해졌다.
- `gitSnapshot` 의 확인 순서
  1. 공통 디렉터리
  2. `--absolute-git-dir` = `<common>/worktrees/<이름>`
  3. `gitdir` 역참조 = 등록 워크트리 `.git`
  4. main 이 기준이면 git-dir = common
  - 하나라도 어긋나면 `head:null, clean:null` 이다.
- replace 를 무시하는 곳: `taskGit`(`validateTaskCommit`·merge), Codex supervisor·자식, `runProcess` 자식. 모두 `GIT_NO_REPLACE_OBJECTS=1` 이다. 사용자 검증 명령 env 는 그대로다.
- 훅: 쓰기 가능 git 명령에 `refs/replace` 인자가 있으면 거부한다. `git replace -l <pattern>` 은 허용한다.

부수 효과가 하나 있다. 등록되지 않은 `task.worktree`(두뇌가 편집할 수 있는 backlog 값)가 가리키는 경로는 이제 clean 증거가 null 이다.

- REVIEW 게이트는 워크트리 task 에 `clean === true` 를 요구하므로 막힌다.
- 2차에서 후속으로 남긴 "기준 경로 폴백" 중 REVIEW 게이트 부분은 fail closed 가 됐다.
- 정상 흐름(`fodh worktree create` 로 등록)은 영향이 없다.

실제 프로젝트 확인: `기획/일반앱 아이디어` 는 이 소스 트리로 돈다. 등록 워크트리 `wt-T05` 의 verify 증거는 `clean:true`·head 기록이었고 REVIEW 로 넘어갔다.
