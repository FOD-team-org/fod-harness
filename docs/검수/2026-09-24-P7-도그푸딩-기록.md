IMPLEMENT 템플릿·Codex 머리말에 "작업 커밋은 Codex 가 워크트리 브랜치에 만든다" 를 명시(현재 Codex 는 git 금지 → 두뇌의 `git commit` 은 MERGE·DOCS 에서만 허용이라 커밋 주체가 비어 있음 — 설계 §3-2 VERIFY 산출물 "실제 작업 커밋" 과 어긋남). 해소안: `fodh worktree commit <task> -m` 를 하네스 CLI 로 제공(워크트리 안에서만, 사용자 승인 불필요, 원장 기록) 하고 VERIFY 통과 뒤 두뇌가 호출한다.
- 두뇌 시행착오(VERIFY→PICK, PICK 상태 아님)는 CLI 가 막았다. haiku 는 "통과 조건" 을 자의적으로 완화하는 경향이 강하므로 모든 단계 전이는 하네스 증거로 잠가야 한다(F4·F5·F6·F12 공통 교훈).

### 시나리오 B — 3~4턴 계속(REVIEW→MERGE→DOCS→CLEANUP→PICK→T02, 20:42~20:47, 같은 자동 턴)

| 단계 | 두뇌 동작 | 결과 |
|---|---|---|
| REVIEW | Claude Agent(haiku 자식) 검수 → `backlog set --review-commit df47623… --review-high 0` → `transition MERGE` | 보정 1 코드에서 delegate codex 는 증거 면제(N2) → 통과. `df47623` 은 착수 전 토이 HEAD(구현은 untracked) |

- **F15(high)**: DoD 플래그(`--verify-ok`·`--docs-ok`·`--cleanup-ok`)와 `--merge-commit` 이 두뇌 자기 보고다. 검증 실패·병합 없음·작업일지 없음 상태로 task 가 `done` 이 됐다. → 세 플래그 삭제, `verify.ok` 는 VERIFY→REVIEW 전이 통과 시(F12 증거), `cleanup.ok` 는 `cleanup run --task` 성공 시, `docs.ok` 는 DOCS→CLEANUP 전이(작업일지·백로그 동기화 검사) 통과 시 하네스가 기록; `--merge-commit` 은 검수 커밋을 포함하는 실제 커밋만. 스펙 [P7 보정 3](../위임스펙/2026-09-24-P7-보정-3.md).
- 종합: F4·F5·F6·F12·F14·F15 는 모두 같은 결함 — "두뇌가 말하면 통과". P7 의 가장 큰 교훈은 **모든 단계 전이·DoD 를 하네스가 만든 증거로만 잠근다** 는 것이며, 설계 §3-2 표의 "규칙" 열은 이 게이트 기준으로 다시 쓴다.
