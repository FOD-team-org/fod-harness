## 문제없음으로 확인한 것

- 한 레포 불변:
  - 머리말은 `{{targetRepo}}` 를 빼면 HEAD 와 같다.
  - 원장 evidence 에 `repo` 가 없다.
  - `--base` 와 상태 `mergeBase` 대체값이 그대로다.
- REVIEW→MERGE 기준점:
  - `updateState` 콜백 안에서, 재개가 아닐 때만 계산한다.
  - `rootHead` 가 null 이면 건너뛴다.
- 재개 검사:
  - ① 답일 때만 재설정한다. dedupeKey 가 있다.
  - `resume ?? { state: 'MERGE' }` 로 재개 지점을 보존한다.
  - 이 task 의 `resumeTask` 만 푼다. 반복 한도가 있다.
- `worktree merge`:
  - pre 를 먼저 쓰고 finally 에서 끝맺는다.
  - 표시 파일은 runId·task·review 가 모두 맞아야 하네스 것이다.
  - `--no-ff --no-commit --no-autostash` 로 병합한다.
  - 프로세스 그룹을 종료한다. stdin 은 무시한다.
  - stderr 는 4KB 를 redact 해 원장에만 남긴다.
  - 이미 병합됨·fast-forward 판정이 맞다.
- 설정: 멤버 경로를 검증한다. `worktrees.root` 가 루트·모든 멤버 밖이어야 한다.
- 위임·검증·감사·복구:
  - 위임은 research `--repo` 를 검사하고, 멤버 `.git` 으로 gitTask 를 판정한다.
  - 검증은 현재 task 워크트리 안에서만 한다. 기준 브랜치 경고는 예외를 던지지 않는다.
  - 감사는 멤버 main 쓰기(Bash 포함)를 경계 경고로 잡는다.
  - 복구 줄에는 `repo` 가 있을 때만 붙는다.
- 잠금 순서가 일관된다. CLAUDE.md 필터가 `worktree merge` 를 뺀다. `--repo` 는 `codex research` 만 받는다.
- 기존 테스트 파일 수정 없음.
