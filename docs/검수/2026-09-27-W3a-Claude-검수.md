## 낮음

| # | 지적 | 조치 |

| L-1 | `{` 중괄호 확장을 동적으로 보지 않는다(`npm i --prefix=../{chemical,chemical}` 0). `xargs -I{}` 치환자도 | 동적 판정에 `{` 추가, `xargs -I` 치환자 인자는 동적 |

| L-5 | 비밀 검사 내부 예외는 바깥 catch 문구가 아니라 `경로 확인 불가` 가 된다. 차이를 내는 입력은 못 찾았다 | 결과 문서에 한 줄만 |

## 테스트 공백 → 보강 지시

1. 비밀 거부 단언이 문구 앞부분만 본다. 파일 이름까지 정확히 단언한다.
2. `toContain` 으로만 확인하는 행(우선순위·별칭·cwd, git M5, `cd docs && cd docs`)을 정확한 stderr 로.
3. 빠진 사례: M-1·M-2·L-1·L-2, 단독 할당(통과)과 앞붙임 할당(M1) 짝, BFS·시간 상한, 한 레포에서 cwd 가 루트 밖.
4. 골든에 Glob·NotebookEdit·MultiEdit 가 없다. 골든은 다시 만들지 않는다. 검수에서 HEAD 와 같음을 확인했으므로 결과 문서에 적는다.

## 문제없음으로 확인한 것

- 멤버 main 쓰기·실행 거부: 리다이렉트·heredoc·`cp`·`sed -i`·`sort -uo`·`exec 3>`, cd·`make -C`·`pnpm --dir`·`yarn --cwd`·`env -C`, `~/..`·`$HOME/..`·조상 cwd, 심볼릭 링크 경유, 앞붙임 할당.
- 멤버 git 변경 거부: fetch·stash·branch·add·commit, 긴 옵션 줄임.
- 동적 경로 M5, `GIT_*` M6, 전역 옵션 M7. 기존 문구가 먼저 나는 순서.
- 비밀: 심볼릭 링크 경유, `rev:path`·`:path`·`./`·`../`, cd 집합, 재귀.
- 승인이 M1 보다 먼저 난다(워크트리 cwd 포함).
- 허용돼야 할 것이 통과한다: 허용 목록 읽기, git 읽기, `ls ..`, 워크트리 작업, fodh, `$PWD/..`, `$(date)`.
- 한 레포 불변: HEAD 대비 차이는 모두 §0-7 범위다. Read·Grep·Glob·NotebookEdit·Write, 워크트리 cwd, heredoc 커밋 메시지, AUTO_CD, 재귀 가지치기, `git -c … log` 는 같다.
- fail-closed: 바깥 catch 문구는 그대로다.
- Codex 선택 3·4·6 은 타당하다. 7 은 L-4 로 문구만 고친다.
- 보통 사례 성능: 한 호출 약 40ms, rev-parse 약 47ms, 멈춤 없음.

## 반영 결과

- Codex 가 M-1·M-2·L-1~L-4·L-6 과 테스트 공백을 반영했다. L-5 는 결과 문서에 동작만 적었다([결과 문서 `검수 반영` 절](../위임스펙/2026-09-27-W3a-결과.md)). W3a 테스트는 19개에서 24개(7파일)가 됐다. 기존 테스트 파일은 고친 줄이 없다.
- 골든은 다시 만들지 않았다. SHA-256 이 그대로다(`b5b3666c…`).
- 메인 확인 결과:
  - `npm run typecheck` 통과.
  - 전체 직렬 **111파일 · 3481 / 3481 통과**(`--maxWorkers=1 --no-file-parallelism`, 463초).
- 반영 방식:
  - M-1: 쓰기 값에 출처(리다이렉트 / 피연산자)를 붙여, git 대상 기준 풀이는 피연산자에만 한다.
  - M-2: 줄 안의 `CDPATH` 할당·선언과 `setopt`·`set -o` 의 cdablevars·autocd 가 있으면 두 모드 모두 cwd 를 unknown 으로 본다.
  - L-3: 호출 안 메모, 확장 2,000회 상한, cwd 집합은 한 번 계산해 비밀 검사에 넘긴다(`cwdSet`).
  - L-4: 멤버 비밀 정책 컴파일 오류는 `hookWorkspace` 단계에서 잡아 기존 설정 오류 문구(`[보호]` `하네스 설정을 읽을 수 없습니다.`)로 모든 두뇌 도구를 막는다. 두뇌 아님은 한 레포로 돌아간다.
