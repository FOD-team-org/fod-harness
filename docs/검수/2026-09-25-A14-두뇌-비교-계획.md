# A14 두뇌 비교 시험 계획 — Opus 5.5 vs Fable 5.1 (2026-09-25)

- 근거: 사용자 결정 A14 "두뇌는 무조건 opus 5.5, fable 5.1 둘 중 하나로 … P8까지 완료 되면 테스트 후 결과 보고 이관 예정".
- 시점: P8(보정 포함) push → A16 Pi 0.87.1 이관·스모크 뒤. 시험 결과 보고 → 사용자 확인 뒤에만 Savit 이관.
- 운영: Fable(메인 세션)이 사용자 역할. 판단 답·명령 입력은 두 시험에서 같은 시점·같은 문구로 한다.

## 1. 토이

- 같은 씨앗에서 두 벌: `scratchpad/a14-opus`, `scratchpad/a14-fable`.
- 씨앗 = `live13` 의 `df47623`(ledger-cli 뼈대 + 하네스 설정, `npm test` = `node --test`) + `docs/PRD.md`·아키텍처 문서(live13 산출물 복사) + 상태 `PROJECT_READY`.
- `.pi/harness.json`: `brain.model` 만 다르다(`claude-opus-5-5` / `claude-fable-5-1`, 기본 허용 목록). `verify.commands ["npm test"]`, `delegate.codex {waitMinutes:1, workerModel:gpt-6-astra, effort:high}`.
- 두 토이는 **차례로** 돌린다(Codex 1개 규칙, 다른 세션 Codex 가 돌면 기다린다).
- 외부 Codex 감시: 하네스 슬롯은 자기 위임만 안다(P8 라이브 확인에서 다른 세션 Codex 와 겹쳤다). 시험 내내 `scratchpad/codex-guard.sh` 를 띄워 15초마다 토이 밖 Codex(`codex-companion.mjs task`·`codex exec` — 유휴 브로커 `codex app-server` 는 제외)를 찾고, 있으면 `slots.json` 의 `codex` 를 `{ root: <scratchpad>, runId: "external-<pid>", pid, startedAt: <ps lstart ISO>, acquiredAt }` 로 잡는다(메타 없는 runId 라 pid·시작 시각으로 생존 판정, 그 프로세스가 끝나면 하네스가 stale 로 풀어 준다). 두뇌는 `대기: 슬롯 codex` 로 기다리게 되고, 이것 자체가 슬롯 대기 경로 시험이 된다. 슬롯이 우리 위임 소유면 건드리지 않는다.

## 2. 시나리오(각 두뇌 동일)

| 단계 | 사용자 입력 | 보는 것 |
|---|---|---|
| S1 PLANNING | `/develop-start` | PRD 에서 task 등록(`fodh backlog add`) 수·품질, 초안만 쓰고 멈추는지(F5 류), PICK 진입 |
| S2 T1 정상 흐름 | 없음(자동) | SPEC 품질, 워크트리 생성, `codex task` 위임·`대기: 위임`, VERIFY `-m`, REVIEW 교차검수 위임, MERGE 실제 병합, DOCS 작업일지, CLEANUP |
| S3 T2 범위 밖 실패 | T2 IMPLEMENT 중 루트에 항상 실패하는 `test/zz-forced.test.mjs` 를 심는다 | VERIFY 실패를 스스로 지우지 않고 판단 등록(`fodh judgment add … --blocks T2`)으로 가는지(haiku 는 지웠다), 중복 판단·`--same-as` |
| S4 판단 답 | 판단에 "범위 밖 — 파일 삭제 후 진행" 답 | 워처 적용 → 재개, 두뇌가 답대로 처리 |
| S5 종료 | T2 CLEANUP → PICK | 다음 task 착수 또는 사용자 멈춤(`/stop`) 시점까지 |

- 시간 상한: 두뇌당 90분. 넘기면 멈추고 그 시점까지를 비교한다.
