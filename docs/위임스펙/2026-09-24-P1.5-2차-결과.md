# P1.5 2차 수정 결과

작성: 2026-09-24 KST.
기준: `2026-09-24-P1.5-2차-수정.md`, 설계 v0.3, Claude 검수 및 Fable 실기 기록.

**코드 반영 완료, 전체 테스트 통과 기준은 미충족이다.** 최종 `npm test`는 **191개 중 156 통과 / 35 실패**, `npm run typecheck`는 **exit 0 / 오류 0**이다. 이 샌드박스에서 `/bin/ps` 실행이 `spawn EPERM`으로 거부된다. M10의 “ps 실패 시 살아있음”을 유지했으므로 회수 완료를 증명하지 못한 실행은 `cleaned:false`와 레지스트리 기록을 남긴다. 이를 성공으로 바꾸거나 테스트 기대값을 완화하지 않았다.

## 검증 결과

실행한 테스트 명령은 `npm test`, `npm run typecheck`뿐이다. 다른 프로젝트 테스트·별도 실행 검증 명령은 사용하지 않았다.

최종 `npm test` 출력:

```text
Test Files  3 failed | 4 passed (7)
Tests       35 failed | 156 passed (191)
Duration    67.35s
exit        1
```

| 파일 | 전체 | 통과 | 실패 |
|---|---:|---:|---:|
| core.test.ts | 32 | 32 | 0 |
| hook.test.ts | 86 | 86 | 0 |
| runner.test.ts | 8 | 8 | 0 |
| turn-policy.test.ts | 7 | 7 | 0 |
| provider.test.ts | 25 | 6 | 19 |
| extension.test.ts | 5 | 1 | 4 |
| revision.test.ts | 28 | 16 | 12 |
| 합계 | 191 | 156 | 35 |

`turn-policy.test.ts`는 실행 관리자 결과를 대역으로 주는 정책 단위 테스트다. 실제 가짜 Claude 실행 또는 OS 회수의 성공 증거로 세지 않는다. 확장 테스트에서는 doctor를 mock하지 않는다. runner 테스트는 오류 주입 7개와 실제 hang-orphan 1개로 구성된다. hang-orphan은 약 5.99초에 반환했고 분리 자손은 테스트 finally에서 직접 기록한 PID만 종료한다.

35개 실패 중 34개는 회수 확인 불가로 인한 `cleanupFailed`, 후속 전환/usage/doctor 기대값 불일치, 레지스트리 미삭제 assertion 또는 회수 대기 중 5초 테스트 타임아웃과 연결된다. 나머지 1개는 다음 시작 시각 관찰 단계에서 직접 실패한다.

```text
/bin/ps -p <현재 테스트 PID> -o lstart=
Error: spawn EPERM
```

M10을 문자 그대로 유지하면 이 환경에서 ESRCH만으로 회수 성공을 확정할 수 없다. `/bin/ps -axo pid=,pgid=` 재확인도 실패하므로 alive/cleaned:false를 유지한다. 레지스트리 잔존은 프로세스 생존이 증명됐다는 뜻이 아니라 회수 성공을 증명하지 못했다는 뜻이다. 이번 실행의 전체 프로세스 잔존 0은 주장하지 않는다.

초기 수정 중 실행은 156개 중 132 통과/24 실패였고, 다음 실행은 184개 중 149 통과/35 실패였다. 첫 실행에서 발견한 `2는 제외` 명시 부정 회귀는 수정하여 최종 core 32개가 통과했다. 최종 집계에는 후속 정책 테스트 7개가 포함된다.

`npm run typecheck`: `tsc --noEmit`, exit 0, TypeScript 오류 0.
`src/` 파일에 `@mariozechner` 참조가 없다는 import 경계 검사도 통과했다.

## 설계 판단과 의도적 이탈

1. **M10의 환경 실패를 성공으로 우회하지 않았다.** ps 실패를 alive로 취급하는 스펙을 유지했다. TERM/KILL의 ESRCH 뒤에도 ps로 부재를 확인할 수 없으면 불필요한 대기를 줄여 false를 반환한다. 그룹 회수와 close 제한은 유지한다.
2. **codex 토큰의 범위:** “토큰 중 하나가 codex면 차단”을 모든 인수에 적용하면 필수 음성 예시 `grep -r codex docs/`와 충돌한다. 실행 위치 및 env/command/sudo/npx 래퍼 뒤 실행 파일을 비교한다. 따옴표·백슬래시를 해제하므로 c\\odex도 차단한다. 일반 인수의 codex는 허용한다.
3. **doctor TTL:** CLI 상태 전이에는 H1의 고정 12시간을 적용한다. 확장의 session_start/model_select는 M8의 brain.doctorTtlHours를 적용한다. 미래 checkedAt은 유효한 캐시로 인정하지 않는다.
4. **컴팩션:** Pi 0.73.1 설치본 README와 공개 ExtensionContext 타입을 확인했다. 전역 `~/.pi/agent/settings.json`, 프로젝트 `.pi/settings.json`에 `compaction.enabled=false`를 안내한다. 공개 설정 변경 API가 없어 자동 파일 수정 대신 경고한다.
5. **문항 직접 편집:** 이전에 읽거나 저장한 문항의 제목·배경·선택지·추천·막힌 작업 해시가 바뀌면 rev를 올린다. 답만 입력한 것은 문항 개정으로 취급하지 않는다. 비교 기준이 없는 첫 관찰은 기준을 저장하며 개정을 추정하지 않는다. `2는 제외`처럼 선택 자체를 부정하는 문구는 기존 부정 규칙을 유지한다.
6. **원장 종결:** 존재하는 미해결 runId/action만 증거와 함께 닫는다. resolve는 자동 상태 전이를 만들지 않는다. `recovering` 상태 자체는 별도 state transition으로 변경한다.
7. **검증 한계:** 스펙의 전체 테스트 통과 완료 기준은 아직 충족하지 못했다. ps 조회·소유 그룹 신호가 허용된 환경에서 동일한 `npm test` 및 `npm run typecheck` 재검증이 필요하다. 이것은 실제 Claude/cswap/Codex 실기를 뜻하지 않으며 가짜 실행파일만으로 재검증할 수 있다.
8. 실물 한도 픽스처 채집과 ppid 트리 잔존 검사는 스펙대로 각각 Fable 자연 발생 시점/P4에 남겼다.

git 명령은 status/diff를 포함해 실행하지 않았다. 실제 claude/cswap/codex 호출, 커밋, 비밀값 추가도 하지 않았다. 서브에이전트는 동시에 최대 1개만 사용했다.
