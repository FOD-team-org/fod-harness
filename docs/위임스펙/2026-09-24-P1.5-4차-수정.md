## 1. `groupAlive`: ESRCH 는 확정적 "없음" (필수)

- 현재: `kill(-pgid, 0)` 이 `ESRCH` 를 던져도 ps 로 재확인하고, ps 가 실패하면 살아있음으로 본다. 그래서 샌드박스(ps 불가)에서는 정상 종료조차 회수 실패가 된다.
- 수정: `ESRCH` → **즉시 `false`(그룹 없음, 커널 판정)**. `EPERM` → `true`. 그 외 오류만 ps 재확인(ps 실패 시 `true`). 즉 정상 경로는 ps 없이 판정된다.
- `reclaimOwnedGroup` 끝의 ps 잔존 검사는 "ps 가 성공했고 그룹이 보이면 false" 로만 쓰고, ps 실패는 무시한다(현행 유지).

## 2. 상속 파이프 휴리스틱 제거 → `close` 대기로 대체 (필수)

- 현재 `beginReclaim` 은 회수 뒤 50ms 만에 `child.stdout.readableEnded` 를 보고 false 면 `inheritedPipe` 로 간주한다. 그러나 `registerProc`(ps 조회) 가 끝나기 전에 자식이 종료하면 readline 이 아직 읽기를 시작하지 않아 `readableEnded` 가 false 다 → 정상 종료가 항상 `cleaned:false`.
- 수정: `readableEnded` 판정을 삭제한다. 흐름은 다음과 같다.
  1. 이벤트 루프(for await)는 그대로 stdout 을 끝까지 소비한다.
  2. 종료/중단 시 `reclaimOwnedGroup(pgid)` 로 그룹 회수(§1 판정).
  3. 그 뒤 `close` 이벤트를 **최대 `closeGraceMs`(기본 3000ms)** 기다린다. `close` 가 오면 파이프 상속 자손 없음 → `cleaned = reclaimed`. 안 오면 그룹 밖 자손이 파이프를 잡은 것 → `child.stdout.destroy()`·`child.stderr.destroy()` 후 `cleaned = false`.
  4. `closed` 전체 대기 10초 타임아웃은 유지(3 의 grace 가 그 안에 포함되게).
- `hang-orphan` 시나리오(그룹 밖 자손이 stdout 보유)는 여전히 `cleaned:false` 이고 ~3초 안에 반환해야 한다(기존 10초 이내 기준은 그대로 만족).
