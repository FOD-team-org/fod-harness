# AP1 오토파일럿 위임 스펙 (2026-09-27)

- 기준 설계: [오토파일럿 모드 v0.2](../설계/2026-09-27-오토파일럿-모드-v0.2.md). 이 스펙과 설계가 다르면 이 스펙이 이긴다.
- 선행: 워크스페이스 W1 커밋 뒤에 시작한다. `config.ts`·`cli/index.ts` 는 W1 이 고친 상태 위에서 작업한다.
- 범위 밖: 워크스페이스 W2·W3, 훅의 승인 규칙 변경.

## 1. 출처 표지 (`src/core/judgment.ts`, `src/core/brain-guard.ts`)

1-1. `brain-guard.ts`
- `export async function isBrainProcess(root: string): Promise<boolean>` 를 새로 만든다. 지금 `assertNotBrain` 의 판별(FODH_BRAIN=1, 또는 잠금 소유자 자식)을 그대로 옮긴다.
- `assertNotBrain` 은 `isBrainProcess` 를 부르게 바꾼다. 문구와 동작은 바꾸지 않는다.

1-2. `JudgmentItem.origin?: { kind: 'brain' | 'cli' | 'stall' | 'interview'; scope?: string }`
- 저장 꼴은 항목 끝 숨은 줄 `<!-- fodh-origin: <kind>[ <scope>] -->` 이다. `fodh-dedupe` 줄 바로 앞에 둔다.
- `JudgmentInput.origin?` 로 받는다.
- 두 가지 계산에 넣지 않는다. 기존 항목의 rev·`questionHash` 가 바뀌면 안 된다.
- `migrateItem` 의 `known` 과 `ordered` 에 더한다. 순서는 `fodh-dedupe` 앞이다.

1-3. 표지를 적는 곳
- `addCliJudgment`: `await isBrainProcess(root) ? 'brain' : 'cli'`. `attachJudgmentTask`(`--same-as`)는 표지를 바꾸지 않는다.
- `stopForJudgment`(`state.ts:339`): `{ kind: 'stall', scope: \`${state}:${phase}:${taskId ?? '-'}\` }`. `phase` 는 지금 상태의 단계 값이다(`project`/`task`).
- `deferQuestion`(`interview.ts:189`): `{ kind: 'interview' }`.
  - 추천이 선택지에 맞으면(이미 ①로 옮겨짐), 또는 기본 선택지면 `recommend: \`① ${q.recommend}\`` 로 적는다.
  - 맞지 않으면 지금처럼 글만 적는다.
- 나머지 `addJudgment` 호출(pick·cleanup·orphan·훅 승인·재질문)은 표지를 적지 않는다.

## 2. 답 쓰기 (`src/core/judgment.ts`)

2-1. 시그니처를 바꾼다.

```ts
export class AnswerConflict extends Error {}
answerJudgment(root, id, answer, options?: { expectEmpty?: boolean; expectedRaw?: string; source?: 'autopilot' })
```

- 파일 잠금 안에서 `requireItem` 뒤에 비교한다.
  - `expectEmpty` 인데 답이 있으면 `AnswerConflict`.
  - `expectedRaw` 가 있는데 `item.raw` 와 다르면 `AnswerConflict`.
- `source: 'autopilot'` 이면 `- 답 기준 rev:` 다음 줄에 `- 답 출처: 오토파일럿` 을 같은 쓰기로 적는다. 기존 `답 출처` 줄은 지운다.
- 사용자가 답을 고치면(`- 답:` 을 바꾸면) 출처 줄이 거짓이 된다. `reconcileEdits` 나 파서가 `답 기준 rev` 처럼 다룬다. 답이 바뀌었으면 출처를 무시해야 한다. 판별은 `답 출처` 를 쓸 때 `<!-- fodh-answer: <답 해시> -->` 를 같이 적고, 읽을 때 해시가 맞을 때만 `answerSource` 를 준다.
- 옵션이 없으면 지금과 **바이트까지 같은** 결과여야 한다.

2-2. `JudgmentItem.answerSource?: 'autopilot'`, `CompletedJudgment.answerSource?: string`.
- `completeJudgment` 가 판단기록으로 옮길 때 `- 답 출처: 오토파일럿` 줄을 남긴다.
- `parseArchive` 가 이 줄을 읽는다.
- `최근 결정` 줄은 출처가 오토파일럿이면 `→ 답 "1"(오토)` 로 쓴다.
- `migrateItem` 알려진 줄에 `답 출처` 와 `fodh-answer` 를 더한다.

## 3. 오토파일럿 핵심 (새 `src/core/autopilot.ts`)

3-1. 상태 파일 `.pi/harness-autopilot.json` 모양은 설계 §1 과 같다. 읽기는 없으면 `{ enabled: false }` 다. 쓰기는 `withFileLock(harnessPath(root, 'harness-autopilot'))` 안에서 `atomicWrite` 한다.

3-2. 순수 함수(파일·시계 없음)

```ts
recommendedOption(item: JudgmentItem): number | undefined          // 1부터
autopilotBlocked(item: JudgmentItem, config: HarnessConfig): boolean
autopilotEligible(item: JudgmentItem, config: HarnessConfig, state: AutopilotState, now: Date):
  { ok: true; option: number } | { ok: false; reason: string }
normalizeTitle(title: string): string
```

- 규칙은 설계 §2-2 그대로다.
- `autopilotBlocked` 는 기존 `approvalRequired` 를 export 해 먼저 부르고, 설계의 낱말 목록을 더한다. 영문은 대소문자를 무시하고, 영문 짧은 낱말(`tag`·`prod`·`drop`·`reset`·`force`·`token`)은 단어 경계로 본다.
- 설정 `requiresApproval` 값이 approvalRules 의 id 면 그 규칙의 `pattern` 을 원문 글자에도 적용한다(정규식 오류는 무시).

3-3. 명령 함수(CLI·Pi 공용)

```ts
autopilotOn(root, { forMs?, max?, interview?, now }): Promise<AutopilotState>   // assertNotBrain
autopilotOff(root): Promise<AutopilotState>                                      // assertNotBrain
autopilotStatus(root, now): Promise<AutopilotStatus>
```

- `--for` 는 `30m`·`8h`·`2d` 꼴이다. 최대 7일.
- `--max` 는 1~200.

3-4. 훑기

```ts
autopilotSweep(root: string, deps: {
  now: () => Date; idle: () => boolean; hasUI: boolean;
  apply: (ids: string[], expected: Record<string, string>) => Promise<{ applied: string[] }>;
  notify: (key: string, body: string, level: 'info' | 'warning') => void;
}): Promise<{ registered: string[]; answered: string[]; applied: string[]; skipped: Record<string, string> }>
```

- 흐름은 설계 §2-3 의 1~8 이다.
- 두뇌 턴 판별은 `deps.idle()`(Pi `ctx.isIdle`)이다.
- `apply` 는 orchestrator 가 `applyAndResume` 으로 넘긴다. 코어는 Pi 를 모른다.
- 끝난 판단(열린 목록에 없음)은 `pending` 에서 지운다.
- `until` 이 지났거나 `answered >= maxAnswers` 면 끄고 알린다: `오토파일럿이 꺼졌습니다 — 기간 만료` / `— 한도 30개 도달`.

## 4. orchestrator (`extensions/orchestrator/index.ts`, `resume.ts`)

4-1. `applyAndResume(pi, context, root, ids, expectedAnswers, kind)`
- decideInbox 의 `if (ready.length) { … }` 블록 몸통을 옮긴다.
- decideInbox 는 이 함수를 부르게 바꾼다. 알림·원장·반환값은 지금과 같아야 한다.

4-2. `startDevelopment(pi, ctx, root, source: 'command' | 'autopilot')`
- `/develop-start` 처리기 몸통을 옮긴다.
- 명령은 이 함수를 부른다. 동작은 지금과 같다.

4-3. 오토파일럿 연결
- `/autopilot on|off|status [--for 8h] [--max 30] [--interview]` 명령을 등록한다. 결과는 `ctx.ui.notify` 로 보인다.
- 훑기 호출 지점:
  - watcher `run()` 에서 `decidePending()` 뒤(`extensions/watcher/index.ts`)
  - `agent_end` 처리 끝
- tick 에서 켜져 있고 상태가 PROJECT_READY 이며 `userHold`·`userAborted` 가 없으면 `startDevelopment(…, 'autopilot')` 를 부른다. `/autopilot on` 직후에도 한 번 확인한다.
- DONE_ALL 에 처음 들어오면 한 번 알린다(키 `autopilot:done-all`).
- 상태줄: 켜지면 `ctx.ui.setStatus('fodh-autopilot', \`오토 ${answered}/${max}\`)`, 꺼지면 `setStatus('fodh-autopilot', undefined)`.

4-4. `대기: 사용자` 자동 회신
- `agent_end` 의 `awaitingUser: true` 를 적기 직전(지금 295-297행 근처)에 설계 §3 조건을 검사한다.
- 통과하면 `awaitingUser` 를 적지 않고, 설계 §3 문구를 `autoResume(pi, root, context, 'agent_end', 문구)` 로 보낸다.
- 계수는 상태 파일 `chat` 에 둔다.

4-5. `instruction()`(`resume.ts:17`)
- 켜져 있으면 맨 앞에 설계 §5 한 줄을 붙인다. 꺼져 있으면 출력이 바이트까지 같아야 한다.

## 10. 구현 중 결정(2026-09-27, Codex 1차 중단 뒤)

Codex 가 소스를 고치기 전에 두 가지 충돌로 멈췄다. 아래처럼 정했다.

1. **열거형 기대값 추가 허용.** `test/orchestrator.test.ts` 의 명령 목록처럼 "새 기능이 등록돼 하나 늘어나는" 기대값은 새 항목을 더해도 된다. 기존 기대값을 지우거나 약하게 바꾸는 것은 여전히 금지다. 고친 줄은 결과 문서에 모두 적는다.
2. **출처는 곁 파일에 둔다.**
   - §1-2·§1-3 의 `<!-- fodh-origin -->` 줄 대신 `.pi/harness-judgment-origin.json`(판단 번호 → `{kind, scope, createdAt}`)을 쓴다. 꺼져 있을 때도 판단 파일 바이트가 바뀌지 않는다. 두뇌는 훅의 `harness-judgment*.json` 보호로 이 파일을 쓸 수 없다.
   - 인터뷰 추천 글은 바꾸지 않는다. `recommendedOption` 이 `interview` 출처일 때 추천이 ①과 같거나 기본 선택지 쌍이면 1 로 본다.
3. **CLAUDE.md 에서 뺀다.** `autopilot` 명령은 CLAUDE.md 에 넣지 않는다. W1 검수 M2 와 같은 이유로, 한 레포 CLAUDE.md 바이트가 바뀌지 않아야 한다.
