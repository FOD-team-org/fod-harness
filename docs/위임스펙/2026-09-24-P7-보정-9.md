## Q1 (높음) — 다른 task 진행 중 판단 적용이 `resumeTask` 를 덮어쓴다 (`src/core/judgment.ts:354-356`, `src/core/state.ts:281`, `src/core/pick.ts`)

1. `applyJudgments` 는 state 의 `resumeTask` 를 **쓰지 않는다**. 복귀 정보는 task 의 `resume { status, state, at }` 에만 둔다(회수 시 reclaim 이 기록, 답 적용 시 status 를 `resume.status` 로 되돌리는 것은 유지).
2. `decidePick` 순서: (a) `current.taskId` 가 있으면 그 task 를 먼저 처리(기존 보정 8 규칙, `current.resumeTask` 는 정지 복귀 경로에서 프로바이더가 넣은 값만 신뢰); (b) 진행 중 task 가 없을 때 `status ∈ inProgress && task.resume?.state` 인 task 를 **고아 판정보다 먼저** `RESUME <taskId> <resume.state>` 후보로 삼는다(여러 개면 `resume.at` 오래된 순); (c) 그 다음 기존 규칙(ready 선택·고아·EMPTY).
3. 정지 복귀(`paused(*)` → PICK) 의 `returning` 은 **현재 taskId 의 checkpoint 만** 쓴다. `current.resumeTask.taskId !== current.taskId` 이면 무시하고 원장 `pick:stale-resume-task` 를 남긴다.
4. Q5 함께: RESUME 전이가 실제로 일어날 때(PICK→`resume.state` 전이 성공) task 의 `resume` 을 지운다.
5. 테스트(`test/p7-correction8.test.ts` 에 이어서): MERGE 의 T01 회수 → T02 SPEC→IMPLEMENT 진행 중 T01 답 적용 → ① T02 `paused(slot)` → PICK 이 **T02 IMPLEMENT** 로 RESUME ② T02 CLEANUP→PICK 뒤 PICK 이 **T01 MERGE** 로 RESUME ③ RESUME 뒤 `task.resume` 없음.

## Q2 (중간) — F21 답 파서 회귀 (`src/core/judgment.ts:92-100`)

1. 선두 번호 정규식: `^(10|[1-9])(?:번)?(?=$|[\s\p{P}])` 단, 소수점은 제외 — 선두 숫자 바로 뒤가 `.` + 숫자(`1.5배`) 이면 번호가 아니다(참고 3).
2. 복수 선택 판정은 **독립 숫자 토큰**만 센다: 영숫자에 붙지 않은 1~10(앞뒤가 문자열 경계·공백·구두점·`번`·조사 `과/와/또는/혹은/이나` 등 한글 조사도 허용), 원문자 ①~⑩ 포함. `T02`·`fce149f`·`v2` 처럼 영문자/숫자에 붙은 숫자는 세지 않는다. 독립 토큰이 2개 이상이면 `ambiguous`(재질문). 승인 필수 판단의 자유 서술 규칙은 기존대로.
3. 테스트: 보정 8 에서 완화한 4건(`1또는2`, `1번과2번`, `선택지는 1 혹은 2`, `1과 2 제외`)을 다시 `ambiguous` 로; `2번`·`2번으로 진행`·`1번 선택` → 선택 2/2/1; `T02 를 fce149f 로 진행` → freeform(번호 없음); `1.5배로` → freeform; `② 그대로` → 2.
