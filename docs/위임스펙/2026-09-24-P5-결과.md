## 선택 사항과 해석

- Fable 확정 기본값: **CLAUDE.md만 생성**, interview.enforce=true, roundSize=6, maxAsks=2, 프로젝트 `.claude/skills` 설치. 이 저장소 루트에 CLAUDE.md나 AGENTS.md를 생성하지 않았다. 생성기 검증은 임시 프로젝트 안에서 했다.
- maxAsks는 최초 질문을 포함한 총 질문 횟수다. CLI `next --count`는 작은 후속 라운드를 위해 1~8, 설정 roundSize는 스펙대로 5~8만 허용한다.
- 한도에 도달한 미답 선택 문항도 mustDefer에 포함한다. 이로써 questions와 mustDefer가 모두 빈 경우 모든 필수가 완료라는 불변식을 지킨다. 선택은 skip도 가능하며 필수 skip은 거부한다.
- status는 질문별 유효 상태 `questions`도 반환한다. 판단 완료 표는 읽기만 하며 상태 파일의 judgment 원본은 보존한다. 기록 문서는 변이 때 새로 그린다. 원장에는 고정 형식 ID·상태만 기록하고 답 원문·질문 텍스트는 넣지 않는다.
- 추가 질문의 추천값이 생략되면 “직접 답하기”로 둔다. 추가 질문은 Qnn-xNN ID로 상태에만 저장한다.
- commandTable의 단일 원본을 `src/cli/commands.ts`에 두고 `src/cli/index.ts`에서 요구한 타입의 const로 공개한다. 생성기에서 CLI 전체를 가져오는 순환 의존을 피했다.
- 공통 치환·KST 날짜·프로젝트 경로 확인은 `src/core/template-values.ts`에 분리했다. 문서·스킬·인터뷰 문서 경로는 실제 경로도 확인해 외부/끊어진 symlink를 거부한다.
- backlog는 docs.root와 무관하게 `docs/backlog.md` 고정이다. worklog와 그 밖의 문서는 docs.root를 따른다.
- 스킬은 `.fodh-managed`의 package가 맞을 때만 관리 대상으로 인정한다. 저장된 해시와 실제 SKILL.md 내용까지 확인한다. version만 바뀌고 해시가 같으면 덮어쓰지 않는다. 사용자 파일이나 잘못된 표지는 conflicts로 보존한다.
- 관리 블록은 모든 대상을 먼저 검증한 뒤 쓴다. 블록 밖 CRLF·공백도 보존한다. AGENTS.md 옵션은 검증·금지·문서 위치와 fodh/git 실행 금지만 담으며 기본으로 켜지 않는다.
- 설계 §10의 묶인 승인 범주를 의미 변경 없이 16항으로 펼쳤다(DB 마이그레이션/데이터 삭제·이관, main push/force·삭제, 약관/개인정보 문안 분리). 설정 requiresApproval도 별도로 싣는다.
- 프롬프트의 INTERVIEW는 기존 답을 먼저 record한 뒤 next를 호출하도록 배치했다. 첫 단계는 status이며, 답이 없는 첫 라운드는 바로 next로 진행한다. 사용자의 “추천대로” 의사 없이 default 출처로 기록하지 않도록 명시했다.
- skill-creator 지침을 참고해 스킬 4종을 작성했다. 스펙의 name/description만 사용하는 형식을 우선했고 스크립트·추가 메타데이터·실제 평가 에이전트 실행은 넣지 않았다.

### 선택 사항·기존 테스트 수정

- openRound는 스펙의 round/ids에 `processed?: boolean`을 추가했다. 처리 ID를 ids에서 제거한 뒤에도 일부가 처리됐다는 사실을 보존해 다음 next에서 새 라운드를 뽑기 위한 내부 표지다. 전부 처리하면 openRound를 지운다. input 훅은 이를 지우지 않는다.
- 현재 열려 있고 아무 답도 처리하지 않은 라운드는 횟수 한도에 도달했어도 같은 라운드로 반복 반환한다. 부분 처리 후 남은 문항의 한도를 판정하므로, 반복 호출만으로 mustDefer/skipDue로 밀어내지 않는다.
