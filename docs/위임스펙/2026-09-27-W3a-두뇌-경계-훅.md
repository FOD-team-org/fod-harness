0-4. 가능한 cwd 집합(`hooks/effective-cwd.mjs`)
- `possibleCwds(entries, cwd, { home, workspace })` 는 `{ cwds: string[], unknown: boolean }` 을 돌려준다.
  1. `[cwd]` 에서 시작한다.
  2. 모든 항목을 본다(치환 `$( )`·`bash -c`·서브셸·함수 몸통 항목 포함). `commandWords(withoutRedirects(words))` 가 `cd`·`pushd` 로 시작하는 항목이 cd 항목이다. 8 의 AUTO_CD 항목도 cd 항목이다.
  3. 가능한 cwd = 시작 cwd 에서 cd 항목을 **각각 최대 한 번**, 아무 순서로 적용해 닿는 곳 전부다.
     - 상태 (cwd, 이미 적용한 cd 항목 집합)를 넓이 우선으로 돈다. 같은 항목을 되풀이 적용하지 않는다. 그래서 `cd docs` 는 `docs/docs` 로 커지지 않고, `cd ..` 는 루트 깊이와 상관없이 한 번만 올라간다.
     - cd 항목이 7개 이상이거나 결과 cwd 가 64개를 넘으면 `unknown` 이다.
     - 반복·함수 몸통 안의 cd 도 한 번만 적용한다(메모 R12).
  4. 후보는 논리 경로 `resolve(c, X)` 와 물리 경로(아래) 둘 다다.
  5. 옵션 `-P` `-L` `-e` `-@` `--` 는 건너뛴다.
  6. 인자가 없으면 HOME 이다. `~`·`~/…`·`$HOME`·`${HOME}` 으로 시작하면 HOME 기준으로 푼다.
  7. `popd` 는 무시한다.
  8. zsh AUTO_CD: 단어 하나짜리 단순 명령이 어떤 cwd 기준으로 디렉터리로 존재하면 `cd` 로 본다.
  9. `unknown` 이어도 `cwds` 에는 그때까지 모은 cwd(시작 cwd 포함)를 담는다. 쓰는 쪽은 `unknown` 을 후보를 더하는 신호로만 쓰고, 알려진 cwd 를 빼지 않는다.
- 다음이면 `unknown = true` 다.
  - `cd -`
  - 동적 대상: `$`·백틱·`*`·`?`·`[`·`{` 가 남은 단어
  - `~이름`·`~+`·`~-`
  - 인자 없는 `pushd`, `pushd +N`·`pushd -N`
  - 옵션이 아닌 인자가 2개 이상(zsh `cd old new`)
  - `env -S`·`--split-string` 이 있는 항목
  - 워크스페이스 모드에서만: 훅 환경의 `CDPATH` 가 비어 있지 않고, 대상이 정확히 `.`·`..` 가 아니며 `/`·`./`·`../` 로 시작하지도 않을 때. 한 레포 판정이 테스트 환경의 `CDPATH` 에 따라 바뀌지 않게 하려는 것이다.
- 집합은 명령 줄 전체에 하나다. 모든 단순 명령을 모든 후보로 판정한다.
  - 함수·반복·`||`·서브셸의 순서를 따지지 않는다. 그래서 넓게 거부한다(메모 D11).
  - 예: `npm test && cd ../chemical && git log` 는 `npm test` 가 멤버 cwd 후보를 가져서 M1 이다.
- `commandCwds(words, set)`: 단순 명령의 사전 단어(래퍼를 벗기기 전)에 `env` 의 `-C v`·`-Cv`·`--chdir v`·`--chdir=v` 가 있으면, 그 명령의 cwd 는 `set.cwds.map(c => resolve(c, v))` 다. v 가 동적이면 그 명령은 `unknown` 이다.
  - `commandWords` 는 `env -C` 값을 버린다(`env -C ../c npx tsc` → `["tsc"]`). 그래서 사전 단어에서 읽는다.
- 물리 경로: 성분을 하나씩 붙인다. `..` 를 만나기 전에 지금까지의 경로를 realpath(존재하는 앞부분까지)로 바꾼다.
  - 그러면 `lnk/../chemical` 이 `lnk` 실제 위치의 부모를 기준으로 풀린다.
  - 기존 `normalizePath` 는 논리 `resolve` 뒤에 realpath 하므로 이것을 놓친다. 이 한계는 멤버 판정에서만 고친다.
- 이 모듈은 throw 하지 않는다. 내부 오류는 `unknown = true` 로 바꾼다.
- 리다이렉트: 파서는 리다이렉트를 항목 단어에 붙이고, 그룹 리다이렉트는 안쪽 항목마다 붙인다(`cd docs 2>/dev/null` → `["cd","docs",">","/dev/null"]`, `{ …; } 2>&1` → `["}",">&","1"]`).
  - 이 절의 cd 인자 세기·대상, §1-1 규칙 1·3, §1-2 후보 모으기, §2-2 리터럴 경로 인자, §2-3 대상 계산은 모두 `withoutRedirects(words)`(`hooks/write-paths.mjs` 5, export 됨) 뒤의 단어로 한다.
  - 리다이렉트 대상은 §1-5 쓰기 검사와 비밀 검사만 본다.

0-5. 실패 방향
- 새 코드는 543 의 바깥 catch 에 닿으면 안 된다. 닿으면 모든 청중이 `훅 입력을 해석할 수 없습니다.` 로 거부된다. 새 코드는 자기 오류를 안에서 잡는다.

0-7. 한 레포 모드에 의도적으로 바뀌는 것
모두 거부나 승인이 **늘기만** 한다.
1. commit·merge·push 대상 검사(§2-3). 두뇌가 아니어도 적용한다(D6).
   - 대상이 루트 밖이고 등록 워크트리 밖이면 M3.
   - 대상을 알 수 없으면 M4. 예: `cd $X`, `git -C $X`, `GIT_DIR`/`GIT_WORK_TREE` 할당·export, `--git-dir`, `--work-tree`.
   - cwd 집합은 순서를 보지 않는다. 그래서 `cd docs && git commit -m x && cd ..`·`cd docs && npm test && cd .. && git commit -m x` 는 M3(`cd ..` 가 루트에도 적용됨), `git commit -m x && cd -` 는 M4 다. 두뇌 아님도 같다. 거부 문구를 보고 명령을 나누면 되므로 받아들인다(D11). 순서 추적은 반복·함수에서 덜 막는 쪽으로 틀리기 쉽다.
2. 승인 정규화(§4). 내장 규칙과 프로젝트 규칙이 정규화한 꼴에도 걸린다. 지금 새는 `npx -c "…"`·`npm exec -c "…"` 속 명령도 포함한다.
3. `rev:path`(§3-2). 대상 레포 최상위와 워크트리 주인 기준 후보가 더해진다. `:path`·`:N:path` 꼴도 새로 본다.
4. 비밀 검사의 cwd 집합(§3-3). D5 가 ① 일 때만이다. `cd sub && cat <비밀>` 이 걸린다.
- 이 넷 밖의 판정 차이는 버그다. §5 골든 비교가 잡는다.

## 1. 멤버 main 은 읽기 명령만 (설계 8-1)

적용 범위: 워크스페이스 모드이고 두뇌일 때.

1-1. 판정할 항목
- 파서는 묶음·제어문에서 원문 조각 항목을 먼저 내고, 정규 항목을 하나 더 낸다. 확인한 예는 다음과 같다.
  - `(cd ../chemical && git log)` → `["(cd","../chemical"]`, `["cd","../chemical"]`, `["git","log)"]`, `["git","log"]`
  - `f(){ npm i; }` → `["f(){","npm","i"]`, `["npm","i"]`, `["}"]`, `[]`
  - `case x in a) cd ../chemical;; esac` → `["case","x","in","a)","cd","../chemical"]`, `["cd","../chemical"]`, `["esac"]`, `[]`
- 이 절과 §2-2 는 아래 문법 조각 항목을 건너뛴다.
  1. 빈 항목, 또는 단어가 모두 `{` `}` `fi` `done` `esac` `then` `else` `do` `!` 중 하나인 항목
  2. 첫 단어가 `for`·`select`·`case` 인 머리 항목, 또는 `((…))` 한 단어 항목
  3. 다음 항목의 단어가 이 항목에서 아래를 벗긴 것과 같은 항목
     - 앞의 예약어 `if` `elif` `while` `until` `then` `else` `do` `!` `{`
     - 첫 단어 앞의 따옴표 없는 `(`·`((`
     - 함수 머리 `이름()`·`이름(){`
     - 마지막 단어 뒤의 따옴표 없는 `)`·`;;`
     - 따옴표 여부는 `rawWords` 로 확인한다.
- 3 을 확인할 수 없으면 건너뛰지 않는다(보수적).
- 기존 검사(승인·쓰기·`FODH_`·게이트)는 지금처럼 모든 항목을 본다.

1-2. 대상 모으기(단순 명령마다)
1. 유효 cwd: `commandCwds(words, set)`
2. 디렉터리 옵션 값을 유효 cwd 기준으로 푼 것
   - `git -C`(연쇄), `npm --prefix`·`npm -C`, `pnpm -C`·`--dir`, `yarn --cwd`, `bun --cwd`, `make -C`·`--directory`, `tsc -p`·`--project`
   - 그 밖의 `--cwd`·`--dir`·`--directory`·`--project`
   - 각각 `=` 꼴과 붙인 꼴(`-C../x`)을 포함한다.
3. 경로 후보: 사전 단어(래퍼 포함)에서 아래를 모아, 유효 cwd 마다 논리 경로와 물리 경로로 푼다.
   - 옵션이 아닌 단어
   - `--x=값` 의 값
   - 붙인 짧은 옵션 값(`-I../x` → `../x`)
   - `/` 를 담은 첫 단어
   - 할당 `X=값` 의 값
   - `~`·`$HOME`·`${HOME}` 은 먼저 푼다.
- 래퍼: `commandWords` 가 벗긴 래퍼 부분(`time -o …`, `xargs -a …` 등)의 경로가 멤버를 가리키면, 그 명령은 허용 목록 밖으로 본다.
  - 예외: `env -C`·`--chdir` 값은 유효 cwd 로 다룬다.

1-3. 판정
- **멤버 대상**: 대상 하나라도 `memberMainOf` 또는 `memberAncestorOf` 에 걸리는 경우다. 이름은 처음 걸린 멤버다.
  - `memberAncestorOf` 는 유효 cwd, 디렉터리 옵션 값, 옵션이 아닌 단어에만 건다. `--x=값`·붙인 짧은 옵션 값·할당 값에는 `memberMainOf` 만 건다.
  - 정확히 `/` 인 단어는 후보에서 뺀다(`cut -d/ -f1`, `awk -F/`, `IFS=/ read`, `tr / _`).
- **멤버일 수 있음**: 다음 중 하나다. 동적 여부는 `rawWords` 로 본다.
  - 작은따옴표 안의 `$`·백틱은 리터럴이다(`awk '$2 ~ /fix/ {print $1}'` 는 동적이 아니다).
  - 글롭 문자(`*`·`?`·`[`)는 따옴표와 상관없이 동적으로 친다(보수적).
  - `$PWD`·`${PWD}`·`$(pwd)` 는 동적이 아니라 각 유효 cwd 로 푼다.
  1. cwd 집합이 `unknown` 이다.
  2. 디렉터리 옵션 값이나 `cd` 대상 자체가 동적이다.
  3. 동적 단어의 기준 디렉터리가 멤버 조상이다.
     - 기준 디렉터리 = 리터럴 앞부분 P 의 마지막 `/` 까지를 유효 cwd 기준으로 푼 것. P 는 첫 `$`·백틱·`*`·`?`·`[`·`{` 앞까지다. P 에 `/` 가 없으면 유효 cwd 다.
     - 기준 디렉터리가 멤버 main 안이면 이 경우가 아니라 멤버 대상이다(`../chemical/$X`).
  4. 단어가 확장으로 시작하고, 그 확장이 끝난 **뒤에** `/` 가 있다(`$D/src`, `$(cmd)/x`). 확장 안의 `/`(`"$(date +%Y/%m)"`)는 치지 않는다.
     - 기존 `substitutions`(261)가 임시 경로로 푸는 값이면 푼 경로로 판정한다.
  5. `xargs` 로 감싼 목록 밖 명령이고, 같은 줄의 다른 단순 명령이 멤버 대상이거나 cwd 후보에 멤버 main·멤버 조상이 있다.
  - 그 밖의 동적 단어는 무시한다. 예: 위치 인자 `$(date +%F)`, `$X` 단독.
- git 은 조상과 동적 인자를 보지 않는다. `-C` 연쇄를 적용한 대상 디렉터리와 리터럴 경로 인자만 본다. 동적 `-C` 는 "멤버일 수 있음"이다.
- 결과
  - 멤버 대상이고 허용 목록에 있으며 옵션 제한을 지킨다 → 통과
  - 멤버 대상이고 git → §2-2
  - 멤버 대상이고 그 밖 → M1
  - 멤버일 수 있음이고 목록 밖(git 은 §2-2 목록 밖) → M5
  - 둘 다 아님 → 지금 규칙 그대로

  - 멤버의 `defaults: false` 도 루트 기본 목록을 끄지 못한다.
  - 푸는 길은 최상위 `secrets.readAllow` 다.
- 멤버 경로 패턴(`/` 를 담은 것)은 멤버 경로 기준이다.
  - `config/prod.json` 처럼 쓴다. `/config/…` 는 절대 경로가 된다(`secret-paths.mjs` 25-26).
  - 멤버 워크트리에는 걸리지 않는다. 한 레포 모드에서 루트 경로 패턴이 워크트리에 걸리지 않는 것과 같다.
  - 예외는 §3-2 의 주인 기준 후보다(D12).
- 파일 이름 패턴(`neon_api.json`)은 어디서나 걸린다. 설계 §3-2 의 "막는 쪽으로만 넓어진다" 그대로다.
- 한 레포 모드는 `policies = [루트 정책]` 이다. 지금과 같다.

3-2. `rev:path`
- 대상 단어: 기존 103 조건(`git` 의 `show`·`cat-file`)에 걸리는 단어 중
  1. `<rev>:<path>`(`/^[^:]+:.+/`). 지금과 같다. 옵션 단어도 지금처럼 본다.
  2. 새로 보는 꼴: 옵션이 아닌 단어 중 `:<path>` 와 `:<0-3>:<path>`(색인). 단, `:/…`(커밋 메시지 검색)는 뺀다.
- 후보 경로. 하나라도 비밀이면 지금 문구로 거부한다.
  1. 지금 그대로 `check(path, false)`. cwd 기준이고 동적 처리를 포함한다.
  2. git 대상 디렉터리 t(가능한 cwd 마다 이 명령의 `-C` 연쇄를 적용)마다 최상위 T 기준 `resolve(T, path)`.
     - t 가 등록 워크트리 안이면 T 는 둘이다. 그 워크트리, 그리고 주인(`repo` 멤버 경로, `repo` 가 없으면 루트)이다.
     - 멤버 안이면 멤버 경로다.
     - 루트 안이면 루트다.
     - 그 밖이면 `git -C t rev-parse --show-toplevel` 을 부른다. timeout 1000ms 이고, 실패하면 t 다.
  3. path 가 `./`·`../` 로 시작하면 `resolve(t, path)`. git 규칙이 그렇다. 설계는 `./` 만 적었다.
- git 의 `HEAD:<path>` 는 cwd 가 아니라 최상위 기준이다.
  - `git -C ../chemical/src show HEAD:config/prod.json` 은 `chemical/config/prod.json` 을 연다(거부).
  - `git -C ../chemical/config show HEAD:prod.json` 은 `chemical/prod.json` 을 연다(통과).
- 설계는 "그 멤버 정책을 적용"이라고 적었다. 이 스펙은 합집합 정책을 적용한다. 더 엄격하다.

3-3. cwd 집합
- `secretReadGuard` 의 `bash(entries)` 안에서 `possibleCwds` 를 부른다. 단순 명령별 `env -C` 도 반영한다.
- 비밀 검사의 상대 단어는 이벤트 cwd 와 알려진 각 cwd 로 푼다. 지금의 이벤트 cwd 기준 `check` 는 그대로 남는다.
- cwd 집합이 `unknown` 이면 후보를 더한다. 빼지 않는다.
  - `basenameDenied` 를 더한다.
  - 워크스페이스 모드에서는 모든 멤버 경로와 등록 워크트리 경로도 cwd 후보로 더한다.
  - 상대 단어 풀기와 재귀 검색 기본 대상 모두에 적용한다.
- 재귀 검색에 피연산자가 없으면 기본 대상은 위 cwd 후보 전부다(지금은 `[cwd]`, 130).
- D5 가 ① 이면 두 모드에 쓴다. ② 면 워크스페이스 모드에서만 쓴다.

3-4. 재귀 검색 가지치기(133-139)
- 워크스페이스 모드에서는 디렉터리를 주인별로 나눈다.
  1. 등록 워크트리 안: `git -C <워크트리> check-ignore --stdin -z`
  2. 멤버 안: `<멤버>/.git` 이 있으면 `git -C <멤버> check-ignore --stdin -z`
  3. 그 밖: 지금 그대로. `<root>/.git` 이 있을 때 `git -C cwd` 다.
- 주인마다 한 번 부른다. timeout 1000ms 는 그대로다. 실패하면 가지치기를 하지 않는다(= 더 막는다).
- 한 레포 모드는 지금 그대로다.
  - 워크트리를 주인별로 나누면 한 레포에서 거부가 **줄어든다**. 그래서 한 레포에는 넣지 않는다.
  - 지금은 루트 밖 워크트리 경로에 `git -C root check-ignore` 가 실패해 가지치기가 없다.

3-5. `secretReadGuard` API
- `secretReadGuard({ root, cwd, config, deny, members?, worktrees? })`
  - `members?: { name: string; path: string; secrets?: unknown }[]`
  - `worktrees?: { path: string; repo?: string }[]`
- 둘 다 없으면 한 레포 동작이다. 직접 부르는 기존 테스트 `test/a14c-doctor.test.ts:51-54`·`test/a14c-review-secrets.test.ts:7` 이 그대로 통과해야 한다.

  - 내장 명령이 아닌 S → `npm run S …`, `S …`(pnpm 은 스크립트가 없으면 bin 을 실행한다)

  - `workspace <이름> …` → 나머지로 다시 판정한다.
  - `run S …` → `npm run S …`, `S …`

  - 내장 명령: `add` `install` `remove` `upgrade` `up` `info` `why` `init` `run` `test` `start` `exec` `dlx` `workspace` `workspaces` `config` `cache` `pack` `publish` `link` `unlink` `bin` `global` `list` `outdated` `audit` `version` `set` `plugin` `node` `constraints` `explain` `npm` `patch` `rebuild` `stage` `unplug` `dedupe`

  - `run S …` → `npm run S …`, `S …`

  - 내장 명령이 아닌 S → 두 꼴
  - 내장 명령: `run` `test` `x` `repl` `exec` `install` `i` `add` `a` `remove` `rm` `update` `outdated` `link` `unlink` `pm` `build` `init` `create` `upgrade` `publish` `audit` `info` `patch`

   - fod-harness 저장소에서 commit·branch·stash·reset·checkout 등을 하지 않는다.
   - 테스트가 만든 임시 저장소 안의 git 만 허용한다.
2. **전체 테스트 스위트 실행 절대 금지.**
   - 새 `test/w3a-*` 와 §8-1 의 영향받는 기존 테스트 파일만 `--maxWorkers=1 --no-file-parallelism` 으로 돌린다.
   - 전체 직렬은 메인이 돌린다.
3. 기존 테스트 파일은 고치지 않는다.
   - 예외: 새 기능이 등록돼 목록이 하나 늘어나는 열거 기대값에 새 항목을 **더하는 것**만 허용한다. 이번 단계에는 없을 것으로 본다.
   - 지우거나 약하게 바꾸는 것은 금지다.
   - 고친 줄은 결과 문서에 파일:줄과 전후를 모두 적는다.
4. 실제 claude·codex·pi·osascript 를 실행하지 않는다. 네트워크를 쓰지 않는다. `FODH_NOTIFY_OS=off` 다.
5. 비밀 파일(`.env*`·키·인증 파일)을 열지 않는다.
   - 테스트가 임시 폴더에 만드는 가짜 파일은 예외다.
   - 실제 저장소와 실제 HOME 의 파일은 금지다.
6. 스펙과 코드가 어긋나거나 더 안전한 방법이 있으면, 추측해서 넓히지 말고 멈춰서 보고한다. 작은 구현 선택은 결과 문서에 근거와 함께 적는다.
7. 골든 파일은 `hooks/` 를 고치기 전에 한 번만 만든다. 다시 만들지 않는다.
8. 새 훅 모듈은 `src/` 를 import 하지 않는다. §0-1 의 "고치지 않는 파일"은 고치지 않는다.

### 설계와 코드의 어긋남·모호한 곳
1. 설계 행 번호는 모두 맞다: `pretooluse.mjs` 143-144·446-455·497-506(게이트 반복은 494-507), `secret-reads.mjs` 103·133-139, `shell-commands.mjs` 7-18.
2. 설계 §8-2 "대상이 워크스페이스 루트일 때만"과 "등록 워크트리 git 은 지금 규칙 그대로"가 충돌한다. 기존 테스트는 루트 안 미등록 경로를 요구한다 → D2.
3. 설계 §8-2 "446-455 의 보수적 판정을 다시 쓴다": 446-455 는 대상 계산기가 아니라 "cd 가 하나라도 있으면 거부"이고 두뇌 전용이다 → D3.
4. 설계 §8-2 "한 레포 모드에서는 대상 = 루트라 동작이 같다"는 엄밀히 틀리다. `-C` 바깥, `GIT_DIR`, 동적 cd 가 바뀐다 → §0-7 에 열거했다.
5. 설계 §13 은 `write-paths.mjs`·`shell-commands.mjs` 를 손댈 곳으로 적었다. `src` 가 import 하므로 고치지 않고 새 모듈로 감싼다.
6. 설계 §8-1 "같은 명령 줄 앞쪽의 cd"는 순서를 뜻한다. 초안은 순서 없는 집합이다 → D11.
7. 설계 §8-2 전역 옵션 허용 목록대로면 `git --version` 도 막힌다. 초안은 단독 `--version`·`--help`·`-h` 만 통과시킨다.
8. 설계 §8-3 "`./` 로 시작하면 유효 cwd 기준": git 은 `../` 도 cwd 기준이다. `:path`·`:N:path` 꼴은 설계에 없다. 초안이 둘 다 더했다.
9. 설계 §8-3 "풀린 경로에 그 멤버 정책을 적용": 초안은 합집합 정책을 적용한다. 더 엄격하다.
10. 설계 §8-1 표의 `diff --output`: GNU·BSD diff 에는 없는 옵션이다(sdiff 의 것). 해롭지 않아 그대로 거부 목록에 둔다.
11. 경로 패턴 앞의 `/`: 설계 §3-2 는 "`/` 패턴은 멤버 기준"이라고 한다. 실제 `secretPolicy` 는 `/` 를 **담은** 패턴을 경로 패턴으로 보고, `/` 로 **시작**하면 절대 경로가 된다(`secret-paths.mjs` 25-26). WisePharm 설정에 멤버 경로 패턴을 쓸 때 앞 `/` 를 붙이면 안 된다. W3b 문서에 적을 것.

### 위험·남는 한계
- R1 CDPATH·zsh `cdable_vars`: 셸 프로필이 설정하면 훅은 보지 못한다. 훅 환경에 `CDPATH` 가 있을 때만 `unknown` 으로 본다(워크스페이스).
- R2 인터프리터(`python -c`, `node -e`, 루트 스크립트)가 안에서 멤버에 쓰는 것: 설계가 받아들인 한계다. 병합 전 검사가 드러낸다.
- R3 변수 값 속의 `..`(`.pi/scratch/$X` 에 `../../chemical`)와 `xargs` 입력 파일(`xargs -a list rm`)의 멤버 경로: 보지 못한다. 한 레포의 동적 쓰기 한계와 같은 수준이다.
- R4 훅의 멤버 해석이 `loadConfig` 와 어긋날 수 있다. 일치 테스트가 막는다. W1 검증이 바뀌면 함께 고쳐야 한다(결과 문서에 적을 것).
- R5 `git status`·`describe --dirty` 가 멤버 `.git/index` 를 새로 쓴다. 사용자의 git 과 `index.lock` 이 부딪칠 수 있다. brain-rules 에 `--no-optional-locks` 를 권할지 W3b 에서 정한다.
- R6 `git -C <멤버> grep`·`log -p`·`diff` 로 추적 중인 비밀 파일 내용을 볼 수 있다. 한 레포도 같다(`show`·`cat-file` 만 막는다).
- R7 `sed` 정규식 주소(`/foo/p`)를 허용하지 않는다. 두뇌는 `rg` 나 `sed -n N,Mp` 로 대신한다.
- R8 기존 `normalizePath` 의 물리 `..` 구멍은 멤버 판정에서만 고친다. 루트 경계 판정은 그대로다.
- R9 자동 진행(`src/core/autopilot.ts:98-110` `autopilotBlocked`)은 최상위 `config.approvalRules` 만 본다. 멤버 규칙은 자동 진행 차단에 들어가지 않는다. 훅이 실행 시점에 막으므로 실행은 되지 않지만, 자동 진행이 판단 없이 그런 task 로 들어갈 수 있다. W3b 나 별도 작은 단계에서 `workspaceMembers` 규칙을 합쳐야 한다.
- R10 `git rev-parse --show-toplevel` 스폰(루트·멤버·워크트리 밖 대상일 때만)과 멤버별 `check-ignore` 스폰이 훅 시간을 늘린다. timeout 1000ms 씩이다.
- R11 두뇌 아님은 비확장 파싱이다. 서브셸의 `git commit)` 같은 조각 단어는 정규 항목이 따로 나와 게이트가 동작한다. 하지만 함수 몸통에는 정규 항목이 생기지 않는다(`f(){ git commit -m x; }` → `["f(){","git",…]` 뿐). 그래서 `f(){ git -C ../chemical commit -m x; }; f` 는 두뇌 아님에서 게이트·승인·§2-3 을 모두 빠져나간다. 지금도 있는 구멍이고 W3a 범위 밖이다. 두뇌는 확장 파싱이라 해당하지 않는다.
- R12 cd 항목은 각각 한 번만 적용한다. 반복 안의 `cd ..` 가 여러 번 도는 경우(`for i in 1 2; do cd ..; done; git commit`)는 한 단계만 본다. 동적 대상이 아니면 반복 횟수를 알 수 없어서다. 두뇌는 brain-rules 로, 두뇌 아님은 받아들인 한계다.
- R13 M6 은 모든 단어를 본다(`FODH_` 검사와 같은 모양). 그래서 `rg 'GIT_DIR=' ../chemical` 도 M6 이다. 반대로 `HOME=`·`XDG_CONFIG_HOME=` 앞붙임으로 전역 gitconfig 를 바꾸는 길은 막지 않는다. 둘 다 이론적이라 받아들인다.
