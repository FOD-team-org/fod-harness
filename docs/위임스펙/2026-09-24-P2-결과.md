## 설계 선택 및 의도적 이탈

1. **`changedLines` 생략**: 위임 스펙대로 이전 본문 사본을 저장하지 않는다. 원시 문서 바이트의 SHA-256과 바이트 크기만 감지한다. 문서 해석/답 적용은 오케스트레이터가 담당한다.
2. **같은 파일의 메타데이터 보존**: `harness-watcher.json` 잠금 안에서 최신 파일을 읽고 `watch`만 변경한다. 판단 모듈의 `judgment.expectedHash/questions`와 기타 키를 유지한다. 워처 잠금을 놓은 뒤 `decideInbox`를 호출해 판단 저장 경로와 잠금을 겹치지 않는다.
3. **폴링 범위**: pollSeconds와 fs.watch 디바운스는 `judgmentOnly` 옵션으로 판단 해시만 검사한다. tickSeconds와 CLI는 전체 검사한다. 전체 타이머를 먼저 등록해 5초/30초가 겹칠 때 전체 검사가 계속 건너뛰어지는 일을 막았다. 모든 타이머는 unref, 파일 감시는 persistent:false다.
4. **중복 수명**: 일반 인박스 dedupe는 미적용 항목만 재사용한다. 정체·자식 이벤트는 `watch.emittedKeys`에도 보존해 applied 이후에도 같은 관측 사건을 재발행하지 않는다. stalled 키는 상태+runId(없으면 enteredAt), 자식 키는 이벤트 종류+pid+startedAt+프로세스 종류다. timeout 뒤 gone은 다른 사실로 각각 한 번 기록한다. 이미 기록된 인박스는 파일 되돌림으로 취소하지 않는다.
5. **자식 `kind` 충돌 해소**: 스펙 §2-3 예시에 `kind`가 두 번 있으므로 이벤트 종류는 `kind`, 프로세스 종류는 **`procKind`**로 저장한다. 레지스트리 삭제·프로세스 종료는 수행하지 않는다. 기존 runner가 ps 제한 시 저장하는 `spawn:<ISO>`도 경과 시간 계산에 사용한다.
6. **복구 식별**: 세션 시작 시각에 UUID를 붙여 같은 밀리초의 다른 세션도 구분한다. 동일 세션 키는 applied 이후에도 다시 만들지 않는다. recovering은 감지 대상이지만 세션 복구 결정에서는 명시 규칙대로 알림만 한다. print 모드는 §3에 따라 복구 기록만 남기고 결정/타이머/감시를 시작하지 않는다.
7. **재질문 경로**: §4-2의 적용 가능한 답 검사와 부정·모호 재질문 요구를 함께 충족하도록 비어 있지 않은 답은 기존 `applyJudgments`로 처리한다. 실제 적용 항목이 있어야 대기를 풀고 재개한다. 재질문 ID/원본 ID와 미적용 이유를 알림에 포함한다.
8. **공용 재개와 원장**: root별 진행 중 재개 집합을 공유해 agent_end와 워처의 동시 요청을 중복 전송하지 않는다. 배치 내 동일 종류는 한 번 결정하고 모든 인박스 ID를 원장에 남긴다. 명시된 `ok|skip`을 표현하기 위해 범위 표에 없는 `src/core/ledger.ts`의 상태 타입에 `skip`을 추가했다. 기존 unknown 판독/해결 규칙은 유지한다.
9. **감시 실패**: fs.watch 생성/비동기 오류는 원장에 남기고 해당 디렉터리에서는 폴링을 계속한다. 설정 경로의 부모가 바뀌면 감시를 교체한다. tick·결정 오류는 콜백 밖으로 전파하지 않고 warning은 분당 최대 한 번이다. 원장 자체가 기록 불가능하면 UI 경고를 시도하며, UI도 폐기되었으면 예외를 삼킨다.

## 남은 확인

Fable이 실제 tmux Pi TUI에서 판단대기 문서 답 직접 기입 후 재개, busy/대기 상태, 세션 종료·재시작을 확인해야 한다. P4 프로세스 회수·외부 알림과 P3 Codex 실행은 구현하지 않았다. git 명령·커밋·push는 실행하지 않았다.
