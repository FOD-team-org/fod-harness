## 0. 문제와 방향

지금 판단 파일 하나(`judgment.file`, 기본 `docs/판단대기.md`)에 네 가지가 쌓인다.

| 쌓이는 것 | 원인 |
|---|---|
| `## 결정 완료` 표 | `completeJudgment` 가 행을 끝없이 덧붙인다 |
| 열린 항목의 군더더기 | 항목마다 같은 `- 회신:` 안내 줄, 한 줄에 몰린 선택지, 제한 없는 배경 |
| 전체를 보는 곳이 없음 | 열린 판단이 여러 개면 끝까지 내려 읽어야 한다 |
| (fod-harness 자체) `## 지금 상태` 이력 | 사람이 손으로 덧붙였다. 하네스 `write-status` 는 원래 한 줄만 쓴다 |

방향은 **파일 하나는 유지하고, 지금 답할 것만 남긴다.** 항목마다 파일을 따로 두는 방식은 쓰지 않는다. 사용자가 답하려고 여러 파일을 열어야 하고, 워처·훅이 디렉터리 단위로 바뀌어야 하기 때문이다.

1. 판단 파일에는 머리말, 지금 상태 한 줄, **한눈에** 표, 열린 판단, (사용자) 보류, **최근 결정** N줄만 둔다.
2. 결정된 항목은 하네스가 **판단기록**(`<판단 파일 디렉터리>/판단기록/YYYY-MM.md`)으로 옮긴다. 질문 원문과 답 원문이 함께 남는다.
3. 항목은 짧게 쓴다. 선택지는 한 줄에 하나로 쓰고, 긴 설명은 문서로 빼서 `- 자세히:` 로 잇는다.
4. 옛 파일은 계속 읽는다. `fodh judgment migrate` 로 한 번에 바꾼다.

## 1. 새 판단 파일 형식

```markdown
# 판단대기

> 답은 각 항목의 `- 답:` 줄에만 쓴다. 번호 하나(1 또는 ①)나 자유 서술로 쓰고, 승인이 필요한 동작이면 번호나 "승인"을 넣는다. 채팅으로 `A23 1` 이라고 답해도 된다.
> `한눈에` 표와 `최근 결정` 은 하네스가 다시 쓴다. 지난 판단: [판단기록](판단기록/). 편집기는 외부 변경 자동 새로고침을 켜 둘 것.

## 지금 상태

대기 중

## 한눈에

| 번호 | 제목 | 막힌 작업 | 추천 |
|---|---|---|---|
| A23 | 결제 모듈 선택 | T03 | ① |

## 열린 판단

### A23 — 결제 모듈 선택 (rev 1)
- 배경: 한두 문장.
- 선택지:
  ① 선택 1
  ② 선택 2
- 추천: ① — 이유 한 문장
- 막힌 작업: T03
- 자세히: [결제-비교.md](조사/결제-비교.md)
- 답:

## 최근 결정

- A22 · 2026-09-26 · backend AGENTS.md 개정 → 답 "1" · [기록](판단기록/2026-09.md)
```

### 1-1. 하네스가 쓰는 부분

| 부분 | 규칙 |
|---|---|
| 머리말 인용 2줄 | 새 파일(`initial`)과 `migrate` 가 넣는다. 그 뒤로는 건드리지 않는다. 판단기록 링크는 판단 파일 디렉터리에서 본 상대 경로다 |
| `## 한눈에` | 하네스가 판단 파일을 쓸 때마다 본문 전체를 열린 항목에서 다시 만든다. 열린 항목이 없으면 `열린 판단 없음` 한 줄이다. 칸 규칙: 제목 40자, 막힌 작업 24자, 추천은 첫 ` — `·`—`·`:` 앞 부분을 24자까지 쓰고, 넘치면 `…` 를 붙인다. `\|` 는 이스케이프한다. 답 칸은 두지 않는다(사용자가 답만 고쳐도 표가 낡지 않게 하기 위해서다) |
| `## 최근 결정` | 완료할 때 맨 위에 한 줄을 넣고 `judgment.recent` 줄(기본 5)만 남긴다. 형식: `- <id> · <결정일> · <제목 30자> → 답 "<답 원문 30자>" · [기록](<판단기록 월 파일 상대 경로>)`. `recent` 가 0 이면 이 절을 만들지 않고, 있던 절은 비운다 |
| `## 지금 상태` | 지금처럼 `write-status` 가 한 문단(한 줄)으로 바꿔 쓴다. 절이 없으면 제목 줄 **바로 앞이 아니라** 머리말(제목 + 이어지는 인용·빈 줄) 뒤에 넣는다 |

- 하네스가 판단 파일을 쓰는 모든 경로(add, attach, answer, status, complete, followup 표시, reconcile 저장, migrate)는 저장 직전에 한 함수 `renderDerived(text, context)` 를 거친다. 반환하는 항목은 **실제로 쓴 텍스트**에서 다시 파싱한다.
- `renderDerived` 는 `## 한눈에`·`## 최근 결정` 이 없으면 만든다. `## 한눈에` 는 `## 열린 판단` 바로 앞에 둔다. `## 최근 결정` 은 옛 `## 결정 완료` 가 있으면 그 바로 앞에 두고, 없으면 파일 끝에 둔다. 옛 파일도 하네스가 처음 쓸 때 두 절이 생긴다. 옛 `## 결정 완료` 는 `migrate` 전까지 그대로 둔다.
- 읽기만 할 때는 쓰지 않는다. 사용자가 `- 답:` 만 고친 파일을 읽어도 저장이 일어나면 안 된다(지금 `text === original` 규칙 유지). 사용자가 `## 한눈에` 를 손으로 고치면 다음 하네스 쓰기 때 되돌아간다. 이 사실은 머리말에 적혀 있다.
- 나머지 절(`## 보류` 등 사용자 절)과 제목·머리말 아래 사용자 문단은 순서·내용을 그대로 보존한다.

### 1-2. 항목 형식

| 필드 | 새 형식 | 파서 |
|---|---|---|
| 제목 줄 | `### A<n>[-<m>] — <제목> (rev <N>)` 그대로 | 그대로 |
| `- 배경:` | 한 줄 | 그대로 |
| `- 선택지:` | 값을 비우고, 다음 줄부터 두 칸 들여쓴 `① …` 한 줄에 하나(`circled` 가 바닥나면 `21.`) | 같은 줄에 값이 있으면 지금 `optionsOf`. 비어 있으면 바로 다음 줄부터 공백으로 시작하는 비지 않은 줄을 모은다. 각 줄 앞의 `①`~`⑳`·`\d+[.)]`·`-`·`*` 표지를 떼고 trim 한다. 공백으로 시작하지 않는 줄이나 빈 줄이 나오면 멈춘다 |
| `- 추천:` · `- 막힌 작업:` | 그대로 | 그대로 |
| `- 자세히:` | 새로 추가(선택). `[<basename>](<판단 파일 디렉터리 기준 상대 경로>)` | `detail` 문자열. `questionHash` 에 넣지 않는다 |
| `- 회신:` | **새로 쓰지 않는다**(안내는 머리말로 옮긴다) | 있어도 무시(지금과 같음) |
| `- 답:` · `- 답 기준 rev:` · `- 적용 정책:` · `- 승인 필수:` · `- 재질문 원본:` · `- 후속 질문:` · dedupe 주석 | 그대로 | 그대로 |

- **같은 내용이면 형식이 바뀌어도 `questionHash` 가 같아야 한다.** 한 줄 선택지와 여러 줄 선택지에서 파싱한 `options` 배열은 같아야 한다. 그래야 migrate 뒤 `reconcileEdits` 가 rev 를 올리지 않는다.

### 1-3. CLI 등록 길이 제한(`addCliJudgment` 경로만)

| 값 | 상한(글자 수 `[...s].length`) |
|---|---|
| 제목 | 60 |
| 배경 | 400 |
| 선택지 하나 | 160 |
| 추천 | 200 |

- 넘으면 등록하지 않고 오류를 낸다: `<필드>가 <상한>자를 넘습니다(<n>자). 자세한 내용은 문서에 쓰고 --detail <경로> 로 연결하라`.
- 내부 등록(재질문, 정체 안전망, 인터뷰 defer)은 제한하지 않는다.
- `--detail <경로>`: 프로젝트 안 상대 경로이고 존재하는 파일이어야 한다. 판단 파일이나 판단기록 안이면 안 된다. 어기면 오류다. `fodh judgment add` 사용법과 `commands.ts` 에 추가한다.

## 2. 판단기록(아카이브)

- 설정: `judgment.archive`(기본 `<dirname(judgment.file)>/판단기록`). 프로젝트 안 상대 경로여야 한다. 판단 파일 자신이거나 판단 파일의 조상이면 안 된다. `worktrees.links` 제외 규칙에도 판단 파일과 같이 넣는다. `judgment.recent`(기본 5, 0~20 정수)도 추가한다.
- 월 파일: `<archive>/YYYY-MM.md`. 월은 **KST 결정일** 기준이다(지금 `completed.date` 와 같은 `Asia/Seoul` 날짜). 파일이 없으면 `# 판단기록 YYYY-MM\n` 으로 만든다. 블록은 뒤에 덧붙인다(시간순).

```markdown
### A19 — WisePharm 이관 순서와 레이아웃 (rev 1)
- 결정일: 2026-09-26
- 답: 1
- 해석: 레포마다 하네스 루트, backend 파일럿 → app → web …
- 반영: 판단 적용; 코드 커밋 없음
- 배경: …
- 선택지:
  ① …
- 추천: …
- 막힌 작업: …
```

- 블록 = 제목 줄 + 결정 4줄(`결정일`·`답`·`해석`·`반영`) + 항목 raw 의 나머지 줄. 나머지 줄에서 제목, `- 답:`, `- 답 기준 rev:`, `- 회신:`, dedupe 주석은 뺀다. 줄바꿈이 든 값(해석 등)은 한 줄로 합친다.
- 재질문 사슬(`resolveChain`)의 각 멤버는 자기 블록을 쓴다. 최종이 아닌 멤버의 답은 지금 표와 같이 `모호: <멤버 답> → <최종 id>: <최종 답>` 이다.
- 조회: `readArchive(root)` 는 모든 월 파일의 블록을 `CompletedJudgment` 로 파싱한다(`commit` ← `반영`, `date` ← `결정일`). `readJudgment().completed` = 옛 in-file `## 결정 완료` 표 행 + 판단기록 블록 전체다. 내부용이다.
- `fodh judgment read` 출력의 `completed` 는 최근 `judgment.recent` 개(결정일·등장 순서 기준 최신)만 싣고 `completedTotal` 을 붙인다. `--all` 이면 전부 싣는다.
- 판단기록 파일은 워처가 보지 않는다(이벤트 없음).

### 2-1. 완료 쓰기 순서와 장애 복구 (`completeJudgment`, `applyJudgments.finish`)

판단 파일 잠금 안에서 다음 순서로 쓴다.
1. 판단기록 월 파일에 블록을 덧붙인다(월 파일 잠금 + atomicWrite). 같은 `id`+`rev`+`답` 블록이 이미 있으면 건너뛴다(멱등).
2. 판단 파일에서 사슬 멤버를 지운다. `## 최근 결정` 에 줄을 넣고, `renderDerived` 를 거쳐 `save` 한다(CAS).

- 1 뒤, 2 전에 죽으면: 다음 적용에서 `finish(pending)` 이 끝난 적용으로 치려면 **판단기록에 있고, 판단 파일 열린 항목에는 없어야 한다.** 판단기록에만 있고 아직 열려 있으면, 먼저 2를 멱등하게 마친다(사슬 멤버 제거 + 최근 결정). 그다음 task 해제·상태 전이를 **한 번만** 한다.
- 불변식(테스트): 이 장애를 주입하고 다시 적용하면 판단기록 블록이 중복되지 않고, task notes 의 `<id>: <해석>` 이 한 번만 붙고, 항목이 열린 판단에서 사라진다.

## 3. 번호 유일성

- 새 번호 = max(판단 파일 전체의 `A\d+`, 판단기록 디렉터리 모든 `.md` 전체의 `A\d+`, 영속 카운터) + 1.
- 영속 카운터: `.pi/harness-judgment-seq.json` `{ "last": <n> }`. 등록이 저장된 뒤 올린다(판단 파일 잠금 안). 이 이름은 이미 훅의 `.pi/harness-judgment*.json` 보호에 걸린다.
- 불변식(테스트): A1~A3 를 완료해 판단기록으로 옮긴 뒤 사용자가 판단기록 파일을 지워도, 다음 등록은 A4 다.

## 4. 이전 — `fodh judgment migrate [--dry-run]`

- 사용자만 실행한다(`assertNotBrain`). 활성 스냅샷(두뇌 턴 중)이 있거나 `harness-judgment-apply.json` 저널이 비어 있지 않으면 거부한다. 오류 문구에 이유를 적는다.
- 판단 파일 잠금 안에서 다음을 한다.

| 대상 | 처리 |
|---|---|
| 열린 항목 | 1-2 새 형식으로 다시 쓴다. 필드 순서: 배경 · 선택지 · 추천 · 막힌 작업 · 자세히 · 답 · 답 기준 rev · 적용 정책 · 승인 필수 · 재질문 원본 · 후속 질문 · dedupe 주석. 모르는 줄은 필드 뒤에 원문 그대로 둔다. `- 회신:` 은 뺀다. **항목마다 migrate 전후 `questionHash` 와 `- 답:` 줄이 같아야 한다.** 다르면 아무것도 쓰지 않고 오류를 낸다 |
| 옛 `## 결정 완료` 절 | 현재 규격 표(`\| 번호 \| rev \| 답(원문) \| 해석 \| 반영 커밋 \| 날짜 \|`)의 행은 날짜 월의 판단기록 블록으로 옮긴다. 질문 원문이 없으니 결정 4줄만 쓴다. 날짜가 `YYYY-MM-DD` 가 아니면 `이전.md` 로 보낸다. 나머지(다른 표, `### …` 자유 블록, 문단)는 `<archive>/이전.md` 에 `## <오늘 KST> 이관 전 결정 완료` 아래 원문 그대로 덧붙인다. 그다음 절을 지운다 |
| `## 지금 상태` | 첫 문단만 남긴다. 나머지 문단은 `이전.md` 에 `## <오늘 KST> 이관 전 지금 상태 이력` 아래 원문 그대로 덧붙인다 |
| 머리말 | 제목 줄 바로 아래에 1-1 머리말 2줄을 넣는다. 정확히 `편집기는 외부 변경 자동 새로고침을 켜 둘 것.` 인 줄은 머리말에 포함되므로 지운다. 다른 사용자 줄은 머리말 아래에 그대로 둔다 |
| `## 한눈에` · `## 최근 결정` | `renderDerived` 로 만든다. 최근 결정은 판단기록 블록 중 최신 `recent` 개로 채운다 |
| 그 밖의 절 | 순서·내용 그대로 |

- 쓰기 순서: 판단기록 파일 → 판단 파일(`save`, 워처가 사용자 변경으로 보지 않도록 `expectedHash` 갱신).
- 멱등: 두 번째 실행은 아무 파일도 바꾸지 않고 `{ changed: false }` 를 낸다.
- `--dry-run`: 아무것도 쓰지 않고 바뀔 파일 목록, 옮길 행·문단 수, 새 판단 파일 크기를 JSON 으로 낸다.
- doctor: 판단 파일에 비지 않은 `## 결정 완료` 가 있으면 경고 `judgment:legacy-format` 를 낸다. 실패가 아니다. 안내 문구는 `사용자 터미널에서 fodh judgment migrate`.
- 옛 파일을 migrate 하지 않아도 동작은 이어진다. 새 완료는 판단기록으로 가고, 조회는 옛 표 행도 읽는다.

## 5. 훅 — 판단기록 보호(두뇌만)

판단기록은 사용자 답의 기록이다. 판단 파일과 **같은 수준**으로 두뇌 쓰기를 막고, 사용자 세션은 막지 않는다. 두뇌가 읽는 것(`cat`, `grep`, Read)은 허용한다.

- `hooks/pretooluse.mjs` 가 `.pi/harness.json` 에서 `judgment.archive` 를 읽는다. 기본값은 설정과 같은 식(`dirname(judgmentFile) + '/판단기록'`)이다.
- 판단 파일 조건이 있는 자리마다 판단기록을 더한다. 거부 문구는 `judgmentMessage`, 분류는 `boundary` 다.

| 자리 | 추가할 조건 |
|---|---|
| `judgmentPath(value)` | `inside(path, archiveDir)`(디렉터리 자신 포함) |
| `patternGuard` | `candidates` 처럼 archiveDir 의 기존 파일을 대조 대상에 넣고, `near([judgmentDirectory, archiveDir])` |
| 복사 `targetDirectory` | 목적지가 archiveDir 이면 판단 디렉터리와 같은 규칙 |
| 압축 해제 `archiveOverwrite` | 목적지가 archiveDir 안이면 거부 |
| 인라인 인터프리터·`sed` 편집 | `inlineText` 에 archiveDir 의 basename 이 있으면 거부 |

- A14-b 원칙은 유지한다: 두뇌는 알 수 없는 구조에서 실패-닫힘, 사용자 판정은 A14-b 이전보다 약해지지 않음, 동적 경로는 정적 단서가 있을 때만 대조. 판단기록 디렉터리 단서는 X1 규칙을 따른다. 루트 안 가드 경로이므로 root 기준 경로 전체(`docs/판단기록`)가 단서다.
- 테스트는 A14-b 와 같이 두 배치(루트가 HOME 밖, HOME 아래)로 돌린다.

| 두뇌 입력 | 기대 |
|---|---|
| Write/Edit `docs/판단기록/2026-09.md` | 거부(boundary) |
| `echo x >> docs/판단기록/2026-09.md` | 거부 |
| `cp note.md docs/판단기록/` | 거부 |
| `rm docs/판단기록/*` | 거부 |
| `tar -xf a.tar -C docs/판단기록` | 거부 |
| `python3 -c "open('docs/판단기록/x.md','w')"` | 거부 |
| `sed -i '' s/a/b/ docs/판단기록/2026-09.md` | 거부 |
| `cat docs/판단기록/2026-09.md`, `grep -r A19 docs/판단기록` | 허용 |
| `judgment.archive: "records/decisions"` 설정 뒤 `echo x > records/decisions/a.md` | 거부 |
| 같은 입력들을 사용자 세션(두뇌 아님)으로 | 판단기록 때문에 거부되지 않음 |

## 7. 테스트(새 파일 `test/j1-judgment-structure.test.ts`, 필요하면 `test/j1-hook.test.ts`)

1. 새 프로젝트 판단 파일은 머리말·지금 상태·한눈에(`열린 판단 없음`)·열린 판단·최근 결정 순이다. 등록하면 한눈에 행이 생기고, 선택지는 여러 줄이고, `- 회신:` 줄이 없다.
2. 파서: 같은 선택지를 한 줄로 쓴 것과 여러 줄로 쓴 것의 `options`·`questionHash` 가 같다. 옛 한 줄 형식 파일도 그대로 파싱되고 `classifyAnswer` 결과가 같다.
3. 적용: 항목이 KST 월 판단기록에 블록으로 옮겨진다(답 원문·해석·반영·결정일 포함). 판단 파일에서는 사라진다. 최근 결정 맨 위에 한 줄이 생기고 `recent` 개로 잘린다. 한눈에 행이 없어진다.
4. 재질문 사슬 적용: 멤버마다 블록이 생기고, 최종이 아닌 멤버는 `모호:` 답이다.
5. 월 경계: 결정 시각 `2026-09-30T15:30:00Z` 는 `2026-10.md` 로 간다(KST). 시계는 주입하거나 fake timer 를 쓴다.
6. 번호 유일성: 3장 불변식.
7. 장애 복구: 2-1 불변식(판단기록 쓰기 뒤, 판단 파일 쓰기 전에 실패를 주입).
8. 사용자가 `- 답:` 만 고친 파일을 `readJudgment` 로 읽으면 저장이 일어나지 않는다(mtime·hash 불변). 사용자가 한눈에 표를 손으로 고친 뒤 하네스가 쓰면 되돌아간다.
9. 워처: complete·migrate 쓰기는 `judgment-changed` 를 내지 않는다. 사용자 답 수정은 지금처럼 낸다.
10. CLI 길이 제한과 `--detail`(없는 파일, 판단기록 안 경로는 오류, 정상이면 상대 링크).
11. `fodh judgment read` 는 `completed` ≤ recent + `completedTotal` 을 낸다. `--all` 은 전부 낸다.
12. migrate: 픽스처 `test/fixtures/judgment/fod-harness-legacy.md` 로 한다. 메인 세션이 `git show 041978b:docs/판단대기.md` 로 넣어 둔다. 이 파일은 긴 지금 상태 이력, 옛 한 줄 선택지·`회신` 항목(A19~A22 는 답 없는 상태), 보류 절, `### … (결정 완료 …)` 자유 블록, 옛 4칸 표를 담고 있다. 확인할 것:
    - 열린 항목이 새 형식으로 바뀌고, 그 뒤 `readJudgment` 의 rev 가 그대로다.
    - 보류 절이 보존된다.
    - 지금 상태는 첫 문단만 남는다.
    - `이전.md` 에 옮긴 원문이 빠짐없이 들어간다(옮긴 문단·블록마다 포함 여부 확인).
