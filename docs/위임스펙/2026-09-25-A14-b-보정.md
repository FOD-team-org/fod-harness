## H1 (낮음) — `fodh … --help`

재현: 두 두뇌 모두 PLANNING 첫 턴에 `fodh backlog add --help` 를 쳤고 `Unknown option '--help'` 오류가 났다.

1. `src/cli/commands.ts` 의 `commandTable` 항목에 `summary`(한 줄 설명)와 `usage`(인자·옵션을 적은 사용법 한 줄, 예: `fodh backlog set <T번호> [--title …] [--category …] [--depends T01,T02] [--delegate codex|claude] [--judgment A번호] [--worktree 경로] [--notes 메모] [--review-commit sha] [--merge-commit sha] [--spec-rev N]`)를 넣는다. 실제 파서가 받는 옵션과 일치해야 한다.
2. `parseArgs` 에 `help: { type: 'boolean', short: 'h' }`. 명령 검증·`assertHarnessAlive` 전에 처리한다: `fodh`(인자 없음)·`fodh help`·`fodh --help` → 전체 목록(`usage` + `summary`), `fodh <group> --help` → 그 그룹 항목, `fodh <group> <action> --help`·`fodh pick --help` → 그 항목. 출력은 다른 명령처럼 JSON(`{ "help": [ { "usage": …, "summary": … } ] }`), exit 0, 상태·원장 변경 없음, 두뇌 허용.
3. 알 수 없는 옵션·인자 수 오류 문구 끝에 `(사용법: fodh <group> <action> --help)` 를 붙인다(해당 명령을 알 수 있을 때).
4. `claude-md generate` 가 `commandTable` 을 렌더링한다면 렌더 결과가 바뀌지 않게 하거나, 바뀌면 관리 블록 해시 갱신이 기존 테스트와 맞는지 확인한다.
5. 테스트: 모든 `commandTable` 항목에 비어 있지 않은 `usage`/`summary`; `backlog set --help` exit 0·`--notes` 포함; `fodh --help` 목록 수 = 표 길이; 알 수 없는 옵션 오류에 사용법 안내; 두뇌 env(`FODH_BRAIN=1`)에서도 help 동작.

## H2 (중간) — 임시 디렉터리 쓰기·삭제 과잉 거부 (`hooks/pretooluse.mjs`)

재현(A14 원장 permission_denials, 모두 워크트리 읽기·테스트 목적):
- `… && T=$(mktemp -d) && EXPENSE_DATA_DIR=$T node bin/expense.js add --help; …; rm -rf "$T"` → `$T` 를 cwd 기준 문자 그대로 풀어 프로젝트 안 소스 쓰기로 거부.
- `… >/tmp/t11rev-run.txt 2>&1 …; rm -f /tmp/t11rev-run.txt` → rm 의 `-f` 대상이 프로젝트 밖이라 "프로젝트 밖 … 삭제 금지".
- `D=$(mktemp -d "${TMPDIR:-/tmp}/t03rev.XXXX"); export EXPENSE_DATA_DIR=$D … ls -A $D; rm -rf $D` → `$D` 문자 그대로.
- `r(){ out=$(node bin/expense.js "$@" 2>/tmp/_e_$$); … }; …; rm -f /tmp/_e_$$` → rm `-f` 프로젝트 밖.

1. **임시 경로 판정** `tempSafe(path)`: `realpath` 로 푼 경로가 임시 루트(`os.tmpdir()`, `process.env.TMPDIR`, `/tmp`, `/private/tmp`, `/var/tmp` 의 realpath) 안에 있고, 임시 루트 자체가 아니며, 프로젝트 root 와 같거나 그 안이거나 그 조상이 아니고, 등록 워크트리와 같거나 그 조상이 아니며, 훅 패키지 디렉터리 안이 아니어야 한다(토이처럼 root 가 임시 디렉터리 아래에 있어도 root·워크트리는 보호된다. 워크트리 안은 기존 규칙대로 허용).
2. **rm 규칙**: 두뇌의 `rm -r/-f` 대상이 `tempSafe` 면 허용(지금은 `!inside(root) && !inWorktree` 면 거부). 나머지 판정(root·docs·.git·.pi·프로젝트 밖 일반 경로 거부)은 그대로.
3. **임시 변수**: 쓰기 대상(리다이렉트·`writePaths` 피연산자·rm 대상)이 `$NAME`, `${NAME}` 이거나 그 뒤에 `/<나머지>`(`..` 세그먼트·추가 `$` 없음)가 붙은 형태이고, NAME 이 **임시 변수**면 `<임시루트>/fodh-var-NAME/<나머지>` 로 바꿔 판정한다. 임시 변수 조건:
   - 원문 명령(최상위 문자열과 `sh -c` 로 풀린 중첩 문자열 각각)에서 NAME 대입이 **정확히 한 번**(`NAME=`, `export NAME=`, `local NAME=`, `readonly NAME=`, `declare NAME=` 모두 셈)이고, 값이 `$(mktemp …)` 또는 `` `mktemp …` `` 이며, mktemp 인자에 템플릿이 없거나 템플릿이 `/tmp/`·`/private/tmp/`·`/var/tmp/`·`$TMPDIR`·`${TMPDIR}`·`${TMPDIR:-…}` 로 시작하거나 `-t <접두>` 형태다(상대 템플릿 `mktemp -d tmp.XXXX`, `-p .`, `--tmpdir=.` 은 임시 변수가 아니다).
   - 또는 값이 임시 루트 안의 리터럴 절대 경로다(`T=/tmp/x`).
   - 또는 NAME 이 `TMPDIR` 이고 명령 안에서 대입되지 않았다.
   - 셸 파서는 `$(…)` 를 단어로 쪼개므로 대입 탐지는 원문 문자열 정규식으로 한다.
4. 그 밖의 `$`·백틱·글롭이 든 쓰기 대상은 지금처럼 판정한다(확인할 수 없으면 거부 유지).
5. 테스트(훅 단위 호출, root 를 임시 디렉터리 아래에 둔 경우와 아닌 경우 모두): 위 A14 명령 4개(경로만 테스트용으로 바꿔서) 허용; `rm -rf /tmp`·`rm -rf "$TMPDIR"` 거부(임시 루트 자체); root 의 조상 삭제 거부; `T=src; rm -rf $T` 거부; `T=$(mktemp -d); T=src; rm -rf $T` 거부(두 번 대입); `T=$(mktemp -d tmp.XXXX); rm -rf $T` 거부; `rm -rf $UNKNOWN` 는 기존 판정; `echo x > $T/out`(T=mktemp) 허용; `bash -c 'T=$(mktemp -d); rm -rf "$T"'` 허용.

## H9 (중간, 이관 준비) — 프로젝트 정의 승인 규칙 `approvalRules` (`src/core/config.ts`, `hooks/pretooluse.mjs`)

근거: WisePharm 의 `npm run db:migrate`(drizzle-kit, 기본 `.env` 가 운영 DB 일 수 있음)·`npm run db:push`·앱 스토어 업로드 스크립트 등은 내장 정규식(`prisma migrate`, `psql`, `neonctl` …)에 걸리지 않는다.

1. 설정 `approvalRules: { id: string; pattern: string; flags?: 'i'; description?: string }[]`, 기본 `[]`. 검증: id 는 `^[a-z][a-z0-9-]{1,39}$` 이고 내장 범주 이름과 겹치지 않으며 중복 없음, pattern 은 `new RegExp` 로 컴파일 가능, flags 는 없거나 `'i'`. 잘못되면 `loadConfig` 오류.
2. 훅: 내장 범주 판정 뒤, 각 규칙을 명령 그룹마다(`commandWords` 로 래퍼·대입을 벗긴 뒤 `[basename(words[0]), ...words.slice(1)].join(' ')`, `sh -c` 중첩 그룹 포함) 시험해 맞으면 `deny('승인 필수 동작(<id>)입니다. 판단대기 항목을 만들어라.', 'approval')`. 설정을 읽을 수 없거나 규칙이 잘못되면 두뇌는 `하네스 설정을 읽을 수 없습니다.` 로 거부(fail-closed), 두뇌가 아니면 규칙 없이 진행.
3. `requiresApproval` 에서 빠진 범주와 달리 `approvalRules` 는 항상 적용한다(목록에 있으면 적용). README 설정 표에 예시: `{"id":"db-migrate","pattern":"^npm run db:(?:migrate|push)\\b|^drizzle-kit (?:migrate|push)\\b"}`.
4. 테스트: 사용자 규칙이 `npm run db:migrate`·`DATABASE_URL=x npm run db:migrate`·`npx drizzle-kit migrate`·`bash -c "npm run db:migrate"` 를 승인 거부; `npm run db:generate` 허용; 잘못된 regex → loadConfig 오류 + 두뇌 훅 fail-closed; 내장 이름과 같은 id 거부.

## H10 (중간, 이관 준비) — 워크트리 의존성 링크 `worktrees.links` (`src/core/worktree.ts`, `src/core/config.ts`)

근거: 워크트리는 새 checkout 이라 `node_modules` 가 없다. Codex 수행자·VERIFY 가 테스트·타입검사를 돌리려면 의존성이 필요하다. 매번 설치하면 디스크·네트워크·메모리 부담이 크다(사용자 규칙: 워크트리는 node_modules 를 링크).

1. 설정 `worktrees.links: string[]`, 기본 `[]`. 각 항목은 root 기준 상대 경로(절대 경로·`..` 세그먼트·`.git`·`.pi`·판단 파일·`.claude` 로 시작 금지, 중복 금지).
2. `fodh worktree create` 가 워크트리를 만든 뒤, 각 항목에 대해 root 쪽이 존재하고 워크트리 쪽이 없으면 `<wt>/<p>` → `<root>/<p>` 심볼릭 링크를 만든다. 그다음 `git -C <wt> check-ignore -q <p>` 로 무시 여부를 보고, 무시되지 않으면 `git rev-parse --git-common-dir` 의 `info/exclude` 에 `/<p>` 줄을 없을 때만 추가하고 원장 `worktree:link-excluded` 를 남긴다(추적 파일은 바꾸지 않는다). 결과 원장 `worktree:link` `{ taskId, linked: [...], skipped: [...] }`.
3. `fodh worktree remove`·CLEANUP·디스크 집계는 링크를 따라가지 않는다(링크만 지우고 root 쪽 원본은 남는다). `git worktree remove` 가 링크 때문에 실패하지 않는지 확인한다.
4. 테스트(임시 git 저장소): `node_modules` 디렉터리 링크 생성·무시 확인; `.gitignore` 에 `node_modules/`(끝 슬래시 — 링크는 디렉터리가 아니라 무시되지 않음)만 있을 때 info/exclude 추가; worktree remove 뒤 root 의 `node_modules` 와 그 안 파일 보존; 잘못된 항목(절대 경로·`..`·`.git`) 설정 오류; root 쪽이 없으면 skipped.
