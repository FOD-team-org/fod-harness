P2(워처)·P3(`fodh codex`)·P4(정리 실행)·P5(스킬·인터뷰 은행)는 범위 밖. 이 단계에서 `IMPLEMENT` 의 실제 위임과 `CLEANUP` 의 실제 정리는 **스텁**(두뇌가 지시문대로 직접 수행하되, `fodh codex` 는 아직 없으므로 지시문에 "P3 전까지는 판단대기에 '위임 필요' 항목을 만들고 RECLAIM" 로 적는다). 단, CLEANUP 은 스텁이어도 `fodh cleanup report` 로 프로세스 레지스트리 잔존 0 을 확인하는 부분은 구현한다.

## 1. 상태기계 (`src/core/state.ts`)

- 상태 집합은 현행 `states` 유지. 전이 그래프(허용 목록, 그 외는 오류 "허용되지 않는 전이"):

```
IDLE → INTERVIEW | PLANNING(백로그 존재 시 /develop-start) 
INTERVIEW → RESEARCH | WAIT_JUDGMENT
RESEARCH → PRD_DRAFT | WAIT_JUDGMENT
PRD_DRAFT → ARCH | WAIT_JUDGMENT
ARCH → REVIEW | WAIT_JUDGMENT
REVIEW → PROJECT_READY | INTERVIEW(반려) | WAIT_JUDGMENT
PROJECT_READY → PLANNING
PLANNING → PICK
PICK → SPEC | DONE_ALL | WAIT_JUDGMENT | WAIT_RETRY | WAIT_RESOURCE | DEADLOCK
SPEC → IMPLEMENT | RECLAIM
IMPLEMENT → VERIFY | RECLAIM
VERIFY → REVIEW | FIX | RECLAIM
REVIEW → MERGE | FIX | RECLAIM
FIX → VERIFY | RECLAIM
MERGE → DOCS | RECLAIM
DOCS → CLEANUP
CLEANUP → PICK | CLEANUP_FAILED
CLEANUP_FAILED → CLEANUP | paused(cleanup)
RECLAIM → PICK | CLEANUP_FAILED
WAIT_JUDGMENT → PICK | INTERVIEW..REVIEW(project-start 단계로 복귀: 진입 전 상태를 `resumeState` 에 저장하고 그리로만)
WAIT_RETRY → PICK ; WAIT_RESOURCE → PICK ; DEADLOCK → WAIT_JUDGMENT
DONE_ALL → IDLE | PLANNING
paused(*) → recovering | PICK(사용자 /develop-start 재실행) 
recovering → PICK | IDLE
어느 상태 → paused(billing|quota|error|memory|budget|cleanup) (시스템 전이, `--system` 플래그로만)
```

- 가드:
  - `SPEC|IMPLEMENT|VERIFY|REVIEW|FIX|MERGE|DOCS` 진입은 `--task <ID>` 필수이고 백로그에 존재해야 한다.
  - `IMPLEMENT|MERGE` 진입은 저장된 doctor(12h) 필요(현행 H1).
  - `FIX` 진입 시 task `repair += 1`; `repair > 3` 이면 전이를 거부하고 `{ error: "repair 초과", action: "reclaim" }` 반환(두뇌가 `fodh judgment add` → `fodh reclaim`).
  - `MERGE → DOCS` 는 검수 증거 필요: task `review.commit` 이 있고 `review.high === 0` 이며 `review.commit` 이 현재 작업 커밋(`--commit <sha>` 인자)과 같아야 함. 아니면 거부.
  - task `done` 은 `fodh backlog set T07 --status done` 에서 DoD 검사: `verify.ok`, `review.high===0`, `review.commit`, `merge.commit`, `docs.ok`, `cleanup.ok` 모두 참. 하나라도 없으면 거부하고 빠진 항목 목록 반환.
  - `WAIT_JUDGMENT` 진입 시 `resumeState` 저장. 진입 상태가 task 루프면 `resumeState = PICK`.
- 상태 파일 `taskId`, `resumeState`, `enteredAt`, `autoTurns`(§5) 필드 추가. 모든 전이는 원장에 `state:<from>→<to>` 항목(status ok) 기록.
- `fodh state transition <to> [--task T07] [--commit sha] [--system]`.

## 2. 백로그 (`src/core/backlog.ts`, `docs/backlog.md`)

- 표 형식은 설계 §5. 열: ID, 제목, 분류(`design|non-design|docs|research`), 의존(쉼표 ID), 상태(`ready|doing|verify|review|fix|merge|done|blocked(A12)`), repair, 판단(A번호), 워크트리, 검수(커밋), 비고. 표 밖의 문서 앞머리(제목·설명)는 보존한다.
- 내부 저장은 표 파싱 결과 + 부가 필드(`verify.ok`, `review.{commit,high}`, `merge.commit`, `docs.ok`, `cleanup.ok`, `spec.rev`)를 `.pi/harness-backlog.json` 에 둔다(표는 사람용 뷰, JSON 이 진실; 표 편집이 감지되면(해시 불일치) 표를 진실로 재동기화하되 부가 필드는 유지).
- `fodh backlog list [--json]`, `fodh backlog get T07`, `fodh backlog set T07 --status … --depends T03,T04 --title … --category … --repair 0 --judgment A12 --worktree wt-t07 --review-commit sha --review-high 0 --verify-ok --merge-commit sha --docs-ok --cleanup-ok`, `fodh backlog add --title … --category … [--depends …]`(ID 자동 `T%02d`, 고유·재사용 금지).
- 원자 저장·잠금은 `storage.ts` 규약.

## 3. PICK (`src/core/pick.ts`, `fodh pick`)

- 입력: 백로그, 상태(`paused` 이력), 슬롯/메모리(P4 전까지는 `{ slots: ok }` 스텁). 출력 `{ outcome, task?, reason, cycle? }`:
  - `SPEC`(선택됨): `ready` 이고 의존이 모두 `done` 인 task 중 우선순위(표 순서) 최상. 상태를 `SPEC --task` 로 전이하고 백로그 `doing`.
  - `DONE_ALL`: 모든 task `done`.
  - `WAIT_JUDGMENT`: ready 0, `blocked(A*)` ≥ 1, 다른 원인 없음.
  - `WAIT_RETRY`: ready 0 이고 마지막 paused 원인이 `error|quota`. 백오프 5·15·60분(`retry.count`, `retry.nextAt` 상태 필드; 3회 뒤 판단대기 항목 자동 생성 → WAIT_JUDGMENT).
  - `WAIT_RESOURCE`: 마지막 paused 원인이 `memory|budget` 또는 슬롯 없음.
  - `DEADLOCK`: ready 0, blocked 0, 미완료 task 들이 의존 순환(또는 존재하지 않는 ID 의존). 판단대기 항목 자동 생성(순환 목록 + 추천 해소안) → `WAIT_JUDGMENT`.
- 순수 함수 `decidePick(backlog, state, resources)` 는 부작용 없이 판정만; `fodh pick` 이 전이·백로그·판단대기 부작용을 수행.

## 4. RECLAIM (`src/core/reclaim.ts`, `fodh reclaim --task T07 --judgment A12`)

- 절차: (1) 레지스트리에서 `taskId` 소유 프로세스(kind ≠ brain) 회수(`reclaimOwnedGroup`) (2) 잔존 확인(레지스트리 비어야 함) (3) 워크트리·검수 증거는 보존 (4) 백로그 `blocked(A12)` (5) 상태 `RECLAIM → PICK`. 회수 실패 → `CLEANUP_FAILED`.
- 두뇌용 축약: `fodh judgment add … --blocks T07 --reclaim` 은 add 뒤 reclaim 까지 한 번에 수행하고 `{ judgment: "A12", reclaimed: true, next: "PICK" }` 반환.

## 5. 판단 적용 (`fodh judgment apply [A12…]`)

- `readJudgment --answered` 의 분류(§4-3)를 사용: 확정 답 → 결정 완료 표로 이동(원문·해석·반영 열), 해당 task 의 `blocked(A12)` → `ready`; 승인 필수 항목은 번호/승인/진행 토큰 없으면 미적용 + 재질문 항목 생성; 모호·rev 불일치 → 미적용 + 재질문 항목 생성. 반환에 적용/미적용 목록.
- `/judged` 명령과 워처(P2) 둘 다 이 명령을 부른다.

## 6. Pi 명령과 자동 재개 루프 (`extensions/orchestrator/index.ts`)

- `pi.registerCommand`: `/project-start [이름]`, `/develop-start`, `/status`, `/judged [A번호…]`, `/cleanup`.
  - `/project-start`: 상태 `IDLE → INTERVIEW`, `docs/` 초기 템플릿(판단대기·backlog·작업일지) 없으면 생성, 두뇌에 INTERVIEW 지시문 전송(`pi.sendMessage(..., { triggerTurn: true })`).
  - `/develop-start`: `docs/backlog.md` 없으면 `PLANNING` 지시문, 있으면 `PICK` 실행 → 결과에 따른 지시문.
  - `/status`: 상태·task·인박스 미적용·원장 unknown·최근 rateLimit 요약을 Pi 에 표시(두뇌 턴 없음).
  - `/judged`: `fodh judgment apply` → 결과 요약 표시 → 상태가 WAIT_JUDGMENT 이고 적용 ≥1 이면 `PICK` 지시문으로 턴 시작.
  - `/cleanup`: `fodh cleanup report`(P4 전엔 레지스트리·잔존 보고만) 표시.
- **자동 재개**: `agent_end` 에서 상태를 읽어 활동 상태(`INTERVIEW..REVIEW`, `PLANNING`, `PICK`, `SPEC..CLEANUP`, `RECLAIM`, `recovering`)면 다음 지시문을 `sendMessage({customType:"harness-orchestrator", …}, { triggerTurn: true, deliverAs: "followUp" })` 로 보낸다. 정지 상태(`IDLE`, `PROJECT_READY`, `WAIT_*`, `DONE_ALL`, `DEADLOCK`, `paused(*)`)면 보내지 않는다.
  - 무한 루프 방지: 상태·task 가 바뀌지 않은 채 자동 턴이 `maxAutoTurns`(기본 3) 연속되면 중단하고 판단대기 항목("진행 정체: <state>/<task>") 생성 → WAIT_JUDGMENT. 상태 파일 `autoTurns` 로 셈, 전이 시 0.
  - 두뇌 턴이 `error/aborted` 로 끝났으면 자동 재개하지 않는다(프로바이더가 이미 `paused/recovering` 로 바꿈; `recovering` 은 1회만 자동 재개).
- 지시문 템플릿 `templates/prompts/<STATE>.md`: 상태별 "지금 할 일·산출물·끝내는 조건·다음 fodh 명령" 을 담은 짧은 한국어 문서. 자리표시자 `{{taskId}}`, `{{judgmentFile}}`, `{{backlogFile}}`. INTERVIEW 는 §12 18 영역을 라운드로 나누는 규칙과 "유한 선택지는 판단대기 항목으로, 서술형은 채팅 질문으로" 만 담고 문항 은행은 P5.
- `brain-rules.md` 에 1줄 추가: "턴 마지막 줄 `상태: <fodh state get 의 state>`" 는 이미 있음 — 유지.
