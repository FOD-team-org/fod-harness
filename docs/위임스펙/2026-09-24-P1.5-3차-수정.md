## 1. `ps lstart` 로케일 버그 (필수, 실패 11건의 원인)

- 이 Mac 은 한국어 로케일이라 `/bin/ps -o lstart=` 가 `2026년  9월 24일 목요일 05시 39분 16초` 를 출력한다. `Date.parse` 가 `NaN` → `RangeError: Invalid time value`(`test/revision.test.ts:200`) 와 시작 시각 불일치 → 잠금 소유자 stale 오판·레지스트리 잔존(`listProcs` 가 빈 배열이 아님)으로 이어진다.
- 수정: 모든 `/bin/ps` 호출(`src/core/lock.ts:28`, `src/provider/runner.ts:47`, `test/revision.test.ts:198`, 그 외 `ps` 호출 전부)에 `env: { ...process.env, LC_ALL: 'C', LANG: 'C' }` 를 넣어 `Thu Sep 24 05:39:36 2026` 형식으로 고정한다. 파싱 실패(NaN) 시에는 예외 대신 **원문 문자열 비교**로 후퇴하고, 그것도 불가하면 "살아있음" 으로 간주한다(절대 throw 하지 않는다).
- 레지스트리 `startedAt` 저장값도 C 로케일 문자열로 통일한다. 이미 저장된 다른 형식의 값은 문자열 비교로 처리한다.
- 테스트: `LC_ALL=ko_KR.UTF-8` 을 `vi.stubEnv` 로 넣어도 `startedAt` 파싱이 성공하는 회귀 테스트 1개 추가.
