## B1 (높음) — pi 실행 중 `.pi/harness.lock` 이 사라짐

재현(확인됨): 아이디어 폴더에서 pi(pid 48725)가 도는 동안 `.pi/harness.lock` 이 없다. 같은 폴더에서 `fodh` 를 한 번 더 치면 막히지 않고 두 번째 하네스가 열린다.

원인:
1. `acquireLock`(`src/core/lock.ts:39`)은 소유자 `startedAt` 을 node 기준(`Date.now() - process.uptime()*1000`)으로 적는다.
2. `lockOwnerAlive` 는 `/bin/ps -o lstart=`(C 로케일)와 비교하고 2000ms 넘게 차이 나면 죽은 소유자로 본다.
3. A14-c 의 `bin/fodh` 는 sh → `exec env … pi` 로 같은 pid 를 이어 쓴다. 이때 `ps lstart` 는 **sh 가 시작한 시각**이다. 설치 질문에 답하는 약 4초가 그대로 차이가 됐다. `sh -c 'sleep 3; exec node …'` 로 재현하면 3663ms 차이가 난다.
4. 결과: provider `session_start` 가 잠금을 잡는다. 바로 뒤 orchestrator `session_start` 의 `recoverOrphanBrain(ctx.cwd)`(비신규 경로)가 이를 죽은 잠금으로 판정해 회수한다(unlink → 자기 획득 → 해제). 그래서 파일이 사라진다. provider 의 `recoverOrphanBrain(root, true)` 도 같은 이유로 고아 회수를 건너뛴다.

고칠 것:
1. `acquireLock` 의 `startedAt` 은 `processStartedAt(process.pid)`(C 로케일 lstart 문자열)을 우선 쓴다. 얻지 못하면(ps 제한) 지금의 node 기준 ISO 로 되돌아간다. `lockOwnerAlive` 는 옛 ISO 형식 잠금도 지금처럼 읽는다(`Date.parse` 비교 유지).
2. 같은 프로세스의 잠금 판정. 프로세스 안에서 **현재 보유 중인 잠금 token 집합**을 `globalThis[Symbol.for('fodh.lock.held')]` 에 둔다. 확장이 jiti 로 따로 로드돼도 공유된다.
   - 획득하면 넣고, 해제하면 뺀다.
   - `lockOwnerAlive(owner)` 에서 `owner.pid === process.pid` 이면 ps 비교 없이 판정한다. token 이 집합에 있으면 살아 있음, 없으면 죽음이다(같은 pid 의 이전 프로세스가 남긴 파일이거나 이미 해제된 잔재).
   - `storage.ts` 의 `withFileLock` 도 같은 `acquireLock` 을 쓰므로 함께 적용된다.
3. `processStartedAt`·ps 호출은 주입할 수 있게 한다. 예: `acquireLock(path, { startedAt?: () => Promise<string|undefined> })`, `lockOwnerAlive(owner, { startedAt?: (pid) => … })`. Codex 샌드박스는 `/bin/ps` 를 막기 때문이다.
4. 테스트:
   - (a) 주입한 lstart 가 node 기준보다 4초 이르다 → 획득한 소유자가 `lockOwnerAlive` 로 살아 있다.
   - (b) 같은 프로세스에서 provider 획득 뒤 `recoverOrphanBrain(root)`(비신규)를 불러도 잠금 파일과 token 이 그대로다. orchestrator 확장 `session_start` 경로로도 확인한다.
   - (c) 같은 pid 인데 집합에 없는 token 파일 → 회수된다(획득 성공).
   - (d) 옛 ISO 잠금 호환.
   - (e) 실제 ps 가 되는 환경에서만 도는 통합 1건(`it.skipIf(ps 불가)`): `sh -c 'sleep 2.5; exec node <스크립트>'` 가 잠금을 잡고, 같은 프로세스에서 `lockOwnerAlive`·`recoverOrphanBrain` 뒤에도 파일이 남는다.
   - (f) `fodh start` 의 "이미 실행 중" 판정이 새 형식 잠금에서 동작한다.

## B2 (중간) — 테스트가 실제 macOS 알림을 띄움

재현(확인됨): 다른 세션이 fod-harness `npm test` 를 돌린 01:13~01:18 에 macOS 알림이 쏟아졌다. `paused(error)`, `doctor 실패`, `누락 스킬… CLAUDE.md 로드: false`, `알 수 없는 설정 키: brain.custom, custom, project`(`test/config-model.test.ts` fixture) 등이다. `src/core/notify.ts` 의 macos 채널은 `options.exec` 가 없으면 실제 `osascript` 를 실행한다.

고칠 것:
1. `notify()` macos 채널에서 `options.exec` 가 주입되지 않았고 `process.env.FODH_NOTIFY_OS === 'off'` 이면 osascript 를 부르지 않는다. 대신 원장에 `notify:macos` `skip`(evidence `{ reason: 'FODH_NOTIFY_OS=off' }`)을 남긴다. tui 채널과 원장 기록은 그대로다.
2. `vitest.config.ts` 의 `test.env` 에 `FODH_NOTIFY_OS: 'off'` 를 넣는다. 자식 프로세스(가짜 두뇌·CLI)도 상속한다.
3. 저장소 전체에서 테스트가 실제 OS 부수효과(osascript, `open`, 소리 등)를 낼 수 있는 경로를 grep 으로 확인하고 같은 방식으로 막는다. 찾은 목록을 결과 문서에 적는다.
4. 테스트:
   - env off + exec 없음 → 기본 execFile 경로가 불리지 않는다(`vi.mock('node:child_process')` 로 확인) + 원장 skip.
   - exec 주입 → 지금처럼 호출된다.
   - env 가 없으면 기본 경로를 탄다(모킹으로 확인).
   - `vitest.config.ts` 에 env 가 있다는 회귀 1건.

## U1 (높음) — 두뇌가 정리한 결과만 보기

재현(확인됨): 아이디어 폴더 한 턴에서 화면에 도구 호출 50번과 결과 미리보기가 찍혔다. 두뇌 자신의 호출은 11번이었고, 나머지 39번은 두뇌가 띄운 보조 에이전트 4개의 내부 호출이다. 원인은 세 가지다.
1. `src/provider/turn.ts:185-200` 은 모든 `assistant` tool_use(입력 JSON 전체 — 보조 에이전트 프롬프트 포함)와 모든 tool_result(400자)를 `parent_tool_use_id` 구분 없이 `onText` 로 보낸다.
2. Pi 가 이를 마크다운으로 그려서 명령 속 `*`·`\` 가 사라진다.
3. 사용자 요청: "브레인이 정리한 결과만 확인할 수 있게".

실측한 stream-json 형태(2026-09-27, `claude -p --output-format stream-json --verbose --include-partial-messages`, haiku, Agent 1개):
- 메인 스레드 `assistant`/`user` 는 `parent_tool_use_id: null` 이다. 보조 에이전트의 `assistant`(tool_use·text)/`user`(tool_result) 는 `parent_tool_use_id: "<Agent tool_use id>"` 다. `stream_event` 는 메인 것만 나온다(모두 null).
- 보조 에이전트는 기본으로 백그라운드다. 순서는 다음과 같다.
  1. 메인 tool_use `Agent`
  2. `system/task_started`(`task_id`, `tool_use_id`, `description`, `subagent_type`, `is_backgrounded:true`)
  3. 메인 tool_result(즉시 "launched")
  4. 보조 tool_use/tool_result
  5. `system/task_progress`(`usage.tool_uses`, `last_tool_name`)
  6. 메인 text("Agent launched. Waiting…")
  7. **첫 `result`**(`result:"Agent launched. Waiting for it to complete."`)
  8. `system/task_updated`(`patch.status:"completed"`)
  9. `system/task_notification`(`status:"completed"`, `summary`)
  10. 새 `system/init`
  11. 메인 text(최종)
  12. **두 번째 `result`**(최종 답)
  
  즉 한 프로세스에 `result` 가 여러 번 온다. 최종 답은 **마지막 `result.result`** 다(지금 `reportText` 도 마지막 것을 쓴다).

고칠 것:
1. 설정 `ui.brainOutput`: `'result'`(기본) | `'full'`. 승인 키가 아니다. `fodh config set ui.brainOutput full` 로 바꾸고 다음 턴부터 적용된다(턴마다 `loadConfig`). 다른 값은 설정 오류다.
2. `runTurn` 에 표시 방식을 넘긴다. 예: `TurnOptions.display?: 'result'|'full'`, `onProgress?: (line: string) => void`.
   - **doctor 턴은 항상 지금 방식(full)이다.** doctor 는 `onText` 로 받은 전체 텍스트에서 `문서 확인 FODH-DOC-…` 을 찾는다.
   - `display` 를 안 주면 `full` 로 둬서 기존 호출부와 호환한다. provider(`extensions/provider/stream.ts`)만 설정값을 넘긴다.
3. `result` 모드:
   - 진행 중에는 `onText` 를 부르지 않는다. 대상은 text_delta, `[tool]`, `[도구 결과]`, 메인·보조 모두다. 원장·상태·거부 처리·감사 등 나머지 동작은 그대로다.
   - 진행 상황을 모은다.
     - 경과 시간
     - 메인 도구 호출 수
     - 보조 에이전트 시작 수(`task_started`, 없으면 메인 `Agent`/`Task` tool_use) / 끝난 수(`task_notification`, 또는 `task_updated.patch.status` 가 completed/failed/killed)
     - 보조 도구 호출 수(parent 가 있는 tool_use 수)
     - 마지막 메인 도구 설명(`input.description` → 없으면 도구 이름, 60자)
   - `onProgress` 로 보낸다. 형식 예: `작업 중 2분 10초 · 도구 11 · 보조 2/4 · 파일 목록 확인`. 변화가 있을 때만, 최대 초당 1회이고, 경과 시간은 5초 간격으로 갱신한다.
   - 턴이 끝나면(정상·오류·중단 모두, runTurn 이 반환하거나 던지기 직전) 딱 한 번 `onText` 로 다음을 보낸다.
     - 본문: 마지막 `result.result`(비어 있지 않은 문자열). 없으면 마지막 메인 `assistant` 메시지의 text 블록들. 둘 다 없으면 생략.
     - 훅 차단: 이번 턴의 `[훅 차단] …` 문구. 중복을 빼고 본문 뒤에 줄마다 한 번씩.
     - 끝줄: `\n\n— 도구 11회 · 보조 에이전트 4개 · 4분 41초`. 훅 차단이 있으면 `· 훅 차단 N건`, 정상 종료가 아니면 `· 중단: <classification>`.
     - `redact` 는 지금처럼 `text()` 를 거친다.
4. provider 확장: `session_start` 에서 `ctx.ui` 를 보관한다(`hasUI` false 면 없음). `result` 모드 턴 동안 `onProgress` → `ctx.ui.setWorkingMessage(line)` 이고, 턴이 끝나면 `ctx.ui.setWorkingMessage()` 로 되돌린다. `session_shutdown` 에서도 되돌린다. UI 호출 예외는 삼킨다.
5. `full` 모드(지금 동작 유지 + 두 가지만 보정):
   - (a) 보조 에이전트 줄(parent 있음)은 앞에 `↳ ` 를 붙인다.
   - (b) `[tool]`·`[도구 결과]` 줄은 코드 블록(``` 펜스)으로 감싼다. 펜스 길이는 내용 속 가장 긴 백틱 연속보다 1 길게 해서 마크다운이 명령을 망가뜨리지 않게 한다.
6. README: "화면 출력" 절(기본은 결과만, 전체 보기는 `fodh config set ui.brainOutput full`, 원장·Claude 대화 기록 위치).
7. 테스트(가짜 두뇌 명령으로 위 실측 순서를 그대로 재생):
   - result 모드: `onText` 1회. 최종 본문 + 끝줄이다. `[tool]`·`[도구 결과]`·"Agent launched" 가 없다.
   - `onProgress` 가 보조 1/1·도구 수를 반영한다.
   - 결과가 두 번 올 때 마지막 것을 쓴다.
   - 훅 차단 문구가 1회 들어가고 끝줄에 N건이 붙는다.
   - 오류·중단이면 마지막 메인 text + `중단:` 끝줄이 나온다.
   - doctor 턴은 모드와 무관하게 full 이다(기존 doctor 테스트 통과).
   - full 모드: 보조 줄 `↳`, 코드 펜스(내용에 ``` 포함한 경우).
   - stream.ts: result 모드에서 text_delta 1회, 작업 메시지 설정·복원(ui 주입).
   - 설정 기본값·허용값·오류, `fodh config set` 허용.
   - 기존 테스트 중 `[tool]` 출력 등을 확인하던 것은 fixture 에 `ui.brainOutput: 'full'` 을 넣어 유지한다(단언을 지우지 않는다).
