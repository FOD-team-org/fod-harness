## R1 (높음) — `tempSafe` 는 완전한 리터럴에만 (`hooks/temp-paths.mjs`, `hooks/pretooluse.mjs`, `src/core/audit.ts`)

2. 임시 변수 형태는 단어 전체가 `$NAME` 이나 `${NAME}` 뒤에 선택적 `/<나머지>` 가 붙은 것만이다. `<나머지>` 는 1 의 문자를 포함하지 않고 `..` 조각도 없어야 한다.
3. 감사(`audit.ts`)도 `{}` `()` 를 동적 단어로 취급한다.

## R2 (높음) — 대입은 최상위 원문 전체에서 센다

1. NAME 대입 횟수는 최상위 명령 원문 **전체**(중첩 `sh -c`·`eval` 문자열 포함)에서 센다. 정확히 한 번일 때만 임시 변수다. 재대입으로 볼 형태(`+=`, `read`, `printf -v`, `for NAME in`, `declare -n`, `mapfile`, `getopts`, `unset NAME`)가 원문 어디에든 있으면 임시 변수가 아니다.
2. `TMPDIR` 가 원문 어디에서든 바뀌면 `$TMPDIR` 계열 치환과 `mktemp` 템플릿의 `$TMPDIR` 인정을 모두 끈다. 해당 형태: 접두 대입 `TMPDIR=… cmd`, `export`/`declare`/`local`/`readonly TMPDIR`, `env TMPDIR=…`, `unset TMPDIR`, `eval` 안의 대입.
3. 중첩 원문 안에서의 치환은, 그 중첩 원문이 바깥에서 **작은따옴표**로 감싸인 경우에만 한다. 큰따옴표나 따옴표 없는 중첩 원문 안의 변수는 바깥 셸이 먼저 펼치므로 치환하지 않는다(HEAD 판정).
4. 감사도 같은 규칙을 쓴다(`TMPDIR=/project sh -c "echo x > \$TMPDIR/src/a.ts"` 는 비어 있지 않은 결과를 낸다).

## R3 (중간) — 변수가 비었을 때의 경로도 통과해야 허용

임시 변수 치환으로 허용하려면 두 해석이 **모두** 통과해야 한다.
- 치환 해석: `<임시>/fodh-var-NAME/<나머지>` 가 tempSafe 여야 한다.
- 빈 변수 해석: NAME 을 빈 문자열로 바꾼 경로가 HEAD 판정을 통과해야 한다. 이 경로는 `/<나머지>` 이고, `<나머지>` 가 없으면 빈 인자라서 대상이 없다.

이것으로 대입 실패·미실행(`false && T=…`, 파이프 `T=… | cat`, 백그라운드 `&`, 서브셸, 함수, 없는 템플릿 디렉터리)이 모두 막힌다. 그 결과 `rm -rf "$T"`·`rm -rf $D` 는 허용되고, `rm -f "$T/out"` 은 빈 해석 `/out` 이 프로젝트 밖 삭제라서 거부된다. 거부는 의도된 것이다. README 한계 표에 "임시 변수 아래 개별 파일 삭제 대신 `rm -rf "$T"`"를 적는다.

## R4 (중간) — 같은 명령에서 링크를 만들 수 있으면 임시 예외 없음

명령 원문(중첩 포함)에 실행 파일 `ln`, `mv`, `cp`, `rsync`, `tar`, `unzip`, `ditto`, `bsdtar`, `git` 중 하나라도 있으면, 그 명령 전체에서 임시 예외(리터럴·변수 모두)를 주지 않는다.

같은 명령 안에서 새로 만든 링크를 통해 **쓰는** 경우(`ln -s "$PWD" /tmp/l && echo x > /tmp/l/src/a.ts`)는 HEAD 때부터 있던 한계다. README 한계 표에 적는다.
