## 구현 선택과 스펙 해석

1. **부분집합 검증 유지.** 훅에서는 W1의 멤버 이름·개수 상한·포함 관계·baseBranch·verify 등의 검증을 추가하지 않았다. 잘못된 workspace를 비두뇌가 읽으면 최상위 규칙과 secrets를 유지한 채 workspace만 꺼진다.
2. **경로 오류의 지역 처리.** 독립 모듈은 기존 resolvePath와 같은 기존 조상·끊어진 심볼릭 링크 해석을 사용한다. 물리 `..` 후보를 추가하며, 오류는 cwd unknown 또는 해당 경계 거부로 처리한다. 기존 전역 normalizePath 자체는 변경하지 않았다. CDPATH는 기본으로 훅 환경을 읽되 단위 테스트에서는 옵션으로 주입한다.
3. **단독 할당은 실행 명령이 아니다.** `D=../chemical; cd $D && npm i`의 첫 항목은 commandWords 결과가 빈 배열이므로 실행 허용 목록 위반으로 보지 않는다. 뒤의 동적 cd/실행에서 스펙의 M5가 난다. 실행 명령 앞 할당의 멤버 경로는 계속 검사한다.
4. **임시 폴더의 멤버 삭제 우선순위.** 기존 임시 삭제 예외는 `/private/tmp`의 멤버 디렉터리도 임시 경로로 인정했다. 따라서 스펙 §6-2의 `rm -rf ../chemical/dist`가 기존 삭제 문구 대신 M1으로 내려갔다. workspace의 멤버 main에 한해서 임시 삭제 예외를 제외해 요구된 기존 삭제 문구를 먼저 낸다. 단일 레포 조건은 바꾸지 않았다.
5. **원문 call 후보.** unresolved인 call 문자열은 배열의 읽기 전용 `raw` 표시를 통해 basename을 적용하지 않는다. 깊이·꼴 상한, 원문 첫째, 범주→규칙 순서를 유지한다.
6. **리터럴 달러 경로.** rawWords에서 작은따옴표·escape로 리터럴임을 확인한 `$`·백틱 경로도 멤버 경로로 비교한다. 변수로 간주해 버리지 않는다. 실제 확장·글롭의 보수적 판정과 분리했다.
7. **멤버 비밀 정책 초기화 실패(최초 구현, 아래 검수 L-4에서 변경).** 멤버 정책의 경로 컴파일 오류도 지역적으로 잡는다. 새 오류가 최외곽 `훅 입력을 해석할 수 없습니다`로 바뀌지 않으며, 실제 경로나 값을 표시하지 않고 비밀 경계의 `경로 확인 불가`로 거부한다.
8. **추가 확장 없음.** 스펙 §9의 D1~D13과 받아들인 한계는 유지했다. W3b·자동 진행의 규칙 합집합은 구현하지 않았다.

## 기존 파일 보존과 금지 작업

기존 테스트 수정 **0개·0줄**이다. §7-3의 열거 예외도 쓰지 않았다.

작업 시작 때 기존 테스트·도우미·fixture 119개를 포함한 기존 파일 252개를 SHA-256으로 기록했다. 이후 변경이 확인된 기존 파일은 허용된 `hooks/pretooluse.mjs`, `hooks/secret-reads.mjs`, `hooks/secret-reads.d.mts`뿐이다. 기존 테스트, src, 변경 금지 훅, 설계, templates, skills, extensions는 동일했다.

- 실제 fod-harness 저장소에서 Git 명령을 실행하지 않았다. Git 실행은 테스트가 만든 임시 저장소 안의 초기화·커밋·워크트리·메타데이터 검사뿐이다.
- 실제 claude·codex·cswap·pi·osascript, 네트워크, 전체 테스트 스위트는 실행하지 않았다. 기존 런처·위임 테스트의 실행기는 가짜 파일/주입이다.
- 실제 저장소·HOME의 `.env*`·키·인증 파일을 열지 않았다. 비밀 파일 테스트는 임시 폴더의 `FAKE_VALUE`만 사용했고 비밀값을 결과에 기록하지 않았다.
- 모든 검사에 `FODH_NOTIFY_OS=off`를 적용했다.
- 첫 기존 회귀에서는 `/bin/ps`·실제 저장소 `.git` 쓰기 차단으로 인한 실패나 건너뜀이 **0건**이었다. 24파일 통합 실행과 마지막 관련 5파일 실행도 같은 항목의 실패·건너뜀 **0건**이었다.

## 남은 한계

- cwd는 순서를 추적하지 않는 집합이다. 명령마다 cd를 한 번씩 적용하므로 넓은 거부가 있고, 반복 안에서 같은 cd가 여러 번 수행되는 실제 횟수는 추적하지 않는다.
- 셸 프로필 내부의 CDPATH/cdable_vars, 루트 인터프리터·스크립트 내부 쓰기, 변수 값 속 `..`, xargs 입력 파일의 내용은 분석하지 않는다.
- **R3에 추가한 심볼릭 링크 TOCTOU 한계:** `ln -s ../../../chemical .pi/scratch/c && cd .pi/scratch/c && npm i`는 막지 못한다. 훅 검사 시점에는 링크가 없고 같은 명령이 실행되면서 링크가 생기는 경우다. 검수에서 받아들인 한계로 남긴다.
- 비두뇌 함수 몸통의 기존 비확장 파싱 한계는 그대로다. 추적 비밀의 git log/diff/grep 읽기까지 새로 막지 않는다.
- 멤버 경로 비밀 패턴을 일반 워크트리 파일 Read에 적용하지 않는 D12를 유지한다. rev:path에서만 워크트리 주인 기준 후보가 추가된다.
- git status 등의 선택적 index 갱신, 1초 제한의 rev-parse/check-ignore 비용, 훅 검증과 W1 loadConfig의 향후 동기화 필요성은 남는다.
- 실제 사용자 레포·프로바이더·터미널 실기는 수행하지 않았다. 전체 테스트 실행은 메인의 별도 검증 범위다.

## W3b 인계

### 거부 문구

아래 일곱 문구의 stderr 접두는 모두 `하네스 가드[경계]: `이고 끝은 개행이다.

| 이름 | 문구 |
| --- | --- |
| M1 | `멤버 main(<이름>)은 읽기만 합니다 — 바꾸거나 실행하는 일은 task 로 위임합니다` |
| M2 | `멤버 main 은 fodh worktree merge 로만 바꿉니다` |
| M3 | `commit·merge·push 는 루트 저장소나 등록 워크트리를 대상으로만 합니다` |
| M4 | `git 변경 대상을 확인할 수 없습니다 — cd·git -C 는 리터럴 경로로 쓰세요` |
| M5 | `멤버 main 을 가리킬 수 있는 동적 경로입니다 — 리터럴 경로로 쓰세요` |
| M6 | `GIT_* 환경변수는 워크스페이스 모드에서 쓸 수 없습니다` |
| M7 | `git 전역 옵션은 -C·--no-pager·-P·--no-optional-locks 만 씁니다` |

멤버 main에서도 먼저 나올 수 있는 기존 문구:

| 상황 | 종류·문구 |
| --- | --- |
| Edit/Write 등 | 경계: `프로젝트 밖 쓰기는 금지합니다. .pi/scratch/를 사용하세요.` |
| rm -rf 등 | 경계: `프로젝트 밖·루트·문서 트리·.git·.pi 삭제는 금지합니다.` |
| find -delete | 경계: `find -delete 대량 삭제는 금지합니다.` |
| reset·branch -D 등 | 보호: `두뇌의 git 이력·참조 재작성은 금지합니다. 사용자 터미널에서 처리하세요.` |
| 직접 worktree add/remove/prune | 경계: `git worktree 직접 실행 대신 fodh worktree를 사용하세요.` |
| revert/cherry-pick/am | 경계: `main 변경은 task 워크트리 위임으로만 한다` |
| 추출·재귀 복사와 cd | 경계: `추출·재귀 복사의 실행 경로를 확인할 수 없습니다` |
| 비밀 읽기 | 경계: `비밀 파일은 두뇌가 읽을 수 없습니다: <이름>. 값이 필요하면 판단으로 사용자에게 요청하세요` |
| 승인 대상인 비쓰기 명령 | 승인: `승인 필수 동작(<id>)입니다. 판단대기 항목을 만들어라.` |
| 잘못된 설정 | 보호: `하네스 설정을 읽을 수 없습니다.` |

승인 검사는 비쓰기 멤버 명령 검사보다 앞선다. 그래서 `cd ../chemical && npm run db:migrate`는 M1 대신 승인(web-db)다.

### 새 모듈 API

```ts
hookWorkspace(root, rawConfig)
// { enabled, members: [{ name, path, secrets, approvalRules }] }
// 실패는 throw; pretooluse 설정 블록이 청중별 처리.

possibleCwds(entries, cwd, { home?, workspace?, cdpath? })
commandCwds(words, set)
// { cwds: string[], unknown: boolean }. words는 래퍼 제거 전 단어.
// unknown이어도 알려진 후보를 버리지 않는다.

gitTargets(words, set)
// cwd 집합 + action, args, invalidGlobal. -C 연쇄를 적용한다.

memberMainOf(path, members, worktrees?)
memberAncestorOf(path, members)
// 멤버 이름 또는 undefined. 경로 오류는 호출부에서 잡는다.

approvalForms(words)
// (string[] & { readonly raw?: boolean })[]
// 원문 첫째, 최대 깊이 3/32꼴. raw이면 basename 없이 문자열 그대로 매칭.

secretReadGuard({ root, cwd, config?, deny, members?, worktrees? })
// members?: { name: string; path: string; secrets?: unknown }[]
// worktrees?: { path: string; repo?: string }[]
// fileTool(name, input), bash(entries). 기존 옵션은 바꾸지 않았다.
```

brain-rules에 넣을 조언:

- 멤버는 `git -C <멤버>` 또는 명시적인 경로 인자로 읽는다.
- 한 줄에 `cd <멤버>`와 실행 명령을 섞지 않는다. 전체 줄의 cwd 후보 집합이 모든 단순 명령에 적용된다.
- cd·git -C·--prefix에는 리터럴 경로를 쓴다. 거부되면 명령을 나눈다.
- 멤버 main 변경은 task 위임과 `fodh worktree merge`로만 한다.
- 멤버 비밀 경로 패턴은 `config/prod.json`처럼 쓰며 앞 `/`를 붙이면 절대 경로가 된다.
- `git --no-optional-locks -C <멤버> status` 권고 여부는 W3b에서 정한다.

**자동 진행 공백:** `src/core/autopilot.ts`의 `autopilotBlocked`는 여전히 최상위 `config.approvalRules`만 참조한다. 멤버 규칙은 실행 시 이 훅에서 차단되지만 자동 진행의 판단 차단 합집합에는 없다. W3b 또는 별도 단계에서 연결해야 한다. 해당 src 파일은 수정하지 않았다.


## 검수 반영

[Opus 독립 구현 검수](../검수/2026-09-27-W3a-Claude-검수.md)의 M-1·M-2·L-1~L-6과 테스트 공백을 반영했다. L-5는 지시대로 구현을 바꾸지 않고 동작만 기록했다. 이번 실행은 W3a와 지정된 기존 18파일로 한정했다. 검수 기록의 전체 직렬 110파일·3,476개 통과는 메인의 선행 검증이며 이번에 실행한 수치가 아니다.

### 항목별 처리

| 항목 | 변경과 확인 |
| --- | --- |
| M-1 | `pretooluse.mjs`에서 쓰기 값에 `redirect` / `operand` 출처를 유지한다. `writePaths`가 리다이렉트→자신의 피연산자 순서로 반환하는 기존 계약을 감싸며, 같은 문자열이 양쪽에 있어도 출처를 구별한다. git 대상 cwd 풀이는 자신의 피연산자에만 적용한다. log/diff/show의 scratch 출력 3개는 통과, 멤버 출력은 M1(web), stash/restore/checkout 피연산자는 M2다. |
| M-2 | `effective-cwd.mjs`에서 줄 안의 `CDPATH=` 단어, export/declare/typeset/local/readonly의 CDPATH 선언, setopt / set -o의 cdablevars·autocd(대소문자·밑줄 무시)를 unknown으로 본다. 할당·env 인자·치환·bash -c도 포함한다. 두 모드에 적용하며 npm/git add는 두뇌 workspace에서 M5, MERGE commit은 청중과 모드에 관계없이 M4다. 한 레포 변화는 §0-7 1·4에 한정한다. |
| L-1 | `member-main.mjs`에서 따옴표 밖 `{`와 xargs -I 치환자가 들어간 인자를 동적으로 분류한다. 중괄호 3개 재현과 -I{} / -IITEM / -I ITEM은 M5다. 따옴표 안의 리터럴 중괄호는 통과한다. |
| L-2 | git grep의 묶인 O, tree의 묶인 o를 검사한다. sort의 o/T와 file의 C도 같은 방식으로 맞췄다. grep -nO는 M2, tree -ao / sort -ro·-rT / file -bC는 M1(web)이다. |
| L-3 | cwd 호출 안에서 `(cwd, 값)`별 경로 후보와 디렉터리 판정을 메모한다. 전체 확장 시도를 2,000회로 제한하고 초과하면 알려진 후보를 유지한 unknown을 반환한다. pretooluse가 계산한 집합을 `secretReadGuard`의 선택 옵션 `cwdSet`으로 전달한다. 옵션이 없으면 기존처럼 자체 계산한다. 병적 입력의 훅 판정은 1초 미만이며 M5로 거부한다. |
| L-4 | 멤버 정책 컴파일 오류는 `하네스 가드[보호]: 하네스 설정을 읽을 수 없습니다.`와 개행으로 거부한다. 모든 두뇌 도구에서 같은 설정 오류가 우선되도록 `hookWorkspace`에서 정책 컴파일도 검증하고, 비두뇌는 설정 블록의 기존 한 레포 폴백을 적용한다. 독립 `secretReadGuard`의 멤버 정책 생성 오류도 같은 종류·문구다. |
| L-5 | **비밀 검사 내부 예외는 `경로 확인 불가`로 거부한다(바깥 catch 문구가 아님).** 이 동작은 변경하지 않았다. L-4의 정책 생성 오류와 구별한다. |

작은 구현 선택: `secret-reads`의 선택 `cwdSet`은 생성 옵션이다. Bash만 파싱·계산하고 그 결과를 전달해 비밀 검사에서 BFS를 반복하지 않는다. 파일 도구는 cwd 계산을 하지 않는다. 멤버 비밀 정책의 원문 반환과 루트 정책 처리 방식은 유지했다. 컴파일 오류를 설정 단계에서 잡는 것은 L-4의 모든 두뇌 도구 거부와 비두뇌 폴백을 함께 만족시키기 위한 것이다.

### 테스트 보강
