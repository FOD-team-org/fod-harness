## 설치 환경과 실행 준비

- Node 24.13.1, Pi 0.73.1, TypeScript 5.9.3, Vitest 3.2.4, @types/node 24.12.3을 사용했다.
- `npm install --ignore-scripts --cache /private/tmp/fodh-npm-cache --no-audit --no-fund --fetch-retries=0 --fetch-timeout=15000`는 registry DNS `ENOTFOUND`로 실패했다. 이를 테스트 실패로 집계하지 않았다.
- 로컬에 이미 설치된 정확한 버전의 도구를 이 저장소의 무시된 `node_modules`에 심링크하여 검증했다. Pi 패키지는 복사하지 않았다. 다른 프로젝트의 테스트를 실행하지 않았다. 이 심링크 환경은 다른 머신에 이식되지 않으므로 Fable 환경에서 의존성을 설치해야 한다.
- Pi의 devDependency는 계약에 지정된 전역 설치본 `file:` 경로이며, Pi 코어 패키지는 문서대로 peerDependencies에도 선언했다. package-lock은 생성하지 않았다.
- 프로젝트 `.claude/settings.json`에 템플릿 내용을 설치해야 한다. 템플릿은 `FODH_PACKAGE_ROOT/hooks/pretooluse.sh`를 호출하고, 프로바이더·doctor가 자식 환경에 패키지 경로를 넣는다. 프로바이더 밖에서 해당 settings를 사용하는 경우에도 이 환경변수를 지정하거나 훅 명령을 설치 경로의 절대 경로로 바꿔야 한다.
- `.pi/harness.json`의 `brain.command`, `brain.switchCommand`는 문자열 또는 인자 배열이다. 공백이 있는 경로는 배열을 권장한다. 기본값은 claude 및 cswap switch이며, 테스트에서는 항상 가짜 실행파일의 절대 경로로 덮어썼다.
- `fodh judgment add --options`는 JSON 문자열 배열 또는 `선택1|선택2`를 받는다. 출력은 JSON 한 덩어리다.
- IMPLEMENT·MERGE 진입 CLI와 claude-code 모델 세션 시작은 doctor 성공을 요구한다. 실제 작업 프로젝트에서 실행하면 실제 두뇌를 호출하므로 해당 실기는 Fable 담당이다.

## 설계와 차이·범위

1. **Pi 종료 이벤트:** 설계의 `done(reason:error/aborted)`는 설치된 Pi 문서·타입에 존재하지 않는다. 정상 종료는 `done(reason:stop)`, 오류·중단은 문서화된 `error(reason:error/aborted)`를 사용했다. AssistantMessage.stopReason에도 실제 원인을 기록한다.
2. **잠금 의존성:** proper-lockfile 대신 Node 파일 API로 완성된 소유자 JSON을 하드링크하여 잠금을 획득하고, 쓰기는 고유 tmp→rename으로 저장한다. pid·시작시각·소유 토큰 및 stale 회수로 보호한다.
3. **프로세스 신원·회수:** 실행 관리자가 현재 spawn 핸들을 가진 소유 그룹만 회수한다. startedAt은 ps lstart를 우선하고, ps 사용 불가·종료 경합 시 spawn 시각을 기록한다. 저장된 오래된 PID만으로 임의 종료하지 않는다. 과거 레지스트리의 PID 재사용 대조·회수 정책은 P4 대상이다. 잔존은 ps와 그룹 kill(0)으로 검사하고, ps가 제한되면 kill(0)의 ESRCH로 확인한다.
4. **한도 전환:** 계약대로 switchCommand 1회와 재시도 1회만 구현했다. 설계의 `cswap status`를 이용한 90% 자동 전환 중복 방지는 실행·출력 계약이 확인되지 않아 구현하지 않았다. 원장은 현재 턴뿐 아니라 전체 미해결 항목을 보수적으로 검사한다.
5. **상태기계·자동 진행:** 상태 이름 검증과 영속 전환은 구현했지만 전체 전이 그래프·DoD·RECLAIM→다음 task·백오프·4계정 순회는 P1 이후 범위다. 전체 정리·전역 슬롯·워처·세션 회전·사후 감사 완성도 후속 단계다.
6. **훅:** 규칙 1·3·5·6의 패턴 기반 차단을 구현했다. 규칙 2·4 및 스크립트 내부·MCP 쓰기 우회 분석은 P6 범위다. 승인 분류 패턴은 보안 경계의 완전성 증명이 아니다.
7. **알림:** 프로바이더 콜백과 Pi UI 알림까지만 연결했다. 외부 Slack 등 실제 발송은 하지 않았다.
8. **패키지 발견:** Pi manifest는 `extensions/provider/index.ts`만 등록한다. runner/stream 등 보조 모듈을 확장으로 잘못 읽지 않도록 경로를 명시했다. 아직 없는 skills/prompts는 등록하지 않았다.

## 프로세스 정리 및 픽스처 보존 증거

- 각 테스트는 spawn close까지 기다리고, 프로바이더 테스트 종료 후 레지스트리가 비었는지 검사한다. hang 시나리오가 남긴 부모·자식·손자 PID도 각각 kill(pid,0)이 ESRCH인지 확인했다.
- 최종 실행은 임시 Node preload로 npm·Vitest 워커·CLI·가짜 Claude 등 생성된 Node PID를 수집했다. 실행 명령은 `node /private/tmp/fodh-pid-audit-run.mjs`이며 내부에서 위 `npm test`를 실행했다. 종료 후 PID 검사 결과:

```json
{"observedPids":95,"survivors":[],"exitCode":0}
```

- 따라서 최종 실행에서 추적한 프로세스의 잔존은 **0개**다. pgrep은 사용자 지시대로 생략했다. 시스템 전체의 다른 작업 프로세스를 검색하거나 종료하지 않았다. 임시 추적 스크립트는 검증 후 제거했다.
- 원본 JSONL의 작업 전·후 SHA-256이 각각 일치했다:

```text
first-run-hook-deny.jsonl 632b4513f403c31d79538d4718f4f1fb05a71ac5ab950f6bb589552b5954e42f
resume-run.jsonl         5398a84b5c55763747d66b7f1307d81de928fbbfe389d2d472ea8273156575e9
```

빌드는 실행하지 않았고 tsc는 noEmit으로 실행했다. node_modules와 테스트 캐시는 커밋 대상에서 제외했다. 커밋은 Fable 담당이다.
