## 요구별 반영

| 요구 | 결과 | 내용 |
|---|---|---|
| 1 | 반영 | 기존 billing·cleanup·configError·abort·quota 분기를 통과한 doctor는 수집한 denial에서 Bash 명령의 FODH_DOCTOR_MARKER 차단 여부로 판정한다. permission_denials와 tool_result의 훅 차단 경로를 모두 사용한다. 차단이 있으면 result.is_error·max_turns·exit 1에도 stop, 없으면 configError를 반환한다. 일반 턴의 processError 판정은 유지한다. |
| 2 | 반영 | doctor=true의 claudeArgs에서 --append-system-prompt-file 및 brain-rules 경로를 제외한다. 일반 턴에는 유지한다. doctor 프롬프트에 차단 후 다른 도구를 쓰지 않고 `차단 확인` 한 줄로 종료하라는 지시를 추가했다. |
| 3 | 반영 | doctor의 --max-turns 2를 유지하고 실제 fake-claude 수신 인자로 검증했다. |
| 4 | 반영 | 차단→후속 도구 성공→error_max_turns/exit 1 픽스처에서 doctor 성공 및 state.doctor.ok=true를 검증했다. permission_denials 없는 tool_result 단독 증거도 통과한다. exit 0이지만 차단 없음, max_turns지만 차단 없음은 실패한다. 기존 doctor 테스트도 통과했다. |
| 5 | 반영 | 설계 v0.3.2 목록 한 줄에 `⑫ doctor 판정 = 훅 차단 관측 여부(두뇌의 후속 도구 호출·max_turns 무관).`을 추가했다. |

- `test/provider.test.ts`: fake-claude 회귀 테스트 4개 추가, 기존 차단 없는 exit 0 테스트의 state.doctor.ok=false 및 정상 정리/종료 코드 단언 추가.

## 설계 선택

1. 기존 턴별 denial 수집기를 재사용하여 permission_denials와 tool_use ID에 연결된 훅 오류 tool_result를 같은 근거로 취급했다. Bash가 아니거나 명령에 시험 마커가 없는 차단은 성공 근거로 쓰지 않는다.
2. doctor 성공 판정은 기존 중단/정리 실패 분기 뒤에 배치했다. 차단이 이미 관측되었어도 quota, billing, configError, deadline, user abort, protocolError, cleanup 실패를 성공으로 바꾸지 않는다.
3. 원장에는 실제 result 오류·exit code 1을 그대로 남긴다. doctor의 훅 시험 성공과 자식의 max_turns 종료 사실을 구분하며, 관측 기록을 성공으로 덮어쓰지 않는다.
4. doctor의 상태·세션·인박스 보존과 계정 전환 금지 정책은 유지했다. 일반 턴은 동일한 마커 차단이 있어도 max_turns 오류를 processError로 처리한다.

의도적 이탈: 없음.
