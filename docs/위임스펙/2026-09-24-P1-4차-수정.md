## F8 현상

대화형 Pi(`pi -e provider -e orchestrator --model claude-code/haiku`) 세션 시작 시 provider 의 `ensureDoctor` 가 매번 실패한다.

```
Extension "…/extensions/provider/index.ts" error: configError: 훅 실제 차단 시험에 실패했습니다(processError).
```

`fodh doctor` 도 3/3 실패. 원장(`.pi/harness-ledger.jsonl`)과 직접 재현(`claude -p --max-turns 2 --settings … --append-system-prompt-file brain-rules.md`)으로 확인한 경위:

1. 턴 1: `echo FODH_DOCTOR_MARKER` → 훅이 exit 2 로 차단(정상). `permission_denials` 에 기록됨.
2. 턴 2: 두뇌(haiku)가 brain-rules 의 "상태 조회는 `fodh state get`" 을 따라 `fodh state get` 을 실행 → 성공.
3. 답을 쓰기 전에 `--max-turns 2` 에 걸려 `subtype: error_max_turns`, `is_error: true`, exit 1.
4. `runTurn` 은 `outcome.code !== 0 || result.is_error` 를 먼저 보고 `processError` 로 분류한다. `markerDenied` 검사(훅이 실제로 막았는지)는 그 뒤에 있어 도달하지 못한다.

즉 훅은 정상인데 doctor 가 두뇌의 후속 행동(모델 성향)에 따라 실패한다. 어제 실기에서 통과한 것은 haiku 가 차단 뒤 바로 답을 썼기 때문이다.

## 요구

1. **doctor 성공 기준 = 훅 차단 관측.** `options.doctor` 일 때는 (a) 자식이 정상 정리(`outcome.cleaned`)되었고 (b) `FODH_DOCTOR_MARKER` 를 담은 Bash 호출이 `permission_denials`(또는 `hook:` 원장에 기록되는 tool_result 차단)로 관측되면, `result.is_error`·`terminal_reason: max_turns`·exit code 1 이어도 `reason: 'stop'` 을 반환한다. 차단이 관측되지 않으면 지금처럼 `configError`. quota·abort·cleanup 실패 분기는 그대로.
2. **doctor 턴은 brain-rules 를 붙이지 않는다.** `claudeArgs(…, doctor=true)` 에서 `--append-system-prompt-file` 을 뺀다(시험 대상은 훅·settings 이지 규칙이 아니다). 프롬프트도 "차단되면 다른 도구를 쓰지 말고 `차단 확인` 한 줄만 답하고 끝내라" 로 보강한다(`src/cli/doctor.ts`).
3. **`--max-turns` 는 2 유지.**
4. **테스트**(가짜 claude 픽스처): (a) 턴 1 차단 + 턴 2 다른 도구 성공 + `error_max_turns`/exit 1 → doctor ok, `state.doctor.ok=true`. (b) exit 0 이지만 차단 없음 → configError. (c) doctor 인자에 `--append-system-prompt-file` 이 없고 일반 턴에는 있다. 기존 doctor 테스트는 통과 유지.
5. `docs/설계/2026-09-24-하네스-설계-v0.3.md` v0.3.2 목록에 ⑫ "doctor 판정 = 훅 차단 관측 여부(두뇌의 후속 도구 호출·max_turns 무관)" 한 줄 추가.
