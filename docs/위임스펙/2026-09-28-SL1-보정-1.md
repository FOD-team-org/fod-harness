## F1 [중간] 따옴표 없는 공백 경로

- `ps -o command=` 는 인자를 따옴표 없이 공백으로 잇는다.
  - 실제 출력: `codex exec -s read-only -C /Users/minseok/Desktop/기획/일반앱 아이디어 --skip-git-repo-check -m …`
  - 지금은 `-C` 값이 `…/기획/일반앱` 까지만 잡힌다. 그래서 영역 밖으로 판정되고 조용히 무시된다.
  - 실제 하네스 프로젝트 `~/Desktop/기획/일반앱 아이디어` 가 이 경우다.
- 고칠 것
  - 위치 플래그 값 = 플래그 뒤에서 `-` 로 시작하는 다음 단어 직전까지의 단어들.
  - 이 단어들을 앞에서부터 1개, 2개, … 이어 붙인 후보를 만든다. 원래 문자열의 부분 문자열을 써서 연속 공백을 보존한다.
  - 후보 중 **실제로 존재하는 가장 긴 경로**를 쓴다.
  - 하나도 존재하지 않을 때:
    - 단어가 1개면 지금처럼 그 값을 쓴다(prospective realpath).
    - 단어가 2개 이상이면 위치 모름으로 처리한다(`slot:external-unlocated`).
  - `=` 형태(`--cwd=/a b/c`)도 같은 규칙을 따른다.
  - 상대 경로 후보는 cwd 기준으로 푼 뒤 같은 방식으로 존재 여부를 본다.
- 테스트: 따옴표 없는 공백 경로를 ps 문자열 그대로 주입한다(`JSON.stringify` 로 따옴표를 붙이지 않는다). `-C`, `--cwd`, `--cwd=` 세 형태 모두.
  - 뒤에 `-` 로 시작하지 않는 단어(예: 프롬프트 `-` 가 아닌 위치 인자)가 따라와도 존재하는 가장 긴 경로를 고르는지 본다.
  - 기존 T4 의 따옴표 붙인 입력 테스트는 지우지 말고 둔다.

## F2 [중간] 셸 래퍼 후보와 플래그 탐색 범위

- Claude 실기에서 확인했다. Claude Code Bash 도구의 companion 호출은 이런 구조다.
  - `/bin/zsh -c source <snapshot> … && export CODEX_COMPANION_SESSION_ID=… && node …/codex-companion.mjs task --cwd <X> …`
  - zsh 래퍼(pid 66898)와 그 자식 node(pid 66900)가 **둘 다** 후보다.
  - 지금 코드는 래퍼를 먼저 만나고, `shellParts(...).groups[0]`(= `source …` 부분)에서 플래그를 못 찾는다. 그래서 lsof cwd, 즉 그 Claude 세션의 셸 cwd 로 위치를 정한다.
  - 실기 결과 소유자가 `external-66898`, root 가 `…/savit/scl-wt-perf01/server` 였다. `--cwd` 값이 아니라 세션 셸 위치다.
  - 결과: 셸 cwd 가 프로젝트 X 안에 있는 세션이 다른 곳을 대상으로 Codex 를 돌려도 X 가 막힌다. 사용자가 지적한 문제와 같은 종류다.
- 고칠 것
  1. **가장 안쪽 후보만 센다.** 어떤 후보의 자손 중에 다른 후보가 있으면 그 후보(바깥 래퍼)는 건너뛴다. 스냅숏의 ppid 사슬로 판정한다. `codex exec` 의 node → vendor 바이너리 쌍도 같은 규칙으로 안쪽 하나만 남는다.
  2. **플래그는 Codex 명령 뒤에서만 찾는다.** 명령 문자열에서 `codex-companion.mjs task` 또는 `codex exec`(`codex exec resume` 포함) 토큰 위치를 찾고, 그 뒤의 단어에서만 위치 플래그를 찾는다.
     - 이렇게 하면 앞쪽 셸 구문, node 옵션 `-C`(`--conditions`), 프롬프트 본문 속 ` -C ` 오인식도 줄어든다.
     - 셸 그룹 분리(`shellParts`)에 기대지 말고 이 토큰 기준으로 자른다.
  3. 래퍼만 있고 안쪽 후보가 없는 경우(예: 자식이 이미 끝남)는 지금 규칙대로 처리한다. 플래그를 2번 규칙으로 찾고, 없으면 lsof cwd 를 쓴다.
- 테스트
  - 실제 구조 스냅숏: zsh 래퍼(cwd = 프로젝트 A 안, 명령 끝에 `--cwd <A 밖>`) + 자식 node companion(`--cwd <A 밖>`). A 획득은 **성공**해야 한다.
  - 같은 구조에서 `--cwd <A 안>` 이면 거부. 소유자 pid = 자식 node.
  - `codex exec` node → vendor 쌍: 소유자는 vendor(안쪽) 하나.
  - 명령 앞부분에 `node -C development …/codex-companion.mjs task --cwd <X>` 같은 형태가 있으면 X 로 판정.

## F3 [낮음] 영역 (d) = 하네스 등록 워크트리만

- 지금은 `listWorktrees().porcelain` 의 `worktree` 줄을 전부 영역에 넣는다.
  - 멤버 레포의 git 워크트리 전체가 영역이 된다. 사용자가 손으로 만든 워크트리, 하네스 루트가 더 큰 레포의 하위 폴더일 때의 git toplevel 까지 들어간다.
- 결정: (d) 는 **하네스가 등록한 워크트리(`listed.worktrees`)만** 쓴다. porcelain 은 영역에 넣지 않는다.
  - 루트·멤버·prefix 디렉터리(a~c)는 그대로다.
- README 141행 부근 (d) 설명도 "하네스가 등록한 워크트리"로 맞춘다.
- 테스트: 비-git 루트에 상태 등록 워크트리 경로를 두고, **mock 없이** 실제 `listWorktrees` 를 거쳐 그 경로 안의 외부 후보가 거부되는지 본다. 이 테스트는 `beforeEach` 의 전역 mock 을 쓰지 않게 분리한다.

## F4 [낮음] 영역 계산의 항목별 실패와 원장 구분

- 한 항목 때문에 영역 전체가 루트 하나로 줄지 않게 한다.
  - 예: prefix 로 시작하는 깨진 심링크 → `stat` throw, `readdir` EACCES.
  - 항목별로 try/catch 해서 그 항목만 건너뛴다.
- `slot:external-scan fail` 원장에 `evidence: { stage: 'config' | 'ps' | 'areas', error }` 를 넣는다. error 는 redact 후 200자.
  - 항목을 건너뛸 때도 `stage: 'areas'` 로 남긴다. 같은 획득 시도 안에서는 1건으로 합쳐도 된다.
- 테스트: 깨진 심링크 prefix 항목이 있어도 멤버·다른 prefix 영역 판정이 유지된다.
