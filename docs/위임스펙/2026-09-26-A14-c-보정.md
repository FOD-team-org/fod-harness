## P1 (중간) — 메모리 중단이 CLEANUP·DOCS 를 막지 않게

재현: T01 이 CLEANUP 에 들어간 직후 `memory-critical` 이 와서 `CLEANUP→paused(memory)`. 정리는 위임이 없고 자원을 줄이는 단계인데 멈췄다. 회복 뒤에는 `PICK→RESUME CLEANUP` 으로 정상 복귀했다(2026-09-26 22:34 확인).

1. `extensions/orchestrator/index.ts` `memory-critical` 처리: 현재 상태가 `CLEANUP` 또는 `DOCS` 면 `paused(memory)` 로 전이하지 않고 `updateState(root, { lastPaused: 'memory' })` 만 한다. 알림 본문은 "정리·문서 단계는 계속합니다. 다음 task 는 메모리 회복 뒤 시작합니다".
2. 그 뒤 두뇌가 `CLEANUP→PICK`(또는 DOCS→CLEANUP→PICK)으로 넘어가면 `decidePick` 의 `lastPaused === 'memory'` 분기가 `WAIT_RESOURCE` 를 돌려준다(지금 코드). `memory-recovered` 는 `WAIT_RESOURCE && lastPaused==='memory'` 를 이미 처리한다. 이 경로가 끝까지 이어지는지 테스트로 고정한다.
3. `lastPaused==='memory'` 인 동안 `startCodex` 거부(지금 `codex.ts:47`)와 H12 준비 명령 거부는 그대로.
4. 테스트: CLEANUP 중 critical → 상태 CLEANUP 유지 + lastPaused memory; 이어 PICK → WAIT_RESOURCE; recovered → PICK + 자동 재개; IMPLEMENT 중 critical → 지금처럼 paused(memory).

## P4 (중간) — 외부 Codex 감지를 하네스에 내장

배경: 사용자는 Codex 를 한 번에 하나만 돌리는 규칙(메모리 OOM 대응)을 쓴다. 하네스 슬롯은 하네스 run 만 알아서, 파일럿 동안 메인 세션이 임시 스크립트(`codex-guard.mjs`, 44 MB 상주)로 외부 Codex 를 슬롯 소유자 `external-<pid>` 로 잡아 두었다. 사용자가 터미널에서 하네스만 띄우는 운영(L1)에서는 이 스크립트가 없으므로 하네스가 직접 한다. ChatGPT 앱이 띄우는 짧은 `codex exec` 까지 잡아 5분 대기가 생긴 것(P4 원래 항목)도 고친다.

1. 설정 `delegate.codex.externalGuard`(기본 `true`). 끄는 것은 승인 키(`approvalConfigKeys`)에 넣는다.
2. 하네스가 Codex 슬롯을 잡기 직전(`startCodex` 등 `acquireSlot('codex', …)` 호출 경로)에 프로세스 스냅샷(기존 process-tree 유틸, `LC_ALL=C`)에서 **외부 Codex** 를 찾는다: 명령줄이 `codex-companion\.mjs task` 또는 `(^|/)codex exec\b` 이고, 조상(최대 30단계) 중에 `fodh-codex-supervisor` 도 `/Applications/(ChatGPT|Codex)\.app/` 도 없고, 현재 프로세스의 조상·자손이 아닌 것. 유휴 `app-server-broker`·`codex app-server` 는 대상이 아니다.
3. 외부 Codex 가 있으면 그 pid 를 소유자로 슬롯에 기록한다(`runId: external-<pid>`, `pid`, `startedAt`=그 프로세스 lstart, `root`=감지한 프로젝트 root, `external: true`). 결과는 지금의 "다른 소유자가 잡고 있음"과 같아서 기존 `paused(slot)`→`slot-free` 흐름을 탄다. 외부 프로세스가 끝나면 기존 pid 동일성 검사(`slotOwnerAlive`)로 죽은 소유자로 판정돼 풀린다. 워처의 slot-free 감지가 `external` 소유자에도 동작하는지 테스트로 고정한다.
4. `fodh slots status` 는 외부 소유자를 `external` 로 표시한다. `fodh codex cancel` 등은 외부 소유자를 건드리지 않는다(취소 대상 아님 안내).
5. 스냅샷을 얻지 못하면(ps 실패) 지금처럼 하네스 슬롯만 보고 진행하고 원장에 `slot:external-scan fail` 한 줄을 남긴다(차단하지 않음).
6. 테스트는 스냅샷 함수를 주입해서 한다(Codex 샌드박스는 `/bin/ps` 를 막는다): companion task → 슬롯 external 기록·획득 실패; ChatGPT.app 조상 `codex exec` → 무시; fodh 감독 자손 → 무시; 외부 pid 소멸 → 다음 획득 성공 + `slot:stale`; externalGuard false → 검사 안 함.

## L1 (중간) — 프로젝트 폴더에서 `fodh` 한 단어로 하네스 열기

배경: 지금 실행 명령은 `env -u CLAUDECODE -u CLAUDE_CODE_ENTRYPOINT -u ANTHROPIC_API_KEY PI_SKIP_VERSION_CHECK=1 pi -e <pkg>/extensions/provider/index.ts -e …/orchestrator/index.ts -e …/watcher/index.ts --model claude-code/<모델>` 로 길어서 메인 세션이 tmux 로 대신 띄웠다. 사용자 요청(2026-09-26 23:0x): "프로젝트 폴더에서 `fodh` 치면 하네스 창이 열리면 좋겠다 — 매번 긴 명령을 칠 수 없다".

1. **인자 없는 `fodh`** 의 동작을 바꾼다(H1 의 "인자 없음 → 도움말" 을 대체):
   - `FODH_BRAIN=1` 이면 지금처럼 도움말만(절대 실행하지 않는다).
   - 하네스 루트를 찾으면(아래 2) 그 루트에서 하네스를 연다(아래 3).
   - 못 찾고 stdin·stdout 이 TTY 면 `이 폴더(<경로>)는 하네스 프로젝트가 아닙니다. 여기에 하네스를 설치하고 열까요? [y/N]` 을 묻고, y 면 L2 `fodh init` 을 실행한 뒤 연다. N·TTY 아님이면 도움말 + `fodh init` 안내, exit 0.
   - `fodh help`·`fodh --help`·`fodh -h` 는 계속 도움말. `fodh start [--model <별칭|id>] [--dry-run]` 은 같은 동작의 명시형으로 둔다(루트를 못 찾으면 묻지 않고 오류 exit 1).
2. 루트 찾기: cwd 에서 위로 올라가며 `.pi/harness.json` 이 있는 디렉터리. git 저장소 안이면 git 최상위에서 멈추고, 밖이면 HOME 에서 멈춘다. HOME 자체의 `.pi`(Pi 전역 설정 디렉터리)는 하네스 루트로 치지 않는다.
3. 여는 방법: 모델 = `--model` 또는 설정 `brain.model`, `brain.allowedModels` 검사는 provider 와 같은 함수. 환경에서 `CLAUDECODE`·`CLAUDE_CODE_ENTRYPOINT`·`ANTHROPIC_API_KEY` 를 지우고 `PI_SKIP_VERSION_CHECK=1`, `FODH_PACKAGE_ROOT=<패키지 루트>` 를 넣어 루트 cwd 에서 `pi -e …provider -e …orchestrator -e …watcher --model claude-code/<id>` 를 실행한다. **상주 프로세스를 늘리지 않는다** — 최종 프로세스는 pi 하나다. Node 는 exec(2) 가 없으므로 `bin/fodh` 를 POSIX sh 래퍼로 바꾸고(실제 CLI 는 `bin/fodh.mjs` 등으로 옮김), 인자 없음·`start` 일 때 Node 가 `--print` 로 계산한 결과(루트·argv·env 변경, 또는 오류/도움말/설치 질문 결과)를 받아 셸이 `cd <root> && exec env -u … pi …` 로 교체한다. 다른 인자는 지금처럼 Node CLI 로 넘긴다(`exec node …/fodh.mjs "$@"`). Node 가 pi 를 자식으로 들고 기다리는 구조 금지 — 신호 경로(터미널 닫기 SIGHUP, Ctrl+C, Ctrl+Z)가 지금 검증된 pi 직접 실행과 같아야 한다.
4. sh 래퍼는 심볼릭 링크로 PATH 에 걸려도 패키지 루트를 찾아야 한다(`~/.local/bin/fodh → ~/Desktop/fod-harness/bin/fodh`). 링크를 끝까지 따라가 실제 경로를 얻는다(macOS 기본 셸 도구만 사용). `pi` 가 PATH 에 없으면 설치 안내와 함께 exit 1. Node 경로는 `FODH_NODE` 또는 PATH 의 node(지금 훅과 같은 규칙).
5. 같은 루트에 살아 있는 하네스 잠금(`.pi/harness.lock`, 기존 pid 동일성 판정)이 있으면 열지 않고 `이미 이 프로젝트의 하네스가 실행 중입니다(pid N). 그 터미널 창을 쓰세요` 로 exit 1. 죽은 잠금은 지금처럼 새 실행이 인수한다.
6. 두뇌가 `fodh start`(dry-run 아님)를 부르면 거부한다. `--dry-run` 은 명령·env 변경을 JSON 으로 출력(두뇌 허용).
7. README 첫 실행 절을 다음 기준으로 고친다: 한 번만 `ln -s <패키지>/bin/fodh ~/.local/bin/fodh`(또는 PATH 에 있는 다른 디렉터리), 이후 프로젝트 폴더에서 `fodh`. 터미널 창을 닫으면 SIGHUP 으로 두뇌까지 회수되고 다음 `fodh` 가 이어간다. tmux 는 필요 없다.
8. 테스트: 하위 디렉터리에서 루트 찾기, git 최상위·HOME 에서 멈춤, HOME `.pi` 무시, allowlist 밖 모델 거부, `--print` 결과의 argv·env(지운 키·넣은 키)·cwd, 두뇌 env 에서 인자 없음 → 도움말, 살아 있는 잠금 거부, TTY 아님 + 루트 없음 → 도움말 exit 0, 래퍼를 심볼릭 링크로 부른 경우 패키지 루트 해석, 다른 인자 전달(`fodh state get` 등 기존 CLI 테스트가 래퍼 경유로도 통과). 실제 pi 실행은 하지 않는다(가짜 `pi` 를 PATH 앞에 둔 임시 디렉터리로 exec 경로와 전달 인자 1건 확인은 허용).

## L2 (중간) — `fodh init`: 새 폴더를 하네스 프로젝트로

배경: 파일럿 준비(backend `0fa3aec`)는 메인 세션이 `.pi/harness.json`·`.claude/settings.json`(템플릿 복사)·스킬 설치·CLAUDE.md 생성·`docs/판단대기.md`·`.git/info/exclude` 를 손으로 했다. L1 의 "설치하고 열까요?" 가 이것을 한 번에 해야 한다.

1. `fodh init [--brain opus|fable] [--dry-run]`(사용자 전용, 두뇌 거부). 대상 = cwd 의 git 최상위, git 저장소가 아니면 cwd 에서 `git init`(기본 브랜치 설정은 사용자 git 설정 그대로).
2. 만드는 것(이미 있으면 건드리지 않고 "있음" 으로 보고 — 다시 실행해도 안전):
   - `.pi/harness.json`: `{ "brain": { "model": <--brain 또는 패키지 기본> } }` 만. 나머지는 기본값.
   - `.claude/settings.json`: P2 새 템플릿. 파일이 이미 있으면 PreToolUse 에 하네스 훅이 있는지만 보고, 없으면 덮어쓰지 않고 합칠 방법을 안내(오류 아님, 결과에 `settingsNeedsHook: true`).
   - `fodh skills install`, `fodh claude-md generate` 와 같은 결과.

## H11 (높음) — 두뇌의 비밀 파일 읽기 차단 (`hooks/pretooluse.mjs`)

배경: web 루트에 운영 DB URL 이 든 `.env`, `.env.slack`, `neon_api.json` 이 있다(모두 gitignore). 지금 훅은 비밀값 **쓰기**만 막는다. 두뇌가 읽으면 값이 모델 컨텍스트·원장 요약에 들어간다. worktrees.root 가 `..` 라 backend 두뇌도 `../chemical/.env` 에 닿는다.
실측(2026-09-26 22:4x, `claude -p` haiku, 임시 git 저장소): Claude Code **Grep 도구는 숨김 파일을 검색하고 `.gitignore` 대상은 건너뛴다**(`.env` 무시됨, gitignore 밖 `.env.local`·`neon_api.json` 은 내용이 출력됨). Bash `grep -r` 은 gitignore 를 모른다. `rg` 는 기본으로 gitignore·숨김을 건너뛴다.

적용 범위: `FODH_BRAIN=1` 인 호출만. 사용자 세션은 바뀌지 않는다.

1. 설정 `secrets.readDeny`·`secrets.readAllow`(둘 다 승인 키, 두뇌 `config set` 거부 목록에 `secrets.*` 추가).
   - 기본 readDeny: `.env`, `.env.*`, `*.pem`, `*.p8`, `*.p12`, `*.key`, `*.jks`, `*.keystore`, `key.properties`, `~/.ssh/*`, `~/.aws/credentials`, `~/.netrc`, `~/.codex/auth.json`, `~/.pi/agent/auth.json`, `~/.claude/.credentials.json`, `~/.config/gh/hosts.yml`.
   - 기본 readAllow: `.env.example`, `.env.sample`, `.env.template`, `.env.*.example`, `~/.ssh/*.pub`, `~/.ssh/known_hosts`.
   - 항목 뜻: `/` 가 없으면 **어느 경로든 basename** 에 대한 글롭, `~/` 로 시작하면 HOME 기준 경로 글롭, 그 밖의 `/` 포함 상대 경로는 프로젝트 root 기준 경로 글롭. 설정 사용자가 더한 항목은 기본값에 합친다(기본값을 빼려면 `secrets.defaults: false` — 승인 키).
   - `worktrees.links` 가 readDeny 에 걸리면 설정 로드 오류.
2. 판정 함수 `secretPath(absPath)`: realpath(없으면 가장 가까운 조상 realpath + 나머지)로 정규화한 경로가 readDeny 에 맞고 readAllow 에 맞지 않으면 참. darwin 대소문자 규칙은 기존 경로 비교와 같게.
3. 파일 도구: `Read`(`file_path`)·`NotebookRead` 류·`Grep` 의 `path` 가 비밀 파일이면 거부. `Grep` 의 `glob` 인자가 readDeny basename 항목과 겹치면(예 `.env*`, `*.pem`, `neon_api.json`) 거부. 디렉터리 대상 `Grep` 은 허용한다(gitignore 를 따른다 — 3-1 doctor 로 보완). `Glob`(이름만) 허용.
   - 3-1. doctor: 프로젝트 root 아래(`.git`·`node_modules` 제외, 깊이 6, 항목 20,000개 상한)에서 readDeny 에 맞는데 `git check-ignore` 로 무시되지 않는 파일이 있으면 경고 `secretsNotIgnored: [상대경로…]`(값은 읽지 않는다). Grep 도구·`rg` 가 그 파일을 읽을 수 있다는 뜻이다.
4. Bash — 정적으로 확인되는 비밀 경로 언급:
   - 셸 파서(`shellCommands`, `sh -c` 중첩 포함)의 각 명령에서 피연산자·`--opt=값` 의 값·입력 리다이렉트(`<`, `<>`) 대상 단어를 cwd·`~`·`$HOME` 기준으로 풀어 `secretPath` 면 거부. 글롭 단어는 그 디렉터리 목록을 셸 규칙(점으로 시작하는 이름은 패턴이 점으로 시작할 때만)으로 맞춰 하나라도 비밀이면 거부.
   - 예외(메타데이터만 보는 명령): `ls`, `stat`, `test`, `[`, `[[`, `file`, `du`, `git check-ignore`, `git ls-files`, `git status`. `rm`·`mv` 는 기존 규칙(승인·보호)을 따르고 이 규칙에서 읽기로 보지 않는다. `cp`·`rsync`·`ditto`·`install`·`ln` 의 **원본**이 비밀이면 거부(복사 뒤 읽기 방지).
   - 동적 단어(`$VAR`, `$(…)`)는 정적 단서가 있을 때만 판정한다: 단어의 정적 부분 마지막 성분이 readDeny basename 항목에 맞으면(`$ROOT/.env`, `"${W}/neon_api.json"`) 거부. 단서가 없으면 허용.
   - 인라인 코드(`node -e/--eval/-p`, `python* -c`, `perl -e`, `ruby -e`, `deno eval`, `bun -e`) 문자열에 readDeny basename 리터럴(`.env`, `.env.<이름>`, `neon_api.json` 등, readAllow 제외)이 있으면 거부. `node --env-file=<비밀>`, `dotenv -e <비밀>`, `source`/`.` `<비밀>` 은 위 피연산자 규칙으로 걸린다.
5. Bash — 재귀 검색이 비밀 파일을 훑는 경우:
   - 대상 명령: `grep`/`egrep`/`fgrep` 에 `-r`·`-R`·`--recursive`·`--dereference-recursive`·`-d recurse`; `rg` 에 `-u`/`-uu`/`-uuu`·`--hidden`·`--no-ignore*`·`--unrestricted`·`-.`; `ag` 에 `-u`·`--unrestricted`·`--hidden`·`-U`; `find … -exec|-execdir|-ok <읽기 명령>`(읽기 명령 = cat, head, tail, less, more, grep 류, sed, awk, strings, xxd, od, hexdump, base64, jq).
   - 검색 디렉터리(피연산자, 없으면 cwd)를 제한 탐색(심볼릭 링크 디렉터리 따라가지 않음, `.git`·`node_modules` 제외 — `rg`/`ag` 는 제외 목록을 적용하지 않고 gitignore 무시 여부만 본다; 깊이 8; 항목 20,000개 상한)해서 비밀 파일이 하나라도 있으면 거부. 상한을 넘으면 비밀이 있는 것으로 본다(거부). 단, 찾은 비밀 파일이 모두 명령의 `--exclude=GLOB`/`--exclude GLOB`(basename 글롭)·`--exclude-dir`·`--include`(어느 include 에도 안 맞으면 제외)·`rg -g '!GLOB'`/`--glob '!GLOB'`/`--iglob '!GLOB'` 로 빠지면 허용.
   - 거부 문구: `하네스 가드[경계]: 비밀 파일(<root 기준 상대경로 1개>)이 있는 디렉터리를 재귀로 읽습니다. rg(기본으로 .gitignore·숨김 제외) 또는 --exclude='.env*' 를 쓰세요`.
6. 거부 종류는 `boundary`, 문구 기본형 `하네스 가드[경계]: 비밀 파일은 두뇌가 읽을 수 없습니다: <basename>. 값이 필요하면 판단으로 사용자에게 요청하세요`. 문구·원장에 경로의 basename 이상, 값은 절대 넣지 않는다.

## H12 (중간) — 워크트리 준비 명령 `worktrees.setup`

배경: app(Flutter)은 `.dart_tool` 을 링크로 공유할 수 없어 워크트리마다 `flutter pub get --enforce-lockfile --offline` 이 필요하다.

1. 설정 `worktrees.setup: string[]`(기본 `[]`, 승인 키), `worktrees.setupTimeoutMinutes`(기본 10, 1~60).
2. `createWorktree` 가 새로 만들었을 때(링크 뒤), 그리고 이미 등록된 워크트리의 기록에 `setupOk: true` 가 없을 때 명령을 순서대로 실행한다. 각 명령은 `/bin/sh -c <명령>`, cwd = 워크트리, env = 현재 env + `FODH_WORKTREE=<경로>` + `FODH_TASK=<T번호>`, 자기 프로세스 그룹. 시간 초과면 그룹을 죽이고 실패. stdout·stderr 는 redact 해서 `.pi/worktree-setup/<T번호>-<runId>.log` 에 남긴다.
3. 원장 `worktree:setup` pre/ok/fail(evidence: 명령 순번, exitCode, durationMs, 로그 경로). 전부 성공하면 state.worktrees 기록에 `setupOk: true, setupAt`. 실패하면 워크트리는 등록된 채 두고 `worktree 준비 실패: <명령 순번> exit <code> (로그 <경로>)` 로 throw — 다음 `worktree create`·위임 시작이 준비만 다시 한다.
4. `lastPaused === 'memory'` 또는 `paused(memory)` 면 준비 명령을 실행하지 않고 거부(위임 시작과 같은 문구 계열).
5. `fodh worktree list` 에 `setupOk` 표시. README 설정 표에 두 키와 app 예시.
6. 테스트: setup 없음 → 기존 동작 동일; 성공 → setupOk + 로그 + 원장; 실패 → 등록 유지 + 오류 + 재호출 시 준비만 재실행; 시간 초과 → 그룹 종료(자손 포함); 메모리 중단 중 거부; 승인 키 검사.
