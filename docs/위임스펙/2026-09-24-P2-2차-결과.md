## 설계 선택·의도적 이탈·한계

- **M1 기존 1차 결과 정정**: 모듈 전역 Set이 실제 Pi 확장 간 공유된다는 보장은 폐기했다. 새 `.pi/harness-resume.lock` 파일 잠금으로 카운터/원복을 직렬화하고, 최종 idle 검사와 실제 sendMessage는 await 없는 구간에 둔다. 준비/전송 실패는 기존 경고와 원복 동작을 유지한다.
- **H1 안정화 기준**: externalPending이 이미 있으면 유지한다. 흡수할 원문의 해시를 워처가 관측했다면 그 since를 at으로 보존하고, 아직 관측하지 않았다면 저장 시각을 쓴다. 추가적인 사용자 편집이 있을 때 이벤트에는 실제 최신 디스크 hashAfter를 넣어 관측 사실을 유지한다. 정상 흡수 경로에서는 이 값이 expectedHash와 같다.
- **M4 기록 순서**: 판단 문서와 워처 메타데이터를 같은 워처 잠금으로 보호한다. 문서 rename 직전 원문을 검사하고 문서 저장 성공 뒤 expectedHash를 저장한다. 충돌이 나면 기대 해시도 갱신하지 않는다. lock을 따르지 않는 편집기와 파일 시스템의 읽기→rename 사이를 완전한 CAS로 만들지는 못하므로, 요청한 낙관적 충돌 검사와 편집기 자동 새로고침 안내를 함께 적용했다.
- **M4/M5 추가 보호**: 자동 적용에는 안정화 판단 때 읽은 항목 원문을 넘긴다. 그 뒤 번호 답이 자유 서술로 바뀌면 그대로 적용하지 않고 충돌로 재결정 경로에 돌린다. 수동 `/judged`는 기존 즉시 적용 경로다.
- **M2 결정 추적**: decided 및 실패 횟수는 디스크에 남긴다. 성공한 다른 항목은 예외 항목 때문에 되풀이하지 않도록 확장은 항목별로 결정한다. 자유 서술 대기는 decided/applied로 닫지 않는다. 같은 ID 3회 실패는 decided에 넣고 fail 원장을 남기며, 미적용 인박스 자체는 다음 두뇌 턴의 전달 대상으로 보존한다.
- **M5 타이머**: root별 지연 타이머 1개를 unref로 관리하고, 재관측/세션 종료 때 교체·해제한다. 확장에서 재결정 타이머가 만료되면 tick과 영속 미결정 조회를 다시 거친다. 문서 전체 해시 기준이므로 다른 항목의 적용/편집도 자유 서술 안정화를 더 늦출 수 있다. 조기 적용을 막는 보수적 선택이다.
- **L3 메모리 범위**: Pi의 분리된 모듈 캐시를 고려해 Symbol.for/globalThis로 같은 프로세스의 tick 시각을 공유한다. 별도 CLI 프로세스에는 메모리 값이 없으므로 마지막 영속 시각을 보여 준다. 다른 워처 메타데이터는 계속 디스크에서 읽는다.
- **테스트 경로 범위**: 이번에 수정한 P2 관련 테스트의 mkdtemp를 os.tmpdir로 옮겼다. 실행만 한 기존 P1/revision 테스트의 임시 경로까지 일괄 수정하지 않았다.

위 선택 외 필수 요구의 의도적 생략은 없다. git 명령과 실제 claude/cswap/codex/pi를 실행하지 않았다. 가짜 claude/switch 및 Node/CLI fixture만 사용했다. 실제 Esc 중단 후 방치·TUI 종료 경합·편집기 자동 저장을 포함한 실기는 Fable이 확인해야 한다.
