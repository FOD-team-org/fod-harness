## 고른 방식과 현재 코드에 맞춘 해석

- **F5 ②: EMPTY 반환.** CLI도 `{ outcome: 'EMPTY', reason: '백로그가 비어 있습니다' }`를 반환한다(exit 0). 오케스트레이터는 EMPTY 알림 뒤 새 턴을 보내지 않는다. 스펙은 오케스트레이터 호출부 두 곳을 언급하지만 현재 소스에는 `extensions/orchestrator/index.ts` 1곳과 `src/cli/index.ts` 1곳이 있다. 두 경로 모두 확인했다. 기존 빈 백로그 PLANNING 분기는 유지했다.
- **F6 증거 소스: `.pi/codex/*/meta.json`.** `codex-record.ts`의 기존 `readMeta`를 재사용한다. `kind === 'review'`, `status === 'ok'`, `startedAt >= REVIEW.enteredAt`을 요구하고 task 검수는 taskId도 일치해야 한다. REVIEW 진입 시각이 없거나 유효하지 않으면 허용하지 않는다. 원장 스캔은 사용하지 않는다.
- **F1 적용 영향:** 판단 적용은 현재 판단 항목의 선택지 텍스트를 해석하므로 번호 변경 후에도 추천 텍스트가 정확히 applied에 반영된다. 은행 원본 및 이미 생성된 판단 항목은 재정렬하지 않는다.
- **템플릿 구조:** 스펙의 “4절”과 달리 기존 템플릿·구조 검사는 `지금 할 일 / 산출물 / 끝내는 조건 / 다음 fodh 명령 / 금지`의 5절이다. PROJECT_READY도 이 구조와 25줄 제한을 따랐다.
- **설정 알림:** 실제 사용 중인 최상위 `maxAutoTurns`는 알려진 키로 취급했다. 알림이 설정을 다시 읽으므로 dedupe 표식을 먼저 저장하고, notify는 잠금을 잡기 전에 설정을 읽도록 조정했다.

### N3 reviewSince 처리

- 새 REVIEW 진입 시 상태 저장 시각으로 reviewSince를 설정한다. enteredAt은 기존처럼 상태·task 변경 시 갱신한다.
- REVIEW에서 WAIT_JUDGMENT·paused·recovering으로 일시 중단하면 reviewSince를 지우고 기존 값을 별도 resumeReviewSince에 보관한다. PICK·WAIT_RETRY·WAIT_RESOURCE를 거치는 동안 이 복귀용 값을 유지한다.
- WAIT_JUDGMENT→REVIEW 또는 검증된 options.resume 경로에서 보관한 시각을 reviewSince로 복원하고 resumeReviewSince는 지운다. 따라서 중단 전에 시작된 유효한 review meta를 그대로 사용할 수 있다.
- MERGE·PROJECT_READY·FIX 등으로 REVIEW를 끝내면 검수 시각을 제거한다. VERIFY 등에서 새로 REVIEW에 들어가면 새 시각을 사용하므로 이전 검수 meta로 통과하지 못한다.
- 프로젝트 판단 복귀와 task paused→PICK→resume REVIEW를 각각 검증했고, 후속 새 REVIEW가 오래된 증거를 거부하는 것도 확인했다.
