# J1 판단대기 구조화 — 1차 구현 결과

기준: [2026-09-26-J1-판단대기-구조화.md](2026-09-26-J1-판단대기-구조화.md). 관련 23개 테스트 파일의 최종 결과 합계 **1,768/1,768 통과**, `npm run typecheck` 통과. 전체 테스트는 실행하지 않았다.

## 구현

- 모든 판단 저장은 `save` 안의 `renderDerived(text, context)`를 거친다. 한눈에 표·최근 결정, 여러 줄 선택지, 머리말, 자세히 링크를 지원하고 반환 item은 저장된 문서에서 다시 파싱한다. 읽기만 할 때 판단 파일을 다시 쓰지 않는다.
- 완료는 판단 파일 잠금 안에서 월 기록 잠금/atomicWrite → 판단 파일 CAS 순서다. 질문·답 원문과 결정일·해석·반영을 기록하고 재질문 사슬 각각을 보존한다. 월은 KST 기준이다.
- `finish(pending)`은 기록이 있어도 열린 항목이 남아 있으면 제거와 최근 결정 저장을 먼저 마친다. 장애 주입 후 재적용에서 기록 1블록·task notes 1회·상태 전이 1회·열린 항목 제거를 검증했다. 월 경계를 넘어 재시도해도 기존 월 블록을 재사용한다.
- 저장 CAS가 실제 사용자 편집을 발견한 경우 이번 시도의 아카이브 추가만 되돌려 기존 P2의 최신 답 재분류 동작을 유지한다. 중단/일반 쓰기 장애로 남은 아카이브는 적용 저널 복구에 사용한다.
- 새 번호는 판단 파일 전체·판단기록의 모든 `.md`·`.pi/harness-judgment-seq.json`의 최댓값으로 정한다. 등록 저장 후 카운터를 올리며 migrate도 기존 번호 최댓값을 보존한다.
- CLI에 `judgment migrate [--dry-run]`, `judgment add --detail`, `judgment read --all`을 연결했다. 기본 read는 최근 기록과 completedTotal을 반환한다. 내부 read는 옛 표와 아카이브 전체를 반환한다.
- migrate는 질문 해시·답 줄 동일성을 확인한 뒤 쓴다. 옛 표·자유 블록·상태 이력을 보존하고 재실행은 무쓰기다. dry-run은 설정 경고를 포함한 영속 쓰기가 없으며 판단 파일·아카이브·워처 메타데이터·카운터의 변경 예정 경로를 보고한다.
- doctor의 `judgment:legacy-format`은 경고이며 실패가 아니다. 테스트는 `runTurn`을 mock하여 실제 두뇌를 실행하지 않았다.
- 훅에 기본/사용자 지정 판단기록 보호를 추가했다. Write/Edit·리다이렉트·복사·glob 삭제·압축 해제·인터프리터·sed 쓰기를 두뇌에만 막는다. 읽기와 사용자 세션은 기존 판정을 유지한다. X1 동적 경로 단서와 HOME 밖/아래 두 배치를 검증했다.
- 인터뷰 완료 조회가 옛 파일 내부 표만 읽던 경로에 `readArchive`를 더했다. 인터뷰 답 해석 규칙은 바꾸지 않았다.

## 구현 판단과 남은 한계

- 실제 legacy 픽스처 A19~A22 제목은 `(rev N)`이 아니라 `(2026-09-25)`였다. §4와 §7-12의 실제 픽스처 이전을 충족하도록 이 날짜 제목을 rev 1로 읽고 migrate에서 정규화한다. 질문 hash·답 줄·이후 read의 rev 1 유지 검증을 포함했다. 픽스처 자체는 수정하지 않았다.
- 머리말의 예시 번호는 `A23 1` 대신 `A<n> 1`로 썼다. §3은 파일 **전체**의 `A\d+`를 번호 계산에 포함하고 §7-6은 A1~A3 다음 A4를 요구하므로, 안내 예시 때문에 번호가 A24로 뛰지 않도록 했다.
- migrate 자체 쓰기는 기대 해시를 갱신하고 이전 원문을 새 사용자 편집으로 예약하지 않는다. 기존 externalPending은 유지한다. 워처의 안정화 시간·답 분류·감시 대상 로직은 수정하지 않았다.
- 아카이브를 읽고 번호를 계산할 때 기록 파일을 스캔한다. 별도 색인이나 보관량 성능 최적화는 이번 구현에 넣지 않았다.
- 실제 Pi/Claude/Codex/cswap 실행과 운영 판단 파일 migrate는 **미실행**이다. 자동 테스트의 임시 프로젝트·mock으로만 검증했다. 사용 중인 판단 파일을 실제로 이전하는 작업은 이번 코드 구현과 분리되어 있다.

## 범위 확인

- 작업 저장소에서 git 명령을 실행하지 않았다. 테스트 내부의 임시 저장소 작업만 기존 테스트에 따라 실행했다.
- 전체 테스트를 실행하지 않았다. 관련 파일 지정 테스트와 typecheck만 실행했다.
- `docs/설계/` 및 `test/fixtures/judgment/fod-harness-legacy.md`는 작업 전후 SHA-256 대조로 바이트 동일함을 확인했다.
- `src/core/watcher.ts`는 수정하지 않았다. A14-b 기존 테스트 파일도 수정하지 않았다.
- 훅의 위험 명령 문자열은 테스트 헬퍼가 JSON으로 `hooks/pretooluse.sh`에 넣었다. 해당 입력 명령을 실제 셸로 실행하지 않았다.
