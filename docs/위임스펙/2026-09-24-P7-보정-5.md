## H1 — 검수·병합 커밋 게이트를 실제 작업으로 잠근다 (`src/core/worktree.ts` `validateTaskCommit`)

1. 워크트리 등록 시(`createWorktree`) `base`(만든 시점의 base 커밋 sha)와 `branch` 를 `state.worktrees[]` 항목에 기록한다(기존 항목에 없으면 `git merge-base <branch> <main>` 로 보완).
2. `--review-commit <sha>`(task, git): sha 가 **워크트리 HEAD 와 같아야** 하고(`git rev-parse HEAD`), 워크트리 브랜치가 등록 branch 여야 하며, **`base..HEAD` 커밋 수 ≥ 1** 이어야 한다(착수 전 HEAD 거부). `git status --porcelain` 비어 있음 유지.
3. `--merge-commit <sha>`(git): sha 가 **루트 HEAD 의 조상(또는 HEAD 자신)** 이고(`git merge-base --is-ancestor <sha> HEAD` in root), `review.commit` 이 sha 의 조상이며 **`review.commit !== sha` 일 것**(단, fast-forward 병합으로 루트 HEAD == review.commit 이 될 수 있으니 이 경우는 `sha === review.commit && 루트 HEAD === sha` 를 허용). 즉 "실제 병합 뒤의 루트 HEAD 를 적었는가" 를 검사한다.
4. 테스트(`test/p7-commit.test.ts`): git mock 을 제거하고 임시 저장소를 `git init` → base 커밋 → `createWorktree` → (a) 커밋 없이 base HEAD 로 review 거부 (b) `worktree commit` 뒤 HEAD 허용 (c) merge: review sha 자체(병합 전) 거부, 루트에서 실제 `git merge` 뒤 HEAD 허용, fast-forward 허용.

## H2 — verify 증거에 cwd 를 기록하고 게이트에서 대조 (`src/core/verify.ts`, `src/core/state.ts`)

- `state.verify` 와 `result.json` 에 `cwd`(realpath) 를 넣는다. VERIFY→REVIEW 게이트: task 에 등록 워크트리가 있으면 `verify.cwd` 가 그 워크트리(realpath) 와 같아야 하고, 없으면(비-git 루트 폴백) 루트와 같아야 한다. 다르면 거부 `검증 증거가 다른 경로에서 만들어졌습니다`.
- `fodh verify run` 은 `--cwd` 를 생략하면 현재 task 의 등록 워크트리를 기본 cwd 로 쓴다(없으면 루트). VERIFY 템플릿 문구 갱신.
- 테스트: 루트 cwd 증거로 워크트리 task 의 REVIEW 거부, 워크트리 cwd 허용.

## M3 — `awaitingSlot` 잔존으로 자동 재개가 막히지 않게

- `awaitingSlot` 을 지우는 지점을 통일한다: (a) 슬롯 획득 성공, (b) 상태 전이(`transitionState`) 가 일어날 때마다(어떤 전이든), (c) `autoResume` 이 `skipped:'slot'` 으로 건너뛰기 전에 `slotOwnerAlive` 를 직접 확인해 소유자가 없으면 표지를 지우고 재개한다. 또 `paused(slot)` 이 아닌 상태에서 `awaitingSlot` 만 남아 있으면(전이·오류로 어긋난 경우) 워처가 표지를 지운다.
- L2 함께: 워처가 `slotOwnerAlive` 'unknown' 을 연속 10회(10분) 보면 알림 1회(`slot:unknown-owner`) + 판단대기 항목 없이 계속 대기(사용자가 `fodh slots status` 로 확인). 알림은 60초 dedupe 로 반복되지 않게.
- 테스트: WAIT_JUDGMENT 전이 뒤 `awaitingSlot` 없음; 소유자 사망 시 `autoResume` 진행; unknown 10회 알림 1회.

## L4 — `fodh worktree commit` 세부

- 워크트리의 현재 브랜치가 등록 branch 가 아니면 거부.
- untracked 파일 비밀값 검사는 1 MB 이하 텍스트 파일만 읽고, 그 이상·바이너리는 이름만 원장에 남긴다.
- 비밀값 검사는 diff 의 추가 줄(`+`)만 본다(문맥 줄 제외).
- `git add -A` 대신 `git add -A -- . ':!.pi' ':!.pi/**'` 로 `.pi/` 를 제외한다.
- 변경이 없으면 git 오류 대신 `{ ok: false, error: '커밋할 변경이 없습니다' }` 를 돌려준다.
- 테스트: 각 경우 1건(실제 git 저장소).
