**N1 소유 CLI 가 죽은 verify 자식이 영구 보호됨** — `src/core/verify.ts`, `src/core/cleanup.ts protectedProcessGroups`, `src/core/slots.ts`
- verify 기록에 `ownerPid`(= `process.pid`)·`ownerStartedAt`(`processStartedAt(process.pid)` 또는 `spawn:`) 을 저장한다(`ProcRecord` 선택 필드).
- `protectedProcessGroups` 의 verify 보호 조건: 자식 신원 owned **그리고** 소유 CLI 신원(`processIdentity(ownerPid, ownerStartedAt)`) 이 owned 일 때만. 소유 CLI 가 죽었거나 `ownerPid` 가 없으면 보호하지 않고 일반 회수 대상(신원 owned 면 회수, 아니면 unverified).
- heavy 슬롯 생존 판정도 슬롯 owner pid(= CLI) 기준으로만 본다(이미 `pid`·`startedAt` 이 CLI 것이면 그대로, 자식 생존으로 대체 판정하는 코드가 있으면 제거).
- 테스트: (a) 소유 pid 죽음(`processIdentity` mock: owner dead, child owned) + child 살아 있음 → protected 아님, 회수됨; (b) 둘 다 owned → protected; (c) heavy 슬롯 owner 죽음 → `slotsStatus alive.heavy=false`.

**N2 codex 기록의 stale 선처리가 도구 그룹 회수를 건너뜀** — `src/core/cleanup.ts processes()`, `src/core/reclaim.ts cleanupReport`
- `isStaleProcess` 선처리는 `kind !== 'codex'` 이거나 `meta?.toolGroups` 가 비어 있을 때만 적용한다.
- codex 기록은 `reclaimCodexOwner` 를 먼저 탄다: `gone` → 검증된 도구 그룹 회수 후 `retireStaleProcess`(stale 보고); `foreign` → 도구 그룹을 witness 로 검증해 회수한 뒤 retire, 검증 안 된 그룹(`skippedGroups`)이 있으면 `reportToolResidual` 로 보고하고 `residual` 로 남긴다(stale 처리 안 함).
- `cleanupReport` 도 같은 순서(코드 공유).
- 테스트: 죽은 codex 기록 + 살아 있는 owned 도구 그룹(mock) → 도구 그룹 회수 호출 후 stale; foreign codex 기록 + 검증 안 되는 도구 그룹 → residual 보고, retire 안 함; toolGroups 없는 죽은 codex 기록 → 기존 stale 경로.

**N3 critical 래치가 표본 하나로 풀림** — `src/core/memory.ts judgeMemory`
- `watch.critical` 은 `memory-recovered` 를 낼 때만 `false` 로 내린다(임계 아래 표본은 `overSince` 만 지운다). 임계 재초과 시 `overSince` 는 새로 시작하되 `critical` 은 유지(새 `memory-critical` 중복 발행 금지).
- 테스트: critical → 중립 표본 1개 → `critical` 유지 + `startCodex` 거부 유지; 5분 회복 → recovered 이벤트 + `critical:false`.
