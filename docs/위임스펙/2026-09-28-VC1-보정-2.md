## H1 [높음] 두뇌는 검증 명령을 줄일 수 없다

- 검수 재현: 훅은 두뇌가 등록 워크트리 안에서 Write·`mv` 하는 것을 허용한다(`hook.test.ts:202`).
  1. 두뇌가 워크트리 `package.json` 에서 `test` 스크립트를 지운다.
  2. `--cwd` 없이 `fodh verify detect --apply` 를 친다(표지 hash 일치라 허용됨).
  3. `package.json` 을 되돌린다.
  4. 설정이 `[typecheck,lint,test]` → `[typecheck,lint]` 로 줄고, `verify run` 이 `ok:true, clean:true` 로 끝난다. 검증 시점의 트리는 원래와 같아서 검수 diff 에 흔적이 없다.
  - 빈 설정·자리표시의 첫 자동 채움도 같은 방식으로 흔들 수 있다.
- 결정: 두 겹으로 막는다.
  1. **깨끗한 트리에서만 자동 기록(사용자 `--approve` 제외).**
     - `runVerify` 의 자동 채움과 `detect --apply` 는 감지 기준 경로가 git 작업 트리이면 먼저 clean 을 확인한다. 기준은 `git status --porcelain` 이 비어 있는지다(추적 변경·미추적 파일 포함, .gitignore 존중). 지금 `gitSnapshot` 의 `clean` 과 같은 기준을 쓴다.
     - clean 이 아니면 설정을 쓰지 않는다.
       - `runVerify`: `finish({ ok: false, error: autoVerifyDirtyError })`
       - `detect --apply`: 같은 문구로 throw
     - 문구: `검증 명령 자동 설정은 커밋된 깨끗한 작업 트리에서만 합니다 — 먼저 fodh worktree commit 으로 커밋하세요`.
     - 비-git 기준 경로는 이 검사를 건너뛴다.
     - 사용자의 `--approve`(assertNotBrain 통과)는 이 검사를 건너뛴다. `fodh init`·`workspace init/add`(사용자 전용)도 검사하지 않는다.
  2. **단조 규칙(`writeAutoVerify`).**
     - `--approve` 가 없고 현재 설정이 "빈 설정"도 "자리표시"도 아니면, 감지 결과가 현재 명령을 하나라도 빠뜨릴 때 기록하지 않고 throw 한다.
       - 자리표시 = 표지 있음 + hash 일치 + commands 가 정확히 `['git diff --check']`.
     - 비교는 문자열 그대로다.
       - commands: `current.commands − detected.commands`
       - heavy: 보존하지 않는 경우(`preserveHeavy` false)만 `current.heavy − detected.heavy`
     - 문구: `감지 결과가 현재 검증 명령을 줄입니다(빠짐: <redact 한 명령들 · 로 연결>) — 줄이려면 사용자가 터미널에서 fodh verify detect --apply --approve 를 실행해야 합니다`.
     - 더하기(새 스택·새 스크립트)와 순서 변경은 허용한다.
- 템플릿 `VERIFY.md` 자동 설정 줄에 다음을 한 줄로 더한다.
  - `깨끗한 작업 트리` 오류면 커밋 뒤 다시 실행한다.
  - `현재 검증 명령을 줄입니다` 오류면 `fodh judgment add` 로 사용자 판단을 요청한다(추천: 사용자가 `--approve` 로 반영).
- 테스트(검수 probe 재현을 그대로 회귀로)
  - 표지 있는 `[typecheck,lint,test]` 설정 + 두뇌 환경에서 `test` 를 지운 미커밋 상태로 `detect --apply` → dirty 오류, 설정 바이트 그대로.
  - 같은 삭제를 커밋한 뒤 `detect --apply` → 단조 오류(빠짐: `npm test`), 설정 그대로.
  - 사용자 `--approve` → 줄어든 설정이 기록된다.
  - `lint` 를 새로 더한 커밋 뒤 두뇌 `--apply` → 허용(늘어남).
  - 빈 설정 첫 자동 채움에서 미추적 파일이 있으면 → `ok:false`, dirty 오류, 설정 그대로, 명령 실행 없음.
  - 워크스페이스 자리표시 → 감지 결과로 교체는 허용(단조 예외).
  - 비-git 기준 경로의 자동 채움은 지금처럼 동작한다.

## H2 [중간] 읽을 수 없는 폴더는 감지 실패로

- 보정 1 G6 이 `EACCES`·`EPERM` 을 `[]` 로 삼키면서 새 구멍이 생겼다.
  - 훅은 두뇌의 `chmod` 를 쓰기로 보지 않는다. `chmod 000 app/test` 를 하면 `hasTests` 가 false 가 되어 `flutter test` 가 빠진다. `chmod 000 app` 이면 스택이 통째로 빠진다.
  - 디렉터리 권한은 `git status` 에 나오지 않아 H1 의 clean 검사로도 못 막는다.
- 결정
  - 감지 중 `readdir` 이 `EACCES`·`EPERM` 이면(`visit`·`hasTests` 모두) 감지를 **실패**로 끝낸다. 대상은 건너뛸 이름(점·skip 목록·prefix·skipDirs)이 아닌 폴더다.
    - `detectVerify` 는 전용 오류(예: `DetectUnreadableError`, 기준 경로 기준 상대 경로 포함)를 던진다.
    - `ENOENT`·`ENOTDIR` 은 지금처럼 `[]`(경합)로 둔다.
  - 호출자별 처리
    - `runVerify` 자동 채움: `finish({ ok: false, error: '검증 명령 감지 실패: 읽을 수 없는 폴더 <상대경로> — 권한을 확인하거나 사용자가 verify.commands 를 설정해야 합니다' })`. 설정은 쓰지 않는다.
    - `detect`(미리보기·`--apply`): 같은 문구로 throw.
    - `fodh init`·`workspace init/add`(사용자 전용): 미감지로 처리한다(단일 레포는 verify 를 쓰지 않음, 워크스페이스는 표지 있는 자리표시). 결과의 경고 목록에 같은 문구를 넣는다. 설치는 실패하지 않는다.
  - 보정 1 G6 의 "chmod 000 폴더가 있어도 다른 스택 감지" 테스트를 위 동작으로 바꾼다.
    - `runVerify`·`detect` 는 실패한다.
    - init·workspace add 는 경고와 함께 미감지로 설치된다.
    - 테스트 끝에 권한을 되돌리는 것은 유지한다.
  - `chmod 000 app/test` 회귀: `detect --apply` 가 실패하고 설정이 그대로다.
  - VERIFY.md 의 "감지 실패일 때만 판단" 에 이 오류도 포함되는지 확인한다(문구가 `자동 감지된 스택이 없습니다` 만 가리키면 `감지 실패` 도 가리키게 고친다).

## H3 [낮음] 워크스페이스의 docs.root 기준

- `verifySkipDirs(base, docsRoot)` 는 docs.root 를 감지 기준(멤버·워크트리) 기준으로 푼다.
  - 워크스페이스의 docs.root 는 워크스페이스 루트의 문서 폴더다. 그래서 멤버 자신의 `docs/` 스택(예: 문서 사이트 package.json)이 잘못 빠진다.
- 결정
  - 단일 레포: 지금처럼 `docs.root` 를 기준 경로 기준 상대 경로로 푼다. 워크트리는 같은 레포 체크아웃이라 같은 상대 위치가 문서 폴더다.
  - 워크스페이스: `relative(base, resolve(root, docs.root))` 가 기준 경로 **안**일 때만 건너뛴다. 보통은 `[]` 가 된다.
  - `verifySkipDirs` 에 모드(또는 root)를 넘기는 방식은 자유다.
- 테스트: 워크스페이스 멤버에 `docs/package.json`(test 스크립트) → 감지에 포함된다. 단일 레포 `docs/x/pubspec.yaml` 제외는 그대로다.
