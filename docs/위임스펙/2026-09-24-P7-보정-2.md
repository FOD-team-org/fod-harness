## N1 (중간) — 사용자 전용 전이 판정을 `assertNotBrain` 으로

`src/cli/index.ts:106` 이 `FODH_BRAIN` 만 본다(두뇌가 `env -u FODH_BRAIN` 스크립트로 우회 가능).

1. 사용자 전용 전이 집합을 `src/core/state.ts` 에 상수로 둔다: `PROJECT_READY→PLANNING`, `DONE_ALL→PLANNING`, `DONE_ALL→IDLE`, 그리고 `--system` 옵션 사용(N9). 판정은 CLI 에서 `assertNotBrain(root, '<전이 설명>')` 호출로 한다(오케스트레이터 `/develop-start` 는 사용자 세션이므로 통과, 테스트에서는 `FODH_BRAIN` 만으로 두뇌 흉내 가능해야 한다 — `assertNotBrain` 의 기존 동작 유지).
2. 오류 문구는 기존 "PROJECT_READY 는 사용자가 /develop-start 로 시작합니다" 를 유지하고, DONE_ALL 은 "DONE_ALL 은 사용자가 /develop-start 또는 IDLE 전이로 이어갑니다".
3. **N9**: `fodh state transition --system` 은 두뇌 거부(`assertNotBrain`). 오케스트레이터·워처·프로바이더 내부 호출(`transitionState(..., { system: true })`)은 영향 없음.
4. 테스트: `FODH_BRAIN=1` 거부, 잠금 소유자의 자손 프로세스 거부(기존 brain-guard 테스트 방식 재사용), 사용자 허용; `--system` 두뇌 거부.

## N2 (중간) — F6 task 가드의 면제 조건

`src/core/state.ts:176` 이 `task.delegate === 'claude'` 일 때만 검수 증거를 요구한다(두뇌가 `--delegate` 를 안 쓰거나 `codex` 로 적으면 가드 소실).

- REVIEW→MERGE(task) 는 다음 둘 중 하나가 있어야 한다: (a) 해당 taskId 의 `kind: 'review'` ok meta(REVIEW 진입 이후 시작) 또는 (b) 해당 taskId 의 `kind: 'task'` ok meta(= Codex 가 구현했고 Claude Agent 가 검수한 경로, 증거 불가 → 면제). `task.delegate` 값은 보지 않는다. 둘 다 없으면 거부("교차검수 증거가 없습니다").
- 테스트: delegate 미설정 + task meta 없음 + review meta 없음 → 거부; task ok meta 만 → 허용; review ok meta 만 → 허용.

## N3 (낮음) — REVIEW 재진입 시 검수 증거 기준 시각

WAIT_JUDGMENT·paused 에서 REVIEW 로 **복귀**(resume 경로)할 때 `enteredAt` 이 초기화돼 앞선 검수가 무효가 된다.

- 상태에 `reviewSince` 를 둔다: REVIEW 로 **새로 진입**(ARCH·IMPLEMENT·VERIFY·FIX 등 비-복귀 경로)할 때 설정, 복귀 경로(`options.resume` 또는 WAIT_JUDGMENT→REVIEW)에서는 유지. F6 가드는 `reviewSince` 를 기준으로 비교한다. REVIEW 를 떠나면 지운다.
- 테스트: REVIEW 진입 → review ok meta → WAIT_JUDGMENT → REVIEW 복귀 → PROJECT_READY 허용.

## F8 (high) — git 프로젝트에서 워크트리 없는 구현 위임 금지

`src/core/codex.ts:62-63` 가 task 에 워크트리가 없으면 루트로 폴백한다(원장 `fallback: 'root'`). 시나리오 B 에서 두뇌가 `fodh worktree create` 를 건너뛰어 Codex 가 루트에 소스를 썼다.

1. `fodh codex task`(kind `task`): 프로젝트 루트에 `.git` 이 있으면(파일이든 폴더든) task 의 등록 워크트리(`task.worktree` + `state.worktrees`)가 없을 때 거부: `IMPLEMENT 는 워크트리가 필요합니다: fodh worktree create <task>`. `--cwd` 가 주어지면 그 워크트리 안이어야 한다(기존 검사 유지). `.git` 이 없으면 기존 루트 폴백 유지(evidence `fallback: 'root'`).
2. `templates/prompts/IMPLEMENT.md` 3단계: "git 프로젝트면 `fodh worktree create {{taskId}}` 가 **필수**다(없으면 `codex task` 가 거부된다). 비-git 만 루트 폴백."
3. 테스트: git 토이 + 워크트리 없음 → 거부; 워크트리 등록 → 허용; 비-git → 폴백 허용.
