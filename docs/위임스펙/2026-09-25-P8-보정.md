### 6. (높음) K3 SIGINT 처리기가 signal-exit 리스너 때문에 항상 물러선다 (`src/provider/shutdown.ts:28`)

근거: `docs/조사/2026-09-25-Pi-0.87.1-호환성.md` §5, Fable 이 0.73.1 에서 확인.
- Pi `dist/core/settings-manager.js`·`auth-storage.js` 가 모듈 로드 때 `proper-lockfile` 을 import 하고, `proper-lockfile/lib/lockfile.js:331` 이 로드 즉시 `onExit(...)` 를 불러 `signal-exit` 3.0.7 이 SIGINT 리스너를 상시 단다.
- 그래서 실제 Pi 안에서는 `process.listeners('SIGINT')` 에 표식 없는 리스너가 늘 있어 28행 조건이 항상 참 → fodh 처리기는 아무것도 안 하고 돌아간다.
- 게다가 signal-exit v3 리스너는 `process.listeners(sig).length === emitter.count` 일 때만 재전송(`signal-exit/index.js:120-133`)하는데 fodh 리스너가 하나 더 있으니 재전송도 안 한다. 결과: 외부 `kill -INT <pi>` 가 **아무 효과 없이 삼켜진다**(P8 전에는 signal-exit 가 재전송해 Pi 가 죽었다 — 회귀). P8 테스트는 vitest 프로세스에 signal-exit 가 없어서 통과했다.
- Pi 의 멈춤(Ctrl+Z) 처리(`interactive-mode.js:2700-2719`)는 `process.on('SIGINT', ignoreSigint)` + `process.once('SIGCONT', …)` 를 단다.

고칠 것:
1. "다른 SIGINT 처리기" 판정에서 signal-exit 리스너를 뺀다: 표식 없는 리스너 수 − signal-exit 가 단 리스너 수 > 0 일 때만 물러선다. signal-exit 수는 v3 `process.__signal_exit_emitter__?.count`, v4 `process[Symbol.for('signal-exit emitter')]?.count` 중 있는 것(둘 다 없으면 0). 멈춤 중(Pi `ignoreSigint`)은 여전히 물러서야 한다.
2. 물러서지 않을 때의 흐름(두뇌 TERM→KILL, orphan, 자기 처리기 해제, SIGINT 재전송)은 그대로. 재전송 시 fodh 처리기가 빠졌으므로 signal-exit 가 `length === count` 로 재전송해 기본 종료(signal SIGINT)로 간다 — 이를 실제 프로세스로 확인한다.
3. 테스트(실제 자식 Node 프로세스, 두뇌는 `sleep` 그룹): 자식이 **진짜 signal-exit v3** 를 먼저 로드한다 — Pi 패키지에서 해석(`createRequire(require.resolve('@mariozechner/pi-coding-agent/package.json'))('proper-lockfile')` 또는 `'signal-exit'`). 해석이 안 되면 테스트를 실패시키지 말고 이유를 남기며 건너뛰는 대신 `test/fixtures` 에 signal-exit 3.0.7 계약(동일 알고리즘: `__signal_exit_emitter__.count`, `length === count` 일 때 unload 후 재전송)을 재현한 최소 모듈로 대체한다 — 둘 중 실제로 쓴 쪽을 결과에 적는다.
   - signal-exit 로드 + `kill -INT` → 그룹 사망, orphan `signal: 'SIGINT'`, `child.signalCode === 'SIGINT'`.
   - signal-exit 로드 + 멈춤 모사(`process.on('SIGINT', ignore)` + `process.once('SIGCONT', …)`) + `kill -INT` → 300ms 뒤 자식·그룹 생존, orphan 없음; 이어 SIGTERM → 회수.
   - 기존 P8 SIGINT 테스트 유지.
4. `shutdown.ts` 4·24행 주석에 signal-exit 예외를 한 줄로.

## P8-c 마이크로 라운드 — 검수 `docs/검수/2026-09-25-P8-Claude-검수.md` P8-2~P8-5 + 참고 (2026-09-25)

### 1. P8-3 (중간) + P8-5 (낮음) — 정확한 재등록은 유사도 검사보다 먼저, 답 유무와 무관하게 기존 항목 (`src/core/judgment.ts:256-266`, `src/cli/index.ts:180`)
- CLI add 판정 순서: ① 정확한 dedupeKey(`[title, blocks]`) 일치 → 기존 항목 반환(답이 있어도 — HEAD 동작, `deduped: 'same-key'`), ② 같은 task 중복(답이 빈 항목, 단일 task) → 기존 항목, ③ 유사도.
- 유사도 오류 문구는 blocks 가 단일 task 일 때만 `--same-as A<n>` 을 안내한다. `-`·복수 task 면 `비슷한 열린 판단 A<n>(<제목>)이 있습니다. 같은 원인이면 새로 등록하지 말고 그 판단을 기다려라. 다른 원인이면 --distinct 를 붙여 다시 등록하라`.
- 테스트: `--blocks -` 동일 재등록 → 기존 id·exit 0; `--blocks "T01, T02"` 동일 재등록 → 기존 id; 답은 있고 미적용인 동일 판단 재등록 → 기존 id(새 항목 없음, task 는 기존 id 에 묶임); `-` 유사 제목 → exit 1 + 문구에 `--same-as` 없음.

### 2. P8-2 (중간) — 모델 교체 안내가 실제로 되게 (`README.md` 모델 절, `src/core/config.ts:65-66`)
- README 순서를 "추가 → 전환 → (선택) 제거" 로 다시 쓴다:
  1. `fodh config set brain.allowedModels '["claude-opus-5-5","claude-fable-5-1","claude-opus-6"]' --approve`
  2. `fodh config set brain.model claude-opus-6`
  3. (선택) `fodh config set brain.allowedModels '["claude-opus-6","claude-fable-5-1"]' --approve`
  그리고 Pi 재시작.
- 오류 문구를 바꾸려던 키에 따라 나눈다.
  - `brain.allowedModels` 변경이 현재 `brain.model` 을 목록 밖으로 밀어내면: `새 목록에 현재 brain.model(<값>)이 없습니다. 먼저 fodh config set brain.model <새 목록 안의 모델> 로 옮기거나, 목록에 현재 모델을 남기세요`.
  - `brain.model` 이 목록 밖이면: `brain.model(<값>)이 brain.allowedModels(<목록>)에 없습니다. 먼저 사용자 터미널에서 fodh config set brain.allowedModels '[…,"<값>"]' --approve 로 목록에 넣으세요`.
  - 설정 파일 자체가 이미 어긋난 상태(loadConfig)는 지금 문구 유지.
- 테스트: 위 README 세 명령을 `brain.model=claude-opus-5-5` 상태에서 차례로 실행해 모두 exit 0; 목록만 바꾸다 실패하면 새 문구.

### 3. P8-4 (낮음) — `matchesModel` (`src/provider/turn.ts:397-400`)
- 날짜 접미는 `-` + 8자리 숫자(`/^\d{8}$/`)만 허용한다. `claude-opus-5` 항목은 `claude-opus-5-5` 와 맞지 않는다.
- `[…]` 접미는 **양쪽**(항목·actual)에서 떼고 비교한다. `brain.model` 의 `[1m]` 은 `claude --model` 에 그대로 넘긴다(지금 동작 유지).
- 테스트: `claude-opus-5`↛`claude-opus-5-5`, `claude-opus-5-5`→`claude-opus-5-5-20260901`, `claude-opus-5-5[1m]` 항목 ↔ actual `claude-opus-5-5[1m]`·`claude-opus-5-5` 둘 다 허용, 목록 `["claude-opus-5-5[1m]"]` + model 같은 값 → init 통과.

### 4. 참고 반영
- R1: `shutdown.ts` 의 signal-exit 수는 v3 `__signal_exit_emitter__.count` 와 v4 `Symbol.for('signal-exit emitter')` count 의 **합**(`??` 아님). 테스트는 두 전역을 모두 모사해 합으로 판정하는지 1건.
- R3: `--same-as` 대상의 막힌 작업이 `-` 이면 `-` 를 taskId 로 바꾼다(`-, T01` 금지). 테스트 1건.
- R4: `--same-as` 시 task 가 이미 다른 열린 판단 `blocked(A<m>)`(m≠n)이면 오류 `task <id> 는 이미 A<m> 에 묶여 있습니다`. 같은 A<n> 이면 멱등 성공. 테스트 1건.
- R6: `templates/prompts/VERIFY.md` 의 `--same-as` 줄은 `--reclaim` 을 빼고 "(repair 초과로 회수할 때만 `--reclaim`)" 을 붙인다. 템플릿 테스트가 25줄·플래그 규칙을 지키는지 확인.
- R7: 프로바이더 모델 목록 동기 읽기에서 `.pi/harness.json` 이 **없으면** 경고 없이 기본 목록. 파일이 있는데 읽기·검증이 실패할 때만 경고. README 모델 절에 한 줄: "Pi 가 저장한 예전 기본 모델(`claude-code/fable` 등)이 목록에 없으면 Pi `/model` 에서 `claude-code/claude-fable-5-1` 을 한 번 고른다".
- R8: `test/p1-reclaim.test.ts` L4 가 same-task dedupe 경로로 바뀌면서 "새 판단 생성 뒤 회수 실패" 경로가 다른 테스트로 덮이는지 확인하고, 없으면 새 task(기존 판단 없음)로 그 경로를 타는 테스트를 추가한다.
