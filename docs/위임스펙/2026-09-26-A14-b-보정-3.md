## 원칙 — 나열 대신 fail-closed, 그리고 수렴 기준

검수 2~4차는 같은 부류의 철자 변형을 계속 찾아냈다. 원인은 셸 문법을 **나열해서 벗기는** 방식이다. 이번 라운드부터 다음을 따른다.

1. **두뇌(FODH_BRAIN)는 구조를 모르면 거부한다.** 파서가 인식한 구조만 풀어서 검사한다. 대상은 단순 명령·파이프·목록·서브셸·그룹·if/while/until/for·함수 정의·case·치환이다. 그 밖의 모양(첫 단어에 괄호, 모르는 앞머리 키워드 등)은 unresolved 로 거부한다. 거부 문구는 `검사할 수 없는 셸 구문입니다. 단순한 명령으로 나눠 쓰세요`, 라벨 `경계`.
2. **임시 경로 예외는 확실할 때만 준다.** 원문에 이름을 바꾸거나 값을 몰래 대입할 수 있는 형태가 하나라도 있으면 그 명령의 임시 예외를 모두 끈다. 그러면 HEAD 판정으로 돌아간다.
3. **토크나이저 결함(26)과 glob 목적지(27)는 사용자·두뇌 모두 고친다.** 이 둘은 우회 문법이 아니라 흔한 문법을 잘못 읽은 것이다.
4. **README 에 위협 모델을 한 단락 적는다.** 내용: 이 훅은 협조적인 두뇌의 실수를 막는 가드레일이고, 적대적 우회를 막는 샌드박스가 아니다. 두뇌에게는 모르는 구조를 거부한다. 스크립트 파일 내부·문자 코드 조립·셸 밖 경로(별칭 파일 등)는 한계로 남는다. OS 수준 샌드박스는 후속 후보다.
5. **수렴 기준(다음 검수용).** 높음·중간은 둘 중 하나일 때만 매긴다.
   - 협조적인 두뇌가 평소 작업에서 쓸 법한 형태로 보호 대상이 깨진다.
   - 흔한 문법을 파서가 잘못 읽는다.
   일부러 만든 난해한 변형은 낮음·참고로 매기고 README 한계 표로 보낸다. APPROVE 를 막지 않는다.

## P2 (중간, 검수 21·22) — 복합 구문은 fail-closed (`hooks/shell-commands.mjs:46-64`)

두뇌(`extended`)에 한해 원 토큰(따옴표 정보가 있는 rawGroups)으로 판정한다. `unwrap` 뒤에 다음 중 하나면 unresolved 로 둔다.

1. **첫 단어**가 따옴표 밖 `(`·`)`·`{`·`}` 를 포함하거나 `()` 이다.
   - 예외: `((` 로 시작해 `))` 로 끝나는 산술 그룹. 명령으로 보지 않는다. 그 안의 `$(…)` 는 이미 재귀 검사된다.
2. 그룹 안 어디든 따옴표 밖 단어가 정확히 `()` 이거나, `()` 로 끝나거나, `()` 가 들어 있다(`f ()`, `function g ()`, `my-fn()`, `f()(…)`).
   - 함수 정의는 **정상 철자 `NAME() {`·`function NAME {` 만** 지금처럼 벗기고 본문을 검사한다. 이름은 `[A-Za-z_][A-Za-z0-9_]*`.
3. 앞머리 키워드 처리:
   - 벗긴다: `time`(뒤 `-p` 포함), `nocorrect`, `noglob`, `command`, `builtin`, `exec`(뒤 `-a NAME`·`-c`·`-l` 포함). 벗긴 뒤 다시 1~3 을 적용한다.
   - unresolved: `repeat`, `foreach`, `select`, `end`, zsh 익명 함수 `() {`, `function` 뒤 이름이 없는 형태.
4. case:
   - `case`~`esac` 안에서는 그룹 앞쪽에서 `)` 로 끝나는 첫 단어까지 벗긴다. 패턴에 공백이 있는 `a )`·`( a )` 도 벗긴다.
   - 앞 네 단어 안에 `)` 로 끝나는 단어가 없으면 그 그룹은 unresolved 다.
5. coproc: `coproc NAME (`·`coproc NAME {` 에서 NAME 을 벗긴다. 그 밖의 모양은 unresolved 다.
6. 테스트:
   - 거부: 검수 21·22 의 모든 재현을 두뇌 거부로 넣는다(`rm -rf src` 판본과 `prisma migrate deploy` 판본).
   - 허용: `f() { echo hi; }; f`, `function g { echo hi; }; g`, `case $x in a) echo a;; b ) echo b;; esac`, `(( i++ ))`, `time npm test`, `command -v node`, `diff <(cat a) <(cat b)`, `if [ -f x ]; then cat x; fi`.

## P6 (높음, 검수 26) — 리다이렉트 연산자 토큰화 (`hooks/shell-parts.mjs:49-55`, `hooks/pretooluse.mjs:18-19`·`:86`)

## P7 (중간, 검수 27) — glob 목적지 (`hooks/pretooluse.mjs:184-197`, 판단 파일 판정)

사용자·두뇌 모두 적용한다.

1. **패턴으로 보는 목적지** — 쓰기 목적지(리다이렉트·`tee`·복사 목적지·`touch`·인라인 경로 등 `writePaths` 전체)에 따옴표 밖 `*`·`?`·`[` 가 있으면 패턴으로 본다. zsh 에서는 따옴표 밖 `(`·`<`·`^`·`#` 도 패턴 문자다.
2. **보호 대상과 맞춰 본다** — 패턴을 정규식으로 바꿔(`*`→`[^/]*`, `?`→`[^/]`, `[…]` 는 그대로, 나머지는 이스케이프) 보호 경로·판단 파일·시작 파일(두뇌)과 비교한다.
   - 하나라도 맞으면 그 대상의 기존 거부 문구로 거부한다.
   - 변환할 수 없는 패턴(zsh 특수 문자 포함)이면 판단을 바꾼다: dirname 의 리터럴 부분이 `.pi`·`.claude`·훅 디렉터리·판단 파일 디렉터리·`$HOME`·`$ZDOTDIR` 일 때 거부한다.
3. **두뇌는 한 단계 더 막는다** — 패턴 목적지의 dirname 리터럴 부분이 위 디렉터리면 맞춰 보지 않고 바로 거부한다.
4. **테스트**
   - 거부: 검수 27 재현 전부(사용자·두뇌)
   - 허용: `touch .pi/scratch/*.log`(두뇌, scratch 는 제외), `echo x > docs/notes-?.md`(사용자, 판단 파일과 안 맞음)

## P9 (낮음, 검수 29) — 과잉 거부 두 가지

1. 시작 파일 이름(`.zshrc`·`.profile` 등)은 **경로 조각 경계**에서만 맞춘다.
   - 앞: 문자열 시작·`/`·`~`·따옴표·공백·`=`

   - `mv` 원본은 지금처럼 삭제로 본다.
   - `rsync --remove-source-files` 면 원본도 쓰기로 본다.
   - 허용 확인: `cp src/a.ts .pi/scratch/`, `T=$(mktemp -d) && cp README.md $T/`
   - 거부 유지: `mv src/a.ts .pi/scratch/`
