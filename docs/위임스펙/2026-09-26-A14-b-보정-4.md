## U1 (중간, 31) — 치환은 한 단어로 (`hooks/shell-parts.mjs`)

1. 토크나이저가 따옴표 밖의 `$(…)`·백틱을 괄호 깊이·따옴표를 세어 **한 단어 안에** 둔다. `$((…))` 산술도 같다.
   - 예: `OUT=$(npm test 2>&1)` → 단어 `OUT=$(npm test 2>&1)` 하나.
   - `tee .pi/scratch/t-$(date +%F).log` → 목적지 단어 하나.
   - 치환 본문은 지금처럼 `substitutions` 가 꺼내 재귀 검사한다.
2. 프로세스 치환 `<(…)`·`>(…)` 도 같은 방식으로 한 단어로 둔다. 재귀 검사는 유지한다.
3. 테스트:
   - 두뇌 허용: 검수 31 재현 전부와 `npm test 2>&1 | tee .pi/scratch/t-$(date +%F).log`
   - 거부 유지: `echo "$(rm -rf src)"`, `x=$(prisma migrate deploy)`(README 예시 규칙), `diff <(rm -rf src) x`

## U2 (중간, 32·33) — 그룹 끝 리다이렉트 (`hooks/shell-commands.mjs:58-65`, `:124-136`)

1. 닫는 `)`·`}` 꼬리를 벗기기 전에 그룹 끝의 리다이렉트 쌍(연산자 + 대상)을 떼어 둔다.
   - 쌍은 여러 개일 수 있다(`) > a 2>&1`).
   - 벗긴 뒤 떼어 둔 쌍을 다시 붙인다.
   - 사용자(`legacyGroups`)·두뇌 모두 적용한다.
2. 떼어 둔 리다이렉트 대상은 그 그룹 안 **모든 명령의 쓰기 목적지**로도 검사한다(서브셸 전체 출력이 그 파일로 간다).
3. 테스트:
   - 사용자·두뇌 거부: `(echo x > .pi/harness.json) 2>&1`, `(cp x .pi/harness.json) 2>/dev/null`, `{ echo x; } > .pi/harness.json`
   - 두뇌 거부: `(cp .pi/scratch/j.md docs/판단대기.md) 2>&1`
   - 두뇌 허용: `{ npm test; npm run lint; } 2>&1 | tail -30`, `{ echo a; echo b; } > .pi/scratch/out`, `(cd docs && ls) > .pi/scratch/x`

## U3 (중간, 34) — glob 판정 범위 (`hooks/pretooluse.mjs:197-210`)

1. 패턴을 판정하기 전에 따옴표 밖 `$(…)`·`${…}`·`$NAME`·백틱을 걷어낸다. 치환이 섞인 경로는 P8 동적 경로 규칙이 맡는다.
2. 패턴 문자는 `*`·`?`·`[` 만 본다. `(`·`<`·`^`·`#` 는 뺀다.
   - `#`·`^` 는 zsh `extended_glob` 에서만 패턴이고, 이 옵션은 기본으로 꺼져 있다.
   - zsh 한정자 `(N)` 처럼 따옴표 밖 `(` 가 단어 **끝**에 붙는 경우는 쓰기 목적지일 때 두뇌에 한해 unresolved 로 둔다.
3. 변환할 수 없는 패턴의 dirname 비교는 **같을 때만** 거부한다(P7.2 문구 그대로). 조상 비교는 하지 않는다.
4. 사용자에게는 glob 을 보호 경로(`.pi` 설정·`.claude` 설정·훅)와만 맞춰 본다. 판단 파일은 사용자가 고치는 문서이므로 비교하지 않는다(41①). 두뇌는 판단 파일·시작 파일까지 맞춰 본다.
5. 테스트:
   - 사용자 허용: 검수 34 사용자 재현 전부, `echo x > docs/*.md`(판단 파일과 맞아도 사용자 허용)
   - 두뇌 허용: `echo x > docs/$(date +%F)-note.md`, `echo x > docs/C#.md`
   - 거부 유지: 검수 27 재현(`.pi/harnes?.json`, 두뇌 `docs/판단대?.md`, 두뇌 `~/.zshen?`)

## U4 (중간, 35) — 읽기 모드 아카이브 (`hooks/pretooluse.mjs:306`)

1. 다음은 추출로 보지 않는다. 읽기이므로 P5 목적지 검사를 하지 않는다.
   - `unzip` 에 `-l`·`-v`·`-t`·`-p`·`-c`·`-z`·`-Z` 중 하나가 있다.
   - `tar`·`bsdtar` 에 `-O`·`--to-stdout` 이 있다(묶음 플래그 `-xOf` 포함).
   - `tar -t`·`zipinfo`·`7z l` 은 지금처럼 허용한다.
2. 테스트:
   - 두뇌 허용: 검수 35 재현 전부
   - 두뇌 거부 유지: `unzip a.zip`, `tar -xf a.tar`(루트)

## U5 (낮음, 36) — 링크를 만드는 cp (`hooks/write-paths.mjs:22-24`)

1. `cp` 에 `-l`·`-s` 가 있거나 `--link`·`--symbolic-link` 가 있으면 원본을 `ln` 피연산자처럼 보호·판단 검사한다. `-l`·`-s` 는 `-al` 처럼 묶음 플래그로 와도 해당한다.
2. `rsync --remove-sent-files` 는 `--remove-source-files` 와 같이 본다.
3. 테스트: `cp -l .pi/harness.json .pi/scratch/h`, `cp -s .claude/settings.json x`, `rsync --remove-sent-files .pi/harness.json /tmp/x` → 사용자·두뇌 거부.

## U6 (낮음, 37) — case 가지 (`hooks/shell-commands.mjs:80-83`)

1. 패턴은 두 자리에서만 기대한다.
   - `in` 바로 뒤
   - `;;`·`;&`·`;;&` 로 끝난 가지 바로 뒤
2. case 안의 `|` 는 패턴 구분자로 본다. 파이프로 자르지 않는다.
3. 가지 본문의 둘째 명령부터는 보통 명령으로 검사한다.
4. `function f() {` 는 `function f {` 와 같이 정상 철자로 인정한다.
5. 테스트:
   - 두뇌 허용: `case $x in a) echo a; echo b;; esac`, `case $x in a|b) echo ab;; esac`, 여러 줄 case
   - 두뇌 거부: 같은 형태에서 `echo b` 자리에 `rm -rf src` 를 넣은 것, `a|b) prisma migrate deploy;;`

## U7 (낮음, 38) — rm 피연산자 (`hooks/pretooluse.mjs:420-428`)

1. 두뇌의 `rm -rf` 규칙은 리다이렉트를 뺀 피연산자(`withoutRedirects(args)`)만 삭제 대상으로 본다.
2. 리다이렉트 대상은 지금처럼 쓰기 목적지로 검사한다.
3. 테스트:
   - 허용: `rm -rf .pi/scratch/x 2>/dev/null`, `T=$(mktemp -d); rm -rf "$T" 2>/dev/null`
   - 거부 유지: `rm -rf src 2>/dev/null`

## U8 (참고, 40①) — 동적 경로 문구 (`hooks/pretooluse.mjs:434-438`)

1. 빈 정적 접두(`$VAR/x`, 상대 경로)는 HEAD 판정 경로(프로젝트 안 상대 경로)로 보낸다. 거부 문구도 HEAD 의 것을 쓴다.
2. "동적 쓰기 경로" 문구는 정적 접두가 프로젝트 밖일 때만 쓴다.
3. 결과(거부)는 바뀌지 않는다. 테스트는 문구만 확인한다.

## U9 (README) — 한계 표 (39·40②·41②)

- 39①: GNU 묶음 `-t`(`cp -vt DIR x`, `install -Dt DIR x`)는 마지막 인자를 목적지로 본다. macOS `cp` 에는 `-t` 가 없다.
- 39②: 디렉터리째 원본 삭제(`rsync -a --remove-source-files DIR/ …`), 사용자의 보호 디렉터리 이름 바꾸기(`mv .claude .claude.bak`)는 검사하지 않는다.
- 39③: `cd` 를 거친 복사(`(cd wt && cp x ../.pi/harness.json)`)는 cwd 를 추적하지 않는다. 기존 cd 추적 한계 행에 예로 더한다.
- 40②: `tar -cf`·`zip` 의 출력 파일은 쓰기 경로로 보지 않는다.
- 41②: 임시 변수 삭제 행에 "복사·추출과 삭제는 명령을 나눠 쓴다" 를 더한다.
