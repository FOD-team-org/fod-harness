## 필수 항목

| # | 요구 | 상세 |
|---|---|---|
| H1 | 외부 편집이 기대 해시에 흡수되지 않게 | `save()` 호출자가 읽은 디스크 원문(`original`)을 넘긴다. 잠금 안에서 `hash(original) !== 직전 judgment.expectedHash` 이고 그 해시가 `watch.judgment.lastEmitted` 와도 다르면 `judgment.externalPending = { hash: hash(original), at }` 를 기록한다(이미 있으면 유지). `tick()` 은 `externalPending` 이 있으면 `observed.hash === expectedHash` 여도 안정화 기준 `externalPending.at` 으로 `judgment-changed` 를 발행하고(`hashBefore = lastEmitted`, `hashAfter = expectedHash`, `external: externalPending.hash`) 플래그를 지운다. `readJudgment()` 같은 읽기 전용 경로가 `save()` 를 부르는 이유가 reconcile 뿐이면 변경이 없을 때는 쓰지 않는다. 회귀 테스트 = 검수 H1 재현 시나리오(addJudgment → tick → 사용자 write → tick → addJudgment(다른 판단) → tick(+20s) → 발행 1건, 적용 가능 답 A1) |
| H2 | 사용자 중단 턴은 정체로 재개하지 않음 | `agent_end` 가 `stopReason==='aborted'` 이면 `updateState({ userAborted: true })`, `input` 핸들러(사용자 입력)와 명령(`/develop-start`·`/judged`·`/project-start`)이 지운다. `tick()` 은 `userAborted` 또는 `state==='recovering'` 이면 `stalled` 를 발행하지 않는다(감지 단계에서 제외 — 인박스에 오해를 남기지 않기 위해). `decideInbox` 의 `stalled` 도 같은 조건이면 info 알림만. 테스트: recovering / userAborted 각각 미발행, 입력 뒤 해제 |
| M1 | 이중 전송 방지 | `autoResume` 은 `instruction()` 을 먼저 await 한 뒤, **await 없이** `if (!ctxLike.isIdle()) → 원복 + {skipped:'busy'}` 확인과 `pi.sendMessage` 를 같은 동기 구간에서 수행한다. 모듈 전역 `resuming` Set 은 제거하거나 보조로만 둔다. 테스트: `vi.resetModules()` 로 `resume.ts` 를 두 번 import 해 서로 다른 인스턴스에서 동시에 호출하고, `sendMessage` mock 이 `isIdle` 을 false 로 바꾸게 하여 전송 1회·autoTurns +1 을 단언 |
| M2 | 결정을 프로세스 메모리에 묶지 않음 | `harness-watcher.json` 에 `watch.decided: string[]`(인박스 id) 를 둔다. 확장은 매 tick 뒤 "워처 종류(judgment-changed/stalled/child-*/recover) 이면서 `applied` 가 아니고 `decided` 에 없는 인박스 항목" 전부를 `decideInbox` 대상으로 삼고, 결정이 끝나면 id 를 기록한다(결정 예외 시 기록하지 않아 다음 tick 에 재시도, 단 같은 id 3회 실패 후에는 기록하고 원장 `watcher:decide:<kind> fail`). `session_start` 도 복구 감지 뒤 같은 규칙으로 잔여 항목을 결정한다. CLI `fodh watch tick` 은 결정하지 않는다고 README 에 적는다 |
| M3 | 시작 실패 격리 | `session_start` 에서 복구 감지·결정 블록과 타이머/fs.watch 시작 블록의 try 를 분리. 설정 로드 실패 시 기본값(5/30초)으로 시작하고 다음 tick 에서 재로드. 테스트: detectRecovery 가 throw 해도 타이머가 시작됨 |
| M4 | 저장 충돌 감지 | `save()` 가 rename 직전 디스크를 다시 읽어 `hash !== hash(original)` 이면 `JudgmentConflict` 로 중단. `applyJudgments`·`addJudgment`·`answerJudgment`·`writeJudgmentStatus` 는 충돌 시 원문을 다시 읽어 1회 재시도. 판단대기 문서 머리말에 「편집기는 외부 변경 자동 새로고침을 켜 둘 것」 한 줄 |
| M5 | 자유 서술 답 60초 안정화 | `watch.freeTextStableSeconds`(기본 60) 설정 추가. `decideInbox(judgment-changed)` 는 적용 가능 답 중 `classifyAnswer` 가 자유 서술인 항목이 있고 `stableFor < freeTextStableSeconds` 이면 그 항목은 이번에 적용하지 않고, 남은 시간 뒤 한 번 더 결정하도록 `setTimeout(...).unref()` 를 건다(shutdown 시 clear). 번호·승인 답은 즉시 적용. 알림에 「자유 서술 답 N초 뒤 적용 예정」 표시 |
| F9 | 오케스트레이터가 처리한 인박스 닫기 | `src/core/inbox.ts` 에 `resolveInbox(root, ids, by:'orchestrator', note?)` 추가(어떤 상태든 → `applied`, `resolvedBy` 기록). `decideInbox` 가 judgment-changed 를 적용(또는 자유 서술 대기 없이 "적용할 답 없음")했거나 recover/stalled/child-* 를 알림으로 처리 완료한 항목은 즉시 `resolveInbox`. 두뇌 전달이 필요한 항목만 남긴다(= `stalled` 로 재개한 경우와 child-timeout/child-gone 은 두뇌에게 전달하므로 delivered→ack 경로 유지). 테스트: 자동 적용 뒤 inbox 가 applied |
| L1 | 겹친 전체 tick 병합 | 실행 중 전체 tick 요청은 `pendingFull` 로 표시, finally 에서 1회 추가 실행 |

| L3 | 무변경 tick 은 쓰지 않음 | `lastTickAt` 만 바뀐 경우 파일 미기록(메모리 보관, 전체 tick·변경 시에만 영속). `/status`·`watch status` 는 메모리 값 우선 |
