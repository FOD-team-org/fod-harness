## 1. 규칙 4 — 경로 경계 (F2 강제) — `hooks/pretooluse.mjs`, `src/provider/turn.ts`, `test/hook.test.ts`
- 정의: **문서 경로** = `<root>/docs/**`, `<root>/.pi/**`(보호 파일 제외), `<root>/CLAUDE.md`, `<root>/AGENTS.md`, `<root>/README.md`, `<root>/.claude/skills/**`(스킬은 `fodh skills install` 이 쓰므로 두뇌 Write 는 거부), `<root>/docs` 는 설정 `docs.root` 를 따른다(훅은 `FODH_DOCS_ROOT` env 로 받는다. turn.ts 가 전달). 그 밖의 루트 안 경로 = **소스 경로**.
- 등록 워크트리 = `.pi/harness-state.json` `worktrees[].path`(훅이 읽는다, 실패 시 빈 목록). 워크트리 안 경로는 소스라도 허용(디자인 서브에이전트 예외). 루트 밖 경로(`/tmp`, 홈 등)는 규칙 2 와 별개로 Write/Edit 는 **거부**(두뇌가 루트 밖에 쓸 이유가 없다; 스크래치는 `.pi/scratch/` 를 쓰라고 안내).
- Write/Edit/MultiEdit/NotebookEdit: 대상이 소스 경로이고 워크트리 밖이면 `deny('소스 파일은 두뇌가 쓰지 않습니다. 워크트리로 위임하세요(fodh codex task / Claude Agent).')`.
- Bash 쓰기 패턴(기존 `writes` 판정 재사용: `>`/`>>`, `tee`, `cp`, `mv`, `rm`, `touch`, `install`, `truncate`, `dd`, `perl`, `python*`, `node`, `ruby`, `sed -i`, 추가 `rsync`, `patch`, `git apply`, `git checkout -- <path>`, `git restore`, `git stash`): 인자 중 하나라도 워크트리 밖 소스 경로를 가리키면 거부. 경로 판정은 토큰을 `cwd` 기준 resolve. 인용·변수 확장은 토큰 문자열 그대로(한계 표에 기록).
- 두뇌 자식 env 로 `FODH_BRAIN=1` 이 있을 때만 규칙 4 를 적용한다(사용자의 대화형 Claude Code 세션이 같은 settings 를 로드해도 사용자는 자유롭게 쓴다). `FODH_BRAIN` 이 없으면 규칙 1·3·5·6 만.
- 테스트: docs Write 허용, `src/x.ts` Write 거부, 워크트리 안 `src/x.ts` 허용, 루트 밖 Write 거부, `sed -i` 소스 거부, `echo > docs/a.md` 허용, `cp a src/b` 거부, `FODH_BRAIN` 없으면 소스 Write 허용, state 파일 없음(미초기화) → 규칙 4 통과.

## 2. 규칙 2 — 대량 삭제·프로젝트 밖 삭제 — `hooks/pretooluse.mjs`
- `rm -r*`/`rm -f*` 의 대상이 루트 밖이거나 루트 자체·`.git`·`.pi` 이면 거부. `find … -delete`, `git clean -fdx`(워크트리 밖) 거부. 100개 이상 삭제 판정은 훅에서 못 하므로 사후 감사 몫(한계 표). `rm` 대상이 워크트리 안이면 허용(위임 자식은 다른 훅 경로).
- 테스트: `rm -rf /tmp/x` 거부, `rm -rf .git` 거부, `rm -rf <wt>/build` 허용, `rm docs/a.md` 허용.

## 3. `git worktree` 직접 실행 거부 + `FODH_CODEX_CHILD` — `hooks/pretooluse.mjs`
- 두뇌(`FODH_BRAIN=1`)의 `git worktree add|remove|prune` 거부 → `fodh worktree` 안내. `git branch -D`·`git reset --hard`·`git push --force*` 는 승인 범주(`push-main`) 와 별개로 두뇌에서 거부.
- `FODH_CODEX_CHILD=1` 환경에서 `fodh` 실행은 훅에서도 거부(N9; 현재는 CLI 진입에서만 거부). 훅은 자기 env 를 본다(Codex 는 Claude Code 훅을 쓰지 않으므로 실효는 두뇌가 Codex 를 흉내낼 때뿐 — 한계 표에 "Codex 자식은 훅 밖, CLI 진입 거부가 실제 방어" 로 기록).
- 테스트 3개.

## 4. 승인 전용 설정 키 (L10 확장) — `src/core/config.ts`, `src/cli/index.ts`, README
- P5 2차 M2 의 `FODH_BRAIN` 보호 키에 `verify.*`(P5 3차 N4: 두뇌가 `verify.commands` 를 `["true"]` 로 바꿔 VERIFY 게이트를 무력화할 수 있다 — 두뇌 세션에서는 전부 거부, 판단대기로만) 와 `delegate.*` 를 넣어 두뇌는 **어떤 설정도** 바꾸지 못하게 한다. 그리고 `delegate.codex.command`, `brain.command`, `brain.switchCommand`, `delegate.codex.sandbox` 를 승인 전용 키로 추가하고, 이 키들은 **두뇌가 아니어도** `fodh config set` 에서 `--approve` 플래그 없이는 거부한다(`{"error":"승인 전용 키입니다: <key>. --approve 를 붙여 사용자 터미널에서 실행하세요"}`). `--approve` 는 `FODH_BRAIN=1` 이면 무시하고 거부.
- 테스트 3개.

## 4-1. P5 3차 이월 (N10·N11)
- **N10** 훅의 `FODH_` 환경변수 차단이 토큰 단위라 `sh -c '…unset FODH_BRAIN; fodh …'`, `bash -c`, `node -e "delete process.env.FODH_BRAIN…"` 안 따옴표 문자열은 빠져나간다. `sh|bash|zsh -c`, `node -e|--eval`, `python* -c`, `perl -e` 의 인자 문자열 안에 `FODH_[A-Z_]*` 가 보이면 거부(`하네스 환경변수는 바꿀 수 없습니다`). 테스트 3개. 더 근본적으로 §4 의 보호 키 변경은 `setConfig` 가 잠금 소유 프로세스(Pi 세션 `.pi/harness.lock` 소유자) 를 확인해 두뇌 자식(부모 체인에 소유자 pid) 이면 env 와 무관하게 거부한다 — `src/core/process-time.ts` 의 ppid 체인 조회 재사용. 테스트 2개.
- **N11** `templates/prompts/CLEANUP.md` 15행: storage·worktrees 실패 판단 등록 뒤 `fodh state transition CLEANUP_FAILED` 로 비활성 상태에서 기다린다(판단 답 전 채팅 입력이 CLEANUP 지시를 다시 돌려 판단을 건너뛰는 경로 차단). templates.test.ts 단언 1개.

## 5. `fodh memory reset` (N4) — `src/core/memory.ts`, `src/cli/{commands,index}.ts`, `extensions/orchestrator/index.ts`, README
- `harness-watcher.json watch.memory` 의 `over/critical/overSince` 를 지우고 원장 `memory:reset`. 다음 표본이 다시 임계면 5분 뒤 재설정된다. `memory-critical` 알림 본문에 "해제: `fodh memory reset`(스왑이 실제로 줄지 않으면 다시 걸린다)" 를 붙인다. 상태가 `paused(memory)`/`WAIT_RESOURCE(lastPaused=memory)` 면 reset 뒤 `memory-recovered` 와 같은 회복 경로를 탄다(오케스트레이터 핸들러 재사용 — 인박스 `memory-recovered` 레코드를 CLI 가 직접 넣는다).
- 테스트 2개.
