## 구현 선택과 기존 동작 보존

- 훅은 Node 내장 모듈만 사용하는 `hooks/pretooluse.mjs` 단일 파일을 유지했다. 기존 비밀 패턴 문자열, 승인 범주, 문서 commit 상태 예외와 비두뇌 사용자의 소스 편집을 유지했다. 규칙 2·4는 FODH_BRAIN=1이며 상태가 초기화됐을 때 적용한다. 상태 ENOENT와 손상/읽기 실패는 구별한다.
- `process-time.ts`에는 기존 ppid 체인 함수가 없어 같은 execFile/timeout 방식으로 `processParent`·`descendantOf`를 추가했다. 루프·128단계 상한·조회 불능을 처리한다. 살아 있는 잠금 소유자와 무관함을 증명하지 못하면 보수적으로 설정 변경을 거부한다. 소유 Pi 프로세스 자체는 내부 모델 선택을 할 수 있다.
- 네 키의 --approve 요구는 스펙의 **사용자 CLI 경계**에서 적용한다(`setConfig`의 fromCli/approve 옵션). 내부 TypeScript 호출은 승인 CLI 플래그가 필요하지 않지만, 두뇌 env/부모 체인 검사는 내부 호출에도 공통 적용한다. 승인 키를 포함하는 `brain`, `delegate`, `delegate.codex` 객체 전체 교체도 CLI 승인이 필요하다.
- memory reset은 over=false로 만들고 critical/overSince/underSince를 제거한다. 표본 및 다른 워처 필드는 보존한다. 이전 미처리 pressure/critical 인박스도 닫아 다음 tick 전에 오래된 이벤트로 즉시 재정지하는 것을 막는다. 실제 스왑 감소를 주장하지 않도록 수동 recovered 알림을 구별했다.
- 감사는 셸을 실행하거나 외부 스크립트를 읽지 않는다. 리터럴 경로에 대한 의심만 기록하며 성공/변경 확정을 주장하지 않는다. 경고 경로는 redact한다. 감사 때문에 판단대기를 생성하지 않으며 기존 훅 denial 판단 처리 흐름은 유지했다.
- 기존 테스트 이름·핵심 단언을 유지했다. P5 M2의 delegate/verify 허용 테스트 1개는 새 명세에 맞춰 이름과 기대값을 거부로 바꿨다. templates의 대기 단언과 provider의 hookDenials만 새 명세로 갱신했다.
- provider fixture는 `.pi/harness-state.json`을 초기 IDLE/autoTurns=0으로 명시해 초기화된 경계 시험을 한다. 기존 CLI JSON 정확 일치 단언은 그대로 유지했다. fake-claude는 실제 훅에 Write JSON도 넣어 거부를 확인하며 실제 소스 파일은 만들지 않는다.

### 선택·보존 사항

- 훅은 Node 내장 모듈만 사용하는 단일 `pretooluse.mjs`다. 훅과 감사의 리터럴 토큰·패치 대상 판독은 각각 파일 안에 두어 훅에 런타임 의존성을 추가하지 않았다. 셸을 실행하거나 변수·cd를 해석하지 않는다.

- H1 통합 재현은 fake-claude가 실제 훅을 호출한다. 활성 delegation은 가짜 등록이며 reclaimTask를 spy/mock하여 승인에서만 호출되는지 확인했다. 실제 Codex 실행·취소를 검증했다는 뜻은 아니다.
