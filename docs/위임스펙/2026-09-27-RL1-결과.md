## 판정 및 새 테스트

`legacyVerdict`에 수정 전 두 조건을 그대로 옮겨 비교했다. 격자는 스펙의 `5 × 5 × 3 = 75`칸이며, 키 없음은 실제로 키를 생략해 만들었다. `undefined`·`null`·문자열 info 3건도 비교했다.

달라진 칸은 아래 둘뿐이며, 변경 개수가 정확히 2인지도 단언했다.

| status | overageStatus | isUsingOverage | 이전 | 이후 |
|---|---|---|---|---|
| `allowed` | 키 없음 | `false` | billing | continue |
| `allowed_warning` | 키 없음 | `false` | billing | continue |

새 테스트 23개 구성:

- 전수 비교 1개, 스펙 §1 실제 이벤트 모양 1개.

- 가짜 두뇌 통합 3개: warning은 stop·billing 상태 아님·알림 0회·상태 이벤트 저장. unknown과 기존 overage는 aborted·billing·paused(billing)·알림 1회. 누락 필드도 상태에서 확인.
- doctor 문구 7개: billing·quota 정확한 문구 및 그 밖 기존 문구 유지.
- 기존 가짜 `api-key` 시나리오로 실제 `doctor()` 호출 1개: billing 문구 전달과 doctor 실패 상태 확인.

## 샌드박스 실패 및 범위 보존

- `/bin/ps`: `test/p1-reclaim-integration.test.ts:20`에서 `processStartedAt(child.pid)`가 undefined여서 실패했다. 오류는 `/bin/ps lstart 조회 권한이 필요합니다: expected undefined to be truthy`. 샌드박스의 프로세스 조회 제한에 해당하며 RL1 판정 실패가 아니다. 해당 테스트를 수정·스킵하거나 제한을 우회하지 않았다.
- 이 저장소 `.git` 쓰기 제한으로 발생한 실패: 0건. 이 저장소에서 git 명령은 실행하지 않았다. git을 사용하는 기존 테스트는 자신이 만든 임시 저장소에서만 실행했다.
- 작업 전후 SHA-256 비교에서 변경된 기존 파일은 `turn.ts`, `doctor.ts`, 가짜 두뇌 3개뿐이었다. 기존 `*.test.ts`, `hooks/`, `docs/설계/` 변경은 0개. 가짜 두뇌 원본과의 줄 비교는 insert만 확인했다.
- 실제 claude·codex·cswap·pi·osascript, 네트워크 호출은 실행하지 않았다. 실제 HOME의 `.env*`·키·인증 파일을 열지 않았다.

## 구현 선택과 남은 한계

1. **doctor 문구 검증 방식:** 기존 doctor 테스트 3개는 `runTurn`을 mock한다. provider의 가짜 두뇌 doctor 경로는 별도 분기여서 `overage`의 `rate_limit_event`를 재생하지 않는다. 기존 시나리오를 수정하지 않기 위해 스펙 §3.4가 허용한 작은 문구 함수 직접 검증을 선택했다. 추가로 기존 `api-key` 시나리오를 이용해 `doctor()`에서 billing 문구로 연결되는 것도 검증했다. doctor에서 실제 overage 이벤트를 재생하는 통합 검증은 미실행이다.
2. **분류를 보존한 doctor 문구(최종 검수 보정):** `doctorFailureMessage`에서 `quota`·`configError: quota` 모두 `configError: quota — 사용 한도에 걸려 doctor 두뇌 호출을 끝내지 못했습니다`를 반환한다. billing은 `configError: billing — 과금 보호로 doctor 두뇌 호출이 멈췄습니다. 초과 사용 신호를 확인하세요(/status 의 rateLimit)`를 반환한다. 분류를 앞머리에 남겨 기존 quota 문자열 단언과 호환되도록 했다. RL1의 정확한 문구 단언과 기존 `turn-policy.test.ts:82` 모두 통과하여 이 충돌은 해소됐다. `src/provider/turn.ts:334`의 반환값과 기존 테스트는 보존했다.
3. **키 존재 여부:** 새 행 5는 `overageStatus in value`로 키 존재를 구별한다. 존재하는 undefined도 새 허용 조건에 넣지 않는다. rejected의 기존 undefined → quota 조건은 보존했다.
4. 실제 계정·실제 CLI 실기는 금지 조건에 따라 미실행이다. 검증은 순수 함수, 가짜 두뇌, 기존 mock·임시 저장소 테스트에 한정한다. `/bin/ps`가 필요한 기존 통합 1개는 이 환경에서 통과를 입증하지 못했다.
