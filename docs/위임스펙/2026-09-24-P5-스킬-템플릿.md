## 1. 인터뷰 은행과 진행 추적

### 1-1. 은행 형식 (`templates/interview/bank.md`)

```markdown
## 03 범위·MVP
- [필수] Q03-01 | free | 첫 출시(MVP)에 반드시 들어가야 하는 기능 3개는? | 추천: PRD 초안에서 핵심 흐름 1개만
- [필수] Q03-02 | choice: 1주 이내/2~4주/1~3개월/미정 | MVP 목표 기간은? | 추천: 2~4주
- [선택] Q03-03 | free | 명시적으로 이번에 하지 않을 것은? | 추천: 없음
```

- 영역 머리 `## NN 이름`(01~18, 설계 §12 순서·이름 그대로). 문항 줄 `- [필수|선택] Qnn-mm | free | choice: a/b/c | 질문 | 추천: 값`. 파서는 형식 위반 줄에서 `인터뷰 은행 형식 오류: <파일>:<줄>` 로 실패한다(조용히 건너뛰지 않음).
- 프로젝트 추가 은행: `interview.extraBankFile`(기본 `.pi/interview-bank.md`, 없으면 무시). 같은 ID 는 덮어쓰고 새 ID 는 추가. `fodh interview add` 로 생긴 문항은 상태 파일에만 둔다(ID `Qnn-xNN`).

### 1-3. 진행 상태 (`.pi/harness-interview.json`, `fodh` 단일 작성자, 잠금 + 원자 저장)

```json
{ "startedAt": "…", "docFile": "docs/결정기록/2026-09-24-인터뷰.md", "round": 2,
  "questions": { "Q03-01": { "status": "answered", "answer": "…", "source": "user", "askCount": 1, "round": 1 },
                 "Q08-01": { "status": "judgment", "judgmentId": "A3", "askCount": 1 } }, "added": [] }
```

- 문항 상태: `open`(기본) · `asked` · `answered` · `judgment` · `skipped`. `judgment` 항목은 `status` 계산 때 판단대기 문서를 읽어 **결정 완료 표에 있으면 `answered(source: judgment:A3)` 로 간주**(문서 결합 없이 읽기 시점 판정).
- 기록 문서 `docFile` 은 상태 파일에서 매번 다시 그리는 뷰다(백로그와 같은 방식): 영역별 `### NN 이름` + 표 `| ID | 필수 | 질문 | 상태 | 답 | 출처 |`, 맨 위 `## 요약`(남은 필수 수). 사람이 편집한 내용은 보존하지 않는다고 문서 머리에 적는다.

### 1-4. CLI

| 명령 | 동작 | 허용 상태 |
|---|---|---|
| `fodh interview start` | 상태 파일·기록 문서 생성(이미 있으면 그대로 반환 `created:false`). `/project-start` 가 호출 | INTERVIEW |
| `fodh interview next [--count N]` | 다음 라운드 문항 반환 + `asked`·`askCount+1`·`round+1` 기록. 순서: 이전에 물었는데 답 없는 필수 → 미질문 필수(영역 순) → 선택. N 기본 `interview.roundSize`. `askCount >= interview.maxAsks` 인 문항은 반환하지 않고 `mustDefer:[ID…]` 로 따로 알린다. 결과 `{ round, questions:[{ id, area, must, kind, text, options?, recommend }], mustDefer, remainingMust }` | INTERVIEW |
| `fodh interview record <ID> --answer "<원문>" [--source user\|default]` | `answered`. `default` 는 사용자가 "추천대로" 라고 답한 경우만(템플릿에 명시) | INTERVIEW, REVIEW |
| `fodh interview defer <ID>` | 은행 데이터로 `addJudgment({ title: 질문, background: "인터뷰 영역 NN", options: choice 면 선택지·free 면 ["추천안 채택","직접 답하기"], recommend, blocks:'-', dedupeKey:'interview:<ID>' })` → `judgment` | INTERVIEW |
| `fodh interview skip <ID> --reason "<이유>"` | 선택 문항만. 필수면 `필수 질문은 건너뛸 수 없습니다. 답을 받거나 fodh interview defer 로 판단대기에 넘기세요` | INTERVIEW |
| `fodh interview add --area NN --text "<질문>" [--must] [--recommend …]` | 후속 질문 추가(검수 반려 "질문 추가 필요" 경로) | INTERVIEW, REVIEW |
| `fodh interview status` | 읽기 전용. `{ complete, remainingMust, byArea:[{ area, mustTotal, mustDone, optionalDone, open:[ID] }], mustDefer, docFile }` | 모두 |

- **조기 종료 방지**: `transitionState(INTERVIEW→RESEARCH)` 는 `interview.enforce`(기본 true) 이면 `status().complete` 를 요구한다. 실패 메시지 `인터뷰 필수 질문이 남아 있습니다: 영역 03(1), 07(2). fodh interview next 로 계속하세요` (`TransitionError`, action `interview`). `complete` = 모든 필수 문항이 `answered` 또는 `judgment`. 상태 파일이 없으면 `인터뷰 기록이 없습니다. fodh interview start 를 먼저 실행하세요`. `INTERVIEW→WAIT_JUDGMENT` 는 가드 없음.
- **반복 방지**: `maxAsks`(기본 2) 초과 문항은 `next` 에서 빠지고 `defer` 만 가능. `next` 가 빈 `questions` 와 비어 있지 않은 `mustDefer` 를 돌려주면 템플릿은 전부 `defer` 후 `WAIT_JUDGMENT` 로 가게 한다. 두 조건 모두 비면 `complete:true` 가 보장된다(테스트).
- 원장: `interview:next|record|defer|skip|add` 한 줄씩(답 원문은 넣지 않고 ID·상태만, redact).

- 치환 키: `{{date}}`(기본 오늘, KST `YYYY-MM-DD`), `{{taskId}}`, `{{taskTitle}}`(`getTask`), `{{specRev}}`, `{{topic}}`, `{{subject}}`(= taskId ?? topic), `{{projectName}}`(`state.projectName` ?? 루트 폴더명), `{{judgmentFile}}`. 원본에 목록 밖 키가 있거나 필요한 값이 비면 `템플릿 치환 값이 없습니다: {{키}}` 로 실패(부분 파일 생성 금지). `--topic` 은 `^[가-힣A-Za-z0-9_-]{1,40}$`.
- 프로젝트 재정의: `docs.overrideDir`(기본 `.pi/templates/docs`) 에 같은 상대 경로 파일이 있으면 그것을 원본으로 쓴다.
- 템플릿 내용 요구: 각 문서는 제목 + 채울 절 머리 + 절마다 한 줄 안내(`> 채울 것: …`). 위임스펙 템플릿은 이 저장소 P3/P4 스펙 형식(기준·담당·제약 머리, `## 0. 범위` 표, 수용 기준, 검증 명령, 금지, 결과 보고 형식). 검수 템플릿은 설계 §7(대상 커밋 SHA·모델·effort, 높음/중간/낮음 표 `파일:줄·재현·수정안`, 판정 `APPROVE|REQUEST_CHANGES`). `templates/docs/판단대기-항목.md` 는 설계 §4-1 항목 형식 **참고용**(scaffold kind 아님; 항목은 `fodh judgment add` 로만 쓴다).
- `initialize` 는 `scaffoldDoc('backlog'|'worklog')` 를 쓰되 존재 시 오류가 아니라 건너뛴다(내부 옵션 `ifMissing`).

## 3. CLAUDE.md 생성기 (`fodh claude-md generate [--check]`)

- 대상: `claudeMd.targets`(기본 `["CLAUDE.md"]`, 허용 값 `CLAUDE.md`·`AGENTS.md`, 루트 기준). 관리 블록 표지 `<!-- fodh:managed:begin v1 -->` … `<!-- fodh:managed:end -->`.
- 규칙: 파일 없음 → `# <projectName>\n\n` + 블록으로 생성. 블록 1개 → 블록 안만 교체. 블록 없음 → 파일 끝에 빈 줄 + 블록 추가. 시작·끝 표지 개수가 1:1 이 아니거나 순서가 뒤집히면 `관리 블록 표지가 올바르지 않습니다(시작 N개, 끝 M개). 직접 고친 뒤 다시 실행하세요` 로 실패하고 쓰지 않는다. 블록 밖 바이트는 한 글자도 바꾸지 않는다. 결과 `{ files:[{ path, changed }] }`; 같은 입력으로 두 번째 실행은 `changed:false`(시각 등 비결정 값 금지 — 블록에 생성 시각을 넣지 않고 설정 해시 8자만).
- `--check`: 쓰지 않고 `{ upToDate }`, 낡았으면 exit 1.
- 블록 내용(`CLAUDE.md`, 순서 고정, 한국어): ① 이 블록은 `fodh claude-md generate` 가 관리 — 고치지 말 것 ② 역할: 두뇌는 소스 파일을 쓰지 않는다; design → Claude Agent(`delegate.claude.subagentModel`), 그 외 → `fodh codex task`(`delegate.route` 표) ③ 하네스 흐름 한 줄 표(상태 → 다음 fodh 명령) + 턴 끝 표지(`대기: 사용자`, `대기: 위임 <runId>`, `상태: …`) ④ 쓸 수 있는 fodh 명령(`commandTable` 에서 생성) ⑤ 백로그 규칙(분류 4종, 상태 값, DoD 6항) ⑥ 검증 명령(`verify.commands`, `verify.heavy` 는 `fodh verify run --heavy` 로만) ⑦ 금지·승인 필수(`requiresApproval` 키 + 설계 §10 16종 한국어 목록, 전체 테스트는 VERIFY 만, `codex`·`git worktree` 직접 실행 금지, 비밀값) ⑧ 문서 위치(`docs.root` 아래 폴더 표, 판단대기 파일) ⑨ 설치된 하네스 스킬 이름.
- `AGENTS.md` 블록(Codex 용, 선택): ⑥⑦⑧ + "`fodh` 를 실행하지 않는다, git 을 쓰지 않는다" 만. 하네스 흐름은 넣지 않는다.
- 호출 시점: `/project-start`·`/develop-start`(idempotent, 실패는 warning 알림), ARCH·PLANNING 템플릿의 첫 단계. 생성 파일은 문서 경로이므로 커밋은 평소 흐름(프로젝트 단계·PLANNING 허용)을 따른다.

## 4. 하네스 스킬 (Agent Skills 표준)

- 패키지 `skills/` 에 4개: `fodh-workflow`(상태별 다음 명령·턴 끝 표지·인박스 ack·TransitionError 대처), `fodh-spec-writing`(위임스펙 구조·`fodh docs scaffold spec`·수용 기준 쓰는 법), `fodh-review-checklist`(교차검수 절차·심각도 기준·대상 SHA·판정), `fodh-judgment`(등록 기준·선택지/추천·답 문법 §4-3·`--reclaim` 과 `--blocks -`). 각 `SKILL.md` 는 frontmatter `name`(디렉터리명과 같음, `^[a-z0-9]+(-[a-z0-9]+)*$`, ≤64)·`description`(≤1024, "언제 쓰는지" 포함) 만, 본문 150줄 이하, 스크립트 없음.
- **확인된 사실**(Pi 0.73.1 `docs/skills.md`·`packages.md`): Pi 는 패키지 `pi.skills` 로 스킬을 읽어 **Pi 시스템 프롬프트**에 목록을 넣는다. 그러나 우리 프로바이더 `streamClaude` 는 `latestMessage(context)` 만 `claude -p` 에 넘기므로 **Pi 스킬 목록은 Claude 두뇌에 전달되지 않는다**(Pi 네이티브 보조 두뇌에만 유효). 그래서 두 경로로 싣는다: (a) `package.json` `pi.skills: ["./skills"]` — 보조 두뇌용 (b) `fodh skills install` 이 프로젝트 `skills.target`(기본 `.claude/skills`) 에 복사 — Claude Code 두뇌용. 실기 픽스처의 `system.init` 에 `skills` 배열이 있으므로 (b) 의 로드 여부는 doctor 턴의 `init.skills` 로 확인한다.
- `installSkills(root)`: `skills.install`(기본 = 패키지의 4개 전부) 각각을 `<target>/<name>/` 로 복사 + `.fodh-managed`(`{ package:"fod-harness", version, hash }`). 대상 디렉터리가 있고 표지가 없으면 건너뛰고 `conflicts:[name]`(`사용자 스킬과 이름이 겹칩니다: <name>`); 표지가 있으면 해시가 다를 때만 교체. 결과 `{ installed, updated, unchanged, conflicts }`. `fodh skills status` = 같은 판정의 읽기 전용판.
- doctor: `init.skills` 에 설치 대상이 없으면 결과에 `skillsMissing:[…]` + warning 알림(doctor 실패로 치지 않음 — 로드 규칙이 실기 전 미확정). `init.memory_paths` 에 `CLAUDE.md` 가 있는지도 같은 방식 `claudeMdLoaded:boolean`.
- `brain-rules.md` 에 한 줄: "하네스 스킬(fodh-workflow 등)이 있으면 막힐 때 먼저 읽는다."

## 5. 설정 (`.pi/harness.json`)

```json
"interview": { "enforce": true, "roundSize": 6, "maxAsks": 2, "extraBankFile": ".pi/interview-bank.md" },
"docs": { "root": "docs", "overrideDir": ".pi/templates/docs" },
"skills": { "target": ".claude/skills", "install": ["fodh-workflow", "fodh-spec-writing", "fodh-review-checklist", "fodh-judgment"] },
"claudeMd": { "targets": ["CLAUDE.md"] }
```

| 키 | 검증(실패 메시지) |
|---|---|
| `interview.enforce` | 불리언 (`interview.enforce는 불리언이어야 합니다`) |
| `interview.roundSize` | 정수 5~8 (`interview.roundSize는 5~8 사이 정수여야 합니다`) |
| `interview.maxAsks` | 정수 1~5 |
| `interview.extraBankFile`, `docs.root`, `docs.overrideDir`, `skills.target` | 프로젝트 안 상대 경로(기존 `judgment.file` 과 같은 검사, `…은 프로젝트 내부 상대 경로여야 합니다`) |
| `skills.install` | 문자열 배열, 각 항목이 패키지 `skills/` 에 존재 (`skills.install 에 없는 스킬: <name>`) |
| `claudeMd.targets` | 비어 있지 않은 배열, 값 `CLAUDE.md`·`AGENTS.md`, 중복 금지 |

`fodh config get` 에 기본값이 모두 보여야 한다. 백로그 파일 경로는 기존대로 `docs/backlog.md` 고정(이번에 설정화하지 않음).

## 6. 프롬프트 정비 (약한 두뇌용)

### 6-1. 형식 — 모든 `templates/prompts/*.md` 동일

`# <상태>` 다음 정확히 이 순서의 5절: `## 지금 할 일`(번호 목록, 한 줄에 한 동작, 명령은 백틱) · `## 산출물` · `## 끝내는 조건`(확인 가능한 문장) · `## 다음 fodh 명령`(분기마다 `- 조건 → 명령`) · `## 금지`(첫 줄 고정: `두뇌는 소스 파일을 쓰지 않는다. Write/Edit 는 docs/·CLAUDE.md 에만, 구현은 위임한다.`). 25줄 이하. "P3 전/P4 전" 같은 단계 안내 문구 삭제.
- INTERVIEW: ① `fodh interview status` → ② `fodh interview next` → ③ `choice` 문항은 `fodh interview defer <ID>`, `free` 문항은 번호 붙여 채팅으로 묻고(추천값 함께) 마지막 상태 줄 앞 `대기: 사용자` ④ 답이 오면 문항마다 `fodh interview record` (모호하면 기록하지 않고 다음 라운드에 다시 나온다) ⑤ `mustDefer` 는 전부 `defer` ⑥ `complete:true` → `fodh state transition RESEARCH`, 판단 대기만 남으면 `WAIT_JUDGMENT`. 요약 `{{interviewSummary}}` 를 맨 위에 싣는다.
- RESEARCH/PRD_DRAFT/ARCH/PLANNING/SPEC/FIX/REVIEW 는 §2 표의 `fodh docs scaffold <kind>` 를 첫 동작으로(이미 있다는 오류면 기존 파일을 고친다). ARCH·PLANNING 은 `fodh claude-md generate` 를 포함.

### 6-2. 치환 키와 `templates/README.md`

- `instruction()` 허용 키: `taskId`, `judgmentFile`, `backlogFile`, `docsRoot`, `today`, `interviewSummary`(INTERVIEW 에서만 계산, 그 외 빈 문자열: `남은 필수 N개 — 영역 03(1), 07(2)` 또는 `인터뷰 기록 없음`). 템플릿에 허용 밖 키가 있으면 예외(자동 재개 경로는 기존대로 send-failed 알림).
- `templates/README.md`: 폴더 지도(prompts/docs/interview/brain-rules/codex-header/claude-settings), 파일별 치환 키 표(프롬프트·scaffold·codex-header 각각), 5절 형식 규칙, 은행 줄 문법, 새 템플릿 추가 시 테스트가 검사하는 항목.

### 6-3. 명령 표

- `src/cli/index.ts` 가 `export const commandTable: { group: string; action?: string }[]` 를 내보내고, `main` 은 분기 전에 `(group, action)` 이 표에 없으면 `지원하지 않는 fodh 명령입니다. 가능한 명령: fodh <group> <action>, …` (같은 group 의 항목만 나열) 로 끝낸다. 표에 있는데 분기가 없으면 마지막 else 가 `명령 표와 분기가 어긋났습니다: <group> <action>` 을 던진다(구현 결함 표시). 이것으로 두뇌가 없는 명령을 쳤을 때 가능한 명령을 바로 본다(P3 실기 F3 과 같은 취지).
