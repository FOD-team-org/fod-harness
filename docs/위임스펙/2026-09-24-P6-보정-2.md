## 1. N1 — heredoc 파서가 `<<<` here-string·산술 `<<` 를 heredoc 시작으로 오인 (중간, 필수)

위치: `hooks/pretooluse.mjs` 셸 토크나이저(연산자 정규식 `&>>|&>|>>|<<-|<<|>|<`), `src/core/audit.ts` 의 복제본.

증상: `grep -q foo <<< "$v"` 다음 줄의 `rm -rf .git` 이 종료 표지를 기다리는 본문으로 취급되어 규칙 2·3·4·5·6 검사와 codex 직접 실행 금지가 통째로 빠진다. `$((1<<2))` 도 같다.

수정:
1. 연산자 정규식 맨 앞에 `<<<` 를 넣고, `<<<` 는 heredoc 표지를 만들지 않는다(뒤 단어는 일반 operand).
2. `$((` … `))` 와 `((` … `))` 안의 `<<`·`>>`·`<`·`>` 는 연산자로 보지 않는다(괄호 깊이 추적). 괄호 추적이 과하면 대안: 표지 후보가 식별자 모양이 아니면(인용 벗긴 뒤 `/^[A-Za-z_][\w.-]*$/` 불일치) heredoc 으로 보지 않고 일반 단어로 되돌린다. 두 방법 중 하나를 골라 결과 문서에 적어라.
3. 종료 표지를 끝내 찾지 못한 heredoc 은 fail closed: 두뇌(`FODH_BRAIN=1`)면 `[보호] heredoc 종료 표지를 찾을 수 없습니다` 로 거부한다. 사용자 세션은 허용(기존과 같음). 감사(audit)는 표지를 못 찾으면 남은 줄을 명령으로 검사한다.
4. 훅과 audit 두 파서에 같은 수정을 넣는다. 가능하면 파서를 한 파일로 합쳐라: `hooks/shell-parts.mjs`(순수 ESM, 의존 없음) 를 만들고 `hooks/pretooluse.mjs` 와 `src/core/audit.ts` 가 함께 import 한다(`src/core/audit.ts` 에서 `../../hooks/shell-parts.mjs` 상대 import, 타입은 `hooks/shell-parts.d.ts` 로 준다). `npm run typecheck` 가 0 이 아니면 합치지 말고 복제 유지 + 두 파서가 같은 입력에서 같은 groups/heredocs 를 내는 비교 테스트(`test/hook.test.ts` 또는 새 `test/p6-shell-parts.test.ts`)를 추가한다. 패키지 설치 시 `hooks/` 폴더가 함께 배포되는지(`package.json` `files`) 확인한다.

테스트(두뇌, 상태 IMPLEMENT, 훅 단위 호출): 다음은 거부 —
- `grep -q foo <<< "$v"\nrm -rf .git`
- `cat <<< x\nprisma migrate deploy`
- `echo $((1<<2))\ncodex exec …`
- `cat <<'EOF'\n본문` (표지 없음, 두뇌) → `[보호]`
다음은 허용 — `cat <<< x` 한 줄, `echo $((1<<2))` 한 줄, `cat <<'EOF'\nhello\nEOF` (기존 heredoc 정상).
audit 쪽: `grep -q foo <<< "$v"\necho x > src/a.ts` 에서 `src/a.ts` 가 쓰기 후보로 잡힌다.

## 2. 기존 테스트 정합 (H1 분류 도입에 따른 낡은 픽스처)

H1 뒤로는 `[승인]` 표지가 있는 거부만 판단대기 항목과 RECLAIM 을 만들고, 표지 없는 거부(`unknown`)는 원장 `hook:unknown:…` + `hook:unclassified` warn 만 남긴다(설계 §10, `test/p6-provider.test.ts` 가 이를 검증). 아래 기존 테스트는 표지 없는 문자열 `PreToolUse hook error` 로 승인 흐름을 기대하고 있어 실패한다. **소스는 그대로 두고 픽스처를 승인 표지로 바꾼다.**

- `test/p1-provider-revision.test.ts` `deniedEvents` 의 tool_result content → `PreToolUse hook error: 하네스 가드[승인]: 승인이 필요한 동작입니다 (fixture)`. 영향 테스트 3건: "M8: task 훅 denial 정상종료는 판단 한 개와 RECLAIM을 거쳐 blocked·PICK…", "M8: 프로젝트 훅 denial은 항목만 생성…", "M8·M4: 훅 회수 연속 실패는 CLEANUP_FAILED…".
- `test/fake-claude/claude` `denial-hang` 시나리오의 tool_result content → 같은 `[승인]` 문자열. 영향 테스트 2건: `test/revision.test.ts` "deadline 중단 전 훅 denial을 판단대기와 원장에 보존한다", "user 중단 전 …". 다른 시나리오(`p6-unknown` 의 `legacy error`)는 건드리지 않는다.
- 이 5건 + `test/p6-provider.test.ts` + `test/turn-policy.test.ts` 를 선택 실행해 통과를 확인한다.

## 3. N3 — `normalizePath` 가 EACCES·ELOOP·ENAMETOOLONG 을 던져 사용자 세션 편집 도구까지 "훅 입력을 해석할 수 없습니다" 로 거부 (낮음)

수정: `normalizePath` 가 위 오류를 만나면 두뇌가 아닌 세션은 lexical 정규화 경로(`path.resolve` + darwin 소문자)로 되돌려 비교를 계속한다. 두뇌는 `[경계] 경로를 확인할 수 없습니다: <경로>` 로 거부한다(포기가 아니라 다른 경로/위임으로 바꾸라는 뜻이므로 `[보호]` 가 아니라 `[경계]`). 테스트: 권한 없는 디렉터리 흉내(`chmod 000` 한 임시 폴더 아래 경로; root 로 돌면 건너뛰기) 또는 symlink 순환(`ln -s a a`) 으로 두뇌 `[경계]`·사용자 허용 각 1건.
