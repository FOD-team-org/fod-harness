## M1. Bash 경계 오탐 제거

`hooks/pretooluse.mjs` `writePaths`/`boundary`:
1. `/dev/null`, `/dev/stdout`, `/dev/stderr`, `/dev/tty`, `/dev/fd/*` 는 경계 대상에서 제외(리다이렉트·tee 모두).
2. Bash 경계는 **루트 안 소스 경로만** 거부한다. 루트 밖은 Write/Edit(규칙 4)와 규칙 2 rm 에서만 거부한다.
3. 인터프리터(`python*`, `node`, `perl`, `ruby`, `sh|bash|zsh`)의 operand 는 쓰기 대상이 아니다: `-m <모듈>`·`-e/-c <코드>`·스크립트 파일(첫 operand)·나머지 인자를 전부 경계 대상에서 뺀다(인라인 `FODH_` 판정 N10 과 사후 감사는 그대로).
4. `git stash` 는 `list|show` 면 제외.
5. heredoc: `<<`·`<<-` 뒤 종료 표지(따옴표 유무 무관)를 읽고 그 표지 줄까지의 본문을 명령 해석에서 제외한다. 본문 안 `>`·`codex` 는 판정하지 않는다.
6. 테스트(hook.test): `ls docs 2>/dev/null`, `fodh state get 2>/dev/null`, `cmd &>/dev/null`, `python3 -m json.tool < .pi/harness-state.json`, `node scripts/check.mjs`, `git stash list`, heredoc 본문에 `> 인용`·`codex x` 줄 → 모두 허용. `cat <<'EOF' > src/x.ts` 처럼 heredoc 이 소스로 리다이렉트되면 거부.

## M2. `git apply`·`patch` 는 대상 트리로 판정

1. `git apply`(인자에 `--check|--stat|--numstat|--summary` 없음)와 `patch`(`--dry-run` 없음)는 **작업 디렉터리 쓰기**다. 대상 = `git -C <d>`/`--directory=<d>`, `patch -d <d>`/`--directory=<d>`, 없으면 cwd. 대상이 등록 워크트리 안이 아니면 `[경계]` 거부("패치 적용은 워크트리에서만").
2. `src/core/audit.ts` 도 같은 규칙으로 대상 디렉터리를 후보에 넣는다.
3. README 한계 표에 `git stash pop|apply`, `git checkout <ref> <path>`(`--` 없음) 추가.
4. 테스트: `git apply .pi/scratch/fix.patch` 거부, `patch -p1 < docs/x.diff` 거부, `git -C <wt> apply x.patch` 허용, `git apply --check x.patch` 허용, `patch --dry-run` 허용.

## M3 + F1. 사후 감사 후보를 쓰기 문맥으로 한정, 알림 합치기

`src/core/audit.ts`:
1. 후보 = 리다이렉트 `>`/`>>`/`&>` 대상, `tee` 인자, `sed -i`·`perl -pi` 의 파일 operand, `cp|mv|install|rsync` 의 마지막 operand, `dd of=`, `touch|truncate` operand, 그리고 인라인 코드(`-e/-c` 문자열·heredoc 본문) 안에서 `writeFile(Sync)?|appendFile(Sync)?|createWriteStream|open` 호출 괄호 안 **첫 문자열 리터럴**(open 은 두 번째 리터럴이 `w|a` 를 포함할 때만). 그 밖의 토큰(읽기 명령 인자, sed 식, `require('fs')` 같은 코드 조각, `package.json` 읽기)은 후보가 아니다.
2. `src/provider/turn.ts`: 한 턴의 의심 경로를 원장에는 경로별 `audit:path-boundary warn` 으로, TUI 알림은 **1건**으로 합친다: `훅이 놓친 소스 쓰기 의심 N건: <최대 3개 경로>… (fodh ledger list)`. 같은 root 의 같은 경로는 프로세스 수명 동안 한 번만 알린다(모듈 스코프 Set).
3. 테스트(audit 단위 + p6-provider): `sed -n '1,9p' src/x.ts`, `grep -n foo src/a.ts | sed 's/a/b/'`, `cat package.json | node -e "…split('/')…"` → 빈 결과. `node -e "require('fs').writeFileSync('src/w.ts','x')"` → `src/w.ts` 만. `python3 -c "open('src/z.ts','w').write('x')"` → `src/z.ts`. 경고 3건인 턴 → notify 1회.
