### 범위·한계

### 범위·한계

- 실제 HOME에는 쓰지 않았다. HOME 관련 fixture는 `/private/tmp` 아래에 만들고 제거했다. `/` 검증도 쓰기 없이 가짜 Git만 사용했다. 실제 Git 명령은 테스트가 만든 임시 저장소에서만 실행했다.
- 실제 claude·codex·cswap·pi, 네트워크, 전체 테스트 스위트는 실행하지 않았다. 3회차 대상 훅·memory·state·worktree-setup·codex와 설계 문서는 변경하지 않았다. doctor는 공용 훅 판정 연결만 변경했다.
- doctor에는 기존 정적 PreToolUse 존재 판정 함수가 없고 옛 명령 문자열 감지·실제 두뇌 시험만 있었다. 따라서 init의 판정을 별도 공용 함수로 옮겨 doctor/init/start가 재사용한다. 실제 Claude 훅 작동 검증은 이번에 실행하지 않았고, 현재 판정은 설정의 정적인 존재·형식 확인이다.
- Ctrl-D 경로는 질문 입력의 EOF/close로 재현했다. 실제 터미널에서 키를 누르는 수동 검증은 하지 않았다. 빈 EOF와 정상 y/N 경로는 테스트했다.
- 훅 없는 기존 설정은 자동 덮어쓰지 않는다. init 결과의 병합 안내에 따라 사용자가 JSON 조각을 합친 후 다시 시작해야 한다. 차단된 start dry-run은 실행 없이 exit 0으로 거부 사유를 반환한다.

## 1회차 범위·판단·남긴 한계

- 작업 저장소에서 git 명령을 실행하지 않았다. Git 실행은 테스트가 만든 임시 저장소 안에서만 했다. 실제 claude·codex·cswap·pi, 네트워크, 전체 테스트 스위트는 실행하지 않았다. 런처 검증에는 가짜 pi만 사용했다.
- 프로세스 스냅샷과 외부 PID 동일성 검증은 주입 함수/모의 응답으로 수행했다. 실제 앱의 프로세스 트리 및 pi의 SIGHUP·SIGINT·Ctrl+Z 실기는 실행하지 않았다. 가짜 pi의 동일 PID exec는 확인했다.

- L1 dry-run은 실행하지 않으므로 살아 있는 잠금이 있어도 계획을 출력한다. 실제 start는 잠금을 거부한다. 따라서 실행 중인 두뇌도 dry-run을 사용할 수 있다.
- 재귀 읽기 거부 메시지는 H11-6의 경로 노출 제한을 우선해 상대경로 대신 basename 한 개만 표시한다. doctor의 명시된 진단 목록은 상대경로다.
