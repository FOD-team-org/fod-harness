## H1. 감독만 죽었을 때 codex 고아 (`slots.ts`, `watcher.ts`, `codex.ts`)

감독 pid = pgid, codex 는 같은 그룹. 감독이 SIGKILL 되면 codex 가 pgid 를 유지한 채 계속 돈다. POSIX 에서 그룹 구성원이 하나라도 남아 있는 동안 그 pgid 번호는 재사용되지 않으므로 "리더 사망 + 그룹 생존" 상태에서 `kill(-pgid)` 는 안전하다.

- (a) `slotOwnerAlive(owner)`: `isProcessAlive(owner.pid)` 가 거짓이어도 `groupAlive(owner.pid)`(runner.ts) 가 참이면 **점유 중**으로 본다. 반환값에 이유를 구분할 필요는 없다.
- (b) 워처 lost 경로(`watcher.ts` ~150행): 감독이 죽었고 60초가 지났을 때 `groupAlive(meta.pid)` 이면 먼저 `reclaimOwnedGroup(meta.pid)` 로 그룹을 회수한다. 회수 성공 후에만 `finishRun('lost')`. 실패하면 이번 tick 은 마감하지 않고 원장에 `{ action:'codex:lost', status:'fail', evidence:{ reason:'group-alive' } }` 를 남긴다(중복 방지: 같은 runId 는 tick 당 1회, `watch.codexLostFailed` 같은 필드는 두지 말고 원장만 남긴다).
- (c) `cancel`: 레지스트리 record 가 있고 `!isProcessAlive(record.pid) && groupAlive(record.pgid)` 이면 시작 시각 대조 없이 `reclaimOwnedGroup(record.pgid)`. record 가 없고 `meta.pid` 만 있는 경우도 같은 조건이면 회수한다(리더가 죽었으니 pid 재사용 위험은 그룹 생존으로 배제된다).
- (d) 회귀 테스트(`test/codex-core.test.ts` 또는 `test/slots.test.ts`): 가짜 감독 역할의 자식(예: `perl -MPOSIX -e 'setsid; system("sleep 30 &"); sleep 30'` 처럼 자기 그룹을 만들고 손자를 남기는 스크립트)을 띄운 뒤 리더만 SIGKILL → `slotOwnerAlive` 가 참, `acquireSlot` 거부; 워처 lost 처리 후 `groupAlive(pgid)===false` 와 meta `lost`. 샌드박스에서 ps 가 막혀 실패하면 결과 문서에 적는다.

## M1. meta 없는 `state.delegation` 교착 (`codex.ts`, `watcher.ts`)

- `startCodex`: `state.delegation` 의 meta 가 **없으면** stale 로 보고 원장 `{ action:'delegation:stale', status:'ok', evidence:{ runId } }` 를 남긴 뒤 진행한다(새 delegation 이 덮어쓴다).
- `cancel`: meta 가 없어도 `state.delegation?.runId === runId` 이면 delegation·awaitingDelegation 을 지우고 `{ runId, cancelled:true, meta:null }` 을 반환한다. 둘 다 아니면 지금처럼 오류.
- 워처: `state.delegation` 의 meta 가 없고 `delegation.startedAt` 후 60초가 지났으면 `codex-done`(codexStatus `lost`, `resultDir` 없음) 을 발행한다. dedupe 키는 동일 `codex-done:<runId>`.

## M2. `--wait` 가 두뇌 턴 한계를 넘는 문제 (`codex.ts`, 템플릿, 스펙 §2-5)

- `waitForResult` 상한 = `min((timeoutMinutes + 1), max(1, brain.maxTurnMinutes - 5))` 분. 초과 시 지금처럼 `CodexError('위임이 아직 진행 중입니다', { runId })`(exit 1, 감독은 계속).
- `startCodex` 는 `--wait` 여부와 상관없이 시작 직후 stderr 에 `{"runId":"…"}` 한 줄을 쓴다(stdout 은 JSON 결과 하나만 유지).
- `templates/prompts/REVIEW.md`·`RESEARCH.md`: "`--wait` 가 `위임이 아직 진행 중입니다` 오류로 끝나면 그 runId 로 `대기: 위임 <runId>` 를 적고 턴을 끝낸다" 를 추가한다.
- 스펙 `2026-09-24-P3-codex.md` §2-5 를 같은 내용으로 고친다.

## 실기 추가 항목

- **F5** `result()` errors 제외 정규식에 `unrecognized configuration settings` 를 추가하고, errors 는 중복 제거한다.
- **F6** `result()` changedFiles: `meta.cwd` 안의 경로는 cwd 기준 상대 경로로 바꾼다(밖이면 절대 경로 유지).
- **F7 (H1 보강, 필수)** codex 는 도구 명령을 **자기 pgid** 로 띄운다(실기: `sleep 150` pgid = 자기 pid). 그룹 신호만으로는 도구 자식이 남는다. 공용 함수 `processTree(rootPgid, rootPids)`(`src/core/codex-supervisor.ts` 또는 새 `src/core/proc-tree.ts`, 순수 파서 + ps 호출 분리)를 만든다: `/bin/ps -axo pid=,ppid=,pgid=` 한 번으로 (pgid === rootPgid 인 pid) ∪ (그 pid 들 + rootPids 의 ppid 자손 폐쇄) 를 돌려준다(자기 pid·ps pid 제외). 감독 `stopChildren`, 워처 lost 회수, `cancel`, `reclaim` 의 그룹 회수는 모두 신호 전에 이 스냅샷을 찍고, 스냅샷 전체에 TERM → 5초 대기 → KILL 을 보낸 뒤, (새 스냅샷 ∪ 이전 스냅샷 생존 여부) 로 잔존을 판정한다. `runner.ts reclaimOwnedGroup` 은 두뇌 그룹용이므로 건드리지 않고, codex 전용 회수 함수를 두어도 된다. 테스트: 가짜 codex(`test/fake-codex/codex`)에 `FAKE_CODEX_DETACHED_CHILD=1` 옵션을 추가해 `perl -MPOSIX -e 'POSIX::setsid(); exec "sleep","60"'` 처럼 자기 세션으로 손자를 띄우게 하고, cancel/timeout 뒤 그 손자가 죽었는지 확인한다.
- **F8** 워처 lost 경로: 그룹(및 F7 트리)이 이미 죽어 있고 `events.jsonl` 에 `turn.completed` 가 있으면 `status:'ok'`, `exit:null`, meta `supervisorLost:true` 로 마감한다(원장 evidence 에도 `supervisorLost`). `turn.completed` 가 없으면 `lost`. 그룹이 살아 있으면 H1(b) 대로 먼저 회수한다.
