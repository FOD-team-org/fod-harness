## 스펙이 침묵한 세부 선택·한계

1. H2의 원 단계 재개와 F4의 PICK 복귀 시 resumeState 삭제를 함께 만족시키기 위해, PICK으로 돌아올 때 `{ taskId, resumeState }`를 내부 `resumeTask`에 보관한다. RESUME 성공 또는 일반 task 선택 시 지우며 CLI 재개 우회 플래그는 노출하지 않는다.
2. 고아/정체 판단은 내부 resolution 메타데이터로 재개 ①·보류 ②를 구별한다. 선택 번호 없는 자유 서술은 자동으로 ready로 바꾸지 않는다. 보류는 결정 기록을 남기되 blocked를 유지한다.
3. 죽은 프로세스는 시작 시각을 더 이상 읽을 수 없다. 시각을 얻었는데 불일치하면 레지스트리를 보존하고, 시각 부재일 때는 커널의 그룹 부재(ESRCH) 확인에 한해서 기록을 제거한다. EPERM을 부재로 간주하지 않으며 brain·brain 공유 그룹에는 신호를 보내거나 기록을 제거하지 않는다.
4. 정리했다고 답해도 레지스트리에 살아 있거나 소유 확인이 되지 않는 기록이 남으면 적용을 보류한다. 정리 성공 후 pendingReclaim을 지우고 원 회수 판단이 열려 있으면 그 판단으로 task를 blocked에 남긴다. 정리 완료 답이 업무 승인 답을 대신하지 않는다.
5. 표 행 ID 자체가 손상되어 어떤 기존 행인지 확인할 수 없으면 기존 task 삭제로 추정하지 않는다. 두 번 연속 편집 경합은 오류로 멈추고 JSON·최신 사람 편집을 보존한다. 이 해시 재검사는 파일시스템 CAS가 아니므로 마지막 검사와 rename 사이의 극소 경합까지 제거한다고 주장하지 않는다.
6. provider의 거부 판단·회수는 해당 턴의 종료/중단 분류를 저장한 뒤 수행하여 뒤늦은 상태 저장이 회수 결과를 덮지 않도록 했다. billing 중단은 회수 뒤에도 유지한다.
7. 실제 Pi 이벤트 루프의 followUp 동작과 프린트/TUI 알림 렌더링은 대역 테스트만으로 확정하지 않았다. L1/F6 실기는 Fable에게 남긴다. P2 타이머/워처, P3 위임 생산자, P4 정리 실행은 추가하지 않았다.

의도적 이탈: 없음. 위 항목은 명시된 요구를 결합하거나 스펙이 정하지 않은 실패 상황에 대해 보수적으로 선택한 동작이다. `/bin/ps` 2건과 실제 TUI 확인은 허용된 환경 한계/이관이며 통과로 계산하지 않았다.
