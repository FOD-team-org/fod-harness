## F7 현상

`pi -p --no-session -e extensions/provider/index.ts -e extensions/orchestrator/index.ts --model claude-code/haiku "…"` 로 두뇌 턴을 돌리면 턴 자체는 성공(`상태: SPEC`, ledger `brain:0 ok`)하지만 stderr 에 아래가 찍힌다.

```
Extension error (extensions/orchestrator/index.ts): This extension ctx is stale after session replacement or reload. …
```

원인: `agent_end` 핸들러가 `setTimeout(0)` 뒤 `pi.sendMessage(…, {deliverAs:'followUp', triggerTurn:true})` 를 호출하는데, print 모드는 턴이 끝나면 `AgentSession.dispose()` → `extensionRunner.invalidate()` 로 ctx 를 무효화한다. 즉 print 모드에서는 자동 재개 followUp 이 항상 실패한다. TUI(대화형)에서는 세션이 살아 있으므로 해당 없음(사용자 확인 항목 L1).

## 요구

1. **print/RPC 모드에서는 자동 재개를 건너뛴다.** `agent_end` 에서 `ctx.hasUI === false` 이면 `autoTurns` 증가·followUp 전송을 하지 않고 종료한다(상태 파일 변경 없음). 이유: print 모드는 턴 종료 즉시 세션이 폐기되므로 followUp 이 도달할 수 없다. 자동 재개는 대화형 세션 전용이다.
2. **followUp 전송 실패를 삼키지 않되 확장 오류로 터뜨리지 않는다.** `send(…, automatic=true)` 를 try/catch 로 감싸고, 실패 시 `autoTurns` 를 되돌리고(증가 전 값) `ctx.ui.notify` 가 가능하면 warning 으로 알린다. 예외를 다시 던지지 않는다(다음 사용자 입력에서 정상 흐름으로 복구되면 된다).
3. **테스트**: (a) `hasUI:false` 인 ctx 로 `agent_end` 를 흘리면 `sendMessage` 가 호출되지 않고 `autoTurns` 가 그대로다. (b) `sendMessage` 가 throw 하면 핸들러가 reject 하지 않고 `autoTurns` 가 원복된다. 기존 `agent_end` 테스트는 `hasUI:true` 로 유지.
4. 설계 문서 `docs/설계/2026-09-24-하네스-설계-v0.3.md` v0.3.2 목록에 ⑪ "자동 재개는 대화형(hasUI) 세션 전용, print 모드는 단일 턴" 한 줄 추가. `templates/brain-rules.md` 는 변경 없음.
