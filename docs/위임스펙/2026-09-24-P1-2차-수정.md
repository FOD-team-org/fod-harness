- PLANNING 상태에서 `/develop-start` 를 다시 치면 task ≥1 일 때만 PICK 으로 넘어가고, 0개면 "백로그가 비어 있습니다. PLANNING 을 계속합니다" 알림만.

### H2 — 진행 중 task 고아화 금지 (재개 경로)
- 상태 파일에 `resumeState` 를 **일시정지에도** 기록한다: 프로바이더(`src/provider/turn.ts`)가 `paused(*)`·`recovering` 으로 바꿀 때 `resumeState = 직전 활동 상태`, `taskId` 유지.
- `src/core/state.ts`: `paused(*)→PICK`, `recovering→PICK`, `WAIT_RETRY→PICK`, `WAIT_RESOURCE→PICK` 은 **taskId 를 지우지 않는다**(`clearsTask` 에서 이 출발 상태들을 예외 처리). `IDLE|PLANNING|DONE_ALL|INTERVIEW|PROJECT_READY` 진입은 지금처럼 지운다.
- `src/core/pick.ts` `decidePick` 입력에 `current: { taskId?, resumeState? }` 추가. 판정 순서(위가 우선):
  1. 자원·과금 이력(기존 WAIT_RESOURCE 규칙).
  2. `retry.nextAt` 이 미래 → `WAIT_RETRY` (M6: ready 유무와 무관).
  3. **RESUME**: `current.taskId` 의 task 가 `doing|verify|review|fix|merge` 이고 `current.resumeState` 가 task 상태(`SPEC..CLEANUP`) → `{ outcome: 'RESUME', task, next: resumeState }`. `runPick` 은 `PICK→resumeState` 로 전이(task 상태 진입 가드는 그대로: doctor·task 존재). 이 전이는 `runPick` 내부 전용(`allowedTransition` 표를 넓히지 않고 `resume: true` 옵션으로 허용).
  4. **고아 task**: `current.taskId` 와 무관하게 `doing|verify|review|fix|merge` 인 task 가 있고 RESUME 대상이 아니면 → 판단 항목 "고아 task <ID>: 재개 / 폐기"(선택지 ① ready 로 되돌려 재개 ② blocked 유지(보류)), `--blocks <ID>` 로 task `blocked(A)` → 다음 후보 검토(고아가 여러 개면 각각). 그 뒤 ready 가 있으면 SPEC, 없으면 `WAIT_JUDGMENT`.
  5. 기존: 순환 → DEADLOCK, ready → SPEC, blocked 만 → WAIT_JUDGMENT, 전부 done → DONE_ALL.
- 정체 중단(`stopForJudgment`): task 상태(`SPEC..CLEANUP`, `RECLAIM`)에서 정체면 판단 "진행 정체: <state>/<task>" 를 `--blocks <task> --reclaim` 의미로 만든다(`reclaimTask` 호출 → task `blocked(A)`, 상태 `PICK`→`WAIT_JUDGMENT`). 프로젝트 상태·PLANNING·PICK 에서는 지금처럼 WAIT_JUDGMENT.
- 판단 적용으로 blocked 가 풀리면(ready) 다음 PICK 이 표 순서대로 다시 고른다. 재개 판단 ① 은 `ready`, ② 는 blocked 유지.
- 테스트: paused(error)→PICK→RESUME(IMPLEMENT), recovering→PICK→RESUME, 고아 task → blocked(A) + 판단, 정체 중단 → blocked(A) → apply → ready → PICK → SPEC.

## 2. 중간

### M1 — 사용자 답 대기 표지
- 두뇌 규칙(`templates/brain-rules.md`) 마지막 줄을 "턴 마지막 줄에 `상태: <현재 fodh state>` 를 적는다. 사용자의 채팅 답을 기다려야 하면 그 앞 줄에 `대기: 사용자` 를 적는다." 로 바꾼다.
- 오케스트레이터: `agent_end` 에서 마지막 assistant 텍스트에 `대기: 사용자` 줄이 있으면 자동 재개하지 않고 `autoTurns` 를 0 으로. 또한 `fodh state await-user` 명령(상태 파일 `awaitingUser: true`) 도 같은 효과. 사용자 메시지로 시작한 턴(`before_agent_start` 또는 동등한 0.73.1 이벤트에서 마지막 메시지 role=user 이고 하네스 customType 이 아닌 경우)이 시작되면 `awaitingUser` 해제 + `autoTurns` 0.
- INTERVIEW 지시문에 "서술형 질문을 던지고 답을 기다릴 때는 `대기: 사용자` 를 적고 턴을 끝낸다" 추가. 기존 `orchestrator.test.ts:130-137` 은 "INTERVIEW 정상 종료 + 대기 표지 없음 → followUp / 표지 있음 → 무전송" 으로 바꾼다.

### M2 · F2 — `fodh backlog set` 가드
- `--repair` 옵션 제거(repair 는 FIX 진입 시 +1, `--spec-rev` 증가 시 0 만).
- `--status` 는 `done` 만 받는다. `done` 은 **현재 상태가 `CLEANUP` 이고 `state.taskId === ID`** 일 때만 허용(DoD 검사 유지). 그 외 값은 오류 "상태는 전이로만 바뀝니다". 상태 전이가 task 상태를 함께 기록한다: `SPEC|IMPLEMENT→doing`, `VERIFY→verify`, `REVIEW(task)→review`, `FIX→fix`, `MERGE|DOCS|CLEANUP→merge`. `blocked(A)`↔`ready` 는 reclaim/apply 만.
- SPEC 지시문의 다음 명령을 "스펙을 **개정했을 때만** `fodh backlog set {{taskId}} --spec-rev <n>`" 로 분리(repair 언급 삭제).
- 기존 `p1-core.test.ts:202` 는 FIX 전이 반복으로 repair 를 올리는 방식으로 바꾼다.

### M3 — `CLEANUP→PICK` 완료 가드
- `pendingReclaim` 이 없으면 `getTask(taskId).status === 'done'` 필수. 아니면 오류 `{ error: 'task 미완료', missing: [...] }`(DoD 미충족 목록 재사용).

### M4 — 죽은 레지스트리 기록 정리 + CLEANUP_FAILED 재시도
- `cleanupReport`(및 `fodh cleanup report`)는 각 non-brain 기록에 대해 시작 시각 검증 후 `groupAlive === false`(ESRCH) 인 기록을 레지스트리에서 제거한다(신호 없음). 제거 목록을 `removed` 로 반환.
- 상태 파일 `cleanupFailures` 카운터: RECLAIM/CLEANUP 실패 시 +1. 1회째는 `CLEANUP_FAILED`, 2회째(연속)는 `paused(cleanup)` + 판단 항목 "정리 실패: 잔존 프로세스 <pid 목록>"(선택지 ① 사용자가 정리했음 → PICK ② 보류) 자동 생성. 성공 시 0.

### M5 · M6 — WAIT_RETRY / WAIT_RESOURCE 탈출과 백오프 우선
- `/develop-start` 허용 출발 상태에 `WAIT_RETRY`(`retry.nextAt` 경과 시; 미경과면 "n분 뒤 재시도 예정" 알림만) 와 `WAIT_RESOURCE`(사용자가 명령했으므로 회복으로 간주) 추가.
- `WAIT_RESOURCE→PICK`, `WAIT_RETRY→PICK` 진입 시 `lastPaused` 와 `retry` 를 함께 초기화… 단 WAIT_RETRY 는 nextAt 경과 시에만 초기화(M6 의 백오프 유지).
- `decidePick`: `quota|error` 이력 + `retry.nextAt` 미래 → ready 유무와 무관하게 WAIT_RETRY(위 H2 순서 2). 첫 error 뒤 예약 전이면 5분 예약을 만든다.

### M7 — 재질문 체인 종결

### M8 — 승인 필요 → RECLAIM 일관화
