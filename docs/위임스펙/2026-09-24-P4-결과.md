## 스펙과 다른 선택 및 이유

- §5-3 진입 지점은 실제 코드에서 오케스트레이터뿐 아니라 CLI·프로바이더에도 있다. 따라서 공용 `updateState`에서 WAIT/paused 저장 직전에 정리한다. 긴 정리 중 상태 잠금을 점유하지 않고 저장 직전에 기존 상태가 유지되는지 비교·재시도하여 동시 기록과 교착을 막는다. `cleanup-due`는 만들지 않았다.
- `unverified`도 `ok:false`로 처리한다. 신원 미확인을 정리 완료 증거로 사용하지 않기 위해서다. `cleanupReport` API는 유지하며 neverKill/활성 위임을 보호 항목에 포함해 보호된 개발 서버가 `--cleanup-ok`를 막지 않게 했다. RECLAIM의 다른 task 잔존에 대한 기존 보수적 성공 제한은 유지한다.
- `.pi`·`.git`와 프로젝트 루트는 rebuildablePaths로 삭제하지 못한다. keepPaths의 부모도 삭제하지 않는다. 부모 재귀 삭제로 보존 대상이나 하네스 증거가 사라지는 것을 방지한다. 내부 Codex 실행 보존 정책만 별도 적용하며, meta.runId와 디렉터리 이름이 다른 손상 기록은 건드리지 않는다.
- killPatterns/neverKill은 명령 문자열의 리터럴 부분 문자열로 분류/보호한다. killPatterns는 회수 필터가 아니며 전역 신호를 허용하지 않는다.
- 사용자 Bash timeout이 짧으면 설정 파일을 덮어쓰지 않고 실제 wait 상한을 해당 timeout의 90%로 낮춘다. CLI 반환 여유를 확보하고 정수 waitMinutes 설정 계약을 유지한다.
- 세션 소유권은 레코드의 선택 필드 `sessionId`와 자식 환경 `FODH_SESSION_ID`로 전달한다. 이전 세션/구형 레코드는 shutdown에서 건드리지 않고 명시적 정리에서 처리한다. 기존 print 모드의 무타이머 계약을 유지한다.
- heavy 슬롯에 선택 필드 `kind`와 검증 자식 신원을 저장하여 CLI가 먼저 죽어도 살아 있는 검증 자식 동안 Codex 진입을 막는다.
- sharedCaches는 enabled=true여도 **크기·경로 보고만** 한다. 삭제 없음. 경로/크기 측정 불가 시 크기는 null이다. Slack은 **`notify:slack skip` 원장만**, SDK/네트워크 호출 없음. budget은 값 검증·저장만 한다.

### 제한으로 완료하지 못한 검증

- **샌드박스 `/bin/ps` 실패 1건**: `test/verify.test.ts:46` 「타임아웃은 등록된 프로세스 트리만 회수하고 뒤 명령을 실행하지 않는다」. `:52`에서 timedOut:true이나 residual:true로 실패했다. 실제 프로세스 트리 조회가 제한되어 residual:false를 확인하지 못했으며, 기존 단언을 그대로 두었다. 외부 재확인이 필요하다.
- **git 금지에 따른 미선택**: 기존 `test/cleanup.test.ts`는 git worktree를 실행하는 통합 테스트를 포함한다. 이번 사용자의 예외는 임시 디렉터리 `git init`뿐이므로 파일 전체는 실행하지 않고 수정한 verify 보호 케이스만 선택했다. 나머지 17개(실제 sleep 회수, 워크트리 3건, 기존 프로세스·저장소 검증 포함)는 이번 실행에서 검증하지 않았다. 새 N1/N2 경로는 git 없는 전용 파일에서 모두 검증했다.
- 실제 Pi TUI·샌드박스 밖 회수 실기는 하지 않았다. 전체 스위트·git 명령·실제 claude/codex/cswap 실행·전역 pkill/killall은 모두 0회다. Codex 시작 테스트는 spawn mock이고 verify는 테스트용 짧은 Node 스크립트만 실행했다.
