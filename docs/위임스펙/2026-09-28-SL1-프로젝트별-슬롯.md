## 3. 변경

### 3-1. `slots.ts` 시그니처

- `slotsPath(root)` — 프로젝트 슬롯 파일 경로.
- `acquireSlot(kind, owner, options)` — 파일은 `owner.root` 기준. 나머지 동작(죽은 소유자 `slot:stale` 정리, codex↔heavy 배타)은 그대로.
- `updateSlot(root, kind, runId, patch)`, `releaseSlot(root, kind, runId)`, `slotsStatus(root)` — `root` 인자 추가.
- 호출부 전부 맞춘다: `codex.ts`, `codex-record.ts`, `codex-supervisor.ts`, `verify.ts`, `watcher.ts`, `extensions/orchestrator/resume.ts`, `src/cli/index.ts`.
- `Slots` 형식(`codex`·`heavy`·`claude`)과 `SlotOwner` 필드는 그대로 둔다.

### 3-2. 외부 Codex 감지

1. 후보 = 지금 `externalCodex()` 조건을 만족하는 **모든** 프로세스(companion `task` 또는 `codex exec`, 하네스 감독·ChatGPT.app·Codex.app 자손과 현재 프로세스 조상 제외, 유휴 app-server 제외 — 조건 자체는 바꾸지 않는다).
2. 후보마다 위치를 정한다.
   - 명령 인자 `-C`·`--cd`·`--cwd`·`--root`·`--project-root`(공백 또는 `=` 형태)가 있으면 그 값.
     - 상대 경로면 그 프로세스의 cwd 기준으로 푼다. cwd 를 모르면 위치 모름.
   - 인자가 없으면 그 프로세스의 cwd(`lsof -a -p <pid> -d cwd -Fn`, 1초 제한, `LC_ALL=C`).
   - cwd 조회는 테스트에서 주입할 수 있게 한다(예: `options.cwdOf?: (pid) => Promise<string | undefined>`). 지금처럼 `commandSnapshot` 이 첫 후보만 `root` 를 채우는 방식은 버린다.
3. 프로젝트 영역 = 아래 경로 자신 또는 그 하위. 비교는 realpath 기준(macOS `/var` → `/private/var` 포함, 없는 경로는 기존 `prospectiveRealpath` 방식).
   - (a) 하네스 루트
   - (b) 워크스페이스면 각 멤버 레포 경로(`workspaceMembers`)
   - (c) 워크트리 영역: 단일 레포는 `worktrees.root` 바로 아래에서 이름이 `worktrees.prefix` 로 시작하는 디렉터리. 워크스페이스는 멤버마다 같은 규칙
   - (d) `listWorktrees(root)` 가 돌려주는 등록 워크트리 경로
4. 판정
   - 영역 안 후보가 하나라도 있으면: 그중 첫 번째를 지금처럼 `external: true` 소유자로 슬롯에 기록하고 거부한다. `owner.root` = 그 후보의 위치(정규화 경로).
   - 영역 밖 후보: 세지 않는다. 원장도 남기지 않는다.
   - 위치 모름 후보: 세지 않는다. 원장 `slot:external-unlocated`(status ok, evidence `{ pid, command }`, command 는 기존 redact 후 앞 200자).
   - ps 조회 실패는 지금처럼 `slot:external-scan fail` 만 남기고 진행.
5. 영역 계산 실패(설정 읽기 오류 등)는 지금 externalGuard 경로와 같은 방식으로 원장에 남기고, 이 경우만 **보수적으로** 루트 하나만 영역으로 쓴다.

### 3-3. 대기 해제 판정

- 워처 `slot-free`(`watcher.ts` 128 부근): 읽는 파일만 `slotsPath(root)` 로 바꾼다. 로직은 그대로.
- `resume.ts` 85 부근: `slotOwnerAlive(state.awaitingSlot.owner)` 대신 **이 프로젝트 슬롯 파일의 현재 소유자(heavy·codex) 중 살아 있는 것이 있는지**로 판단한다.
  - 살아 있는 소유자가 없으면 표지가 가리키는 소유자가 아직 살아 있어도 낡은 표지다. 지금의 정리 경로(표지 지움, `paused(slot)`·슬롯 대기 `WAIT_RESOURCE` → PICK)를 탄다.
  - 수용 기준: 업그레이드 직후 `awaitingSlot.owner` 가 다른 프로젝트의 살아 있는 외부 Codex(`external-63785` 같은)인 프로젝트가 워처 60초 주기 안에 스스로 풀린다.

### 3-4. `fodh slots status`

- 현재 프로젝트 슬롯을 보여준다. 루트 해석은 다른 `fodh` 명령과 같다.
- 출력에 `path`(슬롯 파일 경로)를 더한다. 나머지 필드(`codex`·`heavy`·`claude`·`alive`)는 그대로.

## 4. 테스트

새 파일 `test/sl1-project-slots.test.ts`. 루트는 임시 디렉터리, HOME 도 임시로 둔다.

| # | 시나리오 | 기대 |
|---|---|---|
| T1 | 프로젝트 A 가 codex 보유 중 B 가 codex 획득 | 성공. A·B 슬롯 파일이 각자 루트에 따로 생김 |
| T2 | A 가 heavy 보유 중 B 가 codex 획득 / 같은 A 에서 codex 획득 | B 성공 / A 거부(배타 유지) |
| T3 | 외부 후보 `--cwd <A 영역 밖>` 하나 | A 획득 성공, 원장 `slot:external-*` 없음 |
| T4 | 외부 후보 `--cwd <A 루트 하위>` / `--cwd=<A 워크트리 prefix 디렉터리>` / `-C <워크스페이스 멤버(루트 밖) 하위>` / 인자 없음 + cwdOf = A 루트 | 모두 거부, 슬롯에 external 기록, `owner.root` = 후보 위치 |
| T5 | 후보 순서: 영역 밖 후보가 먼저, 영역 안 후보가 뒤 | 거부(첫 후보만 보던 동작의 회귀) |
| T6 | 인자 없음 + cwdOf 실패 | 성공 + `slot:external-unlocated` 1건 |
| T7 | 상대 경로 인자 + cwdOf 있음 / 없음 | cwd 기준으로 풀어 판정 / 위치 모름 |
| T8 | 루트가 심링크 경로(realpath 다름) | 영역 판정이 realpath 로 맞음 |
| T9 | 임시 HOME 의 `~/.pi/agent/fod-harness/slots.json` 에 살아 있는 소유자 | 무시하고 획득 성공, 그 파일은 바뀌지 않음 |
| T10 | 상태 `paused(slot)` + `awaitingSlot.owner` = 살아 있는 다른 프로젝트 외부 프로세스 + 프로젝트 슬롯 비어 있음 | 워처가 `slot-free` 를 내고, `resume.ts` 가 `skipped: 'slot'` 을 돌려주지 않는다 |
| T11 | `slotsStatus(root)` | `path` 가 프로젝트 파일, 다른 프로젝트 소유자는 안 보임 |

기존 테스트:

- `FODH_SLOTS_DIR` 를 쓰는 기존 테스트(약 14개 파일)는 새 시그니처·경로에 맞추기만 한다. 단언 의미를 바꾸는 줄은 **전·후를 결과 문서 표에 전부** 적는다.
  - 두 루트가 전역 슬롯을 공유한다는 전제의 단언이 있으면 뒤집고 표에 적는다.
- 그 밖의 기존 테스트 단언은 바꾸지 않는다.

## 5. 작업 규칙

- 전체 테스트(`npm test`, 인자 없는 `npx vitest run`)는 돌리지 않는다. 관련 파일만 `npx vitest run <파일…>` 로 돌린다. 전체는 Claude 가 돌린다.
- `npm run typecheck` 는 돌려도 된다.
- 샌드박스가 `.git` 쓰기와 `/bin/ps` 를 막는다. 커밋·브랜치는 만들지 않는다. ps 가 필요한 테스트는 스냅숏 주입으로 쓴다.
- 비밀값을 파일·출력에 쓰지 않는다.
- 결과 문서 `docs/위임스펙/2026-09-28-SL1-결과.md`: 요약, 변경 파일:줄 표, 기존 테스트 변경 전·후 전체 목록, 새 테스트 목록, 돌린 테스트 파일과 결과 수, 남은 한계.
