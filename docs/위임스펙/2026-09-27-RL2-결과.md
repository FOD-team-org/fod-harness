# RL2 사용량 관리 cswap 일임 — 구현 결과

## 요약

- 사용량 이벤트는 `status === 'rejected'`만 `quota`, 나머지는 `continue`로 처리한다. `rateLimitInfo` 기록은 유지한다.
- 하네스의 계정 전환·즉시 재시도·`switch` 원장을 제거했다. 한도 분기는 doctor 오류 → 현재 run의 unknown 복구 → `paused(quota)` 순서를 유지한다. 재시도는 기존 PICK 백오프가 맡는다.
- API 키 과금 차단은 유지하고 알림·doctor 문구를 스펙과 일치시켰다. `brain.switchCommand` 설정 읽기·검증·승인 목록은 호환용으로 유지했다.
- 지정 범위 **16개 파일, 682개 테스트 통과**(신규 114개 + 기존 568개), 실패·skip 0개. `npm run typecheck` 통과.
- `/bin/ps` 샌드박스 차단 실패: **0건**. 실제 서비스·계정 전환 연동은 실행하지 않았다.

## 새 테스트

`test/rl2-usage.test.ts`의 114개 테스트:

- status 5종 × overageStatus 5종 × isUsingOverage 3종 = 75칸. rejected인 15칸만 quota.
- undefined·null·문자열 및 boolean·숫자·배열 6건, 실제 warning 객체 1건, 특이 overageStatus 6건, 특이 isUsingOverage 4건.

## 범위 확인과 남은 한계

- `/bin/ps` 차단 실패는 이번 실행에서 **0건**이었다. 해당 환경 제약으로 미실행·skip한 테스트도 없다.
- 작업 전후 해시 비교로 `hooks/`, `templates/`, `skills/`, `docs/설계/`, `test/fake-claude/claude`, `test/fake-claude/switch`, `src/core/pick.ts`, `src/core/config.ts`, `src/provider/preflight.ts`가 변경되지 않았음을 확인했다. 기존 테스트 변경도 위 허용 목록으로 한정했다.
- 소스 검색상 `brain.switchCommand`는 설정 타입·읽기/검증·승인 목록에만 남아 있으며 provider에서 실행하지 않는다. `/status` 표시·PICK 문구·백오프는 변경하지 않았다.
- 저장소에서 git 명령을 실행하지 않았다. 테스트 내부 git은 테스트가 생성한 임시 저장소에서만 실행됐다. 전체 테스트 스위트는 실행하지 않았다.
- 실제 claude·codex·cswap·pi·osascript, 네트워크 요청은 실행하지 않았다. 가짜 두뇌 테스트는 임시 HOME을 사용하며 실제 HOME 인증 파일을 열지 않았다. 비밀값 출력·기록 없음.
- 실제 cswap 자동 전환과 장시간 5·15·60분 운영 연동은 미검증이다. 이번 증거는 가짜 두뇌·기존 백오프 판정·지정 회귀 테스트·타입 검사 범위다.
