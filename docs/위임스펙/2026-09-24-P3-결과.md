## 자식 모델 설정 키 실측

실행한 실제 Codex 명령은 다음 도움말 3개뿐이다. 모두 종료 코드 0이었다.

```sh
codex --help
codex exec --help
codex exec resume --help
```

- 새 `exec`: `-s`, `-C`, `-m`, `-c`, `--json`, `-o`, stdin `-` 확인.
- `exec resume`: `-s`·`-C` 없음. 따라서 스펙대로 `-c sandbox_mode="read-only|workspace-write"`와 spawn cwd를 사용한다.
- **자식 모델 지정 키: 키 없음(이번에 허용된 도움말·로컬 설정 확인 범위에서 발견하지 못함).** `~/.codex/config.toml`은 읽기만 했으며 관련 키만 추려 확인했다. 확인된 것은 `[features] multi_agent = true`이고, 자식 모델/effort 설정이나 agents/multi_agent 설정 절은 없었다. CLI가 제공할 수 있는 모든 미문서화 키가 없다는 뜻은 아니다.
- 확인되지 않은 `-c` 키를 추측해 추가하지 않았다. 머리말로 기본 동시 1개·`gpt-6-sol`·`xhigh`를 지시한다. 부모는 `gpt-6-astra`·`xhigh`다.
- 도움말 실행에서 PATH alias 생성의 `Operation not permitted` 경고가 있었지만 도움말 출력은 정상이다. 실제 에이전트 실행·인증 조작·설정 쓰기는 하지 않았다.

## 스펙이 침묵하거나 기존 계약과 충돌한 부분의 선택

1. **인박스 필드 충돌:** 기존 `InboxRecord.status`는 detected/queued/delivered/applied이고, `runId`는 provider 전달 시 두뇌 턴 ID로 바뀐다. 기존 계약을 유지하면서 완료 사실에 `codexStatus`, `codexRunId`를 추가했다. 발행 당시 `runId`도 Codex runId이며, 결정·결과 조회 지시·중복 방지는 영속 `codexRunId`를 사용한다. 스펙의 완료 status는 `codexStatus`로 표현한다.
2. **시작 경합:** 감독 spawn 전 슬롯을 호출 CLI의 PID로 임시 예약하고 spawn 직후 감독 PID·시작 시각으로 교체한다. 프로젝트 `harness-delegation` 잠금을 감독도 기다려 부모의 meta/레지스트리/task/state 저장이 끝나기 전에 Codex가 시작하지 않게 했다. 초기화 실패는 아직 실행을 시작하지 않은 감독을 종료하고 실패를 마감한다.
3. **마감 공용 모듈:** 감독·cancel·lost의 중복 구현을 피하기 위해 범위 표 외 `codex-record.ts`를 추가했다. meta별 잠금 안에서 thread·원장·슬롯·레지스트리를 처리하고 `finishedAt`을 마지막에 게시한다. 이미 마감한 실행은 다시 마감하지 않는다. 갑작스러운 프로세스/디스크 장애가 여러 파일 사이를 끊는 경우의 원장 복구는 기존 복구 경로가 담당한다.
4. **대기/인박스:** wait 완료는 자기 run의 delegation만 해제한다. 워처 완료 인박스는 그대로 생성된다. 일치하는 완료 인박스는 idle/busy 모두 다음 provider 프롬프트에 남겨 두뇌가 결과를 읽고 ack하도록 한다. 다른 run이거나 이미 해제된 경우만 알림 없이 applied로 닫는다. 표지 검사와 완료 대기 해제는 기존 resume 잠금으로 직렬화했다.
5. **완료 중복 수명:** watch.codexEmitted는 최근 50개다. 오래된 결과 디렉터리를 매 tick 다시 읽으므로 영속 인박스의 codexRunId도 확인하여 50개 밖 완료가 재발행되지 않게 했다.
6. **경로 경계:** spec/cwd/워크트리를 realpath 기준으로 검사하여 심링크 탈출을 거부한다. 등록 워크트리의 하위 디렉터리도 cwd로 허용한다. worktrees.root는 상대 경로이고 최종 위치가 프로젝트 내부 또는 프로젝트의 조상인 경우 거부한다. 실행 정보와 result에 worktree·routeHint를 포함한다.
7. **보수적 소유권:** ps가 불가능하거나 저장된 시작 시각이 `spawn:` 대체값이면, 살아 있는 PID의 슬롯을 임의로 탈취하지 않는다. cancel은 시작 시각을 확인할 수 없으면 신호를 보내지 않고 기존 위임을 보존한다. 이를 별도 회귀 테스트로 확인했다.
8. **회수/측정:** 감독 자신을 제외한 같은 pgid 구성원만 TERM→5초→KILL→잔존 확인한다. 정상 종료 뒤에도 ps로 보이는 잔존 자손은 회수한다. 정상 자식 종료 후 ps가 제한되면 잔존 확인을 성공했다고 주장하지 않는다. RSS는 30초 표본이므로 짧은 실행이나 ps 실패의 peakRssMB=0은 미측정일 수 있다. 분리된 다른 프로세스 그룹 자손의 일반 회수는 P4 범위다.
9. **CLI 보완:** 디자인 Agent 구현 경로가 task.delegate를 기록할 수 있도록 `fodh backlog set --delegate claude|codex`를 추가했다. result는 부분 JSONL의 마지막 불완전 줄을 무시하고 command_execution을 item ID 기준으로 중복 계산하지 않는다.
10. **테스트:** timeoutMinutes의 공개 검증은 양의 정수 그대로다. 실제 환경용 timeout 테스트만 loadConfig 대역으로 짧은 값을 감독 meta에 전달한다. 테스트 fixture의 초기 HEAD는 빈 Git 객체를 직접 작성하여 구성했으며 git commit은 실행하지 않았다. 기존 30분 경계 테스트는 해당 테스트 안에서 30을 명시하여 기존 동작 검증을 유지하고, 기본값 테스트만 90으로 바꿨다.

## 미완·의문·인계

- **샌드박스에서 미실행:** timeout의 stubborn 자손 포함 그룹 잔존 0, cancel의 실제 시작 시각 대조·그룹 회수, 기존 revision의 실제 PID 재사용 확인. 테스트는 실행했으나 `/bin/ps` 선행 호출의 `spawn EPERM`으로 중단되어 이 세 검증 본문은 수행하지 못했다. 조건부 skip·테스트 삭제·단언 완화는 하지 않았다. 일반 환경에서 위 관련 명령을 재실행해야 한다.
- **Fable 실기:** 실제 `codex exec` 1회와 tmux Pi TUI에서 비동기 완료→재개, resume의 sandbox/cwd 적용, 자식 모델 머리말 준수, timeout/cancel과 RSS 측정 확인이 남았다. 도움말 확인과 가짜 Codex 통과는 실제 모델 실행 증거가 아니다.
- 공개 설정 키 미확인으로 자식 모델/effort/동시성은 프롬프트 지시다. 강제 설정 키를 확인하면 별도 보완할 수 있다.
- 구현 항목의 의도적 생략은 없다. 작업 저장소에서 git 명령·커밋·push는 수행하지 않았다. Git 실행은 테스트의 임시 저장소 검증 안에서만 있었고, 실제 claude/cswap/codex 에이전트·서브에이전트는 실행하지 않았다. 비밀 설정 전문·비밀값·zip 등 산출물은 기록하거나 만들지 않았다.

## 2차 수정

### 원인

Fable이 일반 환경에서 전체 테스트를 실행한 결과는 22파일 중 codex-core 9건 실패, 나머지 729개 통과, typecheck 오류 0개였다(전달받은 검증 결과). 감독의 자식으로 실행한 `/bin/ps`가 같은 프로세스 그룹 출력에 자기 PID를 포함하여, 정상 종료도 잔존 자손으로 오인했다. 그 결과 불필요한 TERM/KILL 대기 약 7초 후 `exit:0, status:fail`로 마감했고 후속 테스트는 기본 5초 제한에 걸렸다. RSS 합계에도 표본을 수집하는 ps 자신의 메모리가 포함됐다.

### 변경

- `src/core/codex-supervisor.ts`: 각 `execute('/bin/ps', …)`의 반환 promise에서 **await 전에 `pending.child.pid`를 확보**한다. 그룹 조회는 감독 PID와 그 조회의 ps PID를 정확히 제외한다. 프로세스 이름/comm 기반 판별은 쓰지 않는다.
- 그룹 출력 해석을 순수 함수 `parseGroupMembers(stdout, pgid, excludePids)`로 분리했다. 감독과 조회 ps만 있으면 빈 목록을 반환하므로 정상 종료는 `stopChildren`의 5초+2초 대기로 들어가지 않는다.
- RSS 조회 열을 `pid=,rss=`로 바꾸고 순수 함수 `parseGroupRssMB(stdout, excludePids)`에서 해당 조회 ps PID만 제외한다. 감독과 실제 자식의 RSS는 포함하며 KiB를 MiB로 환산한다.
- `test/codex-core.test.ts`: 순수 함수 회귀 4개(조회 ps 제외 후 잔존 0, 실제 자손 보존/다른 그룹 제외, ps RSS 제외, 빈/잘못된 행)와 정상 fake 종료 1초 미만 단언 1개를 추가했다.
- 타임아웃 재검토: 정상 테스트의 기본 Vitest 5초 제한을 늘리지 않았다. 완료 폴링 helper의 기본 상한은 12초에서 4초로 줄여 테스트 제한보다 먼저 실패하도록 했다. 정상 실행의 실제 완료 시간과 meta.durationSeconds는 별도로 1초 미만을 단언한다. `--wait`의 2초 폴링 및 여러 실행을 포함하는 기존 테스트는 15초, TERM/KILL 회수 통합 테스트는 20초 제한을 유지한다.

### 스펙과 다른 부분·남은 사항

- R1~R3의 의도적 생략이나 스펙 이탈 없음. 옛 숫자 그룹은 생존하더라도 회수 권한으로 인정하지 않는다. 이미 사라진 그룹은 회수 대상 및 `skippedGroups`에서 제외한다. 64개 상한에서는 살아 있는 기존 기록을 우선 보존하고 여유가 있을 때 새 그룹을 추가한다.
- 새 가짜 PID 테스트는 `processStartedAt`·`processGroup` 및 생존 여부를 mock하여 실제 시스템 PID와 무관하게 실행한다. gone의 숫자-only 회수 기대값은 새 스펙대로 비회수·원장 기록으로 바꾸고, 신원이 맞는 그룹의 회수 단언을 별도로 유지했다. 기존 테스트 단언 약화·조건부 skip 없음.
- R4·R5는 스펙대로 P4 이월. 남은 검증은 위 실제 ps 통합 테스트 7개다.
- git 명령, 실제 claude/codex 실행, 전체 스위트, 서브에이전트, 비밀값 기록 및 별도 산출물 생성은 하지 않았다.
