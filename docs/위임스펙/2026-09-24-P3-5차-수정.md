### R1 — toolGroups 가 번호만으로 회수됨
- (a) 감독의 표본(시작 1회 + 30초마다)에서 도구 그룹마다 구성원 하나의 신원 `{ pgid, pid, startedAt }`(ps `lstart`, `LC_ALL=C`)을 meta `toolGroups` 에 저장한다(형식을 `number[]` → `{pgid,pid,startedAt}[]` 로 바꾼다. 읽는 쪽은 옛 숫자 형식도 받되 신원 없는 그룹으로 취급).
- (a-2) 표본마다 이미 죽은 그룹(`groupAlive(pgid)` 거짓)은 목록에서 지운다 — 실기에서 1분 만에 죽은 pgid 8개가 쌓였다(codex 는 도구 명령마다 새 그룹을 만든다). 살아 있는 그룹만 남기되 상한 64개.
- (b) 회수 직전 그 구성원이 같은 시작 시각(±2초)으로 살아 있고 `processGroup(pid) === pgid` 일 때만 그 그룹에 신호를 보낸다. 확인되지 않은 그룹은 원장 `reason:'tool-group-unverified'` 로 남기고 건너뛴다(회수 결과에 `skippedGroups` 포함).
- (c) foreign(`pid-reused`)·unverified 분기에서는 toolGroups 에도 신호를 보내지 않는다(스펙 N2(c) 문구대로 "신호 없이 마감"). gone·orphan·owned 분기만 (b) 의 확인을 거쳐 회수한다.
- (d) 테스트: foreign·unverified·gone 각각에서 신원이 맞지 않는 toolGroup 에 `reclaimCodexTree` 가 호출되지 않는 것, owned/gone 에서 신원이 맞는 그룹은 회수되는 것(모의 ps 표), 실제 ps 통합 테스트(`FAKE_CODEX_BACKGROUND_TOOL=1`)는 새 형식으로 갱신. gone 테스트의 기존 기대값(번호만으로 회수)을 새 규칙으로 바꾼다.

### R2 — 자식 신원 조회 실패가 unverified 로 떨어짐
- `codexOwnership`: 자식 `processIdentity` 가 `unknown` 이거나 `processGroup` 이 undefined 이면 `unknown` 을 돌려준다(보존). 테스트: ps 실패 mock → `unknown` → 슬롯 점유 유지, cancel throw(보존), 워처 건너뜀.

### R3 — `spawn:` 시작 시각이 영구히 남음
- 감독이 시작 직후 같은 meta 잠금 안에서 `meta.processStartedAt` 이 `spawn:` 으로 시작하면 실제 lstart 로 바꾸고, procs 레지스트리 레코드의 `startedAt` 도 갱신한다. 테스트: `spawn:` 으로 시작한 meta 가 감독 시작 뒤 실제 시각으로 바뀌는 것(fake-codex).
