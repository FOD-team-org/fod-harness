## §1 — 자식 PATH

- `src/provider/runner.ts`의 `childEnv()`가 패키지 `bin`을 PATH 선두에 삽입한다. `import.meta.url` 기준으로 `turn.ts`의 `packageRoot`와 동일한 패키지 위치를 사용하므로 실행 프로젝트의 cwd와 무관하다. turn과 runner 사이의 순환 import는 추가하지 않았다.
- 기존 PATH 항목과 순서는 보존한다. 이미 패키지 bin이 선두이면 중복 삽입하지 않는다. PATH가 없거나 빈 값이면 패키지 bin만 설정하며, 새 빈 경로 항목은 만들지 않는다. 전달받은 원본 환경 객체는 수정하지 않는다.
- 기존 과금·중첩 실행 환경변수 제거와 autocompact 환경변수 보존은 유지한다. 해당 기존 테스트는 새 PATH 필드만 기대값에 추가했다.
- `ls -l bin/fodh` 결과는 `-rwxr-xr-x`, 즉 **0755**다. 작업 파일의 실행 권한을 확인했으며 chmod는 필요하지 않았다. git 명령 금지에 따라 Git 인덱스의 파일 모드는 별도로 조회하지 않았다.
- 선택 사항인 `FODH_NODE`용 sh 래퍼는 추가하지 않았다. 기존 `#!/usr/bin/env node`와 TypeScript 직접 import를 유지한다. 테스트에서는 실행 중인 Node 디렉터리만 기존 PATH로 제공해, PATH 상속으로 실제 CLI가 실행됨을 확인했다.

## §2 — brain-rules

`templates/brain-rules.md`의 2번 줄 끝에 정확히 다음 문구를 덧붙였다. 다른 줄은 변경하지 않았다.

```text
상태 조회는 `fodh state get`
```

## 회귀 검증

1. **가짜 Claude의 `ack` 시나리오:** 프롬프트의 인박스 ID 2개를 읽고 `spawnSync('fodh', ['inbox', 'ack', ...ids])`로 실제 CLI를 실행한다. 절대 실행파일 경로가 아닌 자식 PATH에서 찾는다. 이어서 `fodh state get`도 실제 실행한다. CLI stdout은 캡처해 스트림 JSON과 섞이지 않게 했다.
2. **턴 통합 검증:** 테스트가 전달하는 기존 PATH에는 Node 실행파일 디렉터리만 넣는다. runner가 패키지 bin을 추가한 뒤 턴이 정상 종료하고, 두 인박스가 모두 `applied`, 실제 ack 응답도 `applied`, 상태 조회 응답은 `IDLE`임을 검증했다. 다음 프롬프트에 적용된 인박스가 재전달되지 않는 것도 확인했다.
3. **환경 조립 검증:** `childEnv().PATH`의 첫 항목이 `join(packageRoot, 'bin')`인지, 공백이 있는 기존 경로와 순서가 보존되는지, 원본 객체를 변경하지 않는지, 반복 호출 시 선두 중복이 생기지 않는지, 빈 PATH를 처리하는지 확인했다.

### 남은 실패 및 수용 조건 미달

`test/revision.test.ts:198`의 `잠금 소유자의 실제 프로세스 시작 시각이 다르면 PID가 살아 있어도 stale이다`가 실제 `/bin/ps -p <테스트 PID> -o lstart=` 호출 단계에서 `Error: spawn EPERM`으로 실패했다. 4차 실행에서도 남았던 동일한 실경로이며, 이번 PATH 변경·ack 시나리오의 실패는 아니다.

실제 시작 시각 비교 테스트를 삭제·skip하거나 ps를 mock으로 바꿔 통과시키지 않았다. 잠금 구현도 변경하지 않았다. 따라서 **샌드박스 포함 전체 0 실패라고 보고할 수 없으며**, ps 실행이 허용된 환경에서 이 1개를 재검증해야 한다.
