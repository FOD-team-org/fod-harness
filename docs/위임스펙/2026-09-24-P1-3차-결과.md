## 요구별 반영

| 요구 | 결과 | 내용 |
|---|---|---|
| 1 | 반영 | agent_end 맨 앞에서 `ctx.hasUI === false`이면 종료한다. 상태 읽기·쓰기, autoTurns 증가, 사용자 대기 표지 처리, 정체 판단 생성, followUp 전송을 하지 않는다. |

| 3 | 반영 | 기존 테스트 ctx에 `hasUI:true`를 명시했다. 비대화형 상태 파일 불변, 전송 throw의 정상 반환·원복·재시도, warning throw/부재를 검사하는 9개 회귀 테스트를 추가했다. |
| 4 | 반영 | 설계 v0.3.2 목록에 `⑪ 자동 재개는 대화형(hasUI) 세션 전용, print 모드는 단일 턴.`을 추가했다. |

## 설계 선택

1. 비대화형 가드는 핸들러 첫 줄에 배치했다. 대기 표지나 정체 한도에 도달한 이벤트도 상태 파일 bytes가 바뀌지 않도록 했다.
2. 증가 직전 값은 updateState의 잠금 안에서 읽어 복원용으로 보관한다. 실패 시 전체 상태 스냅샷을 덮지 않고 자동 재개가 변경한 필드만 되돌린다.
3. recovering 전송 실패 시 `recoveryAutoResumed`도 이전 값으로 복원한다. 실패한 전송이 한 번뿐인 복구 재개 기회를 소모하지 않게 하며, 다음 재개 성공 시에는 기존 1회 제한을 유지한다.
4. warning은 전송 실패와 다음 사용자 입력에서의 복구 안내를 전달한다. 세션 폐기로 UI가 없거나 notify도 실패한 경우는 경고 전달이 불가능하므로 해당 알림 예외만 전파하지 않는다.
