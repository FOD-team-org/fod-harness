## G1 [높음] `detect --apply` 는 기준 경로에서만 감지

- 지금 `detectVerifyConfig`(`verify.ts:177`)는 `options.cwd` 를 감지 기준으로 쓴다. 그래서 `--apply` 도 그 기준으로 동작한다.
  - `cd` 접두는 이 기준에 대한 상대 경로다. 그런데 실행은 워크트리 루트에서 한다.
  - 표지가 있는 설정(VC1 뒤의 기본 상태)이면 두뇌가 `fodh verify detect --cwd node_modules/<pkg> --apply` 를 칠 수 있다. 그러면 `["npm run lint"]` 만 기록된다. typecheck·test 없이 REVIEW 를 통과한다.
  - Flutter 에서는 테스트 없는 `example/` 을 지정하면 `flutter test` 가 빠진다.
- 고칠 것
  1. 기준 경로를 정한다. 순서는 task 워크트리 루트, 없으면 멤버 경로(워크스페이스), 없으면 프로젝트 루트다. `--apply` 는 **항상 이 기준 경로에서 감지**한다.
     - `--apply` 에 `--cwd` 가 있고 그 realpath 가 기준 경로와 다르면 거부한다. `--approve` 가 있어도 거부한다.
     - 오류 문구: `--apply 는 --cwd 없이 기준 경로(<기준>)에서만 감지합니다`.
     - `--cwd` 는 미리보기(`--apply` 없음)에서만 쓴다.
  2. 감지에서 문서 폴더를 뺀다. 기준 경로 안에 `config.docs.root` 가 있으면(상대 경로로 정규화해서) 그 폴더와 그 아래는 탐색하지 않는다. 두뇌가 쓸 수 있는 문서 폴더에 `pubspec.yaml`·`package.json` 을 두어 감지를 흔드는 경로를 막는다.
     - `detectVerify` 옵션으로 `skipDirs?: string[]`(기준 경로 기준 상대 경로)을 더한다. 자동 채움·`detect`·init·workspace 모두 넘긴다.
  3. 템플릿: `VERIFY.md`·`brain-rules.md`·`SKILL.md` 의 `fodh verify detect --apply` 안내에 "`--cwd` 를 붙이지 않는다"를 넣는다.
  4. README 의 "두뇌는 명령 문자열을 고를 수 없다"가 이 수정 뒤에도 맞는지 확인하고, detect 사용법에 `--apply` 의 `--cwd` 제약을 적는다.
- 테스트
  - 표지 있는 설정에서 두뇌 환경의 `detect --cwd <하위폴더> --apply` 는 거부되고 설정 바이트가 그대로다.
  - `--cwd` 가 기준 경로 realpath 와 같으면 허용된다.
  - 미리보기의 `--cwd` 는 지금처럼 동작한다.
  - `docs/x/pubspec.yaml` 이 있어도 감지 결과에 `docs/x` 가 없다. `docs.root` 를 바꾼 설정에서도 확인한다.

## G2 [중간] 사용자 heavy 출처 보존

- `config.ts:487`: 첫 자동 채움 때는 사용자가 넣은 heavy 를 보존한다. 그리고 그 값을 포함해 hash 를 만든다.
  - 그 뒤 `detect --apply` 는 hash 가 맞아서 두뇌도 실행할 수 있다. `auto` 가 이미 있으므로 `detected.heavy` 로 덮는다.
  - python·dart·swift 는 감지 heavy 가 `[]` 라서 사용자 heavy 가 조용히 사라진다.
- 고칠 것: `verify.auto` 에 선택 필드 `heavySource: 'user'` 를 더한다. 첫 자동 채움에서 사용자 heavy 를 보존했으면 이 값을 쓴다.
  - `writeAutoVerify` 는 `heavySource === 'user'` 이면 hash 가 맞아도 현재 heavy 를 유지한다. `--approve` 로 사용자가 바꿀 때만 감지 heavy 로 바꾸고 `heavySource` 를 지운다.
  - 설정 검증은 이 필드(`'user'` 만 허용)를 받는다. hash 계산 방식(`{commands, heavy}` sha256)은 그대로다.
- 테스트: 사용자 heavy + 빈 commands → 자동 채움 → 파이썬 프로젝트에서 두뇌 `detect --apply` 뒤에도 heavy 가 그대로다. `--approve` 뒤에는 감지 heavy 로 바뀐다.

## G3 [중간] 워크스페이스 자리표시의 감지 실패

- `verify.ts:62-71`: 표지 있는 `git diff --check` 멤버가 task 워크트리에서도 감지에 실패하면 자리표시가 그대로 실행된다. 결과는 `ok:true` 다(거짓 통과). D7 의 판단 경로도 발동하지 않는다.
- 고칠 것: `autoPlaceholder && !detected` 이면 명령을 실행하지 않는다. 단일 레포 빈 설정과 같은 경로로 `finish({ ok: false, error: noDetectedVerify })` 를 돌려준다.
- 테스트: 스택 파일이 없는 멤버 워크트리에서 `verify run` → `ok:false`, 오류 = `noDetectedVerify`, `git diff --check` 는 실행되지 않음(로그·원장 확인), 설정 바이트 그대로.

## G4 [중간] 복수 번호 답은 기존 번호 토큰만

- `judgment.ts:112-114`: `allowMulti` 에서 숫자 패턴을 `([0-9]+)` 로 넓혔다. 그래서 승인 필수가 아닌 모든 항목에서 여러 자리 숫자도 선택 번호로 센다.
  - 기본 모드에서 conditional 로 적용되던 `2, 예산 100 만원`, `1 단 30 분 이내`, `2 2026 년 출시` 가 ambiguous(재질문)가 된다.
- 고칠 것: `allowMulti` 에서도 기존 토큰(`(10|[1-9])`, 동그라미 `①-⑩`)을 그대로 쓴다. 넓힌 정규식과 `⑳` 범위를 되돌린다. D9 의 "범위 밖 번호면 지금처럼 ambiguous"는 기존 토큰 안에서만 판정한다.
- 테스트
  - 위 세 답이 `allowMulti` 에서도 conditional·적용이다.
  - 실제 답 `2,3 1차 출시땐 무조건 ios 만` 은 여전히 freeform 적용이다.
  - `1, 3`(선택지 2개) 은 ambiguous 다.

## G5 [낮음] 대체 종료 경로는 그룹 전체

- `verify.ts:131`: `/bin/ps` 를 못 쓸 때의 대체 경로가 `child.kill('SIGKILL')` 로 sh 만 죽인다. `cd x && flutter test` 의 실제 프로세스는 고아로 남는다.
- 고칠 것: `process.kill(-pid, 'SIGKILL')`(detached 이므로 pgid = sh pid; `closed` 전이라 sh 는 아직 수거되지 않음). 실패하면 지금처럼 `child.kill('SIGKILL')` 로 떨어진다. 그 위 주석도 고친다. residual 판정은 바꾸지 않는다.
- 테스트: 회수 함수가 실패를 돌려주는 스텁에서, sh 아래 `sleep` 손자까지 종료되는지 본다(PID 표지 파일로 확인).

## G6 [낮음] 감지·멤버 경로 오류

- `verify-detect.ts:20`: `EACCES`·`EPERM`·`ENOTDIR` 도 `[]` 로 처리한다(ENOENT 와 같게). 건너뛴 폴더는 그 스택의 notes 가 아니라 결과에 영향 없이 무시한다.
- `workspace.ts:108` `detectedWorkspaceMember`: init·add 모두 **멤버 경로 검증(존재·`.git`·경계)을 먼저** 하고 감지는 그 뒤에 한다.
  - 지금은 감지의 `realpath` 가 먼저 돌아서, 없는 경로에서 친절한 오류(`경로와 .git 디렉터리`) 대신 날것의 ENOENT 가 나온다.
  - 이 때문에 기존 `test/w1-membership.test.ts:109` "add 사전 검사 실패 path" 가 실패한다. 이 테스트는 **단언을 바꾸지 않고** 통과해야 한다.
- 테스트: 깊이 1 에 읽기 권한 없는 폴더(chmod 000)가 있어도 다른 스택 감지가 되고 오류가 나지 않는다. 테스트 끝에 권한을 되돌린다.

## G7 [낮음] `-` 로 시작하는 폴더 이름

- `verify-detect.ts:72`: `cd '-P' && …` 는 옵션으로 해석된다.
- 고칠 것: 상대 경로의 첫 이름이 `-` 로 시작하면 `./` 를 붙여 인용한다(`cd './-P' && …`). 그 밖의 경로는 지금 모양(`cd 'app' && …`)을 유지한다.
- 테스트: `-P/pubspec.yaml` 에서 실제 sh 로 실행해 그 폴더에서 돈다.

## G8 [낮음] 루트 도구용 package.json 이 하위 스택을 가림

- 루트에서 스택을 찾으면 아래로 내려가지 않는다. 그래서 lint 만 있는 루트 `package.json` 하나가 `app/` 의 Flutter 를 가린다.
- 결정: 루트 스택이 **node 이고 워크스페이스가 아니면** 하위 탐색을 계속한다(깊이 2 까지, 다른 규칙 동일).
  - 워크스페이스 = `package.json` 에 `workspaces` 필드가 있거나, 루트에 `pnpm-workspace.yaml` 이 있는 경우.
  - 다른 루트 스택(flutter·dart·go·rust·swift·python·gradle)과 루트가 아닌 폴더는 지금처럼 내려가지 않는다.
- README 프리셋 절에 이 규칙을 한 줄 적는다.
- 테스트
  - 루트 `package.json`(lint 만) + `app/pubspec.yaml`(flutter, test 있음) → node + flutter 둘 다 나온다. 순서는 루트 먼저.
  - `workspaces` 가 있는 루트 + `packages/a/package.json` → 루트만 나온다.
