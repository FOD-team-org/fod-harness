## F4 (high) — PROJECT_READY 를 사용자 정지 상태로

설계 §3: `PROJECT_READY ─/develop-start─▶ PLANNING`. 현재는 두뇌가 `fodh state transition PLANNING` 으로 그대로 통과한다.

1. `src/core/state.ts` `transitionState`: `to === 'PROJECT_READY'` 진입 시 `awaitingUser: true` 를 함께 저장하고 `notify`(key `state:PROJECT_READY`, info, "프로젝트 준비 완료 — `/develop-start` 로 개발을 시작하세요")를 보낸다(DONE_ALL 과 같은 분기).
2. `PROJECT_READY → PLANNING` 전이는 두뇌(`process.env.FODH_BRAIN === '1'`)가 호출하면 거부한다: `Error('PROJECT_READY 는 사용자가 /develop-start 로 시작합니다')`. 오케스트레이터 `/develop-start`(`extensions/orchestrator/index.ts:89`)는 사용자 세션이라 통과. 판정 위치는 `transitionState` 옵션 `{ by: 'brain' | 'user' }` 가 아니라 CLI(`src/cli/index.ts` state transition 처리)에서 env 로 정한다. 다른 사용자 전용 전이가 이미 있다면 같은 방식으로 맞춘다.
3. `templates/prompts/PROJECT_READY.md` 신설(다른 템플릿과 같은 4절 구조): 할 일 = "없음. 프로젝트 단계가 끝났다. 마지막 3줄에 `대기: 사용자` 를 쓰고 턴을 끝낸다"; 다음 fodh 명령 = "없음(사용자 `/develop-start`)"; 금지 = "`fodh state transition PLANNING` 호출". `templates.test.ts` 의 템플릿 목록·구조 검사에 추가.
4. `templates/prompts/REVIEW.md` "프로젝트 통과" 줄: `fodh state transition PROJECT_READY` 뒤에 "이후 `대기: 사용자` 로 턴을 끝낸다" 추가.
5. 테스트: PROJECT_READY 진입 → awaitingUser true + notify 1회; FODH_BRAIN=1 CLI 에서 PROJECT_READY→PLANNING 거부(원장 fail); 사용자 env 에서 허용. 기존 `develop-start` 테스트 유지.

## F5 (high) — 빈 백로그로 PICK·DONE_ALL 진입 금지

1. `transitionState` 가드: `PLANNING → PICK` 은 등록 task ≥ 1 이어야 한다. 아니면 `Error('PICK 진입에는 등록된 task 가 필요합니다 (fodh backlog add)')`. 오케스트레이터 `/develop-start` 의 `!tasks.length && PLANNING` 분기는 이미 PICK 으로 가지 않으므로 그대로.
2. `src/core/pick.ts:59`: `pending.length === 0` 이고 **백로그 전체가 비어 있으면** DONE_ALL 이 아니라 오류(`백로그가 비어 있습니다`)를 던지거나 outcome `'EMPTY'` 로 반환해 PICK 상태를 유지한다(둘 중 하나 골라 결과 문서에 적기; 오케스트레이터 `runPick` 호출부 두 곳도 맞춘다). DONE_ALL 은 백로그 ≥1 이고 pending 0 일 때만.
3. `templates/prompts/PLANNING.md` 4단계 뒤에 "초안 문서만 쓰고 끝내지 않는다. `fodh backlog list` 로 등록 수를 확인한 뒤 PICK 으로 간다" 한 줄.
4. 테스트: 빈 백로그 PLANNING→PICK 거부; pick 빈 백로그 → DONE_ALL 아님; 1개 done 만 있으면 DONE_ALL.

## F6 (medium) — REVIEW 통과에 교차검수 증거 요구

두뇌가 `fodh codex review` 없이 검수 문서를 스스로 쓰고 PROJECT_READY 로 갔다.

1. `transitionState` 가드: `current.state === 'REVIEW'` 에서 `to === 'PROJECT_READY'`(프로젝트) 또는 `to === 'MERGE'`(task, `task.delegate === 'claude'` 인 경우)로 갈 때, REVIEW `enteredAt` 이후에 시작된 `kind: 'review'` Codex 위임 결과(`.pi/codex/*/meta.json`: `status: 'ok'`, task 면 `taskId` 일치)가 하나 이상 있어야 한다. 없으면 `Error('교차검수 증거가 없습니다: fodh codex review --wait 결과가 필요합니다')`. 원장 스캔보다 meta 스캔이 확실하다(`src/core/codex-record.ts` 의 기존 읽기 함수 재사용).
2. `task.delegate === 'codex'` 인 task 의 MERGE 는 Claude Agent 검수라 증거를 잡을 수 없다 → 가드 없음. README·결과 문서에 "알려진 한계" 로 적는다.
3. 테스트: 증거 없음 거부 / REVIEW 진입 전 meta 만 있음 거부 / 진입 후 ok meta 허용 / task 검수 taskId 불일치 거부.

## F1 (low) — 인터뷰 choice 판단 항목의 선택지 순서
