## 6. 스펙 차이와 구현 선택

- §5-4 호출부에 state.ts updateState 전환 알림 추가(검수 M-1, 메인 승인). 상세 결과는 문서 끝 “검수 반영” 절에 기록했다.

- 큰 스펙·코드 불일치는 발견하지 않았다. §8-2의 설정 수 서술은 “3개”지만 뒤의 명시 목록은 기본·등록 사용자 규칙·미등록 사용자 규칙·잘못된 정규식 네 경우다. 누락 없이 네 설정을 사용해 192개를 저장했다.
- 멤버 순서는 `Object.entries` 설정 순서다. 표 값은 줄바꿈을 공백으로, `|`를 이스케이프하고 검증 명령을 먼저 redact한다. 해시에는 상대 경로·기준 브랜치·명령만 더하고 timeout·worktreePrefix·approvalRules·secrets는 더하지 않았다.
- 표시 전용 설정 읽기는 모두 `{ dryRun: true }`와 try/catch를 사용했다. unknown-key 경고 원장·설정 진단 파일을 만들지 않음을 테스트했다. `task-label.ts`는 storage와 타입만 import해 순환을 피했다.
- 한 레포 autopilot의 앞 세 검사와 requiresApproval 콜백은 그대로 보존했다. 멤버 규칙은 task의 멤버로 좁히지 않고 모든 멤버를 훅 순서로 더한다. description 부분 일치는 전체 산문에, pattern은 산문·정규화 후보에 적용한다. 잘못된 정규식은 불일치다.
- 파서/정규화가 예외를 내면 해당 조각 원문만 후보로 추가한다. 기존 훅을 import해서 사용했고 훅 자체는 변경하지 않았다.
- `/status`의 기존 `task` 키는 유지하고 `taskLabel`을 추가했다. 상태줄 오류, 설정 읽기 오류, 백로그 읽기 오류가 작업 흐름을 막지 않게 했다. 한 레포에는 fodh-task setStatus를 한 번도 호출하지 않음을 직접 단언했다.
- 기존 테스트 수정은 §10-3 E1·E2와 허용된 출처 주석만이다. 실패 회피를 위한 기존 단언 약화·삭제는 없다.

## 7. 한 레포 사용자에게 보이는 변화와 남은 한계

한 레포의 지정 변화(I1~I4): 관리 블록 흐름표·명령 목록의 MERGE 안내, brain-rules, 두 스킬, MERGE 프롬프트다. 업그레이드 뒤 첫 develop-start에서 **“CLAUDE.md 하네스 규칙이 바뀌었습니다. 커밋 필요”**가 한 번 뜨고 스킬 두 개가 갱신된다. 출력 JSON·알림 제목/본문·중복 판정·자동 진행 결과는 지정 변경 밖에서 보존한다.

1. **R1:** 첫 develop-start 전까지 CLAUDE.md는 옛 흐름표다. MERGE 프롬프트는 지시문마다 읽혀 새 안내가 적용되고 brain-rules가 우선한다. doctor의 표식은 설정 해시라 템플릿 버전 변경을 감지하지 않는다. 위 업그레이드 안내를 릴리스 안내에도 반영해야 한다.
2. **R2:** `fodh worktree merge`는 같은 `--no-ff` 병합을 하되 루트 브랜치·task tip·기준점을 더 엄격히 검사하므로 판단이 늘 수 있다. 한 레포 직접 git merge를 훅으로 금지한 것은 아니며 안내에 의존한다.
3. **R3:** 상태줄은 session_start·agent_end·/status·develop-start에서 갱신된다. 턴 중간 PICK 전환은 턴 끝에 반영된다.
4. **R4:** 하네스 `listWorkspace`의 git status에는 여전히 `--no-optional-locks`가 없다. 사용자 git과 드문 index.lock 충돌 가능성은 범위 밖이다.
5. **R5:** 코드 조각 없이 산문으로 쓴 위험 동작은 description·기존 키워드에 없으면 멤버 규칙이 놓칠 수 있다. 실행 시 훅이 검사한다. 펜스·짝 없는 백틱은 코드 조각으로 다루지 않고 산문 비교만 한다.

8. **R8:** 멤버 CLAUDE.md·AGENTS.md를 먼저 읽는 것은 안내이며 강제하지 않는다.
9. **R9:** `turn.ts`의 `[경계]` 사용자 안내 “다시 시도하지 말고 위임”과 brain-rules의 구문 교정 1회 예외는 문구가 다르다. turn.ts는 범위 밖이라 그대로다.

### 남은 한계

- **L-3:** 내장 승인 범주 규칙(`pretooluse.mjs` 97~113의 `rules[category]`)은 자동 진행의 코드 조각 정규화 결과에 적용하지 않는다. 예를 들어 `fastlane pilot upload`는 두 모드 모두 자동 진행 차단이 없지만 훅은 막는다. W3b 이전부터 있던 공백이며 한 레포 불변을 건드리므로 후속 별도 스펙이 필요하다. 이번에는 고치지 않았다.
