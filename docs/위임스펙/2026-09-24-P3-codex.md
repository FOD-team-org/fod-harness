## 1. 설정 (`src/core/config.ts`)

```json
"delegate": {
  "codex": { "command": "codex", "brainModel": "gpt-6-astra", "brainEffort": "xhigh", "workerModel": "gpt-6-sol", "workerEffort": "xhigh",
             "sandbox": "workspace-write", "maxChildAgents": 1, "timeoutMinutes": 90, "waitMinutes": 8 },
  "claude": { "subagentModel": "opus", "maxChildAgents": 1 },
  "route": { "design": "claude", "default": "codex" }
},
"worktrees": { "root": "..", "prefix": "wt-" }
```

- `command`: 문자열 또는 문자열 배열(기존 `brain.command` 와 같은 검증). 테스트는 가짜 실행 파일 경로를 넣는다.
- `sandbox`: `workspace-write` | `read-only` 만 허용(`danger-full-access` 거부, 메시지 `delegate.codex.sandbox는 workspace-write, read-only 중 하나여야 합니다`). `task` 종류의 기본값이며 `review`·`research` 는 항상 `read-only`.
- `timeoutMinutes`: 양의 정수, 기본 90. 감독 프로세스가 이 시간을 넘기면 그룹을 회수하고 `status:'timeout'`.
- `route`: 값은 `codex` | `claude`. 키는 backlog 분류(`design|non-design|docs|research`) 또는 `default`. 기본 `{ design:'claude', default:'codex' }`. `fodh codex task` 는 분류가 `claude` 로 라우팅되는 task 를 거부하지 않는다(두뇌가 결정) — 결과에 `routeHint` 만 싣는다.
- `worktrees.root`: 프로젝트 루트 기준 상대 경로(기본 `..` = 프로젝트의 형제 디렉터리). `prefix` 는 `[A-Za-z0-9_-]+`.
- `fodh config get delegate` 로 기본값이 모두 보여야 한다.

## 2. `fodh codex <kind>` (`src/core/codex.ts`)

### 2-1. 인자

`fodh codex task|review|research --spec <file> [--task T07] [--resume <threadId>|last] [--wait] [--cwd <dir>] [--title <짧은 제목>]`

| 항목 | task | review | research |
|---|---|---|---|
| `--task` | 필수(`T\d+`, 존재·`done` 아님) | 선택 | 선택 |
| 샌드박스 | `delegate.codex.sandbox` | `read-only` | `read-only` |
| 실행 디렉터리 | task 의 등록 워크트리(`task.worktree`) → 없으면 프로젝트 루트(결과 `worktree:null`, 원장 evidence 에 `fallback:'root'`) | 프로젝트 루트 | 프로젝트 루트 |
| `--cwd` | 허용 — 단 프로젝트 루트 안이거나 `state.worktrees` 에 등록된 경로여야 한다(밖이면 거부) | 동일 | 동일 |
| `--spec` | 프로젝트 안 상대 경로, 존재해야 함. 본문이 프롬프트 몸통이 된다 | 검수 요청 문서 | 조사 질문 문서 |

- `--resume <id>`: `codex exec resume <id>` 로 실행(§2-3). `--resume last` 는 `task.codexThread` 를 쓰고 없으면 거부. `--resume` 없이 같은 task 를 다시 `task` 로 부르면 새 스레드(FIX 는 템플릿이 `--resume last` 를 쓴다).
- 상태 검사: `task` 는 현재 상태가 `IMPLEMENT`·`FIX` 이고 `state.taskId === --task` 일 때만(그 외 `현재 상태에서는 codex task 를 시작할 수 없습니다`). `review` 는 `REVIEW`, `research` 는 `RESEARCH`·`ARCH`·`PLANNING`·`SPEC`·`REVIEW` 에서. 상태 밖 호출은 거부. (`--wait` 와 무관.)
- 위임 중복: `state.delegation` 이 있고 그 runId 의 meta 가 미완이면 거부(`이미 위임이 진행 중입니다: <runId>`). 완료돼 있으면 stale 로 지우고 진행.

### 2-2. 실행 순서 (설계 §6-0-2 의 5단계)

1. **슬롯 확보** (`src/core/slots.ts`, §3). 실패 시 `{ error:'codex 슬롯 사용 중', owner:{ root, runId, taskId, pid, startedAt } }` exit 1. 아무것도 만들지 않는다.
2. **결과 디렉터리** `.pi/codex/<runId>/` 생성(runId = 기존 방식의 새 id). 파일: `prompt.md`(머리말+스펙), `events.jsonl`(codex `--json` stdout 원본), `stderr.txt`, `last-message.md`(`-o`), `meta.json`, `supervisor.log`(0600, 감독 stderr).
3. **원장** `pre`: `{ runId, taskId, state, action:'codex:<kind>', status:'pre', evidence:{ cwd, sandbox, model, effort, spec, resume?, title } }`.
4. **감독 프로세스 spawn**: `spawn(process.execPath, [<pkg>/bin/fodh-codex-supervisor, root, runId], { detached:true, stdio:['ignore','ignore',supervisorLogFd], cwd:root, env:childEnv() })` 후 `child.unref()`. 레지스트리 등록 `{ pid, pgid:pid, startedAt:(ps lstart, 실패 시 'spawn:'+ISO — 기존 runner 방식), runId, kind:'codex', taskId, cmd:'fodh-codex-supervisor <runId>' }`.
5. **상태 파일** `delegation = { runId, taskId?, kind, startedAt, title }` 기록(`updateState`). `task` 종류면 `setTask(taskId, { delegate:'codex' })`.
6. 출력 `{ runId, kind, taskId, cwd, sandbox, pid, resultDir, wait:false }` 즉시 반환. `--wait` 면 §2-5.

`meta.json` 초기값: `{ runId, kind, taskId, title, cwd, sandbox, model, effort, workerModel, workerEffort, resume, command:[...전체 인자...], startedAt, status:'running' }`. 감독이 마감할 때 `{ finishedAt, exit, status:'ok'|'fail'|'timeout'|'lost', threadId, lastMessageFile, peakRssMB, durationSeconds }` 를 채운다.

### 2-3. Codex 명령 형태

새 스레드: `<command> exec -s <sandbox> -C <cwd> --skip-git-repo-check -m <brainModel> -c model_reasoning_effort=<brainEffort> --json -o <resultDir>/last-message.md - < prompt.md`
재개: `<command> exec resume <threadId> -c sandbox_mode="<sandbox>" --skip-git-repo-check -m <brainModel> -c model_reasoning_effort=<brainEffort> --json -o <resultDir>/last-message.md - < prompt.md` (`resume` 는 `-s`·`-C` 를 받지 않는다 — 실측. cwd 는 spawn 의 `cwd` 로만 준다.)

- stdin = `prompt.md` 파일 스트림. 마지막 인자 `-` 필수.
- 자식 에이전트 모델: Codex 가 `-c` 로 자식 모델을 받는 설정 키가 있는지 `codex exec --help` 와 `~/.codex/config.toml` 문서(`multi_agent`)로 확인하고, 있으면 `-c <키>=<workerModel>` 을 붙인다. 없으면 머리말 문장으로만 지시하고 결과 문서에 "키 없음" 을 적는다.
- `env`: 기존 `childEnv()`(CLAUDECODE·과금 변수 제거, PATH 앞에 `<pkg>/bin`). 추가로 `FODH_PROJECT_ROOT=<root>`, `FODH_RUN_ID=<runId>`.

### 2-4. 자동 머리말 (`prompt.md`)

머리말은 한국어, 아래 항목을 순서대로. `{{ }}` 는 치환.

```
# 하네스 위임 머리말 (자동)
- 종류: {{kind}} / 작업: {{taskId|없음}} / 실행 id: {{runId}}
- 작업 폴더: {{cwd}} — 이 폴더 밖은 읽기만 한다. 파일 변경은 이 폴더 안에서만.
- 샌드박스: {{sandbox}}{{read-only 이면 " — 파일을 쓸 수 없다. 결과는 마지막 메시지에 전부 적는다."}}
- 금지: git 명령(commit·branch·stash·worktree·push) — 커밋은 하네스가 한다. 전체 테스트 스위트·전체 빌드 실행 — 변경 파일과 직접 관련된 테스트만 실행한다. 비밀값(토큰·키·암호) 출력·기록. 배포·업로드·외부 발송. 산출물(zip·빌드 결과·APK) 생성.
- 서브에이전트: 동시 {{maxChildAgents}}개 이하, 모델 {{workerModel}} effort {{workerEffort}}.
- 수용 기준: 아래 스펙의 요구를 모두 만족하고 관련 테스트가 통과한다. 하지 못한 항목은 추정하지 말고 "미완" 으로 적는다.
- 검증: 변경 파일 관련 테스트 + typecheck(있으면). 실행한 명령과 결과 수치를 그대로 적는다.
- 마지막 메시지 형식(반드시): `## 결과` 아래에 (1) 변경 파일 목록 (2) 실행한 검증 명령과 결과 (3) 미완·의문·판단 필요 항목. review 는 `## 판정` (`APPROVE|REQUEST_CHANGES`) + 높음/중간/낮음 표(파일:줄·재현·수정안). research 는 `## 조사 결과` + 출처 목록.

---
{{spec 파일 본문}}
```

- `task.ts`·`review`·`research` 별 문장은 위 표기대로 분기. 머리말 텍스트는 `templates/codex-header.md` 에 두고 치환한다(두뇌 규칙처럼 파일 기반).

### 2-5. `--wait`

- 2초 간격으로 `meta.json` 의 `finishedAt` 을 폴링. `min(timeoutMinutes + 1, max(1, brain.maxTurnMinutes - 5), delegate.codex.waitMinutes)`분까지. 끝나면 `result()`(§2-6) 결과를 출력. 폴링 시간 초과면 `{ error:'위임이 아직 진행 중입니다', runId }` exit 1(감독은 계속 돈다).
- `startCodex`는 `--wait` 여부와 무관하게 시작 직후 stderr에 `{"runId":"…"}` 한 줄을 출력한다. stdout은 JSON 결과 하나만 유지한다. M2 보완(N1): waitMinutes는 기본 8분(양의 정수). 두뇌 Bash 기본·최대 timeout env는 사용자 값이 없으면 600000ms. REVIEW·RESEARCH는 어떤 이유로든 결과 없이 끝나면 stderr runId 또는 status의 delegation.runId로 위임 대기 표지를 쓰고 턴을 끝내며 --wait를 반복하지 않는다.
- `--wait` 로 끝난 경우에도 워처 `codex-done` 인박스는 그대로 생긴다(두뇌가 같은 턴에 `fodh inbox ack` 하면 됨). `decideInbox` 는 `state.delegation` 이 이미 지워졌으면 알림 없이 `applied` 로 닫는다(§4-2).

### 2-6. `fodh codex status [<runId>]`, `fodh codex result <runId>`, `fodh codex cancel <runId>`

- `status`: 인자 없으면 `state.delegation` + 그 meta 요약 + 슬롯 상태. 인자 있으면 그 meta 전체(`command` 포함) + 레지스트리 생존 여부.
- `result`: `{ runId, kind, taskId, status, exit, threadId, durationSeconds, lastMessage:(last-message.md 본문, 없으면 events.jsonl 의 마지막 `agent_message` text), changedFiles:(events.jsonl 의 `file_change` 경로; cwd 안이면 상대 경로, 밖이면 절대 경로), commands:(`command_execution` 개수), usage:(`turn.completed.usage`), errors:(`item.type==='error'` 메시지 중 "Under-development"·"Skill descriptions"·"unrecognized configuration settings" 경고 제외; 최상위 error·turn.failed도 redact 후 중복 제거) }`. 미완이면 `status:'running'` 과 지금까지의 부분 정보.
- `cancel`: 레지스트리(없으면 meta.pid)의 감독과 도구 트리를 codex 전용 경로로 회수(생존 리더는 시작 시각 대조; 리더 사망·그룹 생존이면 기록된 childPid·childStartedAt과 실제 그룹 구성원의 신원이 일치할 때만 회수) → meta `status:'cancelled'` → 슬롯 해제 → 원장 `fail` evidence `cancelled` → `delegation` 해제. meta가 없어도 state.delegation.runId가 일치하면 delegation·awaitingDelegation을 지우고 `{ runId, cancelled:true, meta:null }`을 반환한다. 두뇌·사용자 모두 쓸 수 있다.

## 3. 슬롯 (`src/core/slots.ts`)

- 파일 `~/.pi/agent/fod-harness/slots.json` (테스트는 `FODH_SLOTS_DIR` env 로 위치 변경). 형식 `{ "codex": { "root", "runId", "taskId", "pid", "startedAt", "acquiredAt" } | null, "claude": null }`.
- `acquireSlot('codex', owner)`: 파일 잠금(`withFileLock`) 안에서 읽기 → 점유자가 있으면 생존 확인(`isProcessAlive(pid)` + `processStartedAt(pid)` 가 `startedAt` 과 일치(±2초)) → 리더가 죽었어도 `groupAlive(pid)`이며 슬롯 또는 meta의 childPid·childStartedAt과 같은 그룹 자식의 신원이 일치하면 점유 중이다. 리더·그룹 모두 죽었을 때만 stale 로 덮어쓴다(원장 `slot:stale ok` 기록). 점유자의 pid 는 감독 프로세스 pid 이다(spawn 직후에 갱신).
- `releaseSlot('codex', runId)`: runId 가 같을 때만 비운다.
- `fodh slots status`: 파일 내용 + 각 점유자 생존 여부.
- 두뇌 슬롯·claude 자식 슬롯은 P3 에서 값만 예약(항상 `null`), 강제하지 않는다.

## 4. 감독 프로세스 (`src/core/codex-supervisor.ts`, `bin/fodh-codex-supervisor`)

- `bin/fodh-codex-supervisor <root> <runId>` — `bin/fodh` 와 같은 방식(`#!/usr/bin/env node` + `.ts` import). 자신이 프로세스 그룹 리더가 되도록 부모가 `detached:true` 로 띄운다. 감독은 `codex` 를 `detached:false`(같은 그룹) 로 spawn.
- 절차: `harness-delegation` 잠금을 최대 120000ms 기다려 meta 읽기 → 슬롯 파일의 `pid` 를 자기 pid 로 갱신 → `codex` spawn(stdin=prompt.md, stdout→events.jsonl append, stderr→stderr.txt) → 30초마다 `ps -o pid=,rss= -g <pgid>`에서 조회 ps 자신의 PID를 제외한 합계로 peak RSS 갱신(실패 무시) → 종료 대기.
- 종료 시: `events.jsonl` 에서 `thread.started.thread_id` 추출 → `task.codexThread` 저장(`meta.kind === 'task'`이고 taskId 있을 때만; review·research는 구현 스레드를 덮어쓰지 않는다) → meta 마감(`status = exit===0 ? 'ok' : 'fail'`) → 슬롯 해제 → 레지스트리 제거(자기 pid) → 원장 `codex:<kind>` `ok|fail` evidence `{ exit, threadId, durationSeconds, peakRssMB, changedFiles:n, lastMessageBytes }`.
- 시간 초과(`timeoutMinutes`): `processTree(pgid, rootPids)`가 `/bin/ps -axo pid=,ppid=,pgid=` 한 번으로 같은 그룹 및 ppid·pgid 폐쇄를 찾는다(감독 자신과 조회 ps 제외). 신호 전 스냅샷 전체에 TERM → 최대 5초 → KILL 후 새 스냅샷과 이전 스냅샷 생존 PID의 합집합으로 잔존을 확인한다. 한 번 죽은 PID는 dead 집합으로 옮겨 다시 루트에 넣지 않는다. 별도 세션의 도구 자식도 회수한다. cancel·워처 lost·reclaim도 같은 codex 전용 회수 경로를 쓴다.
- Codex spawn 직후 childPid·childStartedAt(LC_ALL=C ps lstart)을 meta와 슬롯에 기록한다. 30초 표본 때 관측한 별도 도구 pgid를 meta.toolGroups에 누적하고 모든 회수 경로에서 함께 비운다.
- 신호: 감독이 `SIGTERM` 을 받으면 codex 자식을 같은 절차로 종료하고 `status:'cancelled'` 로 마감한다.
- 부모의 pid 기록은 meta 잠금 안에서 다시 읽어 `finishedAt`이 없을 때만 쓴다.
- 감독 자체가 죽은 경우(`meta.status==='running'` 인데 레지스트리 pid 사망)는 워처가 `lost` 로 처리(§5).
- 감독은 `src/core` 라이브러리만 쓴다(상태 단일 작성자 원칙). 예외는 모두 잡아 meta 에 `error` 문자열로 남긴다.

## 5. 워처·오케스트레이터

### 5-1. 워처 (`src/core/watcher.ts`) — 감지만

- `codex-done`: 완료 meta는 인박스에 codexRunId·codexStatus·resultDir을 싣는다. running 실행은 시작 60초 후 감독 사망을 확인하면 살아 있는 그룹·트리를 먼저 회수한 뒤 lost로 마감한다. 회수 실패는 마감하지 않고 `codex:lost fail`, `reason:'group-alive'`를 runId당 첫 1건과 이후 10분마다 기록한다(watcher 상태에 마지막 시각 저장). 그룹이 없으면 죽은 리더 pid를 루트로 조회하지 않는다. 기록된 toolGroups를 회수하고 `turn.completed`가 있으면 `ok`, `exit:null`, `supervisorLost:true`로 마감하고 원장에도 기록한다. PID 신원이 다르면 신호 없이 lost/cancelled 및 `reason:'pid-reused'`, 리더 사망 뒤 그룹의 자식 신원이 다르면 신호 없이 lost 및 `reason:'group-unverified'`로 마감한다.
- state.delegation의 meta가 없으면 시작 60초 후 resultDir 없는 lost codex-done을 낸다. 발행 dedupe 키는 `codex-done:<runId>`, `watch.codexEmitted` 최근 50개와 기존 인박스로 중복을 막는다. 시작 경로도 meta 없는 위임을 `delegation:stale ok`로 기록하고 새 위임으로 진행한다.
- `stalled`: `state.delegation` 이 있으면 제외(감독의 `timeoutMinutes` 와 `child-timeout` 이 대신 지킨다).
- `child-timeout`의 kind `codex`는 해당 meta의 `timeoutMinutes + 5`분 기준(meta 없으면 `childTimeoutMinutes`). **P3 에서 `childTimeoutMinutes` 기본값을 90 으로 올린다**(위임 실행 시간 현실화, `config.ts` 기본값 + 테스트 갱신).

### 5-2. 오케스트레이터

- 사용자 표지는 어느 줄이든 인정하며 앞뒤 `*`·`_`·백틱을 벗긴다. 위임 표지는 마지막 비어 있지 않은 3줄 안에서만 찾는다. 예: `대기: 위임 3f2c…` (`3f2c…` 대신 실제 runId 전체). 줄과 runId 앞뒤 백틱·꺾쇠(`<`, `>`)를 벗기고 `[A-Za-z0-9_-]+`로 인식한다. 유효한 위임 표지는 `awaitingDelegation:true`로 자동 재개를 멈춘다. `대기: 사용자`도 함께 있으면 `awaitingUser:true`도 기록한다. `state.delegation`의 runId와 다르거나 meta가 끝났으면 원장 `delegation:marker skip` 후 평소처럼 재개한다. 표지가 없는데 delegation이 살아 있으면 재개하되 다음 프롬프트에 위임 대기 표지를 쓰라는 안내를 run당 1회 붙인다.
- `decideInbox` `codex-done`: `state.delegation?.runId === runId` 이면 `updateState({ delegation:undefined, awaitingDelegation:false, autoTurns:0 })` → `autoResume(..., 'codex-done')`(idle 이 아니면 건너뜀 — 프로바이더가 다음 턴에 인박스를 붙임). runId 가 다르거나 `delegation` 이 이미 없으면 `resolveInbox(applied)` 만(알림 없음). `status` 가 `fail|timeout|lost` 면 warning 알림 포함. supervisorLost는 인박스와 result에 전달하고 `감독 사망 뒤 추정한 성공 — 결과를 직접 확인` 경고를 표시한다.
- `autoResume` 의 활동 상태 검사 앞에 `awaitingDelegation` 이면 `{ skipped:'delegation' }`(recover·stalled 경로에서도 위임 중엔 재개하지 않는다).
- `/status` 에 `delegation: { runId, kind, taskId, title, status, minutes }` 추가. `/cleanup` 은 그대로.
- 프롬프트 빌드(`buildPrompt`): 인박스 `codex-done` 항목은 resultDir이 있으면 `[인박스 <id>]` 형식에 더해 `fodh codex result <runId>` 지시를 붙인다. 없으면 결과 없음 및 재위임 또는 `fodh judgment add` 판단 등록을 안내한다.

## 6. 워크트리 (`src/core/worktree.ts`)

- `fodh worktree create <T> [--base <ref>]`: 경로 `<root>/<worktrees.root>/<prefix><T>` (정규화, 프로젝트 루트 안이면 안 됨 — `..` 형제 규칙; 루트 안이면 거부), 브랜치 `<prefix><T>`. 고정 인자의 `git worktree prune` 후 `git -C <root> worktree add -b <branch> <path> <base|HEAD>`; 브랜치가 이미 있으면 `-b` 없이 붙인다. 프로젝트가 git 저장소가 아니면 `{ error:'git 저장소가 아닙니다', worktree:null }` exit 1(두뇌는 그대로 `fodh codex task`를 실행해 루트 폴백을 쓴다). 성공 시 `setTask(T, { worktree:path })` + `state.worktrees` 에 `{ taskId, path, branch, createdAt }` 추가 + 원장 `worktree:create ok`. 이미 등록돼 있고 경로가 존재하면 그대로 반환(`created:false`).
- `fodh worktree remove <T> [--force]`: `git worktree remove [--force] <path>` + 등록 해제 + 원장. 브랜치는 남긴다. 상태가 `CLEANUP`·`RECLAIM`·`DOCS` 이거나 task 가 `done` 일 때만(그 외 거부). `state.delegation` 이 그 task 를 가리키고 미완이면 거부.
- `fodh worktree list`: `state.worktrees` + 각 경로 존재 여부 + `git worktree list --porcelain` 대조.
- git 실행은 `execFile('git', [...])` 로만(셸 없음). 오류 stderr 는 `redact` 후 메시지에.
- 훅 규칙 5: `fodh` 단일 명령이므로 통과(변경 없음). 두뇌가 `git worktree` 를 직접 치는 것은 P6 에서 거부 예정(P3 는 `brain-rules.md` 문장으로만 금지).
