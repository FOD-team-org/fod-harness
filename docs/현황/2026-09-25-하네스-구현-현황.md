## 1. 목적과 설계 원칙의 구현 상태

사용자가 겪던 문제는 두 가지였다. 판단할 필요가 없는 일에서도 에이전트가 멈추는 것, 그리고 판단 문서를 스스로 읽지 않는 것이다. 설계 원칙 P1~P10 은 이 둘에서 나왔다.

| # | 원칙 | 구현 상태 |
|---|---|---|
| P1 | 판단이 필요 없는 일은 멈추지 않는다 | `agent_end` 마다 오케스트레이터가 다음 단계 프롬프트를 주입한다. PICK·task 진행 중의 근거 없는 `대기: 사용자` 는 거부하고 재개한다(F25·F28). 멈춤은 열린 판단·정지 상태·명시적 hold 뿐이다. 3턴 정체 안전망이 판단 등록으로 넘긴다 |
| P2 | 문서가 진실이다 | 판단대기·백로그·상태·원장이 모두 파일이다. 워처가 판단 문서 변경을 감지하면 오케스트레이터가 반드시 읽고 적용한다 |
| P3 | 워처는 판단하지 않는다 | 워처는 해시·안정화·heartbeat·슬롯·위임 완료만 인박스로 보낸다. 결정은 `decideInbox` 가 한다 |
| P4 | 검수 없는 완료는 없다 | REVIEW 를 건너뛰는 전이가 없다. 검수 커밋·병합 커밋·검증 증거가 실제 git·실행 결과로 잠긴다. 구현 meta 가 있으면 검수 증거를 면제하는 틈이 남아 있다(L4) |
| P5 | project-start 는 상세히 묻는다 | 18영역 인터뷰 은행, 라운드 6문항, 문항당 2회, 필수 미답이면 RESEARCH 전이 거부 |
| P6 | 띄운 프로세스는 하네스가 회수한다 | 프로세스 레지스트리(pid·pgid·시작 시각), CLEANUP·RECLAIM 필수 상태, 메모리 워치독, 고아 두뇌 회수(F30) |
| P7 | 재생성 가능한 산출물만 정리 | `cleanup.processes`·`storage` 는 프로젝트 안 선언 경로만 지운다. 공유 캐시는 보고만 하고 기본 꺼짐 |
| P8 | 다른 프로젝트에서도 재사용 | 전역 Pi 패키지 + `fodh` CLI, 프로젝트 차이는 `.pi/harness.json` 하나. 다른 Mac 으로 옮기는 데는 제약이 남아 있다(§15) |
| P9 | 두뇌는 직접 구현하지 않는다 | 훅 쓰기 경계(문서·`.pi`·등록 워크트리만), 직접 `codex`·`claude`·companion 실행 거부, 위임은 `fodh codex` 또는 Claude Agent 로만 |
| P10 | 부작용은 한 번만 | 실행 원장 `.pi/harness-ledger.jsonl`, 결과 불명이면 recovering 프롬프트로 증거 대조 뒤 `fodh ledger resolve` |

## 2. 구조

```
Pi TUI (pi -e provider -e orchestrator -e watcher)
 ├ extensions/provider      "claude-code" 모델 제공자. 턴마다 claude -p 를 띄우고 stream-json 을 Pi 로 변환
 ├ extensions/orchestrator  /project-start /develop-start /status /judged /hold /cleanup, agent_end 자동 재개
 ├ extensions/watcher       판단 파일·위임·슬롯·정체·복구 감지 → 인박스 (결정하지 않음)
 │
 ├ 두뇌 = claude -p (detached, 자기 pgid, FODH_BRAIN=1)
 │   ├ Bash 로 fodh … 호출 (상태 변경의 유일한 길)
 │   ├ Claude Agent 서브에이전트 (Opus 5.5)
 │   └ fodh codex task … → 런처 → 감독(ppid 1) → codex exec
 │
 ├ bin/fodh                 CLI. src/core 를 확장과 공유
 ├ hooks/pretooluse.mjs     Claude Code PreToolUse 훅(프로젝트 .claude/settings.json 에 설치)
 └ templates/ skills/       단계별 프롬프트 17종, 문서 템플릿, 인터뷰 은행, 하네스 스킬 4종
```

## 3. 두뇌: Claude Code 헤드리스

### 3-1. 호출

```
claude -p --dangerously-skip-permissions (--session-id|--resume) <sid>
  --output-format stream-json --verbose --include-partial-messages
  --append-system-prompt-file templates/brain-rules.md
  --settings <root>/.claude/settings.json --model <brain.model>
  [--setting-sources project,local --strict-mcp-config --mcp-config '{"mcpServers":{}}']   # brain.allowPlugins=false(기본)
```

- 턴마다 새 `claude -p` 를 띄우고 같은 Claude 세션을 `--resume` 한다. Pi 세션은 고정이고 Claude 세션만 이어진다.
- 자식은 `detached`(자기 pgid)로 뜨고 `FODH_BRAIN=1` 을 받는다. 레지스트리에 `kind:'brain'`, runId 와 함께 등록된다.
- `CLAUDECODE`·`CLAUDE_CODE_ENTRYPOINT` 와 과금 경로 변수(`ANTHROPIC_API_KEY`·`ANTHROPIC_AUTH_TOKEN`·`ANTHROPIC_BASE_URL`·Bedrock·Vertex·Foundry)는 자식 환경에서 뺀다. 사용자 설정 파일의 `env` 에 이 키가 있으면 설정 오류로 멈춘다.
- 기본값 `brain.allowPlugins=false` 는 사용자 전역 플러그인·스킬·MCP 를 두뇌에서 뺀다. 두뇌가 Codex 플러그인으로 `fodh` 를 우회한 라이브 사건(F27) 뒤에 넣었다.
- 두뇌가 claude-code 모델일 때 Pi 도구는 전부 끈다(`setActiveTools([])`). 두뇌의 도구는 Claude Code 자신의 것이다.
- Bash timeout 기본·최대 600000ms 를 주입한다. 턴 deadline 은 `brain.maxTurnMinutes`(기본 45분)이다.

### 3-2. 과금·한도 보호

- `system.init.apiKeySource` 가 `none` 이 아니면 `billing` 으로 중단한다.
- `rate_limit_event` 판정은 `src/provider/rate-limit.ts` `rateLimitVerdict` 가 한다. `isUsingOverage:true` 이거나 `overageStatus` 가 `rejected` 가 아니면 `paused(billing)` 으로 멈추고 알린다. A9 에서 두 계정 모두 조직 수준 extra usage 꺼짐(`org_level_disabled`)을 확인했다.
  - 예외(RL1, 09-27): 7일 사용률 75% 를 넘으면 오는 `status: allowed_warning` 이벤트는 `overageStatus` 키가 빠진다. 키가 없고 `isUsingOverage:false` 가 명시되며 status 가 `allowed`·`allowed_warning` 이면 계속한다. 그 밖은 그대로다.
- 한도 오류(`quota`)는 원장에 결과 불명 항목이 없을 때만 `brain.switchCommand`(기본 `cswap switch`)로 계정을 바꾸고 1회 재시도한다.
- 오류 분류: `deadline`·`user`·`billing`·`configError`·`protocolError`·`quota`. 결과가 불명인 턴은 `recovering` 으로 가서 증거 대조 프롬프트를 받는다.

### 3-3. doctor

- `fodh doctor` 와 session_start 가 haiku 로 짧은 점검 턴(`--max-turns 3`)을 돌린다. 유효 기간은 `brain.doctorTtlHours`(기본 12시간)이다.
- 확인 항목: 훅 차단 증거 2건(Bash 표식, `src/FODH_DOCTOR_MARKER.ts` Write), `claudeMdLoaded`(관리 블록 해시 `FODH-DOC-xxxxxxxx` 응답), `skillsMissing`, `pluginsLeaked`, 요청 모델과 `system.init.model` 일치.
- 최근 12시간 doctor 성공이 없으면 `IMPLEMENT`·`MERGE` 전이가 막힌다.

### 3-4. 두뇌 수명과 고아 회수(F30)

- Pi 가 SIGHUP·SIGTERM 으로 죽으면 프로바이더 처리기가 두뇌 그룹에 TERM→KILL 을 동기로 보내고 `.pi/harness-brain-orphan.json` 을 남긴 뒤 신호를 다시 올린다. 처리기는 `prependListener` 로 붙고, session_start 에서 떼었다가 다시 붙여 Pi 처리기보다 앞에 선다.
- 다음 session_start 는 orphan 파일을 원장 `brain:orphan-reclaimed` 로 옮기고, 열린 `brainTurn` 과 일치하는 살아 있는 두뇌 pgid 를 회수한 뒤 `recovering` 으로 전이한다.
- 잠금 소유자(Pi)가 죽었거나 확인되지 않으면 `FODH_BRAIN=1` 두뇌의 `fodh` 쓰기는 코드 2로 거부된다. 읽기는 허용한다.
- P8 부터 SIGINT 도 같은 방식으로 처리한다(K3). 외부 `kill -INT <pi>` → 두뇌 그룹 회수 → orphan 파일(`signal: SIGINT`) → Pi 종료를 라이브로 확인했다.
- SIGINT 에서 물러서는 조건: Pi 의 Ctrl+Z 일시 정지 중에는 Pi 가 `ignoreSigint` 리스너를 붙이므로 fodh 처리기는 회수하지 않는다. 그런데 Pi 의 `proper-lockfile` 이 끌어오는 signal-exit 3.0.7 도 SIGINT 리스너를 늘 달고 있고, 리스너 수가 자기 count 와 같을 때만 신호를 다시 올린다. 그래서 "다른 리스너가 있으면 물러선다" 는 첫 구현은 외부 SIGINT 를 삼켰다(P8-1, 호환성 조사에서 발견). 지금은 signal-exit 리스너 수(v3 `process.__signal_exit_emitter__.count` + v4 count)를 빼고 판정한다.
- 잠복 결함 P8-6: v4 count 를 `process` 에서 읽는데 v4 는 `globalThis[Symbol.for('signal-exit emitter')]` 에 둔다. 0.73.1·0.87.1 모두 v3 만 있어 지금은 증상이 없다. A16 라운드에서 고친다.
- 처리기 순서(K2): 단위·실제 프로세스 테스트로 고정했고, `streamSimple` 이 턴마다 순서를 확인해 어긋나면 맨 앞으로 되돌린다(원장 `shutdown:reorder`).

### 4-2. 전이 게이트(두뇌가 만들 수 없는 증거)

| 전이·명령 | 확인하는 증거 |
|---|---|
| INTERVIEW → RESEARCH | 필수 문항 답 또는 판단 이관 완료, 선택 문항 `skipDue` 비어 있음 |

| PROJECT_READY → PLANNING | 사용자만(`/develop-start` 또는 사용자 CLI) |
| PLANNING → PICK | 등록 task 1개 이상 |
| IMPLEMENT·MERGE 진입 | 12시간 안 doctor 성공 |
| `codex task`(git 프로젝트) | task 의 등록 워크트리와 그 안의 `--cwd` |
| VERIFY → REVIEW | `fodh verify run` 마지막 성공, 현재 task, VERIFY 진입 이후, 등록 워크트리와 같은 realpath cwd, 검증 당시 clean |
| REVIEW → MERGE | `--review-commit` 이 워크트리 HEAD 이고 base 이후 커밋 1개 이상, 같은 task 의 검수 meta(구현 meta 면제 틈 L4) |
| MERGE → DOCS | `--merge-commit` 이 루트 HEAD 의 조상이고 검수 커밋을 포함, 검수 커밋 자체는 fast-forward 일 때만 허용 |
| DOCS → CLEANUP | `${docs.root}/작업일지/` 오늘 또는 어제(KST) 파일에 taskId, 백로그 문서·JSON 동기화 |

`--verify-ok` 같은 자기 보고 옵션은 없다. 실패한 게이트는 두뇌가 면제할 수 없고 `fodh judgment add` 로 사용자에게 넘긴다.

### 4-3. PICK

- 결과 8종: `SPEC`(새 task), `RESUME`(판단 뒤 원 단계 복귀), `DONE_ALL`, `EMPTY`(백로그 없음, 정지), `WAIT_JUDGMENT`, `WAIT_RETRY`, `WAIT_RESOURCE`, `DEADLOCK`.
- RECLAIM 은 `task.resume{status,state,at}` 를 남긴다. 판단이 적용되면 PICK 이 그 task 를 원래 단계(VERIFY·REVIEW·MERGE 등)로 되돌린다. 진행 중 task 가 없으면 `resume.state` 가 오래된 순이다.
- `fodh pick --dry` 는 상태를 바꾸지 않고 후보만 보여 준다. 완료 task 는 판단 차단의 씨앗·전파에서 빠진다(F26).

### 4-4. 자동 재개 루프

- 두뇌 턴이 끝나면 오케스트레이터가 마지막 줄들을 본다.
  - `대기: 위임 <runId>`: 위임 완료(`codex-done`)까지 기다린다. 표지가 틀려도 살아 있는 위임이 있으면 대기로 본다(`delegation:implied`).
  - `대기: 슬롯 codex`: `paused(slot)` 으로 가고 슬롯이 비면 PICK 으로 돌아온다.
  - `대기: 사용자`: PICK 에서 후보가 있거나, task 진행 중인데 현재 task 를 막는 열린 판단이 없으면 거부하고 재개한다. `/hold` 또는 멈춤 어휘(`멈춰·기다려·잠깐·보류·확인할게·stop·hold·wait·pause` 등) 입력이 있을 때만 수락한다.
  - 표지 없음: 다음 단계 템플릿으로 자동 재개한다.
- 같은 상태에서 진전 없는 재개가 3번이면 정체 판단을 등록하고 멈춘다(`stopForJudgment`).
- 사용자가 Esc 로 중단하면(`userAborted`) 정체 재개에서 빠진다.

## 5. 판단대기·워처·인박스

### 5-1. 판단 문서

- `docs/판단대기.md` 는 J1 부터 짧게 유지된다. 절은 두 줄 안내 → `## 지금 상태`(한 줄) → `## 한눈에`(번호·제목·막힌 작업·추천 표, 하네스가 다시 만든다) → `## 열린 판단` → `## 보류`(사용자 절) → `## 최근 결정`(최근 N줄, `judgment.recent` 기본 5) 순서다.
- `## 열린 판단` 에 `### A<n> — 제목 (rev k)` 항목이 있고, 선택지는 `  ① …` 여러 줄이다. 사용자는 `- 답:` 줄만 채운다. 긴 설명은 `- 자세히:` 링크로 뺀다. 번호는 재사용하지 않는다(판단 파일·판단기록 전체·`.pi/harness-judgment-seq.json` 의 최댓값 + 1).
- 결정된 항목은 판단 파일에서 빠지고 `docs/판단기록/YYYY-MM.md`(KST 월)에 질문 원문·답·해석·반영과 함께 쌓인다. 판단기록을 먼저 쓰고 판단 파일을 나중에 쓰며, 그 사이에 죽어도 다시 적용할 때 블록이 두 번 생기지 않는다.
- 옛 형식 파일은 doctor 가 `judgment:legacy-format` 로 경고하고, 사용자가 `fodh judgment migrate [--dry-run]` 으로 옮긴다. 옛 결정 완료 표·지금 상태 이력은 `판단기록/이전.md` 로 원문 그대로 간다.
- 답 문법: 동그라미 숫자 또는 맨 앞 독립 숫자는 선택 번호, 승인 토큰, 나머지는 자유 서술이다. 본문 속 숫자는 선택으로 보지 않는다(F21).
- 선택·승인 답은 10초, 자유 서술 답은 60초 안정된 뒤 적용한다. 다시 편집하면 안정화를 다시 센다.
- 두뇌는 `fodh judgment add` 로만 판단을 만든다. `--blocks <taskId> --reclaim` 이면 task 를 `blocked(A<n>)` 로 두고 RECLAIM→PICK 으로 간다.
- 판단 답은 사용자만 쓴다. `judgment answer`·`apply` 는 CLI·코어 모두 `assertNotBrain` 으로 두뇌를 거부하고, 훅 규칙 7 이 판단 파일 직접 쓰기를 막는다(F24).

### 5-2. 두뇌 턴 중 변경(held)

- 두뇌·doctor 턴 직전에 `id → 답 줄` 스냅숏을 쓰고, 턴이 끝나면 비교한다. 턴 중에 바뀌거나 새로 생긴 답은 `held` 로 보류하고 알린다.
- held 는 `/judged A5` 처럼 번호를 명시해야 풀린다. 인자 없는 `/judged` 는 held 목록만 보여 준다.
- 비정상 종료 뒤 남은 스냅숏은 다음 session_start·recovering 에서 먼저 정산한다.

### 5-3. 워처와 인박스

- 워처 이벤트 5종: `judgment-changed`, `codex-done`, `slot-free`, `stalled`, `recover`. 워처는 해시·시각·생존만 보고 인박스에 쓴다.
- 오케스트레이터 `decideInbox` 가 이벤트를 결정하고 `autoResume` 을 부른다. 하네스가 쓴 내용은 기대 해시로 구분하고, 외부 편집은 `externalPending` 으로 보존한다.
- 두뇌 프롬프트 맨 앞에 `[인박스 <id>]` 가 붙고, 두뇌는 `fodh inbox ack` 로 닫는다.
- `/status` 는 워처 마지막 tick·판단 해시·안정 시간·정체 시작·초과 자식 수를 보여 준다.

## 6. 위임

### 6-1. Codex (`fodh codex task|review|research`)

- 시작 경로: CLI → 런처(짧게 살고 종료) → 감독. 감독은 ppid 1·자기 pgid 로 떨어져 두뇌 Bash 트리 정리와 무관하게 산다(F23). 런처가 15초 안에 감독 pid 를 못 주면 실패로 마감한다.
- 감독은 `codex exec` 를 돌리고 `.pi/codex/<runId>/` 에 프롬프트·JSON 로그·meta·결과를 남긴다. 완료되면 워처 `codex-done` 이 두뇌를 깨운다.
- 취소는 `fodh codex cancel <runId>` 다. 하네스의 모든 종료 경로는 `cancel.json` 을 먼저 쓰고 신호를 보낸다. 표지 없는 SIGTERM 은 무시한다.
- 슬롯: `~/.pi/agent/fod-harness/slots.json` 에 codex·claude·heavy 가 있고 기계 전체에서 Codex 1개다. 슬롯이 차 있으면 `paused(slot)`, 비면 자동 복귀한다. 외부(사용자 수동 점유)와 토이 사이의 직렬화도 라이브로 확인했다.
- `--wait` 상한은 `min(timeoutMinutes+1, maxTurnMinutes-5, waitMinutes)` 분이다. 결과 없이 끝나면 두뇌는 `대기: 위임 <runId>` 로 턴을 끝낸다. `--wait` 를 백그라운드로 돌리는 호출은 훅이 막는다.
- 복구: 감독이 죽어도 기록된 Codex 자식이 살아 있으면 슬롯을 유지하고, 60초 뒤 도구 그룹까지 회수해 `lost` 로 마감한다. pid 재사용은 `pid-reused`, 신원 불일치는 `group-unverified`.
- 모델: 수행자 `gpt-6-sol` xhigh(A11), GPT 두뇌 `gpt-6-astra` xhigh, 자식 에이전트 상한 1. Codex 자식은 `FODH_CODEX_CHILD=1` 을 받아 `fodh` 실행이 거부된다.

### 6-2. 워크트리

- `fodh worktree create <T> [--base]` 가 `../wt-<T>` 에 브랜치와 워크트리를 만들고 base 커밋을 기록한다. 만들기 전에 stale 등록을 prune 한다.
- `fodh worktree commit <T> -m` 은 등록 브랜치 확인, `.pi` 제외 `git add`, 추가된 줄의 비밀값 검사(1 MB 이하 텍스트 untracked 포함)를 거친다.
- 등록 워크트리 안에서는 `fodh` 실행을 거부한다. 두뇌는 루트에 머물고 검증만 `(cd <워크트리> && …)` 로 한다.

### 6-3. Claude Agent

- 디자인·검수 서브에이전트는 `delegate.claude.subagentModel=opus`(Opus 5.5)다. 두뇌의 Agent 도구로 돈다.
- 하네스는 Claude Agent 검수의 증거를 만들지 못한다. 그래서 REVIEW→MERGE 는 구현 meta 가 있으면 검수 증거를 면제한다(L4). 후속 후보는 `fodh review record` 다.

### 6-4. 우회 차단

- 두뇌의 `codex`·`claude`·`cswap` 직접 실행, codex-companion 스크립트, `plugins/cache/openai-codex` 경로, `mcp__*codex*` 도구, `codex:*` Agent·Task·Skill, `npx` 류 Codex 패키지는 훅이 거부한다.
- 글롭 경유 일부 형태(`node $(ls …/codex-comp*.mjs)`, `| xargs node` 등)는 다시 열려 있다(K1). 두뇌가 플러그인을 물려받지 않으므로 영향은 작다.

## 7. 검증·검수·문서·정리

- **검증**: `fodh verify run [--heavy] [--cwd]` 가 설정된 명령을 순서대로 돌리고 `.pi/verify/<runId>/result.json` 에 cwd·clean·종료 코드를 남긴다. heavy 슬롯과 Codex 슬롯은 서로 배타다. 외부 신호 중단은 `interrupted:"signal"` 로 구분해 코드 결함으로 보지 않는다.
- **검수**: 프로젝트 단계는 Codex review 위임 meta 가 증거다. task 단계는 같은 taskId 의 검수 meta 가 증거다.
- **문서**: DOCS 단계는 날짜별 작업일지와 백로그 동기화를 확인한다. 옛 `docs/작업일지.md` 는 건드리지 않는다.
- **정리**: `fodh cleanup run --scope processes|storage|worktrees|all [--task] [--dry-run]`. 레지스트리 프로세스 회수, 선언 경로 삭제, done 또는 현재 CLEANUP task 의 워크트리 제거를 한다. 죽었거나 pid 가 재사용된 기록은 `stale` 로 신호 없이 뺀다. 실행 중 verify·활성 위임·등록 60초 이내 기록은 `protected` 다.
- **메모리 워치독**: 60초 표본. 스왑이 `cleanup.swapWarnGB`(기본 8, 최소 3)를 5분 넘으면 `paused(memory)`, 경고치−2 GB 아래로 5분이면 자동 재개한다. `fodh memory reset` 은 사용자 전용이다.
- **알림**: TUI, macOS 알림, 원장. 같은 키는 60초에 한 번이다. Slack 은 `skip` 기록만 남긴다(A13 보류).
- **예산**: `budget.dailyTurns`(200)·`dailyHours`(20)는 값 검증만 하고 아직 강제하지 않는다.

## 8. 프로젝트 시작 도구(P5)

### 16-6. WisePharm 이관 방향([설계 v0.1](../이관/2026-09-25-WisePharm-이관-설계.md))

세 레포(web=`~/Desktop/chemical`·backend·app)를 읽기 전용으로 조사했다. 하네스는 루트 하나에 레포 하나라서 레포마다 루트를 둔다. 순서는 backend 파일럿 → app → web 이다. backend 는 push 해도 CI 만 돌고 운영 `.env` 가 없으며 검증이 오프라인이다. web 은 main push 가 운영 배포이고 루트 `.env` 가 운영 DB 이며, `npm run db:migrate`·Slack 봇 같은 위험 명령이 기본 승인 규칙에 걸리지 않는다(H9 설정으로 막는다). web·app 전에 H11(두뇌의 `.env`·`neon_api.json` 읽기 차단)과 H12(워크트리 준비 명령, flutter `.dart_tool`)를 더한다. 사용자 판단 A19~A22(순서·원장·작업 기록·backend AGENTS.md 개정)는 09-26 에 모두 ① 로 결정됐다. backend `03187bd`(AGENTS.md 하네스 흐름 개정·WORKLOG 동결 줄·하네스 `.gitignore` 줄)를 push 했고 CI 만 돈다. 파일럿 설정(`.pi/harness.json`: 두뇌 Opus 5.5, 워크트리 `../wpb-wt-`·`node_modules` 링크, 검증 lint·build·test·schema:check, 무거운 검증 test:infra·test:e2e, 승인 규칙 db-migrate·maintenance)과 새 형식 판단대기·백로그 T01·CLAUDE.md 관리 블록은 backend 로컬 커밋 `0fa3aec` 에 있다(push 안 함, A23). `.claude/`(훅 설정·스킬)는 `.git/info/exclude` 로 로컬에만 둔다. 결과는 16-8.
